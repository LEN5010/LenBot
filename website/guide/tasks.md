# 后台任务

写报告、整理资料、做网页这类长活，Bot 可以交给后台任务。任务在独立的 Docker 容器里由 Pi 执行，聊天不用等它做完。

## 启用

1. 准备任务镜像：用官方的 `ghcr.io/lendevs/lenbot-worker:<版本>`，或者从仓库的 `docker/next-worker/Dockerfile` 自己构建。
2. 在能力页配置任务环境：Docker 命令的绝对路径、Docker socket、工作目录、运行目录和交付目录。三个目录分开，Docker 能访问，容器的 `uid/gid` 能读写。
3. 在模型页绑定 `worker` 用途的模型。
4. 在群设置里开启任务，在设置页的权限里定谁能发起任务。
5. 角色的工具许可里包含 `delegate`、`task` 和 `tool_search`；要用技能时，角色的技能许可也要包含它。

任务容器没有网络，模型和公网请求都经过 LenBot 转发，真实密钥不进容器。Docker 安装的具体挂载见 [Docker](./install-docker#后台任务)。

## 使用

- **资料**：资源页可以上传本群共享资料。新建任务时可以从共享资料、其他任务的文件和交付里选，最多 16 份，任务拿到的是只读副本。
- **追问和续接**：任务可以向发起人提问，等回答期间不占执行名额。任务结束后可以明确续接，沿用原来的会话和文件。失败不会自动重试。
- **产物**：生成文件、登记为交付、发到 QQ 是三件事，各有记录。在任务详情里可以预览、下载、登记和发送。
- **清理**：清理临时文件会保留会话、输入和产物；释放环境会删除整个工作区，之后不能续接，已登记的交付和共享资料保留。
- **渲染**：任务镜像带 `lenbot-render`，能把 HTML 渲染成 PDF 和截图。

## 发到 QQ

OneBot 要能读到交付目录：把交付目录只读挂给 OneBot，再把 `onebot.upload_visible_root` 设成 OneBot 看到的路径。面板显示已登记，不代表 QQ 已经收到，实际上传结果单独记录。

## 停机和升级时

重启或升级会中断正在执行的任务，任务标为中断，保留会话和文件，之后可以续接；排队中的任务继续排队。

用官方任务镜像时，部署包和 Docker 的面板升级会一起换成同版本的任务镜像；自己构建的镜像要自己重建并改配置。
