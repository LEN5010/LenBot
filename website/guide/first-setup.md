# 首次配置

实例里还没有 `lenbot.config.json` 时，LenBot 不会直接启动，而是先开一个网页向导：

```text
尚无根配置。请打开 http://127.0.0.1:52811/#token=...
```

- 部署包和源码运行只监听本机，端口每次随机；Docker 固定用面板端口，默认 11307，见 [Docker](./install-docker#第一次启动)。
- 链接里的 `token` 是这次启动的初始化令牌。刷新页面不会丢掉已填的普通字段，但密码和密钥要重新填，QQ 和模型也要重新测试。
- 已经有配置的实例不能再走一遍向导。

向导分六步，填完一步点「下一步」。

## 1. 管理员账号

面板的用户名和密码（至少 8 位），以及之后面板用的端口，默认 8088。这是这个实例唯一的面板账号，不是注册系统。

## 2. 连接 QQ

| 字段 | 说明 |
|---|---|
| 时区 | 默认 `Asia/Shanghai`，影响时间显示、安静时段和提醒 |
| 连接方式 | LenBot 去连 OneBot（正向 WebSocket），或 OneBot 来连 LenBot（反向 WebSocket），见[接入 QQ](./onebot) |
| 访问令牌 | 和 OneBot 那边填的一致；反向连接监听非本机地址时必填 |
| 回复怎么发 | 模拟发送或真的发到 QQ |

填好后点**测试连接并读取 Bot 账号**。这一步只读取 OneBot 当前登录的 QQ 号，不会往群里发消息。测试通过才能进下一步，所以 OneBot 要先跑起来。

第一次建议选**模拟发送**：Bot 照常收消息、照常调用模型想回复，只是不发到 QQ。之后在**设置 → 连接**里改。

## 3. 主人

填你自己的 QQ 号。主人是这个 Bot 权限最高的人，更多主人之后在面板里加。

## 4. 模型

这里配的是聊天用的主模型（`mind` 用途），看图、记忆整理、后台任务等其他用途进面板再加，见[可选服务](./optional-services#模型用途)。

1. 选协议：OpenAI 兼容聊天、OpenAI Responses、Anthropic Messages 或 Gemini，选服务商实际提供的那种。
2. 填接口地址和 API Key。需要代理的话填 HTTP 或 HTTPS 代理地址。
3. 点**读取模型列表**选一个，或者直接手写模型名。
4. 按服务商文档填上下文窗口。输入压缩阈值和每次最多输出有默认值，一般不用动。

最后点**测试模型连接**，通过后才能进下一步。「文本连接」调用一次模型，「工具调用与续接」调用两次，都会计费，都不往 QQ 发消息。文本测试通过只说明能聊天，不代表这个模型支持工具或图片。

## 5. 角色和第一个群

角色默认用**小然**，带完整的设定、说话方式、底线、资料和表情，之后可以在面板里改。想从头写就选「创建自定义角色」，填文件夹名、名字、它是什么样的人、怎么说话，底线可以留空。

再选先在哪个群或私聊里聊，填群号或对方 QQ。群里默认只回应 @ 它或回复它的消息，私聊每条都回。其他群之后在面板里加。

## 6. 官方插件

可以直接跳过，以后在插件页装。勾选的话，保存时会联网下载插件和它声明的 Python 依赖，装好后先保持停用，进面板再配置、启用和选群。GSUID Core 桥接还需要另外部署 GSUID Core 服务。

插件装失败时，账号和配置都还没保存，已经下好的插件会保留。可以重试，或者取消勾选失败的那个继续。

## 保存之后

向导关闭，程序按新配置继续启动，页面给出面板地址。通过 SSH 转发或反向代理访问、端口和本机不一样时，先改一下地址再打开。

QQ 或模型测试失败、保存失败，表单都不会清空，按错误提示改完重试即可。如果保存后迟迟进不了面板，看终端日志；配置已经写好，不需要重新初始化。

普通聊天不需要先部署任务容器或账号浏览，这些用到时再加。

## 之后改设置

所有设置都在实例目录的 `lenbot.config.json` 里。这是唯一的运行配置，不读环境变量和命令行参数。文件里有密钥，不要提交到 Git，也不要发给别人。

平时在面板里改。需要重启才生效的修改，顶栏会提示，点重启前会列出受影响的设置和正在进行的工作。真要手工编辑这个文件，先停机。

## 从别的机器打开面板

面板默认只监听本机。从别的机器访问，用 SSH 端口转发，或者自己配一个 HTTPS 反向代理，不要直接把监听地址改成公网地址。

```sh
ssh -L 8088:127.0.0.1:8088 你的服务器
```
