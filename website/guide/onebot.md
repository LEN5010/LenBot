# 接入 QQ（OneBot）

LenBot 自己不登录 QQ。它连接一个已经登录 QQ、打开了 OneBot v11 WebSocket 的程序，比如 [NapCat](https://github.com/NapNeko/NapCatQQ)，通过它收发消息。这些程序怎么安装和登录，请看它们自己的文档。

## 选连接方式

| 方式 | 谁连谁 | LenBot 这边填 | OneBot 那边开 |
|---|---|---|---|
| 正向 WebSocket | LenBot 去连 OneBot | OneBot 的地址，例如 `ws://127.0.0.1:3001` | WebSocket 服务端 |
| 反向 WebSocket | OneBot 来连 LenBot | 监听地址和端口，向导默认 `127.0.0.1:8080` | WebSocket 客户端，地址填 `ws://<LenBot 地址>:<端口>` |

两边在同一台机器上，用哪种都行，正向更省事。OneBot 在另一台机器或另一个容器里时，看谁能访问到谁：LenBot 访问得到 OneBot 就用正向，反过来就用反向。

**访问令牌**两边填同一个。反向 WebSocket 监听的不是本机地址（比如 Docker 里的 `0.0.0.0`）时一定要设。

用反向连接时，OneBot 那边要满足三点，否则 LenBot 会拒绝连接：

- 用 Universal 模式，一条连接同时收事件和调接口。
- 同一时间只连一条。
- 登录的 QQ 号和配置里的 Bot 账号一致。

首次配置时点「测试连接并读取 Bot 账号」，能读出 QQ 号就说明通了。之后要改连接方式，到面板的**设置 → 连接**；连接状态在首页看。

## 断线以后

运行中连接断了，不用手动处理：

- **正向**：LenBot 自己重连。第一次等 1 秒，之后每次翻倍，最长 30 秒；连上并稳定 30 秒后，下次断线又从 1 秒开始。重连后会重新核对 QQ 号。重连失败的原因和下次重试的间隔会作为「QQ 连接出错」出现在首页和日志页。
- **反向**：LenBot 一直监听，等 OneBot 连回来。

两种情况要手动处理：

- **启动时第一次就连不上**（地址填错、OneBot 还没起来）：LenBot 不会自己反复试。修好之后点首页的**手动连接 QQ**。
- **在首页点了断开 QQ**：要在右上角账号菜单里重启才会重新连上。

## 模拟发送和真实发送

- **模拟发送**：照常收消息、想回复，回复只记在面板里，不发到 QQ。刚装好时用它看效果。
- **真实发送到 QQ**：角色和设置都调好后，在**设置 → 连接**里切换，重启后生效。

## Docker 里的网络

容器里的 `127.0.0.1` 是容器自己，不是宿主机。让 OneBot 和 LenBot 加入同一个 Docker 网络，用容器名互相访问，例如 `ws://napcat:3001`；或者填宿主机在 Docker 网络里的地址。

## 发文件

后台任务的产物要发到 QQ 时，OneBot 得能读到 LenBot 的交付目录：把交付目录只读挂给 OneBot，再在**设置 → 连接**的高级选项里填「OneBot 可见的文件目录」（配置项 `onebot.upload_visible_root`），写 OneBot 那边看到的绝对路径。见[后台任务](./tasks#发到-qq)。
