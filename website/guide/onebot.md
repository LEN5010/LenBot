# 接入 QQ（OneBot）

LenBot 本身不登录 QQ。它连接一个已经登录 QQ 并开启了 OneBot v11 WebSocket 的程序，例如 [NapCat](https://github.com/NapNeko/NapCatQQ)，通过这个程序收发消息。这类程序的安装和登录方法，请参考它们各自的文档。

## 选择连接方式

| 方式 | 连接方向 | LenBot 一侧填写 | OneBot 一侧开启 |
|---|---|---|---|
| 正向 WebSocket | LenBot 连接 OneBot | OneBot 的地址，例如 `ws://127.0.0.1:3001` | WebSocket 服务端 |
| 反向 WebSocket | OneBot 连接 LenBot | 监听地址和端口，向导默认 `127.0.0.1:8080` | WebSocket 客户端，地址填 `ws://<LenBot 地址>:<端口>` |

两者在同一台机器上时，两种方式都可以使用，正向连接更简单。OneBot 在另一台机器或另一个容器里时，按网络的可达方向选择。LenBot 能访问 OneBot 时使用正向连接，反之使用反向连接。

**访问令牌**在两侧填写相同的值。反向 WebSocket 监听本机以外的地址时（例如 Docker 中的 `0.0.0.0`），必须设置访问令牌。

使用反向连接时，OneBot 一侧需要满足以下三个条件，否则 LenBot 会拒绝连接。

- 使用 Universal 模式，在同一条连接上接收事件和调用接口。
- 同一时间只建立一条连接。
- 登录的 QQ 号与配置中的 Bot 账号一致。

首次配置时点击「测试连接并读取 Bot 账号」。能读取到 QQ 号，就说明连接成功。之后修改连接方式，请到面板的**设置 → 连接**。连接状态显示在首页。

## 断线以后

运行期间连接断开时，不需要手动处理。

- **正向连接**。LenBot 会自动重连。第一次等待 1 秒，之后每次等待时间翻倍，最长 30 秒。连接恢复并稳定 30 秒后，下次断线重新从 1 秒开始计算。重连后会再次核对 QQ 号。重连失败的原因和下次重试的间隔会以「QQ 连接出错」显示在首页和日志页。
- **反向连接**。LenBot 持续监听，等待 OneBot 重新连接。

以下两种情况需要手动处理。

- **启动时第一次连接就失败**，例如地址填错，或者 OneBot 尚未启动。这时 LenBot 不会自动重试。问题解决后，点击首页的**手动连接 QQ**。
- **在首页点击了断开 QQ**。需要在右上角的账号菜单中重启，才会重新连接。

## 模拟发送和真实发送

- **模拟发送**。Bot 照常接收消息并生成回复，回复只记录在面板里，不发送到 QQ。刚安装时可以用这种方式观察效果。
- **真实发送到 QQ**。角色和设置都调整好后，在**设置 → 连接**中切换，重启后生效。

## Docker 中的网络

在容器中，`127.0.0.1` 指向容器本身，而非宿主机。可以让 OneBot 和 LenBot 加入同一个 Docker 网络，用容器名互相访问，例如 `ws://napcat:3001`。也可以填写宿主机在 Docker 网络中的地址。

## 发送文件

后台任务生成的文件要发送到 QQ 时，OneBot 必须能读取 LenBot 的交付目录。设置方法分两步。

1. 把交付目录以只读方式挂载给 OneBot。
2. 在**设置 → 连接**的高级选项中填写「OneBot 可见的文件目录」（配置项 `onebot.upload_visible_root`），值为 OneBot 一侧看到的绝对路径。
