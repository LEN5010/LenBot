# 更新与恢复

部署包和 Docker 安装都带有一个**更新器**。更新器和 LenBot 分开运行，因此 LenBot 停机升级时仍然可以打开更新页，升级失败后也可以从更新页恢复。

从源码运行时不使用更新器，更新方法见[从源码运行](./install-source#更新)。

## 新版本检查

面板启动一分钟后检查一次新版本，之后每天检查一次。部署包和 Docker 向各自的更新器查询，从源码运行时直接查询 GitHub Releases。检查只查询，不安装，升级仍然需要在更新页确认。

有新的正式版本时，顶栏会显示「新版本 x.y.z」。点击后进入**设置 → 版本与更新**。这里显示当前版本，以及上次检查的时间和结果。点击「检查发行版本」可以立即检查一次，列表中会标出比当前版本新的版本。

如果不希望定期访问 GitHub，请停止 LenBot，在 `lenbot.config.json` 的 `panel` 中加入 `"update_check": false`。手动检查仍然可以使用。

## 在面板中更新

1. 在面板中打开设置 → 版本与更新，点击**打开更新与恢复页**。
2. 点击检查发行版本，选择一个版本。默认只显示正式版本，勾选显示预发布版本后才能看到候选版本。
3. 点击**准备更新**。更新器下载新版本（Docker 拉取新镜像），安装新的程序环境，并检查已启用的插件是否兼容。这一步期间 LenBot 照常运行。
4. 准备完成后，确认**停机、备份并升级**。更新器按以下顺序执行。
   1. 停止 LenBot。
   2. 为实例制作完整快照。
   3. 执行数据迁移并检查实例。
   4. 切换到新版本。
   5. 启动新版本，等待它就绪。

制作快照前会先估算快照大小。磁盘空间不足以容纳快照和额外 256 MiB 余量时，升级直接停止，程序和数据都不会改动。清理出空间后重新升级即可。迁移后的检查与 `doctor` 命令相同，检查没有通过同样算作升级失败，可以从快照恢复。

升级期间，聊天和后台任务会暂停。进行中的任务会被标记为中断，会话和文件保留，之后可以续接。

在面板中修改过[框架提示词](./panel.md#框架提示词)时，新版本启动后默认改用新版本自带的提示词，原来的修改移到 `state/prompts/.replaced/`。

### 插件不兼容

准备阶段如果发现已启用的插件不支持新版本，会列出这些插件并停止准备。请先升级这些插件，或者在插件页停用它们，然后重新准备。停用的插件不会丢失源码和参数，数据也会保留。

### 后台任务镜像

使用官方任务镜像 `lenbot-worker` 时，准备阶段会提前拉取同版本的任务镜像，升级时一起切换。自行构建的任务镜像不会被改动，需要时请自己重新构建，再修改配置。

## 出问题时

更新器不会自动重试，也不会自动回退。任何一步失败后，更新页都会显示可以执行的操作。

| 失败的步骤 | LenBot 的状态 | 可以执行的操作 |
|---|---|---|
| 准备阶段（下载、安装环境、兼容检查） | 照常运行 | 解决问题后重新准备 |
| 已经停机，快照尚未完成 | 已停止，程序和数据都没有改动 | 启动原来的版本 |
| 快照完成之后（迁移、切换、启动新版本） | 已停止 | 恢复升级前的程序和数据 |

**恢复**会把程序和实例数据都换回升级前的快照，升级之后产生的聊天记录和修改都会丢失。恢复完成后点击启动。

恢复前，更新器会逐个核对快照中每个文件的长度和 SHA-256，发现缺失或损坏时停止恢复。核对通过后，先把快照完整复制到实例旁边的临时位置。复制中途出错时（例如磁盘已满），当前实例同样不会被改动。全部复制完成后才会替换。

升级成功以后，在准备下一次更新之前，随时可以从更新页恢复到升级前的状态。

### 打开更新页

面板仍然可以使用时，从设置中进入。面板无法打开时，按安装方式找到更新页的链接。

- **部署包**。使用 `run` 启动时，终端会打印一行「更新与恢复」链接。作为服务运行时，在服务日志中查找这个链接。
- **Docker**。执行 `docker compose -p lenbot logs lenbot-updater`，日志中有带会话令牌的链接，默认端口为 11308。

## 离线升级（部署包）

也可以不经过面板升级。停止 LenBot 后，在新版本的部署包目录中执行下面的命令。

```sh
./install.sh upgrade "$HOME/lenbot"
```

离线升级与面板升级执行相同的步骤。先检查插件，然后制作快照和迁移数据，最后切换版本。区别是完成后不会自动启动，需要手动启动 LenBot。之后同样可以在更新页恢复到升级前。如果上一次升级失败后还没有恢复，离线升级会拒绝执行，请先到更新页完成恢复。

## 更新器自身的升级

更新器不会替换自己。新版本需要更新的更新器时，更新页会停止准备，直接给出要执行的命令。

- **部署包**。用新版本的部署包执行离线升级，即上一节的 `install.sh upgrade`，程序和更新器会一起更新。
- **Docker**。用新版本的更新器镜像执行一次 `init.py --updater-only`，再执行 `docker compose up -d` 换上新的更新器，然后回到更新页继续。

## 版本规则

- `0.2.0` 这样的版本号是正式版本。带有 `rc`、`b` 或 `a` 后缀的是预发布版本。
- 补丁版本（例如 `0.2.1`）保持插件接口和数据格式兼容。不兼容的改动会提升次版本号（例如 `0.3.0`）。
- 已经发布的版本不会被覆盖。各个版本的说明见 [changelogs](https://github.com/lendevs/LenBot/tree/master/changelogs)。
