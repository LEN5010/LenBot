# 角色包

角色包决定 Bot 是谁、怎么说话。一个角色包就是一个目录，可以在面板的角色页编辑，也可以直接写文件。完整例子见[示例角色小满](../examples/personas/companion/)。

```text
companion/
  persona.yaml       名字、身份、性格、许可
  voice.md           说话方式
  boundaries.md      底线
  examples.yaml      情境和台词样例
  knowledge/         可检索的资料（可选）
  stickers/          表情图片和 index.yaml（可选）
  avatar.png         头像（可选）
```

## persona.yaml

| 字段 | 内容 |
|---|---|
| `id` | 目录名，小写英文、数字和 `-` |
| `name` | 名字 |
| `brief` | 一两句话说清是谁 |
| `behavior` | 性格和相处方式：对什么感兴趣，遇到不同情况怎么反应 |
| `self_reference` | 自称，例如 `[我]` |
| `aliases` | 别人怎么叫它；群里提到这些名字会引起它注意 |
| `tools` | 允许用的工具，`all` 或名字列表；`[]` 表示不用工具 |
| `skills` | 允许后台任务使用的技能，`all` 或名字列表 |
| `styles` | 可选的轮换风格，每项有 `name`、`weight`、`note`，权重加起来等于 1；不用就写 `[]` |
| `example_tags` | 只用带这些标签的样例；不写就用前 8 条 |

`voice`、`boundaries`、`examples` 必须写在各自的文件里，不能放进 `persona.yaml`。

## 写法建议

**写人，不写规则。** `behavior` 和 `voice.md` 描述这个人平时什么样，模型会自己判断具体场合怎么做。一长串不许做什么，往往让回复变得僵硬。

**一个特点是底色，不是口头禅。** 比如写她爱吃，模型就可能每句都提吃的。写清楚这个特点在什么时候出现，或者只在样例里自然带一下。

**说清打字习惯。** 句子长短、用不用句号和感叹号、会不会只回一个词，这些比形容词更能让回复像真人。

**表情承担情绪。** 有表情包时，在 `voice.md` 里说明：话照常说，情绪交给表情，文字里不再重复强调。

**样例写情境和一句台词。** `context` 写当时的情境，`line` 写它会怎么回。样例只是示范语气，内容不要和真实群聊经历混在一起。准备多套样例时用 `tags` 区分，再用 `example_tags` 选。

**事实放进资料。** 生日、经历、作品这类需要说准的内容写进 `knowledge/` 下的 Markdown，模型需要时会检索；资料里没有的，它应该说不知道。

## 表情

`stickers/index.yaml` 是一个列表，每项对应一张图片：

```yaml
- file: happy.png
  description: 笑脸：眯眼咧嘴笑，脸颊泛红。适合：开心、被逗笑、替别人高兴。
  emotions: [开心, 被逗笑]
  tags: [笑, 开心]
```

`description` 写清画面和适合的场合。模型按情绪或关键词选图，同类里少用的优先。

## 测试和采用

在角色页编辑后，可以先用草稿开一个试聊，觉得可以再保存。哪个群用哪个角色在群设置里选，修改在重启后生效。

改动比较大时，用[表达回放](../examples/replay/)对照改动前后的回复。
