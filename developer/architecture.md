# 架构

本文面向想修改 LenBot 本身的开发者，说明各部分的职责和数据的流向。字段和默认值以源码为准，源码目录的对照见 [CONTRIBUTING](../CONTRIBUTING.md#源码结构)。

## 整体

LenBot 是一个单进程的宿主程序，按群聊场景组织。

- 每个场景（一个群或一个私聊）有一份持久的 Agent 会话。
- 消息、插件事件、任务进展和定时提醒，都作为这个会话的输入。
- 主脑模型读取完整的上下文，自行决定说什么、调用哪些工具。
- 宿主不替模型判断语境，只负责三件事，即真实身份、会话连续性和执行状态。

```text
OneBot ──> 平台适配器 ──> 消息入库 ──┬─> 插件规则直接处理（不经过模型）
                                    └─> 注意力决定开轮 ──> 主脑工具循环 ──> 表达／工具／任务
                                                              ^
                       插件事件、任务事件、提醒 ───────────────┘
```

耗时较长的工作交给独立的容器，长期记忆由本地记忆服务维护，插件和宿主运行在同一个进程中。普通聊天不依赖任务容器或外部服务。

`len-bot` 命令进入 `launcher.py`。启动器只管理一个 `len_bot.next.host` 子进程。宿主的退出码为 75 时，启动器会再启动一次宿主，面板的重启功能就是这样实现的。其他退出码都会结束启动器。

## 平台

`platform/` 把平台的原生事件转换为统一的消息和通知。目前只有 OneBot 适配器，QQ 的消息段和接口只出现在 `platform/onebot*.py` 中。

- 账号写成 `平台:账号`，例如 `onebot:70001`。
- 场景写成 `平台:group:群号` 或 `平台:private:账号`。
- 提及统一为 `mention`，语音统一为 `audio`。
- 原始事件单独保存。通知的规范字段存放在 `notices.body` 中，业务代码不再解析 OneBot 的原始字段。
- 正向连接在运行期间断开后会自动重连。间隔从 1 秒开始，每次翻倍，最长 30 秒，连接稳定 30 秒后重置。重连后会重新核对账号。反向连接则等待对端重新连接。只有启动时第一次连接失败，才需要在面板上手动连接。

## 聊天

| 模块 | 职责 |
|---|---|
| `runtime/network.py` | 连接平台，把消息分发给各个场景 |
| `chat/attention.py` | 决定什么时候开始一轮回复 |
| `chat/session.py` | 主脑的工具循环 |
| `chat/context.py` | 组装模型请求 |
| `chat/expression.py` | 台词、表情、引用和发送 |

### 会话

`messages` 保存真实的收发记录，`mind_entries` 保存已经交给模型的批次和完整的工具交换。轮次只是执行单位，一轮结束不会清空会话。

### 请求顺序

请求按以下顺序组装。

1. 稳定的角色和能力说明
2. 旧的回想
3. 原话和工具交换
4. 本轮的宿主参考

原话保留真实的账号、时间、消息 ID、引用和媒体状态。

启动恢复信息放在本轮宿主参考中，不追加为群友发言。历史中已有的独立宿主启动记录不参与聊天投影或回想压缩，原记录仍保留。

### 表达

同一个主脑决定态度、对象、台词和工具。`say.content` 就是要发送的正文，`react` 可以单独发送表情，模型的普通文字不会发出去。选中的素材、模拟发送、平台确认和发送失败分别记录。

`react` 的图片使用 OneBot 自定义表情子类型发送。超过 320 像素的素材在发送副本上按比例缩小，动画帧、时长和循环保留，原素材不改；插件发送的普通图片继续使用普通图片类型。

`say.sticker` 使用与 `react` 相同的 file/emotion/query 选择方式，把正文和一张表情放在同一条平台消息里。该字段沿用角色已有的表情权限；纯文字仍按既有长度分段，单独的 `react` 仍可使用。

`message_reaction` 是低频独立动作，通过 NapCat 和 SnowLuma 共用的 `set_msg_emoji_like` 给当前群已保存的消息贴表情。它沿用角色工具权限和发送出口，群禁言时不执行；平台返回失败则把原文交还给模型。贴表情不会产生新的聊天消息，成功回执保存在工具记录中，计入本轮首个回应时间；`end_turn` 默认 true，可以直接完成这一轮。

记忆与说法索引支持面板一键重建。记忆重建持有现有各场景和公共分区的写入锁，说法重建持有该场景的索引锁；生成向量时保留旧索引，成功后一次替换。无需增加持久任务、重启流程或数据格式版本。命令行仍用于停机维护。

模型的 `say.mention` 只接受 `onebot:<正整数账号>`，不能用 `onebot:all` 提及全体成员，也不能使用其他平台前缀。可信插件仍然可以使用显式的 `Mention("all")` 接口。OneBot 出口会校验其余被提及的账号，然后再编码发送。

### 一轮的结束

生成期间新到达的消息照常入库，不会插入已经发出的请求。一组工具执行完毕，并且最后一次表达带有 `end_turn=true` 时，这一轮结束，之后到达的消息留给下一轮。否则，把新消息和事件追加到请求中，再请求一次。

### 压缩

输入的估算值超过 `compaction.input_tokens` 时，把较早的完整消息和工具组整理成回想，原始数据不删除。估算优先使用上一次请求的实际用量，没有时按字节数估算。细节见[上下文与模型输入](context.md)。

### 续接协议

调用记录保存完整的原始响应。

- `history_policy=native` 原样回传历史。
- `omit-reasoning` 省去可读的思考内容，并带上稳定的 `Session-Id`，只用于自行维护续接的中转服务。这个标识由实例数据库路径、场景和用途计算哈希得到，不会发送数据库的绝对路径。

## 角色与学习

角色包由 `persona/` 读取，说明见[角色包](personas.md)。提示词放在 `src/len_bot/prompts/`，原则说明见[群聊表达](expression-materials.md)。

`learning/` 从群聊中学习。每个群可以分别开关学习功能，各项能力各自绑定模型。

| 能力 | 作用 |
|---|---|
| 表达 | 提取群友有特点的说法，每轮按近期的对话选出几条作为参考 |
| 黑话 | 找出群里的特殊用词并推断含义，可以人工固定或禁用 |
| 表情 | 收集群里的图片并标注，采用后可以和角色的表情一起使用 |
| 回复效果 | 观察 Bot 发言后群友的反应，用于复盘，不会自动修改角色 |

学到的内容只作为参考进入上下文，不会冒充角色设定或群聊经历。

说法向量索引缺失或与当前绑定不一致时，暂停该场景的说法检索，继续运行聊天和面板。学习页显示具体重建入口；距离计算仍只使用模型和维数一致的向量。

## 记忆

`memory/` 是唯一的长期记忆后端，正文是本地的 Markdown 文件。

- `public/` 存放明确公开的资料。
- `scenes/<场景>/` 存放各个场景自己的记忆，其下再分为 `people/<账号>/`、`events/`、`bot/<角色ID>/` 和 `resources/`。

群聊只读取当前场景和公开资料，同一个人在不同群的记忆不会合并。`.memory-index.sqlite3` 保存索引、修改历史和目录摘要的生成时间。它并非缓存，不能随意删除。摘要的生成和正文的变更都使用应用时钟，判断是否过期时不读取文件的 mtime。

替换正文和摘要时，先保留本次操作涉及的旧文件，索引事务提交后再移除这些记录。如果操作中断，读取时会按索引的提交状态还原未完成的文件替换。角色资料的四个文件也按一次编辑统一提交，未完成的编辑会还原为旧文件。模型调用正文到期清理时，工具参数和结果同批清理。遗忘记忆不等于删除聊天日志或备份。

每轮开始时自动召回记忆。先读取最近几位发言人的画像，再用最近的对话检索。召回结果只放进本轮的参考材料，不写入会话历史。后台整理按批次读取新消息，由 memory 模型浏览、搜索和改写记忆文件。整批成功后，才推进处理进度。

## 工具

`chat/tools.py` 管理工具目录和分派。一个工具同时满足以下条件时才会出现。

- 有实现
- 根配置中已开启
- 场景允许使用
- 角色的 `tools` 许可包含这个工具

常用的工具直接提供给模型。低频工具需要先通过 `tool_search` 发现，下一次请求才会带上它的参数定义。工具出错时，错误原样返回给模型，宿主不重试，也不更换服务。网页、文件和插件返回的内容只是资料，不作为执行授权。

MCP 服务的工具与插件工具使用同一套发现和许可机制。技能由 `SKILL.md` 和资源文件组成，以只读方式挂载进任务容器。

## 后台任务

`work/` 使用 Pi 在独立的 Docker 容器中完成耗时较长的工作，聊天不需要等待任务结束。

- `delegate` 用真实的请求人和场景创建任务。`task` 用于查询、回答、追加、取消和续接任务。
- 任务的完成事件会回到原场景的会话中。
- 容器以非 root 身份运行，根文件系统只读，没有网络。模型请求和公网请求经过宿主转发，真实密钥留在宿主中，任务只拿到本任务的令牌。
- 模型请求只接受客户端的函数工具声明，不转发服务商服务端的网络工具。公网访问会核对并固定真实地址，任务的限速由所有连接共享。
- 输入文件是只读的快照。产物登记为交付后，才能下载或发送。单个文件的大小和整个任务的累计交付大小分别受配置限制。
- 普通场景中的失败通知只给出事件编号、类型和时间。过程原文按原有的任务权限读取。

浏览器有两种，分别是任务容器中的匿名 Chromium，以及主人配对的账号浏览器。

## 插件

插件是与宿主运行在同一进程中的可信 Python 代码，用来处理精确的命令、平台事件、后台监测和专用工具。接口见[插件 v1](plugins-v1.md)。

### 匹配

命令、全文和正则依次匹配纯文本，每条消息最多被一个插件接管。插件处理的消息和结果会作为背景进入会话，但不会因此唤醒模型。

### 唤醒

`send` 直接发送消息，`emit_event` 会唤醒主脑。

### 安装

通过 Git 和 ZIP 安装时，都先准备候选版本，再明确应用。依赖没有变化的插件定向重新加载。依赖有变化，或者插件声明需要重启时，在下次重启的停机阶段统一安装依赖。

### 目录

插件都存放在实例根目录的 `plugins/` 下。

| 内容 | 位置 |
|---|---|
| 已安装的源码 | `plugins/<名字>/` |
| 候选版本 | `plugins/.candidates/` |
| 来源记录 | `plugins/.installations/<名字>.json` |
| 插件数据（默认位置，卸载时保留） | `plugins/.data/<名字>/` |

手动复制进 `plugins/` 的插件也会被发现。

## 配置与权限

`lenbot.config.json` 是唯一的运行参数来源，在入口处一次性解析并完整校验。面板和群里的管理工具都通过 `configuration/editing.py` 保存配置，共用一把写锁。插件配置会定向重新加载，其他修改在明确重启后生效。

权限只看真实身份。判断谁在发出请求由宿主负责，请求指向谁由模型判断。

- `owners` 是全局主人。
- 场景管理员、白名单、黑名单和群角色参与各项能力的判断。
- 群里的管理工具只对主人和全局管理员开放。

宿主、面板和维护命令都必须先获取实例锁 `.lenbot-instance.lock`，防止同一个实例被启动两次。

## 存储

一个 SQLite 业务数据库保存以下数据，各领域的表和查询由所属的模块维护。

- 消息、会话和轮次
- 模型调用
- 任务和提醒
- 学习记录
- 插件事件

`storage/schema.py` 一次建好全部的表。另外有一个记忆处理库 `<数据库>.memory.sqlite3`，保存记忆整理的进度。

业务数据库的公开格式从 v1 开始。修改结构时，按以下步骤操作。

1. 在 `schema.py` 中直接写入新的结构。
2. 在 `maintenance/migrate.py` 中增加一步升级。
3. 提高 `FORMAT_VERSION`。

升级只由停机后的维护命令执行，运行时不兼容旧格式。

运行记录都保存在业务表中（消息、轮次、模型调用、任务事件、学习调用），没有另外一套审计机制。宿主的日志按天轮转。`retention` 为空时，不自动清理数据。

## 面板

后端位于 `panel/`，按业务划分路由。前端位于 `web/frontend/`，使用 Vue 3 和 Vuetify。

- 业务请求集中在 `src/host/api/`。
- 通用组件在 `src/host/ui/`。
- 颜色和尺度在 `src/styles/`。

面板文案写给运营者阅读，要说清操作对象和后果，不写开发细节。

### 视觉规范

#### 颜色

颜色只在 `styles/theme.js` 中定义。

- 品牌粉 `brand`（#E2809F，与图标同色）只用于标志、页面标签的下划线、图表和开关的开启状态。
- 按钮、链接和提示条使用加深的 `primary`，其余部分使用中性灰。
- 内容区是白色背景，侧栏和登录页使用浅灰色的 `sidebar`。输入框和小标签这类填充背景使用 `fill`。
- 不使用渐变和毛玻璃效果。

#### 布局

页面依靠分区组织，不依靠卡片边框。

- `Panel` 本身没有边框和背景色，相邻的两个分区之间用一条细线隔开。
- 设置页的 `SettingSection` 在宽屏下左侧是标题和说明，右侧是表单，保存按钮只在有修改时出现。
- 列表和详情并排显示时，中间只用一条竖线分隔。列表为空时传入 `empty`，只显示列表。
- 首页的统计是一行数字，中间用竖线隔开，没有数据时不绘制走势图。

#### 圆角

圆角分三档，控件 6px，小块 8px，大块 12px。登录框使用 16px。

#### 动效

动效以淡入和小幅位移为主，曲线统一使用 `--ease-out`，时长取自 `tokens.css` 中的 `--dur-*`。页面切换以及详情区和统计块的进场，都使用这一种动效。吉祥物的眨眼、跳动和卷毛摆动，只出现在首次配置和首页的状态上。系统开启了「减少动态效果」时，所有动效都会关闭。`base.css` 中的规则带有 `!important`，因此组件自己的动画也会被关闭。

#### 按钮

按钮分为四级。

| 级别 | 写法 | 说明 |
|---|---|---|
| 主要按钮 | `color="primary"` | 每个区域最多一个 |
| 次要按钮 | `variant="outlined"` | 旧页面中的 `tonal` 也按次要按钮显示 |
| 文字按钮 | `variant="text"` | |
| 危险按钮 | `color="error"` | 只用于确认删除这类破坏性操作 |

#### 输入框

输入框统一使用 filled 和 comfortable 样式，即浅灰色背景、无描边，获得焦点时变为白色背景并加上 primary 色的描边。这些样式由 `plugins/vuetify.js` 的默认值和 `base.css` 设置，页面中不单独修改。键盘焦点必须清晰可见，隐藏 Vuetify 的焦点层时，需要补上 `:focus-visible` 描边。

#### 导航和标签

侧栏的选中项是白色背景加轻微阴影，图标使用 primary 色。页面标签是文字加下划线，选中项下方有一条品牌色的短线。分段选择（`v-btn-toggle`）是灰色底槽加白色的选中块。标签和状态小块使用中性色，不使用 primary。

#### 界面文字

界面文字只说明这个控件的作用和需要填写的内容。不在各处重复「会消耗 token」「不会发到 QQ」这类提醒，真正影响操作的限制只在最相关的位置说明一次。用户看到的名称使用日常说法，例如模型用途 `mind` 显示为「聊天」。

### 其他约定

- 插件的参数表单由 `host/components/SchemaForm.vue` 按插件清单生成，不为单个插件编写专用表单。
- 首页的待处理事项在 `host/attention.js` 中汇总，顶栏的提醒数字和首页的列表共用这一份数据。

## 发行

`scripts/build_release.py` 从同一次提交构建 wheel、源码包和 Linux／macOS 部署包，Docker 宿主镜像安装同一个 wheel。部署包中，`releases/<版本>` 存放程序和依赖环境，`instance/` 存放数据。升级时按以下顺序执行。

1. 安装新版本。
2. 停机并迁移数据。
3. 恢复插件依赖。
4. 切换 `current`。

新版本检查位于 `runtime/releases.py`，只查询，不下载，也不安装。托管安装（存在 `.runtime/update-control.json`）向更新控制器查询，从源码运行时直接查询 GitHub Releases。面板启动 60 秒后检查一次，之后每 24 小时检查一次，失败时记录一条 WARNING `release_check`。在根配置中把 `panel.update_check` 设为 `false`，可以关闭后台检查。

### `GET /api/host/updates`

除了 `version`、`managed` 和 `status`，还返回 `check`，格式如下。

```json
{"enabled": true, "current": "0.2.0", "checked_at": 1791370000.0, "error": null, "latest": "0.2.1", "update_available": true, "latest_prerelease": null}
```

- `checked_at` 是 Unix 时间戳，单位为秒。从未检查过时为 `null`。
- `error` 是上次失败的原因，检查成功后清空。
- 从未成功检查过时，`latest`、`update_available` 和 `latest_prerelease` 都为 `null`。
- `latest` 是最新的正式版本。只有存在比当前版本和最新正式版本都新的预发布版本时，`latest_prerelease` 才有值。

### `GET /api/host/updates/releases`

返回一个数组，按版本从新到旧排列，每一项都带有 `newer`，表示是否比当前版本新。

- 从源码运行时，过滤掉草稿和格式不符合 `v<版本号>` 的标签。每一项为 `{tag, version, prerelease, notes, newer}`，`notes` 为空时是 `""`。
- 托管安装使用更新器提供的列表（另外带有 `assets` 和 `installable`），同样加上 `newer`。

每次调用都会刷新 `check`，后台检查关闭时也可以使用。查询失败时返回 422，正文是错误原因。超时时间为 15 秒。
