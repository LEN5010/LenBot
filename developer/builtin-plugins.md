# 订阅播报与群工作

在「能力 → 插件」启用插件、保存配置，并在目标群打开。保存只重载涉及的插件；无需个人源或账号资料。内置插件跟随主程序更新，不通过插件安装器删除源码。

## rss_broadcast：定点 RSS 2.0 播报

不调用模型。每项订阅填写 name、url、scenes、五段 cron、IANA timezone 和每次条数 limit。scenes 使用 `group:<群号>`／`private:<QQ号>`，且必须是已为该插件启用的场景。

- 首次到点发送当时最新条目，不在加载时立即发送。
- `/订阅播报` 手动查看本群全部订阅的新条目；`/订阅播报 名称` 指定一个。
- 已发送的最近 100 个条目链接保存在该插件 KV，按场景及订阅名区分。没有新条目就不发言；没有生成另一种内容的模型兜底。
- 只支持明确的 RSS 2.0，条目需有 title／link。HTTP、XML 和发送错误原样记录。单次回执未知不当作成功，不在本次调用里重发。
- 重启重新登记 cron，不补发离线期间的日程。内容变化和下一次播报属于新的订阅检查。

## group_digest：群总结和文件工作

- `/群总结`：读取本群最近 message_limit 条消息，用明确的 model_role 做一次生成，再直接回复。可补充要求，如 `/群总结 只列已经决定的安排`。角色人工资料不被改写。
- `/群工作 把刚才的活动安排做成 CSV`：使用真实发送者的任务权限接单，把近期记录作为背景交给独立工作。需要启用 worker 和该群任务能力；不是普通聊天安装的必选项。
- 单次生成和委派本身不启动新的聊天轮；任务结束事件会进入后续群会话。
- 文件生成、宿主登记、平台上传和客户端收到分开看。模拟实例不会向 QQ 发文件。

插件附带只读 `group-digest` 技能，只有在本群启用插件且角色允许该技能时才提供给任务。
