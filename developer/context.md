# 上下文、压缩与模型输入

主脑继续使用原 `mind_entries`、`mind_sessions` 和 `model_calls`，不另建会话、缓存或工具注册框架。

## 主脑请求

请求顺序是稳定角色／能力 system、已保存回想与原生历史、当次参考。启用本地目录摘要且当前群有有效正文时，在请求边界读取并放入参考，不修改 system；空记忆不注入概览说明。本轮开始时间固定，后到批次和 wait 结果提供新的真实时间依据。任务快照只列活动身份、状态与待答问题，长结果由实际结束事件或 task 工具读取。

临时召回不写入原生历史，也不作为旧段摘要源。执行记忆工具前撤下旧召回；群概览下一请求重新读取，包括工具部分完成后报错的情况。配置和能力确实改变时允许前缀变化，不为缓存保留已停用权限。

## 群聊与工具

- 新到消息按批次共享场景、日期和时区头，保留原 QQ、平台 ID、秒级时间、正文、回复、提及、媒体序号及撤回／发送状态。同日 UTC 偏移改变时另起头。
- 长批次只在完整消息之间分组；单条过大不截断，交给明确预算错误处理。同批引用不重复摘录，批次外摘录标为节选。原始平台记录和已保存历史呈现不重写。
- 自有参数 schema 仅移除 schema 节点的自动 title；业务属性、默认值、约束及引用保留。插件／MCP 定义原样使用，装配顺序按名称稳定。
- tool_search 返回名称、简短用途和下一请求生效说明；完整 schema 只在请求 tools 中出现。已发现集合持续到正常压缩重置，停用立即撤下。
- task 模型视图不再复用完整面板 DTO；保留任务目标、实际状态、待答问题、结果与错误，文件保留原 ID、存在性、登记和上传回执状态。send_file 返回可操作的回执及原事件 ID，完整平台原帧留在既有事件中。没有“已上传即客户端已收到”的转换。
- 原生工具调用 ID、参数、完整结果组和不透明续接字段保持。近期结果完整保留；较早的自有 web_read 结果在请求投影中保留文档 ID、来源、范围和重读入口，原结果及旧段摘要源仍完整保留。外部工具文本和错误原文不裁剪。

## 预算与压缩

压缩触发只比较有效输入估算与 `compaction.input_tokens`（含 system、tools、原话和当前参考），不含输出。硬窗口检查另用输入＋当前输出额度，配置要求输入阈值＋主模型输出能放下。缓存仍占窗口，不扣 cached_tokens。当前成功请求、绑定、投影策略、tools 和持久前缀一致时，用实际 prompt_tokens 加减变动材料；其余用 UTF-8 字节启发式估算，调用中明确记录方法，估算不等于实测。新实例缺省输入 60000、近期 20000、回想输出 1024；这些都需按真实服务选择。

模型响应完整存入原调用记录（包含 raw 响应），会话保存真实 assistant／tool。绑定 `history_policy=native` 原样续接；明确选择已核对的 `omit-reasoning` 路由时，请求省去可读 `reasoning_content`，保留其他字段、签名与工具 ID，只略去无内容、无工具也无其他续接字段的纯思考 assistant。该路由自行维护签名续接，请求带基于实例数据库、scene 和用途的稳定 Session-Id。规则不按模型名字或域名猜测，不用于其他协议。

`keep_recent_tokens` 是近期原文的目标，不是最少必须保留量。已有usage_assisted输入时，同请求实测输入与文本启发式估算的比例用于近期单位与压缩后空间估算；不逐条声称计量精确，也不新增持久状态或计量请求。一次准备返回消息与同次输入估算；本次摘要后仍用已取得比例，发送端用同份估算，避免下一循环回到字节口径再压缩一次。切点不拆原生工具组，允许切开长交互的两个完整工具组；摘要在六节回想中交接原请求、更正、已做和未做、原任务／资源 ID。一次摘要只读旧回想和将移出的旧段，不再带整个人格、tools 和保留段。人工压缩也计入当前参考预算。

摘要成功、非空并满足空间后，沿原事务移动起点和重置发现集合。失败保留旧回想与原始记录，不重试。最新不可拆单位或摘要输入过大时，错误给出估算、预留和窗口，不缩参或丢工具结果。end_turn 成功完成的轮次不额外发起摘要。

## 临时请求

普通聊天只有一份长会话，由主脑直接写 say 正文或选 react；不会把内部 assistant 思考发到群里。

vision／ASR 只处理本次媒体；插件 generate 只用插件明确提供的 system 与 prompt；学习和记忆抽取沿各自原游标、真实样本和原记录表，不复制主脑历史。它们使用所属绑定的输出额度，recap 独立使用 `compaction.max_output_tokens`，不增加多余汇总调用。

Pi 代理校验请求的 `max_completion_tokens` 是正整数且不超过宿主上限，合法值原样贯穿预算、转发和记录；缺省才用宿主值。未知字段仍报错，`cacheRetention` 不作为通用协议字段发送。既有 Pi 重试关闭、缓存保温关闭，不按提供方域名猜测控制参数。

配置更新和回退顺序见[运行手册](../deploy/current/operations.md#上下文-token-预算升级)。这次不改数据库格式；先停机人工选定预算，不把旧条数自动换算成 token。
