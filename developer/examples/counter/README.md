# 计数插件

基础计数无需第三方依赖或模型。将整个 `counter` 目录复制到实例根的 `plugins/counter`，在面板「能力 → 插件」启用 `counter`、保存参数，再为目标群启用；保存会直接应用该插件。修改源码后点「重载」，不重启整个宿主。

要分发给其他用户，将目录内容作为独立 Git 仓库发布，用户可在面板填写仓库 URL 或导入 ZIP，先准备候选，再配置和应用。手动复制的目录支持启停和重载，但安装器不会更新或删除它；仓库安装的源码由实例 `plugins/` 管理。

- `/计数`：查看本群计数。
- `计数加一`：增加配置的 `step`，直接回复。
- `/计数清零`：删除本群计数。本示例允许群内使用，不额外要求主人权限。
- `counter_card`：后台调用模型生成计数说明，完成后自行发送；返回 started 不是已送达。
- `counter_read`：大脑可通过工具发现找到的只读工具，使用它的聊天轮本身会调用模型；工具函数不调用模型。

KV 文件位于配置数据根下的 `counter/kv.sqlite3`，源码更新不应删除它。计数以 `ctx.scene` 为 key，群之间不共用计数。返回 JSON 或字符串只是工具结果；处理器返回说明文本也不自动发送，真正发消息使用 `ctx.reply`。

复制后若改插件名，同时改目录名、清单 name、命令和工具名，避免与其他插件冲突。发布自己的版本时填写自己的 authors、license、repository 和 homepage。

本地验证可用 [PluginTest](../../plugins-v1.md#本地测试与发布)，不启动平台、不调用模型。

模板保留两个结果语义清晰的工具：查询与后台发送。相关查询操作优先采用严格 action 请求分支，见[能力组织](../../plugins-v1.md#工具按能力组织)；不要为每个 HTTP 接口再加工具。当前仍是未发行开发版本。
