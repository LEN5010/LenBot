# 群聊表达

普通聊天由同一个 `mind` 模型读完整上下文，自己判断回不回、回谁、什么态度、用什么工具、说什么。`say.content` 就是要发的正文，`react` 可以单独发表情；引用、提及、选图和发送回执由宿主处理。

## 提示词分工

| 文件 | 管什么 |
|---|---|
| `next_response_choice.md` | 判断：要不要回应、回应谁、什么态度 |
| `next_expression_principles.md` | 表达：怎么说话 |
| `next_direct.md` | `say` 正文参数的含义 |
| `next_react.md` | 表情工具怎么用 |
| `next_chat_examples.md` | 几个群聊情境的设计示范 |

共用示范不写具体角色的台词或梗，情境也避开回放用例里的原句。角色专属的说法放在角色包的样例里。

## 原则

这些原则来自实际群聊里的坏例：

- **前后接得上**：接住对方刚才那句的意思，和自己前面说过的话对得上，语气随话题起伏。
- **不凹人设**：角色的特点是底色，不是每句都要拿出来证明的点。同一种嫌弃、撒娇或口头禅连着用，就成了凹人设。
- **被 @ 不必逐条回**：几个人同时起哄，可以一句话一起接、挑一个接或发张表情。
- **关心落在具体事情上**：不管别人的作息；被说管太多，就放下。
- **对方真恼时先站在他那边**：等对方自己笑了再一起笑。
- **标点平实**：结尾不布置下一步，梗只用在原来的情境里。
- **表情带情绪**：文字照常说事，配了图就不在字里重复同一种情绪。
- **身份问题交给角色**：被问是不是真人时怎么回答，由角色材料决定，框架不强制声明。

`say` 的引用和 @ 默认不填，只在不填会让人认错对象时使用。

## 参考材料从哪来

角色身份、关系、边界和人工样例来自角色包。学习开启时，每轮开始会按近期对话选最多五条已采用的群聊说法，和风格一起作为宿主参考放进上下文。原话、人工样例、学习参考和已发送记录在上下文里分别标明来源；参考不代表真人请求，也不代表模型一定用了它。

记忆抽取会把群友对相处方式的明确要求记为本人的偏好，不会把 Bot 某一次的口吻整理成 Bot 的性格。

改提示词或角色前后，用[表达回放](../examples/replay/)对照效果。
