# 发布现场记录模板

复制到本地运维目录填写，真实群原话、凭据和完整配置不进 Git。S0—S7 任务状态只在 docs/plan/README.md 维护；当批观察摘要归 docs/iteration.md，结束后按日期归档。本文件是待填写材料，不是已发生的现场记录；未观察项写“未运行”，不能拿构建结果代替实际链路。

## 填写顺序与候选范围

1. 先由维护者指定候选提交与选入能力；当前仅选定[Linux 容器群报告与文件交付方向](../../docs/support.md#已选验收方向)、本机 SnowLuma 及 amd64／arm64 目标，精确候选尚未确定。OneBot 按协议与文件动作核对，所报版本若有只记录当次实例身份，未报告则记「未提供」，不设固定框架版本兼容名单。开发分支的当前 HEAD 不自动成为发布候选。
2. 填写下列身份和静态证据，再按当次授权记录自然发生的正常业务。历史不同提交的构建、界面或业务观察只列在参考栏，不移成本版结果；无法确定提交的记录写“版本未确认”。
3. 一份现场记录只对应一个候选提交。代码、插件、前端或镜像变化后另起该版本记录；配置发生变更则分段注明当时值、修订和保存／生效时间，旧操作不按新配置解释。
4. 最后填写未确认表，由维护者决定后续。模板填完、代码已实现和平台已确认均不能自动改变路线验收状态。

## 发布身份

- Commit / Parent / 审阅 HEAD：
- 工作区是否有未提交变更；实际构建源码提交／前端构建提交／文档与插件参考提交：
- 选入能力与排除项；维护者确认来源（方向选择、运行授权、发布决定分开）：
- Linux/amd64 的 LenBot / Gateway / worker 实际镜像或代码版本、构建／运行记录：
- Linux/arm64 的 LenBot / Gateway / worker 实际镜像或代码版本、构建／运行记录：
- 两种目标架构各自的 Linux 发行版、内核、CPU/RAM/磁盘；未运行的一端写未运行：
- Docker/Compose、UID/GID、用户命名空间、网络与卷：
- OneBot 实现／当次报告版本／消息与文件协议，Core 版本（可选）：
- 配置观察时间、所属节与非秘密基线／保存差异／已生效差异；已有 credential_revision 等修订（如适用）：
- 对话／工作／维护及实际使用的其他模型职责、渠道／模型标识与协议（不记录凭据或带凭据 URL）：
- 所选插件 ID、自身 version、宿主 api_version、实际加载结果和模板／字体来源：
- 群报告主进程实际字体绝对路径、UID 10000 可读事实与素材使用范围；Gateway 后端／离线 worker 同架构镜像与产物登记前置：
- 一个获准聊天群、一个获准播报群及当次授权范围：
- 备份目录、数据库/文件范围、停止事实与未结束执行：
- 本次启用模块，缺失/未放行可选模块及原因：

配置编辑当前比较原基线与改动值，并非全局配置修订号；没有字段的节不补造 revision、签名或哈希。仅记录必要非秘密选择及时间，敏感原配置仍留在原受控备份中。未运行的阶段没有 event/call/job/action/receipt，不用示意 ID 填满表格。

聊天群从真实原话定位输入范围、接话或沉默、工作及资料（若发生）、表达提交和真实回执。播报群从真实来源定位确定性/公告归属、睡眠/延期（若发生）、成品和真实回执。插件启用或白名单本身不证明两群行为正确。

首个方向按[部署前置](README.md#首个验收方向的报告与文件)分别核对主进程字体和 Gateway 持久产物。群报告先核对原群来源、时间范围与截点、job ID／revision、实际读取覆盖、分析调用和报告／分页图片；再核对表达 action 与 receipt。文件交付另沿原 execution／产物、file_asset、上传 action／attempt／receipt 到平台 data.file_id；若不属于同一工作，分别记各自来源，不把两个工作拼成一条虚构链路。deployment_verified 只说明当前实例与只读挂载已经人工核对，不需要先上传成功；它也不是文件上传回执。

取证沿[日常处置入口](../../docs/operations.md#日常查看与处置)的原消息、工作、执行、资产与行动详情。事件诊断导出只是受限关联投影，不含原话、资料正文、请求快照或全部执行细节，也不是原子快照；截断、缺字段与同轮其他来源必须保留说明。需要确认原话／资料覆盖时在获准原环境查看，不能仅凭诊断附件证明已读、答案正确或送达。

A19/A20 需要执行、文件与平台真实回执；A22—A26 按实际启用的提醒、兴趣、浏览器、媒体、账号和 Core 范围填写，缺失时写不适用或未放行。A16—A18/A29 对照原预算、deadline、在途调用和完整日账，不能补造旧预算或用最近 100 条明细代替总数。未自然发生的失败/竞态只注明源码核对与未确认，不制造故障。
