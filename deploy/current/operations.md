# 使用与维护

安装和启动见[部署](../README.md)。运行期间在面板中保存设置。手动修改配置或执行维护命令之前，请先停止 LenBot。

维护命令都在实例根目录中执行。从源码运行时写成 `uv run --no-sync python -m ...`，部署包和 Docker 使用各自环境中的 `python`。

## 面板一览

| 页面 | 用途 |
|---|---|
| 首页 | 连接状态、各群概况、最近的错误 |
| 对话测试 | 用当前角色和模型试聊，不发送到 QQ |
| 日志 | 每轮回复的经过，以及可以按群、轮次、插件和任务筛选的运行日志 |
| 群聊 | 消息记录、参与节奏、学习、关系说明、本群权限 |
| 角色 | 设定、说话方式、样例、知识、表情、头像，以及草稿试聊 |
| 记忆 | 浏览、修改、删除和遗忘长期记忆 |
| 任务、资源 | 后台任务、提醒、主动话题，以及任务文件和共享资料 |
| 插件、能力 | 插件的安装和配置，以及工具、技能、MCP、网页和任务环境 |
| 模型、设置 | 服务商和用途、token 上限和发言上限，以及连接、权限和面板 |

## 账号与场景

账号写成 `平台:账号`，场景写成 `平台:group:群号` 或 `平台:private:账号`。目前只有 OneBot 一个平台。例如 Bot 是 `onebot:90001`，主人是 `onebot:70001`，群是 `onebot:group:80001`。

在面板中填写以下账号时，都使用这种写法。

- 主人
- 管理员
- 白名单
- 关系说明
- 群里的其他 Bot

本地记忆按场景分目录存放，人物画像存放在 `people/<完整账号>/`。

## 角色

角色包是一个目录，包含以下文件。

| 文件 | 内容 |
|---|---|
| `persona.yaml` | 名字、身份、性格、别名、工具和技能许可 |
| `voice.md` | 说话方式 |
| `boundaries.md` | 底线 |
| `examples.yaml` | 人工编写的情境和台词 |
| `knowledge/` | 按需检索的资料 |
| `stickers/` | 表情图片和 `index.yaml` |

写法见[角色包说明](../../developer/personas.md)，也可以参考[示例角色](../../examples/personas/companion/)。

- 在角色页可以导出和导入表单的 JSON 草稿。导入只替换正在编辑的内容，保存后才生效。
- 可以用草稿开始一次独立的试聊。试聊开始后，发送消息时才会调用模型。
- 导入 ZIP 时会新建一个目录，不覆盖已有的角色。各群使用哪个角色，需要在群设置中另外选择。
- 对角色的修改在重启后生效。

## 首页快捷操作

### 群聊开关

每张群卡片右侧的开关。关闭后，这个群的消息照常记录，但 Bot 不再回复，也不主动发言，被 @ 时同样不回复。插件在这个群也不响应指令，不发送推送。重新打开后，Bot 从新消息开始处理，不补回关闭期间的消息。开关状态保存在数据库中，重启后保持不变。

### 断开 QQ

立即关闭 OneBot 连接。Bot 停止收发消息，正在进行的回复和后台任务会中断，面板仍然可以使用。需要重新连接时，在右上角的账号菜单中重启。

运行期间意外断线时，不需要这样操作。正向连接会自动重连，反向连接会等待 OneBot 重新连接。

### 手动连接 QQ

只在启动时第一次连接失败后出现。修复 OneBot 的问题后，点击这个按钮再试一次。

## 保存与重启

插件参数和插件启用的群保存后，只重新加载这个插件，聊天不会中断。其他需要重启才能生效的设置保存后，顶栏会提示有待应用的修改。

点击重启后会弹出确认窗口，列出受影响的设置和正在进行的工作。确认后会发生以下变化。

- LenBot 不再接收新消息和新工作。正在进行的这一轮回复完成后才停止。
- 后台任务中断，会话和文件保留，之后可以续接。
- 账号浏览会话关闭，试聊停止。
- 新进程启动后，需要重新登录面板。

重启由 `len-bot` 启动器完成。直接运行 `python -m len_bot.next.host` 也可以启动程序，但没有重启功能。Ctrl-C、`systemctl stop` 或 `docker stop` 会停止整个程序。程序异常退出后不会自动重新启动，请查看终端输出或 `journalctl` 找出原因，使用 Docker 时查看容器日志。

在终端中按 Ctrl-Z 会挂起进程，实例锁仍然被占用。请用 `fg` 恢复进程后再按 Ctrl-C。

## 在群里管理设置

在角色的工具许可中开启 `host_manage` 和 `tool_search` 并重启后，主人和全局管理员可以在群里直接让 Bot 修改设置，例如「把本群改成只回应 @ 吧」或「改完以后重启一下」。群管理员和本群管理员没有这项权限。

权限按实际发出请求的那条消息判断。Bot 调用管理、安静、提醒或任务类工具时，必须指明发出请求的消息。宿主读取这条消息的发送者，不接受 Bot 自己填写的账号。

可以修改的设置如下。

- 各群的聊天开关。Bot 能看到群名，直接说群名即可。
- 聊天和学习
- 提醒和任务
- 角色绑定
- 网页和记忆参数
- 模型的生成参数和预算
- 数据保留
- 已安装插件的启用和停用，以及插件的普通参数和启用的群

密钥和身份授权不能在群里修改，连接方式和需要停机转换的设置也不能。默认只保存修改，只有明确要求时才会重启。

跨群切换聊天开关时，最多等待目标群的执行锁 1 秒。锁仍被占用时，报告操作失败，开关不变，也不会自动重试。可以在目标群的这一轮结束后再次明确操作。在本群的对话中关闭本群时，仍然在当前这一轮结束后生效。

## 插件

在插件页可以从插件目录中选择，也可以填写 Git 仓库地址或上传 ZIP。安装分为两步。

1. **准备**。下载或解包插件，读取清单，检查宿主版本和 Python 版本是否兼容，以及系统是否支持。这一步不执行插件代码，也不影响正在运行的版本。
2. **应用**。填写必填参数后应用。依赖没有变化的插件会直接重新加载。依赖有变化，或者插件声明需要重启时，要等到下次重启，在停机阶段统一安装依赖后再切换。

其他规则如下。

- 通过 Git 安装时可以指定分支、标签或提交，更新时沿用原来的选择。通过 ZIP 安装的插件，更新时重新导入新版本的包。
- 更换安装来源（例如从 Git 换成 ZIP）时，需要明确选择替换。
- 插件和 LenBot 使用同一个 Python 环境。依赖冲突时会显示原始错误，不会自动放宽版本要求。
- 停用插件会保留参数和启用的群。卸载插件会删除源码和配置，保留插件数据。删除数据需要单独操作。
- 插件都存放在 LenBot 目录下的 `plugins/` 中，包括已安装的插件和候选版本，以及插件数据（`plugins/.data/`）。也可以直接把插件目录复制进去，这类插件不由安装器管理。
- 业务插件独立安装和更新，不随 LenBot 一起升级。群聊总结和 GSUID 桥接见[独立插件](../../developer/plugin-examples.md)。
- 旧实例需要从根配置和启用的群中删除 `clock` 和 `rss_broadcast` 的引用。`group_digest` 和 `gscore_adapter` 保留原有的参数和数据，更新宿主后安装同名的独立插件即可。

部署包和 Docker 升级时会自动恢复插件依赖。从源码运行时，如果重建了 Python 环境，请停止 LenBot 后执行一次下面的命令。

```sh
python -m len_bot.next.maintenance.plugin_dependencies
```

这条命令把所有已配置插件的依赖合并后安装一次，不执行插件代码，也不更新 Git 仓库。

## 本机代理的 fake-ip 模式

Clash 和 Surge 等代理软件开启 fake-ip（假 IP）或增强模式时，本机查询任何域名都会得到 `198.18.x.x` 这类保留地址，再由代理按域名转发。LenBot 在读取网页和获取图片时会拒绝保留地址，后台任务访问外网时也一样，因此这些请求全部失败。错误信息中会出现 `resolved to 198.18.… (私有或保留地址)`。

在根配置中填写代理实际使用的假 IP 网段，以及一个可以访问的 DNS JSON 服务。

```json
"network": {
  "fake_ip_networks": ["198.18.0.0/15"],
  "public_dns_url": "https://dns.google/resolve"
}
```

按域名连接时，如果解析结果落在假 IP 网段内，LenBot 会向 `public_dns_url` 查询真实的 A／AAAA 地址。确认是公网地址后，LenBot 固定连接这些地址。

- 接口必须接受 `name` 和 `type` 参数，并返回包含 `Status` 和 `Answer` 的响应。
- 查询失败，或者真实地址是私网地址时，这次请求报错。
- 直接写成保留 IP 的地址仍然会被拦截。
- 网段不能覆盖 `10.0.0.0/8` 和 `192.168.0.0/16` 这类真实的局域网，也不能是公网网段。
- 代理软件实际使用的网段以它自己的设置为准。

## 后台任务

### 资料

在资源页可以上传本群的共享资料。新建任务时，可以从共享资料中选择，也可以选择其他任务的文件和交付，最多 16 份。任务得到的是只读副本，之后修改或删除原文件都不影响任务。

### 追问和续接

任务可以向请求人提问，等待回答期间不占用执行名额。任务结束后，可以明确要求续接，续接时使用原来的会话和文件。`worker.max_calls` 按每次执行计算，`max_tokens` 按整个任务累计的输入加输出 token 计算。任务失败后不会自动重试。

### 产物

文件生成以后，登记为交付和发送到 QQ 各是一个独立的步骤，每一步都有记录。在任务详情中可以预览和下载文件，也可以登记和发送。单个文件默认上限为 25 MiB。整个任务登记的交付累计默认上限为 500 MiB（`worker.max_delivery_bytes`），续接不会重置这个累计值。

### 清理

在资源页可以对任务执行两种清理。

- 清理临时文件。会话和输入不受影响，产物也会保留。
- 释放环境。删除整个工作区，之后无法再续接。已登记的交付和共享资料会保留。

任务仍在运行，或者仍然占用着容器和浏览器会话时，无法清理。

### 渲染

任务镜像自带 `lenbot-render`，可以把 HTML 渲染成 PDF 和截图，也可以生成打印预览，例如 `lenbot-render out/document.html --pdf out/document.pdf --screenshot out/page.png`。

### 镜像

使用官方任务镜像 `lenbot-worker` 时，部署包和 Docker 通过面板升级，会一并换成同版本的镜像。自行构建的镜像需要自己重新构建，并在停机后把 `worker.image` 改为新的标签。

## 记忆维护

普通删除会保留修改历史。遗忘会清除这个文件的正文和索引，以及旧版本和摘要。遗忘时还可以选择部分原话，不再从中重新学习。原始聊天记录和模型请求记录仍然保留，外部备份也不受影响。

手动修改了记忆文件，或者更换了向量地址、模型或维数后，停止 LenBot 并重建索引。向量配置可以在「模型 → 向量模型」中修改，普通重启不会重建；仅修改服务商名称无需重建。

```sh
python -m len_bot.next.maintenance.memory_reindex
```

正文和修改历史会保留，目录摘要会被清除，之后按新的正文重新生成。

更换了表达学习使用的向量模型时，停止 LenBot 后执行 `python -m len_bot.next.maintenance.reindex_expressions`。

## 运行日志

宿主的所有组件都写入同一份日志，即实例目录下的 `logs/lenbot.jsonl`。日志目录可以在设置 → 上下文、媒体与日志中修改。日志每天轮转一次，默认保留 14 天。

每行是一条 JSON 记录，包含以下字段。

- `ts`（UTC 时间）和 `level`
- `source`，产生记录的模块
- `event`，事件名，例如 `receipt`、`turn_start`、`tool_call`、`model_call`、`message_sent`、`plugin_error`、`task_finished`
- `message`
- 关联 ID，存在时才写入，包括 `scene`、`platform_message_id`、`message_seq`、`turn_id`、`tool_call_id`、`tool`、`plugin`、`task_id`、`job`
- `error`，包括 `type`、`message` 和完整的 `traceback`

从收到消息到发出回复，中间开始的那一轮回复，以及模型调用、工具调用和插件处理，都可以按 `turn_id` 关联起来。任务按 `task_id` 关联。面板的日志页可以按级别、群、轮次、插件和任务筛选。在回复记录中点击「这一轮的运行日志」，可以直接跳转到对应的记录。

配置中的密钥和插件的密钥字段不会出现在日志中。下载日志文件和诊断包时，5 位以上的数字也会被遮盖。

回复诊断包仍包含消息、模型请求与回复正文，任务诊断包仍包含任务文字。分享前须自行检查。

终端只显示简短的一行，完整记录以日志文件为准。维护命令（例如迁移、升级和 `doctor`）开始和结束时，以及失败时，也会写入同一个文件。以下三条命令例外，它们不写实例日志，由更新器记录在自己的日志中。

- `upgrade inspect` 和 `upgrade paths`，只读取实例
- `upgrade restore`，会整体替换实例，包括日志

部署包的更新器另有两个日志文件。`updates/updater.jsonl` 是同样格式的更新记录，`updates/updater.log` 是子进程的原始输出。文件超过 5 MiB 时，在更新器启动时轮转。

## 检查实例

在实例目录中执行 `python -m len_bot.next.maintenance.doctor`。命令逐项输出以下组件的检查结果，格式为 JSON，每项一行。

- 配置
- 业务数据库
- 记忆处理库
- 本地记忆索引
- 插件，包括插件的数据版本和 KV 文件格式

数据库都以只读方式打开，Bot 运行期间也可以执行。任何一项失败时，退出码为 1。未配置的组件显示为 `disabled`。

## 升级与备份

部署包和 Docker 安装在面板的设置 → 版本与更新中升级。更新器按以下顺序执行。

1. 停止 LenBot。
2. 制作完整快照。
3. 执行下文第 4 步中的迁移，并用 `doctor` 检查。
4. 切换版本并启动。

制作快照前会先估算快照大小。磁盘空间不足以容纳快照和额外 256 MiB 余量时，升级直接停止，不做任何改动。迁移后的 `doctor` 检查没有通过，同样算作升级失败。

升级失败时，可以在更新页恢复快照。快照记录了每个文件的长度和 SHA-256，恢复前会核对整份快照，发现缺失或损坏时停止。核对通过后，先把全部内容复制到各个目标位置旁边的临时位置。复制中途出错时（例如磁盘已满），当前实例同样不会被改动。全部复制完成后，才逐项替换。详见文档站的[更新与恢复](https://lendevs.github.io/LenBot/guide/update)。部署包也可以离线执行 `install.sh upgrade`，见[部署包](../package/README.md#升级)。

面板启动 60 秒后会检查一次新版本，之后每 24 小时检查一次。托管安装向更新器查询，从源码运行时查询 GitHub Releases。检查只查询，不下载，也不安装。检查失败时只记录一条 WARNING `release_check`。在根配置中把 `panel.update_check` 设为 `false` 可以关闭这项后台检查（默认为 `true`，旧配置不需要迁移）。设置页中的手动「检查发行版本」仍然可以使用。

从源码运行时需要手动升级，步骤如下。

1. 停止 Bot 和试聊，以及其他会写入数据的程序。
2. 备份实例目录，以及配置中指向实例以外的任务目录和交付目录。SQLite 的 `-wal` 文件也属于数据，需要一起备份。
3. 换成新版本的程序。
4. 依次执行下面的命令。

   ```sh
   python -m len_bot.next.maintenance.migrate_config
   python -m len_bot.next.maintenance.migrate
   python -m len_bot.next.maintenance.migrate_memory_jobs
   python -m len_bot.next.maintenance.migrate_local_memory
   python -m len_bot.next.maintenance.plugin_dependencies
   ```

5. 执行 `python -m len_bot.next.maintenance.doctor` 检查。全部为 `ok` 或 `disabled` 后，再启动 Bot。

单独运行的数据库迁移命令会在数据库旁边保留一份升级前的副本，例如 `state.db.v2.bak`。确认新版本运行正常后，可以删除这份副本。同名副本已经存在时，命令会拒绝执行，不会覆盖它。每一步升级都在一个事务中完成，中途失败时数据停留在上一个完整的格式。

启动时不会自动升级数据，数据格式不对时直接报错。

- 根配置的 `config_version` 比当前格式旧时，启动直接停止，报错中写明下一步操作。从源码运行时，停机并备份实例目录，在实例目录中执行 `migrate_config`，再按上面的步骤完成其余迁移。部署包和 Docker 使用面板中的更新器。
- `config_version` 比当前格式新时，说明这份配置是由更新的 LenBot 版本写入的。请换回那个版本，或者恢复升级前的快照。
- 没有 `config_version`，同时带有当前版本不认识的字段（例如旧版的模型价格）时，字段校验错误后面也会附上同样的提示。

所有命令和程序运行共用实例锁 `.lenbot-instance.lock`。锁被其他命令占用时，命令会拒绝执行。请不要手动删除锁文件。

## 面板登录限制

面板登录按来源 IP 统计尝试次数。15 分钟内失败或正在校验的尝试达到 5 次后，这个 IP 的登录一律返回 429，不再校验密码。即使用户名和密码正确，也要等这个时间窗口过去。更换用户名不会重置次数。登录成功后，这个 IP 的计数清零。

面板部署在反向代理后面时，所有人共用代理地址的这 5 次额度。一个人连续输错密码，其他人也会暂时无法登录。面板的写入请求和 WebSocket 会核对浏览器的 Origin。反向代理必须保留 Host，并传递正确的 `X-Forwarded-Proto`。

## 数据格式

业务数据库从公开版本的格式 v1 开始，之后每次格式变化都有对应的升级步骤，目前是格式 4。记忆处理库目前是格式 6，本地记忆索引是格式 3。

业务数据库从格式 3 升级到 4 时，新增 `speech` 表，记录每个群每次发言的时间，每小时发言上限按它计数。升级不回填旧记录，升级后的第一个小时从零开始计数。

业务数据库从格式 2 升级到 3 时，提醒中的纯数字目标会补上所属场景的平台前缀，例如 `70001` 改为 `onebot:70001`。自主目标 `self` 保持不变。提醒的时间和状态保留，原文也保留。新的提醒请填写 `self` 或完整的 `平台:账号`。

`migrate_local_memory` 把本地索引从格式 2 升级到 3。它会清除旧的 `.abstract.md`／`.overview.md` 派生摘要，保留正文和修改历史，以及全文索引和向量索引。迁移不调用模型。新摘要的生成时间写入索引，与记忆变更使用同一个时钟。迁移后，在记忆页明确执行一次整理，重新生成摘要。

`migrate_config` 必须在数据库升级之前执行，因为数据库升级会读取根配置。这条命令会删除以下内容，原文件保存为 `lenbot.config.json.pre-tokens.bak`。对话测试实例的配置也会一并处理。

- 旧版本的模型价格，即 `models.prices` 和各用途的 `price`
- 空的金额上限

金额上限（`limits.daily_model_cost`、`scene_daily_model_cost`、`worker.max_cost`）无法换算成 token。配置中填写了这几项时，命令会直接报错并列出原来的值，不修改文件。请手动删除这些字段，改为填写 `limits.daily_tokens`、`scene_daily_tokens` 和 `worker.max_tokens`，然后再执行命令。

根配置从格式 1 升级到 2 时，会移除已退役的旧核心使用的 `history_import`、`reminder_import`、`media_import` 和 `media_archive` 字段。这四项已经没有执行入口，迁移只清理配置，不读写它们引用的旧实例数据。仍在使用的 `task_archive` 会保留。

格式 3 增加了 `worker.max_delivery_bytes` 和 `network.public_dns_url`。已有实例更新源码后，必须先停机执行 `python -m len_bot.next.maintenance.migrate_config`，再启动。原配置按输入的格式保存为 `lenbot.config.json.pre-config-v<编号>.bak`。首次配置向导直接生成格式 3 的配置。

业务数据库从格式 1 升级到 2 时，各条调用记录中原有的估算金额会被删除，改为从同一行保存的 usage 重新统计 token。如果某一行的 usage 读不出 token，升级会停止并报告行号。

## token 计量

任务的 `max_tokens` 按整个任务累计的服务商报告的输入加输出 token 计算。

- 被服务明确拒绝的 HTTP 4xx 请求（例如 401、429）没有 usage 时，修正问题后仍然可以续接任务。
- 已经被接受或中途中断的调用，以及 5xx 等错误，仍然记为用量未知。配置了任务 token 上限时，会暂停续接。
- LenBot 不会估算未知的用量，也不会把未知用量记为零。

`max_daily_tasks` 统计的是新建任务的数量，续接沿用原来的任务。普通成员可以为任务补充信息，确认类操作仍然需要任务管理权限。

每日 token 限额按模型服务报告的输入加输出 token 计算。首页使用相同的统计范围。统计范围包括任务和记忆，也包括公共场景和已移除的场景，以及保留的试聊。ASR 和 embedding 在用量页单独列出，不计入每日限额。

- 失败或中断的调用没有报告 token 时，用量仍然记为未知，不按零计算，也不会因此暂停当天的请求。
- 成功的调用没有报告 token 时，当天的请求会暂停，直到当地时间零点。
- 已经报告的 token，无论调用最终是否失败，都计入限额。

## 测试实例副本

停止 Bot 后，可以复制一份用于测试的实例。

```sh
python -m len_bot.next.maintenance.test_copy <实例目录> <新目录> --panel-port 8089
```

命令只复制配置和配置中引用到的实例文件，不复制源码，文件权限和符号链接会保留。副本会做以下调整。

- 改为模拟发送
- 不连接 OneBot
- 面板使用指定的端口
- 指向原实例内部的绝对路径改为指向副本，指向实例以外的路径保持不变

配置校验失败时会直接报错。副本中的模型和插件照常运行，任务服务也一样。

## 不连接 QQ 的开发输入

配置 `onebot: null` 和 `delivery: "simulated"` 时，LenBot 不连接 QQ。

- 同时配置 `panel: null` 时，`len-bot` 从标准输入逐行读取原始的 OneBot 事件 JSON。读到输入结尾后，处理完已收到的消息就退出。
- 配置了面板时，面板和插件照常运行，MCP 也一样，可以在面板中试聊，直到明确停止。

两种情况下，模型调用和插件自身的网络请求，以及后台任务，都会真实执行。

表达回放见[公开回放用例](../../examples/replay/)。
