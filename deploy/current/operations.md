# 当前核心使用与离线维护

本页保存具体操作与能力边界；首次安装与部署见[部署说明](README.md)，项目概览见[项目首页](../../README.md)。配置只来自实例根 lenbot.config.json。修改配置、离线维护与启动分别执行；迁移前停机并按原运行手册完整备份。

## 任务资料、环境与归档

任务可明确选择本场景普通共享资料的实际文件名（materials，空选集默认不选，最多16份）。宿主在登记前复制私有原件，执行时只读挂载到 `/inputs`；续接保留同一快照，不重取共享目录。任务页支持采用已登记交付副本为普通共享文件，并按需列出、下载和选择；采用/文件存在/挂载均不代表任务已读取或平台已收到。

已结束且容器/账号会话均已关闭的任务，可在面板核对实际目录并填写操作者 QQ，明确放弃环境后清理其工作区/家目录/原生会话/输入快照。受理放弃后不再续接，即使后续删除失败；交付副本、共享采用原件和执行记录保留。错误或无回执先核对部分结果，不自动清理、重试或回滚，不将目录删除称为安全擦除或配额已释放。

停机后可用根 `task_archive: {"destination":".backups/task-originals", "scenes":["group:80001"]}` 和 `uv run --no-sync python -m len_bot.next.archive_tasks` 保全当前终态任务原始行与工作区/runtime/交付原件。目标新建、不覆盖；原链接仅保留不跟随，特殊节点只记元数据。这是私有原件归档，不自动解包、恢复环境或续跑，也不替代完整实例/外部服务备份；源不删除，失败保留部分及原错。

当前运行与离线维护命令对同一实例根使用非阻塞 Unix 文件锁，忙碌时报原错，不并行启动或开始转换。根 `.lenbot-instance.lock` 文件不保存 PID，保留的文件不是仍在运行的证明；不要删除/替换文件解锁。锁只覆盖参与它的当前入口，旧已加载后台和外部服务仍须按部署说明明确停机；不同实例根也不得共用业务库或重复运行同一 QQ 场景。

## 独立开发入口

独立多场景开发可在另一实例根明确配置 `onebot:null`、`delivery:"simulated"`、`panel:null` 后使用同一 `uv run --no-sync len-bot` 入口，向 stdin 输入每行一份原生 OneBot JSON。无 QQ 连接与真实平台出口；输出明确标明 stdin。该模式不接受插件/MCP/账号浏览/实时原生远端记忆或自动语音转写，不修改生产实例；模型及明确启用的普通任务容器/公共出网仍实际执行并计费。EOF 会结束宿主并中断尚未结束的任务，观察任务结束须保持输入管道开放；复制的旧库若残留容器/账号会话则拒绝启动，须先在所属实例处理，不用其定位清理外部运行。它是开发入口，不是已经执行的全链路回放或真实发送验证。

该 stdin 宿主可在各 `scenes.<实际场景>` 内设置 `replay_web` 和 `replay_images` 为本实例根内的固定资料清单。网页读取/搜索、聊天视觉及已启用的图片收集按所选场景取原始资料，缺项报错不联网；不自动改模型或采纳识别结果。未提供清单的场景及任务公共出网仍是明确的正常网络路径，不称全部冻结。固定资料锚不可用于 OneBot 输入。单场景 Lab 的同名顶层参数保持原位置与格式。 多场景原生记忆另可用根 `replay_memory` 指定完整服务HTTP录制：实际服务/账号/全部scene用户须匹配，`memory.ingest` 须明确关闭；同一客户端按实际user和请求消费原回包，缺项不联网，重启沿同目录 `consumption.json` 续读。它不执行真实服务写入或抽取，也不代表任务公共出网和模型回答已经受控。

## 服务装配与原生记忆模板

工具仍受角色允许列表和实际服务装配约束，能力页说明缺项。可选 `worker.mcp` 默认关闭；明确启用后，任务通过宿主桥使用启动时本场景实际运行且角色允许的 MCP 工具，密钥不进容器，掉线/定义变化结束调用而不重试。保存后重启生效，须使用包含当前扩展的任务镜像；已有镜像不会因更新宿主自动升级。个人插件位于独立仓库，不随本仓库默认启用。部分能力目前只有协议/隔离连线证据，真实模型效果、最终任务镜像和实际浏览器扩展连通仍需部署后确认。

原生记忆可明确指定会话抽取策略，并在提交原消息前回读实际保存值；可选事实/事件/Bot说法/承诺分类模板需按[原生模板接线](memory-templates.md)先在服务端加载。默认不替换服务策略或模型，不据此宣称语义质量和完整遗忘已完成。

## 历史计量与任务过程

记忆页可按需查看已保存的向量调用时间、用量、当时费用和错误，开发者模式明确读取实际输入与价目快照；不触发模型或重建。停用记忆后仍只读本根现有处理库，格式/权限错误报原错，不创建或升级库、不修改旧调用状态；文件操作仍要求实际记忆服务。历史记录的场景/分区选择与文件编辑分开，旧版整根重建的公共标签不证明输入都是公开内容。缺费用仍未知、响应摘要只有条数/维度；详情不是匿名导出或完整数值向量。用量汇总的全部范围包含本实例公共及已移除场景，不含独立保留试聊；预算另包含那些试聊，二者范围不混称。

大脑的 `task` 工具可用 `events` 查看本任务最近过程，`read_event` 按原事件位置分页读文本投影；须填写真实操作者 QQ。普通任务限本人或任务管理者，账号浏览过程只给根主人，黑名单/Bot不开放。失败的普通任务公告附最近过程预览，账号浏览不自动公开私密过程；投影省略已识别的图像/音频块与 base64 定位内容，隐藏当前已知凭据，不推断未知旧凭据或旧令牌已经清除。读取不重发任务或操作平台。

## 升级现有开发数据

停止运行并完成数据备份后，在项目根执行：

```sh
uv run --no-sync python -m len_bot.next.migrate
```

当前业务库格式为 35，记忆处理库格式为 5；迁移保留原消息与身份，每个步骤保留原格式副本。当前格式无需再迁移，命令不会自动跳过/覆盖备份。记忆处理库有独立迁移入口 `uv run --no-sync python -m len_bot.next.migrate_memory_jobs`，不能用业务库迁移替代。升级代码不自动操作正在运行的实例。

## 日常使用

启动后登录配置中的面板地址。首页看连接与最近错误；群聊查看消息/设置；能力配置插件、MCP与浏览器；模型分别绑定各用途；对话测试可在不向QQ发消息的条件下检查实际模型回复。保存配置与当前进程生效分开，提示需要重启时由运营者自行重启。

角色页可下载根配置指向的已保存角色包，或上传 ZIP 到新的 `personas/<目录名>`。四个角色文件须直接位于 ZIP 根，知识与表情原件保留；上传不自动切换人格、不改场景配置或人工样例。导入成功后核对返回路径，再在场景设置里明确采用。已有目录不会覆盖；下载不包含编辑器中未保存的草稿。

角色文件编辑器还可用当前未保存的四文件草稿创建独立试聊，在原页面试聊而不丢编辑原文。资料和表情取创建时根配置指向的已保存角色包，场景和模型仍取运行快照，出口始终模拟；原草稿与实际试聊快照分别留在独立试聊目录。勾选费用说明并开始不自动调用模型，随后虚拟发言才调用。离页不自动停止，统一对话测试页可查看来源并管理活动试聊。

角色知识区可查看、新建、编辑与删除 `knowledge/` 内的单个 Markdown 原文（包括 YAML 标签头）。新建不覆盖，编辑不隐式创建；保存前核对共用角色的场景工具依赖，运行旧资料仍保留到重启。知识草稿不随 ZIP 导出或新草稿试聊自动提交；请明确保存后再使用。

表情文件区分别管理 `stickers/index.yaml` 和实际原件：先明确保存索引（首次可用空列表 `[]`），再上传新文件，最后在索引里明确登记。上传只存宿主文件，不覆盖或自动注册；删除只允许保存索引未引用的原件。索引保存前校验实际图片与共用场景依赖；保存清单和运行内存条目分开，上传或预览不代表已向 QQ 发送。

账号浏览先在专用机器/浏览器配置安装并运行所选守护进程和扩展，能力页填CLI/home/socket（必须属于同一守护进程）。实例ID可先留空，生成链接后由主人在扩展配对；读取实际连接得到ID，明确保存后重启。配对不等于登录目标站点，链接生成也不等于浏览器已连接。失败不自动换浏览器或重发操作。

本地定向遗忘可排除明确选中的旧消息；OpenViking 可读取原生快照历史，但完整遗忘及跨后端完全等价语义仍未完成。旧核心源码保留用于迁移与评测参照，正常启动不再进入旧核心；项目尚未完成开源发布验收。

## 旧提醒与媒体移交

旧一次性提醒可在停机备份后，用根配置 `reminder_import` 显式给出 `source`、`backup`、`scenes`、`timezone`，执行 `uv run --no-sync python -m len_bot.next.import_reminders`。只移交未到期、未领取、无条件触发的真人提醒；其他项报告原状态，不复活已结束事项，也不自动停旧后台。当前业务库格式为 35，旧格式仍按现有离线迁移入口升级后使用。

历史原话导入后，图片原件可在停机备份下单独转存：根 `media_import` 明确给出 `source` 旧库快照、`directory` 旧媒体文件副本、`original_directory` 旧库 path 字段的原绝对 POSIX 目录、`backup` 目标库备份及 `scenes`，执行 `uv run --no-sync python -m len_bot.next.import_media`。只按实际原引用挂到已导入的真实收发图片位置；不联网补图、不生成视觉描述、不把停用/公共素材自动启用。不支持的原资料列出保留原因，原资产整行保留在消息 raw 中。它不是语音/视频/任务文件完整搬迁或旧权限与后台归属切换。

旧资产的原件保全另有离线入口：根 `media_archive` 指定 `source` 停机旧库、`directory` 文件副本、`original_directory` 旧绝对目录、根 `.backups/` 内尚不存在的 `destination`、明确 `scenes` 和必填 `include_public`，执行 `uv run --no-sync python -m len_bot.next.archive_legacy_media`。它保留所选资产整行与已有路径对应的真实原件，不限于图片，也不跳过停用/非精选素材；`include_public:true` 才纳入旧 `global-safe`。manifest 保留原状态与身份，result 分开列完成的文件复制和原来没有文件路径的行。缺文件、链接、路径冲突或复制失败会结束，保留已写部分，不覆盖或自动续跑。归档不登记到新核心、不重新启用、不转换格式、不联网、不调用模型或发送；未登记文件和旧任务工作区仍须完整原备份，不能凭此删除旧库/文件或宣称所有媒体已经可用。

## 更换记忆后端

停机并备份后，在同一实例的根配置中设置目标 `memory` 和显式 `memory_transfer`：`source` 是原后端完整配置，`archive` 是实例根内尚不存在的归档目录，`scenes` 是需移交的真实场景，`public_scene` 是其中一个明确的公共目录访问身份。原生源服务也须停止其他写者并先处理未完成抽取；目标本地目录须全新为空，目标原生用户/公共目录须预先准备且没有正文。不要在迁移结束前启动该配置。

1. 设置 `memory_transfer.operation: "export"`，执行 `uv run --no-sync python -m len_bot.next.transfer_memory`。保留当前业务库、记忆处理库和本地源目录原件；原生服务只导出实际可浏览的 Markdown 正文，服务历史仍留源端。
2. 核对归档的 `manifest.json` 与 `export-result.json`，保持实例原话、抽取游标和排除记录不变。修改根配置中的 operation 为 `"import"`，再次执行同一命令。导入保留原文与来源分区，重建目标索引；显式配置本地向量时会实际调用 embedding 并记录用量。
3. 核对 `import-result.json` 中每份实际回执。失败时立即停止，源和已写目标保留；未返回回执的写入结果未知，不自动重复。再次导入被拒绝，应先明确处理目标和失败归档。

本地人物路径映射为原生 `peers/<QQ>/memories/`，其他场景内容映射为 `memories/`；公共内容不变成场景内容。待确认的 `legacy-import/` 不升级为正式原生记忆。源修改历史、摘要和向量不冒充目标历史或有效画像；正文迁移不等于完整遗忘、服务全量备份或质量验收。
