# 版本说明（草稿）

LenBot 的首个公开版本。之前的开发版本都叫 0.1.0，没有公开发行。

## 下载

| 内容 | 位置 |
|---|---|
| Linux（x86_64、ARM64）部署包 | `lenbot-0.2.0-linux.tar.gz` |
| macOS（Intel、Apple 芯片）部署包 | `lenbot-0.2.0-macos.tar.gz` |
| Windows x64 部署包 | `lenbot-0.2.0-windows.zip` |
| 程序 wheel 和源码包 | `len_bot-0.2.0-py3-none-any.whl`、`len_bot-0.2.0.tar.gz` |

| 账号浏览配套组件 | `browserskill-*`，Linux 和 macOS 各两种架构 |

每个附件的大小和 SHA-256 在 `release-manifest.json` 里。安装步骤见[文档站](https://lendevs.github.io/LenBot/guide/quick-start)。

## 包含

- **群聊**：每个群或私聊一份持久会话，主脑自己判断回不回、回谁，会用表情、引用和提及；长对话压缩成回想。
- **角色**：角色包包含设定、说话方式、底线、样例、知识和表情，可导入导出，改动前开草稿试聊；附一个[示例角色](https://github.com/lendevs/LenBot/tree/v0.2.0/examples/personas/companion)。
- **记忆**：本地 Markdown，按群隔离；全文检索，可选向量检索；后台整理、修改历史和彻底遗忘。插件发出的消息不进入记忆抽取。
- **后台任务**：长工作交给独立 Docker 容器里的 Pi，可以选资料、追问、取消、续接，产物登记后发到群里；可选存储池硬上限。
- **插件**：同进程 Python 插件，Git 和 ZIP 安装，版本兼容检查，单插件重载；插件可以按时间段读取消息（`messages_between`）。[插件模板](https://github.com/lendevs/lenbot-plugin-template)。
- 插件工具按业务能力收敛：A-SOUL 10→4、B 站 14→5；查询与实际发送／账号写入分开，相关操作采用严格 action 参数分支。模板同步此设计方式，本次仍未发行。
- 插件接口 1 增加显式工具简介、按需共享指南、真实请求消息来源、原生 JSON 结果、配置可用性与面板模型说明预览；提供公共图片读取和测试时钟／模型协议配置。独立插件与模板统一适配，具体版本及来源参数变化见各仓库 CHANGELOG。
- **独立插件**：[GSUID Core 桥接](https://github.com/lendevs/lenbot-plugin-gscore-adapter)和[群聊总结](https://github.com/lendevs/lenbot-plugin-group-digest)独立安装和更新，不随宿主打包。群聊总结提供每日总结卡片：按群启用，默认每天 22:00 发过去 24 小时的总结，也可以用 `/群日报` 或直接让 Bot 生成；长聊天分批读，引用的原话按消息核对；增量模式默认关闭，按群开启后每小时提前整理，支持小时数和明确起止时间。时间查询和 RSS 播报已移除，聊天模型每轮仍获得当前时间。
- **面板**：首次配置向导；模型、预算、权限、插件、日志；群聊页左侧列群、右侧详情，其余页面在页内切换群或角色。主人也可以在群里用一句话改设置。
- **部署与更新**：Linux、macOS、Windows 部署包和 Docker 安装都带更新器。在面板里准备更新、确认后停机升级，升级前做完整快照，失败时在更新页恢复；部署包也可以离线升级。
- **文档站**：<https://lendevs.github.io/LenBot/>。

## 兼容与升级

- 插件接口 1。插件写 `requires_lenbot = ">=0.2,<1"`；写 `>=0.1` 的插件也能装，但 0.1.0 开发版宿主不保证提供本版的接口。公开入口改为 `len_bot.plugin`、`len_bot.plugin_testing`、`len_bot.image_assets`、`len_bot.text_cards`，`len_bot.next` 下都是内部模块；从开发版 `len_bot.next.plugin` 导入的插件需要改导入路径。
- 管理、临时安静、提醒、任务等原生工具的请求人改为由宿主从模型指明的真实消息读取，模型不能再直接填写账号。
- 统一运行日志：所有组件写实例目录的 `logs/lenbot.jsonl`（每行一条 JSON，带群、一轮、工具调用、插件、任务等关联 ID 和完整错误），默认开启、每天轮转；面板日志页可按这些 ID 筛选，回复记录可直接跳到这一轮的日志；插件和 MCP 的错误历史重启后保留。旧配置里 `logging: null` 在格式 2 迁移时改为默认日志目录；macOS 服务输出改名为 `logs/service.*.log`。
- 新增只读检查命令 `python -m len_bot.next.maintenance.doctor`；升级快照记录文件长度和 SHA-256，恢复前整份核对。
- 根配置格式 2，业务数据库格式 3，记忆处理库格式 6，本地记忆索引格式 3。配置迁移删除已退役旧核心的历史／提醒／媒体导入和媒体归档字段，原配置保留备份；现有任务归档继续支持。
- 旧实例清理 `clock`、`rss_broadcast` 的根配置和选群引用；群总结与 GSUID 桥接更新宿主后安装同名独立插件，原参数与数据保留。
- 从开发版源码升级：停机备份实例，更新代码后按[升级与备份](https://github.com/lendevs/LenBot/blob/v0.2.0/deploy/current/operations.md#升级与备份)依次执行根配置、业务库、记忆处理库、本地索引迁移，再恢复插件依赖。业务格式 2 升到 3 会把提醒目标转换为完整的平台账号；本地索引从 2 升到 3 会清除旧的派生摘要，保留正文、索引内容和修改历史，之后在记忆页明确整理时重新生成。
- 迁移只往新格式走，旧程序读不了迁移后的数据；回到旧版本只能恢复升级前的备份。

## 已知限制

- 只有 OneBot（QQ）一个平台适配器；提示词和面板只有中文；不提供语音合成（TTS）。
- Windows 原生运行支持聊天、面板、插件和记忆；后台任务需要 Docker 管理任务容器，请用 Docker 安装或 WSL2。没有 Windows ARM64 包。
- 没有插件市场，插件靠直接填仓库地址或导入 ZIP 安装。
- 账号浏览需要人工配对和登录，任务结束后不能接着用原来的浏览器环境。
- 部署包首次安装要联网下载 Python 和依赖。
- 服务注册后不开机自启（Windows 是登录时启动），崩溃后不自动拉起。
- 回复效果取决于模型和角色材料，构建和检查通过不代表回复效果已验证。
