# 版本说明（草稿）

这是 LenBot 的首个公开版本。之前的开发版本都叫 0.1.0，没有公开发行。

## 下载

| 内容 | 位置 |
|---|---|
| Linux（x86_64、ARM64）部署包 | `lenbot-0.2.0-linux.tar.gz` |
| macOS（Intel、Apple 芯片）部署包 | `lenbot-0.2.0-macos.tar.gz` |
| Windows x64 部署包 | `lenbot-0.2.0-windows.zip` |
| 程序 wheel 和源码包 | `len_bot-0.2.0-py3-none-any.whl`、`len_bot-0.2.0.tar.gz` |

每个附件的大小和 SHA-256 记录在 `release-manifest.json` 中。安装步骤见[文档站](https://lendevs.github.io/LenBot/guide/quick-start)。

## 包含的功能

### 群聊

每个群或私聊有一份持久的会话。主脑自行判断是否回复和回复谁，会使用表情、引用和提及。较长的对话会压缩成回想。

### 角色

角色包包含设定、说话方式、底线、样例、知识和表情，可以导入和导出。修改前可以用草稿试聊。版本附带一个[示例角色](https://github.com/lendevs/LenBot/tree/v0.2.0/examples/personas/companion)。

### 记忆

记忆以本地 Markdown 文件保存，按群隔离。默认使用全文检索，也可以选用向量检索。支持后台整理、修改历史和彻底遗忘。插件发出的消息不参与记忆抽取。

### 后台任务

耗时较长的工作交给独立 Docker 容器中的 Pi 执行。任务可以选择资料，可以追问、取消和续接，产物登记后可以发到群里。可以选用有硬性容量上限的存储池。

### 插件

- 插件是同进程的 Python 代码，支持 Git 和 ZIP 安装、版本兼容检查和单个插件重新加载。插件可以按时间段读取消息（`messages_between`）。另提供[插件模板](https://github.com/lendevs/lenbot-plugin-template)。
- 插件工具按业务能力合并，A-SOUL 从 10 个减为 4 个，B 站从 14 个减为 5 个。查询与实际发送、账号写入分开，相关操作使用严格的 action 参数区分分支。模板也按这种方式调整，本次仍未发行。
- 插件接口 1 增加了以下能力。独立插件和模板都已统一适配，具体版本和来源参数的变化见各仓库的 CHANGELOG。
  - 显式的工具简介
  - 按需加载的共享指南
  - 真实的请求消息来源
  - 原生 JSON 结果
  - 配置可用性
  - 面板中的模型说明预览
  - 公共的图片读取接口，以及测试用的时钟和模型协议配置

### 独立插件

[GSUID Core 桥接](https://github.com/lendevs/lenbot-plugin-gscore-adapter)和[群聊总结](https://github.com/lendevs/lenbot-plugin-group-digest)独立安装和更新，不随宿主打包。

群聊总结提供每日总结卡片。

- 按群启用，默认每天 22:00 发送过去 24 小时的总结，也可以用 `/群日报` 或直接让 Bot 生成。
- 较长的聊天分批读取，引用的原话按消息核对。
- 增量模式默认关闭。按群开启后，每小时提前整理一次，支持指定小时数和明确的起止时间。

时间查询和 RSS 播报已经移除，聊天模型每轮仍然能获得当前时间。

### 面板

面板包括首次配置向导，以及模型、预算、权限、插件和日志的管理。群聊页左侧列出各群，右侧显示详情，其他页面在页内切换群或角色。主人也可以在群里用一句话修改设置。

### 部署与更新

Linux、macOS、Windows 部署包和 Docker 安装都带有更新器。在面板中准备更新，确认后停机升级。升级前会制作完整快照，失败时可以在更新页恢复。部署包也可以离线升级。

## 兼容与升级

### 模型配置与排错

- 服务商可以直接改名，保存时同步更新聊天用途、本地记忆和各群学习的引用。仅改名或地址末尾斜杠可以保留旧密钥。
- 模型列表显示完整 ID 并支持选择；新增「向量模型」页，分别配置记忆与学习向量，支持读取列表和向量接口测试。
- 聊天模型和协议可以保存并重启应用。切换原生协议时清理隐藏的兼容参数；测试草稿改变后，旧测试结果不会再显示。
- 向量索引兼容性不依赖服务商名称。更换地址、模型或维数后，已有索引需要停机重建；相关错误给出具体绑定和维护命令。
- 自动记忆召回和学习向量检索的错误会标明失败阶段；向量连接错误包含服务商、模型和地址。
- 可选记忆向量查询失败或索引不匹配时使用全文检索；记忆页提供索引状态和重建入口。首次配置可以选择或跳过向量模型。
- Git 源码启动时自动更新缺失或过期的面板；发布包继续使用打包时构建的面板。
- 全局连接状态在所有页面实时更新。安全与运行文档明确诊断包包含对话或任务文字。
- 补全配置发布的目录同步，迁移检查保留表约束，更新存在公开漏洞的依赖。

### 插件接口

- 插件接口为 1。插件填写 `requires_lenbot = ">=0.2,<1"`。填写 `>=0.1` 的插件也能安装，但 0.1.0 开发版的宿主不保证提供本版本的接口。
- 公开入口改为 `len_bot.plugin`、`len_bot.plugin_testing`、`len_bot.image_assets` 和 `len_bot.text_cards`，`len_bot.next` 下都是内部模块。从开发版的 `len_bot.next.plugin` 导入的插件，需要修改导入路径。
- 插件接口 1 已经定稿，之后只做兼容的新增。
  - 插件可以在 `plugin.toml` 中声明 `data_version` 并实现 `migrate_data`。宿主在启动插件前迁移插件数据，迁移前先备份，失败时恢复数据。
  - 应用新版本时保留上一版本的源码。新版本加载失败时自动回到上一版本，面板中也可以手动回退一次。
  - 插件新增 `ctx.log`，日志写入统一的运行日志。
  - 插件的 KV 改为在线程中读写，并记录文件格式。
- 官方插件的 CI 和发行改为调用宿主提供的可复用工作流，跟随宿主的 master 测试。宿主的 CI 按随附目录中固定的提交运行官方插件的测试，目录条目由 `scripts/sync_plugin_catalog.py` 从各插件仓库同步。

### 权限

管理、临时安静、提醒、任务等原生工具的请求人，改为由宿主从模型指明的真实消息中读取，模型不能再直接填写账号。

### 运行日志

- 所有组件都写入实例目录的 `logs/lenbot.jsonl`。每行一条 JSON，带有群、轮次、工具调用、插件、任务等关联 ID，以及完整的错误。
- 默认开启，每天轮转。面板的日志页可以按这些 ID 筛选，回复记录可以直接跳转到这一轮的日志。插件和 MCP 的错误历史在重启后保留。
- 旧配置中的 `logging: null` 在格式 2 迁移时改为默认的日志目录。macOS 服务的输出文件改名为 `logs/service.*.log`。

### 检查和恢复

- 新增只读的检查命令 `python -m len_bot.next.maintenance.doctor`，也会检查插件的数据版本和 KV 格式。
- 升级快照记录每个文件的长度和 SHA-256，恢复前核对整份快照。
- 升级前检查磁盘空间，迁移后必须通过 doctor 检查。
- 恢复快照时，先把整份快照复制到临时位置，再逐项替换。复制失败时不改动实例。

### 数据格式

- 三个数据库的迁移使用同一套执行方式。前后各做一次完整性检查，每一步一个事务，数据库以外的文件操作在提交后执行。单独运行迁移命令时，会保留一份升级前的副本。
- 本地记忆索引的首次创建改为在单个事务中完成。
- 测试使用旧版本代码生成的历史实例，验证升级后的结果与全新建立的数据库一致，并且所有正文都能解码。
- 当前格式为根配置格式 3、业务数据库格式 3、记忆处理库格式 6、本地记忆索引格式 3。
- 根配置格式 3 增加任务累计交付容量 `worker.max_delivery_bytes` 和 fake-ip 的真实 DNS 解析地址 `network.public_dns_url`；开发实例须停机执行根配置迁移。
- 配置迁移会删除已退役旧核心的历史、提醒和媒体导入字段，以及媒体归档字段，原配置保留备份。现有的任务归档继续支持。

### 从旧实例升级

- 旧实例需要从根配置和群选择中清理 `clock` 和 `rss_broadcast` 的引用。群聊总结和 GSUID 桥接在宿主更新后，安装同名的独立插件即可，原有的参数和数据会保留。
- 从开发版源码升级时，先停机并备份实例。更新代码后，按[升级与备份](https://github.com/lendevs/LenBot/blob/v0.2.0/deploy/current/operations.md#升级与备份)依次执行根配置、业务数据库、记忆处理库和本地索引的迁移，再恢复插件依赖。
  - 业务格式从 2 升级到 3 时，会把提醒目标转换为完整的平台账号。
  - 本地索引从 2 升级到 3 时，会清除旧的派生摘要，保留正文、索引内容和修改历史。之后在记忆页明确执行整理时，摘要会重新生成。
- 迁移只能从旧格式升级到新格式，旧程序无法读取迁移后的数据。要回到旧版本，只能恢复升级前的备份。

## 已知限制

- 只有 OneBot（QQ）一个平台适配器。提示词和面板只有中文。不提供语音合成（TTS）。
- 在 Windows 上直接运行时，聊天、面板、插件和记忆可以使用。后台任务需要 Docker 管理任务容器，请使用 Docker 安装或 WSL2。没有 Windows ARM64 的包。
- 没有插件市场，插件需要直接填写仓库地址或导入 ZIP 安装。
- 账号浏览需要人工配对和登录，任务结束后不能继续使用原来的浏览器环境。
- 部署包首次安装时，需要联网下载 Python 和依赖。
- 服务注册后不会开机自动启动（Windows 上是登录时启动），崩溃后也不会自动重新启动。
- 回复的效果取决于模型和角色材料。构建和检查通过，不代表回复效果已经验证。

## 验证范围

（发布时填写：线上实例的真实模型、QQ 收发和插件迁移结果。）

- 宿主的 797 项自动测试通过。独立插件共 151 项测试通过（包括本机的模型 HTTP 协议）。五个 ZIP 的安装准备、Python 编译和面板的生产构建都已通过。
- 远端候选构建（`publish=false`）在 Linux amd64／arm64、macOS Intel／ARM64 和 Windows x64 上安装了部署包，完成了首次配置、登录面板和正常停止。安装目录中带有空格和单引号。
- 用两个实际打包的版本，完整执行了面板升级和恢复，以及新版本启动失败后的恢复。Docker 在 amd64 和 arm64 上用临时的本地 registry 完整执行了镜像切换和恢复。
- 在本机 macOS ARM64 上另外验证了以下三项。
  - 离线升级后通过更新页恢复
  - 更新器被强制结束后重新启动，不会残留宿主进程
  - launchd 服务的注册、启动和停止
- 以上检查全程使用模拟发送，没有连接真实的 OneBot，没有调用真实的模型，也没有覆盖真实的任务。Linux systemd 和 Windows 计划任务的服务注册没有实测。
