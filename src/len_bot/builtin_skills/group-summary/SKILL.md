# 群聊总结

使用本任务已有的 `recall_chat` 读取当前群记录，输出围绕用户所关心话题的报告。需要统计的是实际读到的消息，不是大脑回想或已有报告。任务未开放该工具时，说明缺少原始资料并通过 `ask_requester` 索取，不能从其他群或宿主数据库补取。

## 固定资料范围

- 从任务目标/补充背景确定自然日或起止时刻、群时区和重点。「今天/昨天」按提出请求时的群本地日期；任务入口会给建立时间与场景时区，背景明确另一个日期时采用该日期。区间使用两个带偏移的端点，`after`包含、`before`不包含。自然日按当地相邻午夜计算，夏令时日不一定24小时。
- `recall_chat(action="search", after="2026-09-28T00:00:00+08:00", before="2026-09-29T00:00:00+08:00")` 是形状示例；日期与时区替换为本次范围。完整群日报省略query/who；指定话题检索则记录采用的关键词，不把命中数量当全群数量。
- 首页顶层返回`snapshot`，后续页保持同一时间过滤及该snapshot，使用顶层`next_offset`，直到它为null。snapshot是实际落库截止位置，可避免阅读期间新入库消息改变页边界；不是群在线完整性的保证。
- 每条`previews`通常只有160字符。其`next_offset`不为null时，用`action="read", record=<原返回位置>, offset=<该条next_offset>`继续到全文结束。顶层翻页offset和单条字符offset不要混用。需要判断引用或短句回应时，`context`可读取附近原话；语境含义由你理解。

## 分析与统计

将实际返回的资料和必要的阶段笔记留在`/workspace`，大范围分批读取/归纳，保留话题跨页的前后文；不需要为一句话建立关系证明或审计事务。因时限/工具失败只读完部分范围时，报告已覆盖时段/消息数与未完成部分，结束这一执行单位，不自动用摘要补齐缺页。

- 统计使用返回的真实`sender_qq`、`time`、`is_self`、`send_status`；同名不合并，不同名字的同一QQ仍是同一参与者。`record`仅为读取位置，可供原话复查，不是人物身份。失败、未确认或模拟发送分开说明，不算确认发言。
- 程序计算消息数、实际发言人数、时间分布等请求所需数字，写清是否包含自身发言、媒体及检索筛选。未读取完整范围时使用「已读取资料中的…」，不推测缺失人数或排名。
- 按实际讨论归纳主要话题、事件经过、明确结论/分歧和约定的下一步。人名用原昵称并在有歧义时附真实QQ；少量关键原话附原平台消息ID/时间，既方便核对又不让报告充满编号。没有明确约定就不要为了填栏目造待办。
- 图片、视频和语音占位不等于已理解内容。仅把实际返回的识别文字作为派生资料；需要媒体分析但当前工具不提供时，保留这个缺口。

## 交付

在`/workspace/out`写可读报告；如用户需要图片，用可用绘图库和实际中文字体渲染摘要卡片，长内容分图或随附全文，不靠极小字塞进一张图。检查关键原话、数字与文件中的最终内容；有图片查看能力时检查文字是否裁切，未检查的外观如实说明。

用`deliver_file(path, name, note)`登记已完成文件，在最终说明中给出实际范围、主要结果和未完成项。登记意味着复制到宿主，不代表图片已发群或用户已收到。旧插件的报告查找、批次账本和自动发送不是本技能的隐含能力。
