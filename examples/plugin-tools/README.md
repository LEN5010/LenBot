# 插件工具回放场景

`cases.json` 是脱敏后的工具选择评测资料，用固定的时间和真实的来源关系，对照提示词修改前后的效果。它独立于表达回放的格式，重点是工具调用的顺序、参数和结果的含义，不能直接传给 `lenbot-eval expression`。

## 使用方法

在隔离的实例中安装本机的四个独立插件，把这些虚构的消息作为会话输入。使用真实模型时，逐项检查 expected_tools 和 expect。

- 初始化时间设为 2026-10-06 18:00（Asia/Shanghai），日报的原文也使用虚构数据。
- 预期的区间明确写在用例中。「今天下午」在本用例中指定为从 12:00 开始，其他实际语境仍然由模型判断。

## 覆盖的情况

资料中包含以下情况。

- 账号未开启
- 多人请求，以及主人后发言
- 真实动态 ID 在多个工具之间传递
- 后台自行发送
- 指南的生命周期

非主人的请求应该被拒绝。测试中不要对真实账号执行写操作，只使用 simulated 发送和合成的协议服务。

## 已有测试

- 宿主的 `tests/test_plugin_tool_contract.py` 验证协议和来源权限，以及指南的生命周期。
- 群聊总结的 `tests/test_incremental.py` 使用公共的 PluginTest 时钟和本机的模型 HTTP 服务，验证范围和缓存。
- B 站插件的 `tests/test_content.py` 验证配置是否可用，以及非主人来源的请求会在联网之前被拒绝。

这些协议测试已经执行过。当前的用例用于后续的模型评测，尚未用真实的聊天模型运行。模型协议服务能够通过测试，不代表真实模型具备相应的理解能力。涉及真实费用、账号操作和群发送的运行，需要分别获得明确授权后再进行。
