# 缓存问题交接

当前结论：**应用侧工具定义变化有已观察到的缓存代价，数分钟空档后的留存也是独立因素；不是“代码已无问题”，也不能全归因于缓存容量。** 窗口锚定解决消息布局的一部分，不能保证整条请求命中。

本文只保留判读口径和改动方向。逐次真实请求、失败原文、时间与账单依据见[2026-09-19—21 记录](history/iteration-20260919-21.md)；装配机制见[上下文](context.md)，后续任务见[产品路线](plan/README.md)。以下证据均为当时观察，不证明当前渠道、价格或缓存状态。

## 1. 结论能说到哪里

| 因素 | 现有证据支持 | 不能据此断言 |
|---|---|---|
| 动态工具表 | 相同合成正文只移除两个工具后缺失缓存字段，立即重复新表又命中；恢复旧表仍能复用 | 已逐次证明所有历史冷请求的根因，或已单独测出每个 Schema 字段的代价 |
| 时间间隔 | 服务器本机入口不变、相同请求空闲约五分钟后网关缓存为零，短间隔重复恢复 | 精确固定 300 秒 TTL，或已排除不可见上游淘汰 |
| 窗口锚定 | 曾实际观察到稳定头部及跨边界收缩 | 锚定成功就必定命中；整个请求只受 messages 影响 |
| 多前缀/并发 | 有限合成请求中可以共同命中，旧前缀也曾保留 | 所有负载下均无驱逐，或必须有其他群竞争才会变冷 |
| 输入尺寸 | 历史较短请求缺失缓存字段，较长请求可以命中 | 确切缓存门槛、长度是唯一变量的通用规律，或这已解释更大的小群请求 |
| 备用通道 | 存在批量 502，也有短请求成功 | 永久不可用、任何并发都必失败，或其问题来自同一缓存机制 |
| 费用 | 该批网关缓存倍率为 1，冷热同扣额 | 命中即可节省当前网关费用，或网关账单等于上游实际成本 |

## 2. 统计与关联口径

- 区分**正数缓存、显式零、字段缺失**。该历史批次的中转在计数大于零时才输出缓存字段；缺失可能是上游零，也可能是未上报经转换后缺失，不能反推原始值。
- 缺失字段按零汇总时，只能称“已报告缓存 token 占输入比例”，同时列出缺失次数；不能不加说明称真实命中率，也不能因没有显式零而宣布全部历史统计无效。
- 每轮首次请求与全部请求是不同分母；同群间隔与全局间隔不同；首次建立、窗口变化、工具变化和空档需分别说明。
- `context_plan` 的目录相同不等于正文相同。工具名称相同不等于完整 Schema 相同；实际入口转换也属于请求路径。
- 客户端连接失败而服务端无记录，不算冷请求。客户端或 SSH 输出丢失但服务端已完成时，以明确服务端事实记录，并标注原始响应是否取回。
- 统计不重复累加已包含在输入/输出中的缓存或推理 token。费用只依据实际倍率与账单，延迟只依据实际时间记录。

现有调用账与工作预算页的命中率采用有报告子集：只纳入输入非负、缓存数非负且不超过输入的数值记录，使用该子集的缓存 token 总数除以输入 token 总数，同时展示其占全部匹配调用及已知输入量的覆盖率。显式零参与统计，缺失／无效字段单列，分母为零时不计算；这不等于推断字段缺失调用的实际命中率。原始用量汇总仍可回查，首次／后续调用和跨渠道差异不能只凭一个汇总比例消除。

## 3. 施工顺序

1. 先稳定相同角色、资格和版本下的核心工具目录、参数与终结形状；本轮引用和可用目标移到事实区，仍由原执行边界核验。
2. 同步检查读取工具和发现流程，不只修提案工具；权限撤销与真实新能力发现允许必要变化。
3. 核对实际协议能否保留工具表并定向终结。正确性优先，不为缓存允许最后一步继续执行无预算工具。
4. 使用获准正常业务记录观察效果，区分 UI、模型回答、调用费用与缓存表现；没有真实调用授权就只记录源码核对。

不因本页而运行保温、压力或 200 轮采样任务，不改生产模型、计费参数或真实窗口配置。是否需要后续测量，应由新的具体问题和当次授权决定。
