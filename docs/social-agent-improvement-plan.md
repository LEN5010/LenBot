# LenBot 群聊社会 Agent 改进计划

## 目标边界

本计划把 LenBot 从“收到群消息后回答、按需创建信息工作”的系统推进为一个能够在 Linux VPS 长期运行的群聊社会 Agent。Agent 仍由 LenBot 负责认知、记忆、权限和发送；QQ 框架与 OneBot 负责平台连接；GSUID Core 只作为可选功能插件后端；Python、媒体和浏览器工作由独立 worker 承担。

最终目标不是把所有能力塞进一个无限循环，而是让每一类自主行为都有可追踪的来源、权限、工作状态、资源账和真实发送回执。固定的模型步骤数和工具调用次数不再作为主要停止条件，工作由时间、token、并发、磁盘、网络和发送额度控制。

第一阶段只接入 B 站。其他站点保留为后续功能插件，不在第一阶段把每个站点都抽象成通用浏览器代理。GSUID、评论、关注、私信、投币、账号设置和任意网站登录不属于第一阶段交付。

## 已确认的产品决策

| 领域 | 决策 |
|---|---|
| 自主权限 | 分层授权。自主公开网络探索和兴趣记忆可以运行；长工作、主动聊天、文件发送、点赞和收藏分别授权。 |
| 授权者 | 根配置/面板中的 LenBot 运营者白名单；群内用户不能自行提升权限。 |
| 授权粒度 | 按群、用户、能力分别配置，并可设置有效期、并发和额度。 |
| 主动聊天 | 允许参与公共话题和按心跳发起原创吐槽/分享；允许点名、接梗、调侃和反驳，表达重点放在话题，不持续凹自身人设。 |
| 记忆范围 | 当前群公开上下文和该群确认的长期记忆；不跨群读取，不把私聊带入群聊。兴趣探索形成独立的 Agent 兴趣记忆。 |
| 网络探索 | 主题可以自由扩展，第一阶段只访问 B 站；模型自行决定研究深度。 |
| 视频研究 | 先看目录、时间轴、简介、评论和字幕，再下载选定片段，由媒体 worker 做帧、音频和视觉分析。 |
| 登录态 | 由运营者提供 B 站 Cookie/SESSDATA，保存于根配置的专用字段；暂不加密，但不回显、不写日志、不进入模型上下文。 |
| 点赞收藏 | 点赞和收藏独立开关并有每日额度；评论、关注、私信、投币和账号设置默认关闭。 |
| 心跳 | 全局兴趣状态；每 30 分钟最多一轮，每轮最多 30 分钟，上一轮未结束则跳过下一轮；使用独立系统额度，不占普通用户额度，也不设额外每日 token 上限。 |
| 睡眠 | 按配置时区设置睡眠窗口，例如 01:00–08:00。普通聊天、心跳、兴趣分享、提醒和订阅推送排队；已开始的长工作继续，结果醒来后发送。明确 @ 或直接匹配称呼可按群请求叫醒；叫醒后 30 分钟无直接互动重新入睡。 |
| 睡眠积压 | 醒来后按优先级合并、去重和分批发送，保留原定时间；过期或重复内容不逐条刷屏。 |
| 长工作 | 单轮最长 30 分钟，累计模型输入+输出最多 10M token；取消权限为请求者取消自己的工作、运营者取消任意工作。 |
| 每日额度 | 默认每用户每天 30M token，群总额按授权用户额度累计；供应商无用量时按保守估算扣除。 |
| 安全审查 | 复用工作模型做无工具审查；启动前及新目标、下载、解压、登录态操作和文件发送前审查。高风险审查失败关闭；拒绝在目标群用概括措辞提示，不泄露具体 URL 或判断细节。 |
| Python 网络 | Python 工作默认允许公开网络访问；worker 仍拒绝回环、内网、云元数据和宿主控制地址，防止触达 LenBot、OneBot 和凭据。 |
| 文件发送 | 已开启主动播报的群同时允许文件发送。允许 ZIP、CSV、JSON、TXT、PDF、图片和常见文档；源码可打包进 ZIP，禁止直接上传凭据、配置、数据库和可执行文件。单文件 50MB、每群每天 10 个。 |
| OneBot 文件协议 | 优先使用适配器支持的 `upload_group_file`；不支持时明确失败并保留面板下载。 |
| 部署 | LenBot、QQ/OneBot、GSUID Core 和 worker 分服务部署在同一 VPS 私有 Docker 网络。LenBot 主动连接 OneBot forward WebSocket 和 GSUID Core。 |
| 插件 | Agent、权限、工作、记忆和心跳是系统插件；B 站、浏览器、媒体、游戏、GSUID 是功能插件；小卡片可按群独立启停和授权。 |

## 当前基线与真实缺口

现有代码已经具备 OneBot 收发、事件和记忆存储、信息工作、历史维护、工作级 Python、工作级浏览器、网页 HTTP 检索、媒体登记、调度器和真实发送回执。上一轮修复已提交为 `326ac3f`；这些能力的代码路径存在，但浏览器、worker、GSUID 和新配置仍需要 Linux VPS 上的人工运行验收。

当前 `web_search` 使用轻量 HTTP/Bing RSS，`read_page` 读取网页、文本和 PDF；浏览器 V2 只对 work 开放，页面状态按 work 隔离，但没有持久登录 profile、视频片段下载、音频分析、点赞收藏和普通文件 OneBot 上传。Python worker 当前按调用创建容器并禁止网络，LenBot 直接拥有启动它的宿主边界；这与最终的独立 worker 服务设计不同。

当前 AgentLoop 有会话、工作和专用插件各自的调用/步骤边界。放宽固定调用次数不能只改一个配置字段，必须让 AgentLoop 在 `max_tool_calls=None` 或等价的无限计数模式下仍受 deadline、token 预算和取消信号控制。当前 RuntimeGate 也以人类请求来源为普通聊天消息的基础，心跳需要新增明确的 system-origin 事件，而不是伪造用户消息。

当前工作区支持图片登记和普通文件面板读取，不支持把 ZIP 作为 OneBot 群文件提交；OneBot 适配器的出站消息段没有通用文件上传分支。当前 GSUID 适配层是可选桥接，不应被改成第二个消息入口。当前调度器可以处理提醒和工作到期，但没有兴趣探索循环、睡眠队列或醒来后的积压合并。

## 目标运行结构

LenBot 容器只承担事件编排、AgentLoop、记忆、权限、面板和 OneBot/GSUID 客户端。QQ 框架和 OneBot 在同一私有 Docker 网络的独立服务中运行；GSUID Core 作为另一个可选服务。LenBot 不挂宿主 Docker socket。

Worker Gateway 是 LenBot 与执行环境之间的窄接口。它接受带有 `scene_id`、`requester_qq_uid`、`job_id`、`job_revision`、能力类型和预算的工作请求，返回结构化状态、观察、产物和终止结局。Python worker、媒体 worker 和浏览器 worker 由 Gateway 启动短命容器，工作目录和控制目录按工作隔离。Gateway 不接受模型自选的工作所有者，也不把 OneBot 凭据、根配置或 SQLite 挂入工作容器。

网络路径分成三类。LenBot 到 OneBot/GSUID 使用私有协议连接；普通 Python 工作通过 worker 的公开网络出口执行；浏览器研究通过独立浏览器 worker 执行，拥有独立 profile 和 B 站登录态。Python 与浏览器都保留对回环、内网、元数据地址和宿主控制地址的确定性拦截。公开网站访问是否被模型审查另由工作审查阶段决定。

## 领域对象与状态

新增或调整的数据对象必须沿现有 EventStore、JobStore、ActionQueue 和媒体账本保存，避免建立第二套事实来源。

`CapabilityGrant` 表示运营者对白名单用户在某个群的某项能力授权，至少包含 capability、scene、user、有效期、单次并发、每日 token/时长/文件额度和启停状态。能力 ID 使用 `long_work`、`network_python`、`proactive_chat`、`send_file`、`bilibili_like`、`bilibili_favorite` 等稳定名称。

`ResearchSession` 表示一次网页或视频研究工作，关联原始请求或 system-origin 心跳、目标站点、发现的来源、审查结果、浏览器 page_ref、媒体片段和兴趣记忆候选。每个发现的新域名或下载动作都能回到该 session，不把模型自拟的链接直接当作已取得来源。

`AgentInterestMemory` 表示 Agent 自己通过公开网络形成的兴趣记忆，包含主题、来源 URL、观看时间、摘要、来源类型、可信度、有效期和可发布范围。它不是群友事实，也不参与跨群成员身份检索。群内主动消息只引用已保存且仍有效的兴趣记忆或本轮真实研究结果。

`HeartbeatCycle` 表示一次 30 分钟心跳窗口，包含开始/结束时间、睡眠状态、浏览和媒体工作状态、token 用量、研究来源、记忆提交和候选消息。周期使用 system-origin，不创建虚假的用户事件。

`SleepState` 表示全局 Agent 的睡眠窗口和每个群的临时叫醒状态。群级叫醒不授予任何工作、浏览或发送权限；它只允许该群进入临时清醒状态。提醒、直播订阅和工作结果在睡眠期间进入现有队列的延迟状态，醒来后由合并策略重新提交。

## 权限、预算与取消

面板增加运营者白名单和能力授权页。系统先验证运营者身份，再写入根配置或现有场景配置；普通群消息只能提出请求，不能修改授权。授权显示“已保存配置”和“当前进程生效值”两套状态，撤销后阻止新工作、心跳发布和文件发送，已开始的工作按取消策略处理。

长工作在创建阶段扣除并发资格，模型和工具调用不再检查固定次数上限，而是共享一个 `AgentBudget`。预算包含 deadline、input/output token、网络字节、工作区字节/文件数、浏览器页面数、媒体临时字节和文件发送额度。每次模型请求前更新实际 token 账；每次网络下载、解压、媒体分析和文件发送前重新核对剩余预算。预算不足时保存部分结果和未完成项，不自动换参数或重跑。

单工作 30 分钟是硬 deadline，10M 是累计模型输入+输出上限。用户/群每日 30M 额度只限制新工作；正在等待的工作继续使用开始时的预算快照。心跳使用独立系统额度，但仍受每轮 30 分钟、单轮并发和 worker 容量约束。睡眠不取消已开始工作，只阻止新心跳和新的自主发布。

取消流程必须统一为：记录取消原因、停止接受新工具调用、由 worker Gateway 在有界清理窗口内终止容器、保存最终终止状态、保留已取得观察和产物、把未发送结果留在工作记录。终止未确认时不允许同一工作再次执行或下载，运营者核对后才能解除阻断。

## 网络工作与模型审查

Python 出网模式只对执行 worker 开放，LenBot 不把宿主网络直接暴露给脚本。worker 为每个请求建立独立网络命名空间和工作目录；公开网络允许 HTTP/HTTPS、DNS 和必要的下载连接，回环、内网、云元数据和宿主控制地址在连接前由确定性检查拒绝。响应大小、重定向次数、下载总量、解压文件数和压缩比都属于工作预算。

审查器复用工作模型但不提供工具。启动前输入只包括用户目标、初始 URL/关键词、计划能力和资源预算；发现新域名、下载、解压、登录态操作或准备发送文件时，输入增加该动作的摘要和来源关系。Cookie、SESSDATA、OneBot token、根配置内容、群成员隐私和文件原文不进入审查上下文。

审查结果使用 `allow`、`deny`、`uncertain` 三态并写入当前工作 Trace。高风险工作在 `deny` 或审查超时/不可用时结束为受控失败；普通离线计算不依赖审查。群内提示只说明“当前目标或操作不适合执行”及可继续的概括建议，具体来源和判断理由在运营面板查看。审查调用本身计入该工作的 10M token 和每日额度。

## 统一研究与 B 站视频闭环

对 Agent 暴露统一 `research` 能力，保留 `web_search`、`read_page`、浏览器和媒体工具作为内部后端。研究入口先判断目标是轻量网页检索、动态网页观察还是视频研究；普通网页优先使用 HTTP，B 站登录态、动态页面和需要时间轴的任务转给浏览器 worker。不会直接删除现有工具，先让统一入口覆盖并记录后端选择，再逐步收敛模型可见的工具目录。

B 站研究流程从公开搜索结果或登录态页面开始，保存标题、作者、简介、评论入口、字幕入口、时间轴和原始 URL。Agent 先选定片段，再提交媒体 worker 下载片段；媒体 worker 对时间范围、容器格式、音视频大小和临时目录做检查，使用 ffmpeg 产出帧序列和音频，视觉/音频分析回到同一个 ResearchSession。整片下载只在运营者显式授权的迁移或特殊任务中出现，不作为默认路径。

B 站登录态从根配置读取，面板只显示是否配置。浏览器 worker 使用专用 profile，不把 Cookie 文本交给 Python 或模型；点赞和收藏分别由明确提案提交，发送回执之外还保存平台动作结果。评论、关注、私信、投币和账号设置没有工具入口。登录态操作和每个新站点/下载动作都经过审查。

## 兴趣、心跳、主动聊天与睡眠

心跳调度器每 30 分钟尝试创建一个 system-origin HeartbeatCycle。系统锁保证每个全局周期最多一轮；上一轮仍在运行时写入跳过记录。周期包含浏览、视频分析、兴趣记忆提交和候选消息生成，模型自行决定本轮研究深度，但必须在 30 分钟 deadline 前结束。

兴趣记忆独立存储并带来源、时间和有效期。默认保存本轮有效记忆，不能把摘要中的推测写成事实。每个主动播报群单独配置是否接收兴趣分享；全局兴趣可以被多个群引用，但群成员记忆和私聊资料不能进入兴趣探索。

主动聊天分成事件参与和定时原创两条路径。事件参与读取当前群窗口和该群确认的长期记忆，可以点名接梗、调侃或反驳；定时原创来自兴趣记忆或心跳结果。两条路径分别使用冷却、每日消息额度和现有反刷屏规则。系统提示和人格模板要明确：除非题目确实涉及 Agent，不要把公共话题改写成自我介绍、直播状态或“我被抓包”等人设回应。

睡眠状态按配置时区计算。进入睡眠后停止普通对话响应、心跳、主动原创、兴趣分享、提醒和订阅推送；已开始的工作继续。群内只有 `@` 或直接匹配称呼进入叫醒询问；同一群的有资格用户确认后，本群临时清醒 30 分钟。睡眠期间积累的提醒、订阅通知、工作结果和安全拒绝提示保持原定时间与来源，醒来时合并、去重、排序，再经过主动消息额度和当前群设置提交。系统不修改原始事件时间，也不把延迟发送伪装成准时送达。

所有自主消息通过现有 RuntimeGate 和 ActionQueue，以 system-origin 事件、能力授权、睡眠状态和群设置为输入。消息送达仍以 OneBot 真实回执为准；未知回执不自动跨通道重试。

## 文件产物与 OneBot 发送

工作区服务增加普通文件提案和发送准备。源码 ZIP 可以发送，单独 `.py` 等脚本默认仍不作为群文件；ZIP 条目必须经过路径穿越、设备文件、大小、文件数量和敏感名称检查，禁止打包根配置、token、Cookie、数据库和运行控制目录。文件来源必须是当前工作的已登记产物，不接受模型自拟宿主路径。

已开启主动播报的群自动获得文件发送能力，但工作结果仍要经过工作归属、当前群、文件额度和审查。`upload_group_file` 作为 OneBot 适配器能力探测项；适配器不支持时返回结构化不支持结果，不改发伪造的 `file` 段。上传结果保存 action、工作、文件和真实回执身份，睡眠期间生成的文件发送提案留在延迟队列。

## 插件与 GSUID 组织

系统插件负责 AgentLoop 依赖的权限、预算、工作生命周期、记忆提交、心跳、睡眠和统一发送入口；这些能力应默认随 LenBot 安装并保持可用。现有核心运行时不必为了形式全部搬进插件目录，插件分类主要用于安装、能力发现、配置和启停。

功能插件按大类登记 B 站、浏览器、媒体、游戏和 GSUID。每个大类可以包含独立卡片，例如 B 站搜索、视频研究、点赞、收藏和直播监测；卡片有自己的 Schema、来源、权限和可见范围。GSUID 适配器作为普通功能卡片，只转发游戏或其他 Core 查询，不消费 LenBot 的普通消息入口，也不直接产生第二份记忆或发送队列。其行为符合上游适配器“作为插件连接 Core”的定位，见[适配器说明](https://github.com/KimigaiiWuyi/astrbot_plugin_gscore_adapter)。

| M3 审查链 | 工作模型无工具审查、三态结果、启动前/新目标/下载/解压/登录态/文件发送审查、概括群提示和面板详情。 | M1、M2 | 允许、拒绝、审查超时三种路径均留下工作记录；审查上下文不含凭据。 |
| M4 research facade | 统一研究入口、HTTP 与浏览器后端选择、来源关系、续读和研究 session；保留现有 web_search/read_page 兼容入口。 | M2、M3 | 普通网页走 HTTP，动态页面进入浏览器，来源和未完成项一致保存。 |
| M5 B 站媒体研究 | 根配置 Cookie/SESSDATA、专用浏览器 profile、目录/字幕/评论、片段下载、ffmpeg、帧/音频/视觉分析、点赞收藏提案。 | M2、M3、M4 | 用专用账号读取公开视频，选定片段后生成分析结果；点赞/收藏分别可撤销且有额度。 |
| M6 heartbeat 与睡眠 | 全局兴趣记忆、30 分钟周期锁、system-origin、睡眠/叫醒、通知与工作结果延迟、醒来合并。 | M1、M4、M5 | 手动设置兴趣和时间窗，观察一轮心跳、入睡、叫醒、延迟发送和自动再睡眠。 |
| M7 社会主动性 | 公共话题事件参与、定时原创、话题优先提示、点名接梗、群级主动播报和消息额度。 | M1、M6 | 在选定群中观察不涉及 Agent 的公共话题参与，确认不持续自我中心；未授权群不主动发言。 |
| M8 文件发送与 GSUID 卡片 | ZIP/资料文件提案、内容检查、OneBot `upload_group_file`、不支持回执；GSUID 作为功能卡片接入。 | M1、M2、M7 | 生成源码 ZIP 并在支持的 QQ 框架中真实上传；不支持时面板可下载；GSUID 查询不重复回复。 |
| M9 VPS 运维收口 | Docker Compose、私有网络、卷、健康检查、备份/恢复、日志脱敏、配置权限、升级和回滚文档。 | M2–M8 | 重启 LenBot、QQ、GSUID、worker 后检查连接、工作恢复、睡眠队列和真实 OneBot 回执。 |

每阶段只提交实际完成的代码、配置和文档。人工验收使用一个聊天群和一个只播报群，先 shadow 或小额度运行，再逐步开放；不把编译、面板显示或模型调用账当作 QQ 送达证据。

## VPS 配置与运维要求

Compose 只编排 LenBot、worker、QQ/OneBot 和可选 GSUID 的连接关系，不把 QQ 框架或 GSUID 源码复制进 LenBot 镜像。LenBot 对外只暴露面板所需端口；OneBot 和 GSUID 协议端口绑定私有网络。worker 仅暴露内部 API，媒体和工作卷按工作 ID 隔离。

根配置继续是唯一运行配置来源。B 站 Cookie/SESSDATA 放在根配置专用字段，文件权限为 600，日志过滤器和面板序列化都必须隐藏原文。配置备份沿现有普通备份流程保存，不把凭据复制到 Git、工作目录或容器控制文件。

启动、停止、备份和回滚遵循 `docs/operations.md`。升级前先停止所有服务并普通备份数据库、媒体、工作目录、实际根配置和 Compose 文件；恢复时使用匹配的代码、配置、数据库和媒体。worker、浏览器和媒体临时目录在工作终态后清理，未确认终止目录保留供运营核对。

## 验收证据与暂不实现

验收必须围绕真实链路保存来源和回执：用户请求或 system-origin → 权限检查 → 审查 → worker 工作 → 研究/媒体观察 → 兴趣或工作结果 → Gate/ActionQueue → OneBot 回执。每一步使用已有 Trace、EventStore、JobStore、媒体账本和 ActionQueue，不新增第二套“成功”状态。

本计划暂不实现常驻 Python 内核、Python 自主调用所有 Bot 工具、宿主个人 Chrome 登录态、任意网站账号操作、评论/关注/私信/投币、任意文件上传、浏览器全量网络出口绕过、每次研究独立 VM、跨群成员隐私共享和自动化测试框架。它们可能在 M9 之后单独立项，不能作为本计划已经支持的能力。

模型审查会增加工作模型成本并可能误判；B 站页面、Cookie 有效期、字幕和播放地址会变化；OneBot `upload_group_file` 是实现能力而非所有适配器的统一保证；worker、ffmpeg、浏览器和 GSUID 的版本必须在 VPS 上分别核对。任何一项未取得真实运行证据，都只记录为“代码/配置已就绪”，不记录为“能力已通过”。

## 完成定义

当 M0–M9 的必要阶段完成，并在 Linux VPS 上取得以下证据后，才称为第一版社会 Agent 可用：一个运营者可以在面板为指定群和用户授权长工作、网络研究、主动聊天、文件发送、点赞和收藏；普通用户不能越权；一次 30 分钟/10M 工作可以完成或明确部分失败；B 站研究可以形成独立兴趣记忆；心跳能在睡眠规则下暂停、叫醒、合并积压并恢复；生成源码 ZIP 可以通过支持的 OneBot 适配器真实送达；GSUID 查询作为普通功能卡片工作；所有主动消息、文件和安全拒绝都有可追踪来源与真实回执。
