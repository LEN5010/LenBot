# 上下文装配

面向维护对话、工作与资料读取的开发者。本文说明当前源码如何装配、裁剪和恢复请求，不记录真实配置值或现场统计。行为边界见[架构](architecture.md)，参数保存见[运行手册](operations.md)，缓存结论口径见[缓存问题交接](serious-issue.md)，实际观察见[当前任务](iteration.md)。其余目标见[完整改造计划](LenBot_群聊体验与可靠执行_完整改造计划_20260920.md)；源码改动与实际链路验收分开记录。

## 1. 对话与工作的生命周期不同

- **普通对话**：每轮从事件、场景状态和持久资料重建完整请求，不是跨轮无限累加的供应商会话。同一轮内保留原生工具交换，按需吸收新输入。
- **等待后的对话恢复**：沿 `ConversationResume` 保留原来源、资料、绑定、累计预算、消息数和期限；不是新预算，也不把旧原生轨迹当作一直在线的会话。
- **长期工作**：沿同一 job/revision 保存完整原生交换、已读范围和检查点；在原工作预算内外置或压缩旧材料。
- **历史维护**：按持久批次处理原话，产出的摘要用于连续性与定位；它不是工作上下文压缩，也不授予执行或发送能力。

## 2. 对话请求的来源与顺序

主要实现为 [context.py](../src/len_bot/cognition/context.py)、[projection.py](../src/len_bot/cognition/projection.py) 和 [input_window.py](../src/len_bot/cognition/input_window.py)。

| 来源 | 用途 | 主要容量约束 |
|---|---|---|
| `persona` | 人格、角色资料与当前对话合同 | 本轮配置快照、整个请求容量 |
| `original_input` / `related_original` | 窗外关联原话及未能完整装入的当前片段 | 优先装配，与近期历史共用文字预算 |
| `recent_history` | 本群近期连续完整原话，包含落在该窗口内的当前或关联来源 | `conversation_history_limit` 与 `conversation_recent_tokens` |
| `history_summary` | 已完成摘要及覆盖目录 | 摘要条数、摘要自身文字和整个请求容量 |
| 偏好、媒体目录、表达样例 | 有范围的参考 | 各自上限及整个请求容量 |
| 时钟、运行事实、输入状态、预算 | 本次执行事实 | 不混入人类原话，不作为长期认识 |
| `tools` | 本次可见工具定义 | 独立请求字段，也参与容量估算和缓存变化 |

先保全当前与关联原话，再从最新消息向前装近期历史。近期历史遇到容量不足停止；当前长原话可按字符片段提供，其余部分仍待处理。完整原话与引用先用固定投影，只有必需来源装不下时才缩小片段；不能因本轮关联身份不同而改变完整原话的引用长度。摘要与原话窗口并列，不直接替换某条原文；摘要标为 `locator_only`，精确引述仍须回读。

`build()` 最后按以下顺序排放消息，随后核对容量、锚定和实际阅读集合：

```text
stable（当前只有 persona）
→ window（recent_history，按保存时序）
→ brought_in（窗外引用/取回原话、片段与当前像素，各自保留时间）
→ volatile（时钟、摘要、偏好、运行状态、预算、媒体目录等）
```

窗口归属与本轮关注来源分开：从原近期候选中确认最近一段连续保留的完整固定投影；尾部新输入尚未完整装入时保留在窗口之后，不因此搬走较早的完整窗口。窗内某条旧消息变为关联、邻居或召回来源时，原话仍只在原时序位置出现一次，关注关系留在 input_status。真正窗外取回的消息不会被插到近期窗口最前端。原话定位与成员编号沿真实身份生成；图片使用 `I:<asset_id>`，新增图片不重编号历史资产。原生工具交换不参与上述时序重排。

近期候选身份由入口的实际 get_recent_events 查询产生，作为独立的 recent_event_ids 传入普通对话与插件装配；不能从已经合并的 events 列表猜测。较早的待处理原话、等待恢复锚点和插件来源即使同时提供，也不自动成为窗内消息。插件只读 source/materials 时不为取得窗口身份额外查询群历史；同群、截点、当前来源优先级和原话已读资格仍分别核对。

这是减少前段变动的装配方式，不是供应商缓存承诺。人格、配置、原话、读取范围、工具定义和上游转换均可能改变实际请求。

### 当前互动与行动合同

`input_status` 为已定位的每项来源提供 `speaker`、`event_type`、`is_current_source` 与 `original_complete`。人物、事件类型和本轮来源身份只是索引，唤醒理由只是读取线索；都不代替原话、授予阅读资格或证明对方正在向 Bot 提问。

`runtime_facts.participation` 从本轮已有 Session 快照投影，带 `session_version`：关注只列本轮相关人物且在装配时尚未到期的记录，过期的 `observing_until` 显示为 null。新输入及成功提交后沿原刷新路径替换快照，不新增全群实时状态或持久账本。短期关注只影响读取机会，不是性格、委托或必须发言的义务。等待目录补充已保存的 `question_message`、`created_at` 与 `expires_at`；问话位置是 Bot 的实际发送记录，不是人类原话证据，也不改变等待生命周期。目录与新字段仍受原最终容量核对，省略不能读作空状态。

实际发言和等待资格同时核对回执来源、模式、未知标记及平台消息 ID。模拟、Shadow、仅提交／入队和缺可靠身份的回执不能激活真实等待，也不更新真实 Bot 发言／短期关注事实。旧问话定位仍可作为历史记录查看，但不因此取得当前等待或叫醒资格；对话不能把回执事件名称单独当作对方已收到的问题。

原话投影在原事件已标记模拟时携带 simulated=true；Bot 的 MESSAGE_SENT 记录另带 delivery.status 与 origin_mode，不能仅凭 assistant 角色当成真实发言。来源与回执分类不增加原话已读范围，也不为未确认发送补成功身份。认识操作须用真实原话；即使 Bot 已真实送达，它也不能独立支持群友事实或现实能力。

固定系统合同按当前互动、同一循环行动、读取与表达、提交与真实结果、跨轮记忆与自然结束分组。它要求按实际问题选择直接回应、短查询、回忆、计算、必要澄清或原长工作，而非强制顺序执行。时效/精确外部事实要取得对应资料；普通社交、一般解释和指定照发不强制搜索。纠正先影响当轮表达，持久修改仍沿原认识操作及提交；无必要后续动作时结束，不空转或固定追加追问。

人工人格字段保持原样，与固定合同分别拼接为同一 `persona` 消息。插件 `include_identity=false` 只省略人格段，保留运行合同，再追加插件指令；不依赖对中文提示词截字符串，不更换模型绑定或增加调用。上述是输入合同，不是实际接话、查证或纠正效果的验收结论。

## 3. 锚定窗口与摘要覆盖

`anchor_window_start()` 只处理本次 `recent_history`。设其最老全局 rowid 为 `oldest`、步长为 `step`：

```text
boundary = ((oldest + step - 1) // step) * step
边界前原话 = 本次窗口中 rowid < boundary 的原话
候选裁剪 = 边界前原话中非本轮必需的普通历史
```

每轮重新装填，再对齐边界；不是保存上轮窗口头。边界不变时尾部可增长，跨过新边界时裁掉一段，因此可能呈锯齿形。

裁剪必须同时满足：

1. `step` 非零、近期窗口非空。
2. 边界前原话不是空集，也不是整个窗口；否则保持原窗口。
3. 每条候选原话的真实事件 ID，都在**本次实际保留且未省略的已完成摘要**的 `_summary_complete_ids` 中。

条件满足后，边界前本轮必须保留的当前或关联原话改归 `related_original`，放入窗口之后的 brought_in；正文、引用和 `_original_ranges` 保持不变，不因锚定或普通可选上下文释放而丢失。这些原话仍实际提供，不要求摘要替代，也不单独取消整次锚定。边界及其后的窗口保持原时序，最后按实际载体重新核对已读范围。

第 3 条只检查将被删除的普通历史，使用维护批次保存的 `complete_event_ids`，不拿摘要 JSON 投影的字符偏移与 `event.raw_text` 的偏移相比较，也不是仅看 rowid 区间或假设后台已经概括过。摘要存在于数据库但未装进本次请求，同样不授予裁剪许可。

无边界前原话可能只是窗口头正好位于格点，不能一概解释为锚定失败。普通历史覆盖不足时记录 `window_anchor/summary_does_not_cover_original`，保留整个原窗口，不提前移动必需原话；最终保留哪些原文仍以请求装配记录为准。

### 相互影响的参数

| 参数 | 影响 | 常见误判 |
|---|---|---|
| `conversation_history_limit` | 从数据库取得近期原料的条数上限 | 仅放大 token 预算不能突破原料条数 |
| `conversation_recent_tokens` | 当前/关联原话与近期历史的文字预算；也是摘要装填的独立文字上限 | 不等于每轮请求必定达到该值 |
| `conversation_window_step_rowids` | 窗口头的全局 rowid 对齐间隔 | 不是本群消息数，也不是每轮固定丢弃量 |
| `conversation_summary_limit` | 可尝试装入的最近已完成摘要数 | 数据库有覆盖不等于请求中有覆盖 |
| `history_target_tokens` | 维护批次目标原话量 | 不保证每批都能达到 |
| `maintenance_context_tokens` / `maintenance_output_tokens` | 维护请求输入余量 | 人格、认识、工具和续读也占容量 |
| `conversation_context_tokens` / `conversation_output_tokens` | 最终对话请求容量与输出预留 | 增大窗口不自动增大整个请求上限 |

全局 rowid 包含其他群和运行事件，同一步长在不同群的含义不同。条数上限、文字预算、步长与摘要覆盖应一起理解，不能规定任意群都必须由 token 上限先触发，也不能保证步长调小就有更高命中率。`recent_history/no_capacity` 只能说明本次装填受容量限制，要结合其他省略记录和实际范围判断。

维护容量影响批次覆盖，批次覆盖影响本次是否允许额外裁剪；不存在通用的“摘要条数 × 固定单条大小”裁剪公式。维护被未完成批次阻塞时，后续覆盖不推进，可能使当前窗口无法锚定。已有有限恢复与人工重试方式见[运行手册](operations.md)。

维护片段的 source_context 位于原文外层，按原事件给出类型、说话人、模拟与送达事实，新建及加载原批次均采用同一投影。history_source_text 不变，旧 start/end_offset、total_characters 与 complete_event_ids 不因新增标记重算；位置说明参与原输入容量估算，不追加免费调用。模拟片段可以在摘要中明确描述，但不能进入认识或当前 review_items 的真实来源。旧批次新增外层事实后仍须满足原容量检查，不以删标记或换坐标挤入。

## 4. 实际已读以最终请求为准

定位、取得、展示、已读与已处理是不同事实：

- `TurnReferences` 将短引用映射为真实身份；只有目录项不算已读。
- 提醒目录登记时另保留该记录的控制原值，修改／取消提案由宿主固定这份原值，在原提交事务核对；它不是原话／正文的阅读证明。装配省略项时原引用状态一同恢复，不从后来读取的值偷偷刷新已暂存提案的基线。工具定义不增加原值参数，原来源与可编辑资格仍须满足。
- 原文投影的贡献保存为 `_original_ranges`，包括正文及它引用的原文。
- `reconcile_original_reads()` 在容量裁剪和锚定后，按实际保留且未省略的载体重建范围并集；唯一载体被移除，就不再授予那部分读取资格。
- 工具页按原 `tool_call_id` 关联展示，完整字符串仍须匹配宿主采用的原投影。after_tool 的 notes/view 以独立 plugin_tool_view 放在整组原生工具回执之后，不重序列化原工具正文；说明不增加阅读资格，替换或删除正文也不能继承原有范围。
- `confirm_original_reads()` 在实际模型返回后确认本次提供范围，后续步骤及 checkpoint 沿同一 episode 累积；装配试算不算提供。
- 部分原话不能支持整条证据或完整处理；尚未覆盖部分保留在原 pending 生命周期。

工具资料的 characters 页须与已保存正文的相应片段相同；带本地引用的 records 页及带工作定位前缀的字符页，须与宿主最终采用的投影正文和范围一致。工作中的原始记录数组可按原 JSON 序列化规则确认，恢复后仍能识别原页。before_model 材料复制 result_id/displayed_range 却替换为摘要，不会继承原文已读资格。宿主试装、保存投影及插件说明均不等于实际提供，仍在最终请求保留且模型返回后才累积范围；不重写旧工作已保存的阅读记录。

模型输入中的 `chat_message` 独立保存发送者、原文、时间、引用、提及与范围。纯运行元数据使用 developer；外部资料、人类内容、认识、摘要及插件说明保持有类型的 user 材料，不提升为指令。

图片同时受 `max_context_images`、`media_context_max_bytes` 和整个请求容量约束，不计入原话文字额度。装不下像素时保留目录与未装配说明；已登记资产不等于已看见，指定发送资格与视觉证据资格分开。

对话和工作附件先核当前场景的登记类型。音视频只提供 `available / registered_media_reference_only` 清单与来源，不下载为图片、不消耗图片张数、不称已听过音轨或看过连续画面。即使工作没有确认视觉能力，音轨引用也不应被误报为缺视觉能力；采样帧仍必须满足原视觉条件。媒体总开关关闭时不继续提供可用装配说明，已有观察与资产身份不会因此被删除。

## 5. 需要时取回原话与资料

| 入口 | 当前职责 |
|---|---|
| `recall_chat` | 本群复合回忆入口，按词面、人物和时间寻找原话/摘要线索，按需展开底层读取 |
| `search_history_summaries` | 查询已完成摘要；语义能力受本群开关和检索绑定约束，摘要本身只定位 |
| `query_memory` | 查询有范围、主体、类别与有效状态的认识及来源，不把旧版本当当前事实 |
| `read_context` / `read_message_range` | 实际回读原话及其字符区间 |
| `read_tool_result` | 按明确 result_id 与坐标读取已保存工具正文，不重新执行源端请求 |

`seed_history_recall()` 还会对有限字面线索进行预取，并说明匹配局限；它只是补充，不是每条消息自动语义检索。未命中预取不证明没有相关历史。

recall_chat 的原话查询在数据库内先应用场景、截点、关键词、人物和时间条件，再按保存时序排序并 LIMIT；时间范围为起点包含、终点不包含，不先截取全群结果再筛选。返回保留 message_filters。附带的摘要仍只是同群关键词索引，明确未确认满足本次人物与时间条件，不冒充精确原话命中。

短于三个字符的关键词使用参数化 LIKE 查询，并显式指定 `ESCAPE '!'`；先转义 `!`，再转义 `%` 和 `_`，避免把用户字面内容解释为通配符。三个字符及以上继续使用原带引号的全文检索分支，不改变筛选范围、排序和数量上限。

已确认的有关称呼、偏好和群规则由互动偏好投影带入；其他认识按需查询。摘要、技能正文、Bot 发言或角色资料都不能替代真实来源。检索开关、索引覆盖与网络失败要分开说明，不能以“想不起来”断言历史不存在。

互动偏好在每次对话模型请求的最终装配前，沿原 interaction_preferences 重新读取本群及本轮相关人物的有效项，再执行原容量取舍；自然到期不会增加 knowledge_revision，因而不能只等新输入或成功提交才更新。这里只刷新既有本地投影，不自动调用 query_memory、向量检索或额外模型；只接收指定资料的插件入口仍不引入群偏好。投影仍是请求装配时的快照，不证明推理期间未变化，也不替换 Actor 的知识版本核对。

`query_memory` 的候选可能跨越嵌入和重排调用。返回保存结果前，沿原场景、主体、类别、创建时间与有效状态重新读取原表，只采用与所选候选相同的修订。期间变化的候选被移出，结果标为 partial 而不是冒充查无相关认识；不自动补查或再购重排。`memory_retrieval` 区分候选 ID/修订、返回 ID 与被排除的变化项；返回不等于模型实际读到，实际展示仍由原工具页记录。

认识查询的 fetched_at 固定在这次最终原表复核开始时，使用认识账本时钟，不采用复核后写 Trace 或序列化完成的较晚时间。因此记录在这些等待期间到期，后续展示仍能按原采样时间判断 stale_memory_result；不能把已经查到的旧快照伪装成到期后新取得的历史项。原查询条件、坐标、结果身份与显式续读方式不变。

新查询及 `read_tool_result` 的认识正文在展示前再次核对保存的修订；记录失效、修订变化或查询后到期，整份旧查询返回 `stale_memory_result`，由原循环在剩余预算内决定是否明确重查。字符和记录页都保留这个核对，不悄悄把保存正文替换为新记录，也不改变旧 result_id 或坐标。查询时已作为历史取得的到期条目仍可查看，不能当作当前认识；对话记录投影以 `effective_at_presentation` 区分当时有效性。面板仍能回读原保存资料。以上不撤回此前已经提供的历史交换，后续提交仍受原 knowledge_revision 检查约束。

工具页使用 `characters` 或 `records` 坐标；本地 `next_call` 与尚未取得的源端 `source_next_call` 分开。`presentation_capacity_error` 表示本次没能呈现，不是源无结果；试算未采用的页不推进已读范围。

单条资料答复可在 `answer_basis` 关联已读的人类原话与非空 ResultSpan；source 不自动填入依据。范围只从实际请求返回之后的累计展示记录取得，独立恢复仅有资料 ID 时仍须重新读取，不从导入目录继承已读。工作依据另确认实际请求中的完整结果投影，或已保存工作详情的完整记录区间；省略/紧凑目录不计。当前工作版本与结果来源在原事务再次核对。此状态只补足答复到实际资料的关联，不建立第二个阅读调度器，也不改变原话或工作压缩的所有权。

导入 Python 的是本工作已保存资料或获准图片，不自动要求模型先逐字读完，也不因导入而增加模型实际已读范围。输入清单记录导出时工作修订、原资料状态、source_truncated 和 provenance，源端未取得部分不因复制到文件变完整。清单、程序读取、程序结果、模型读取与发送回执是不同事实；面板查看输入来源不会触发其中任何后续动作。

公共兴趣摘要只作为研究线索或已采用候选，不等于重新读取原始资料。分享入口按本群主题、有效期及匿名来源选择可发布项，不直接分享研究意图；近期表达材料只含当前 Bot 在原截点之前至多四条真实送达文字节选，每条前 300 字符。覆盖和 provenance 只列实际采用记录，模拟与未知回执不冒充已经说过，也不把 Bot 文字当作外部事实证据。

## 6. 长工作检查点与压缩

主要实现为 [work_context.py](../src/len_bot/runtime/work_context.py) 与原工作运行器。检查点保留完整 assistant/tool 交换及供应商原生续接字段，不能拆开工具调用与回执。恢复沿同一目标 revision、绑定和累计账，旧资料不自动变成当前版本的新证据。

`WorkCompressor.prepare()` 的当前顺序：

1. 按最终消息、保留段与工具定义估算，超过 `job_compress_trigger` 才处理。
2. 先外置较早交换中的长工具正文，保留 result_id、原显示范围说明和明确回读入口；近期两组完整交换及工作关键资料不按这条规则移出。
3. 外置后达到 `job_compress_target` 就停止；没有合适完整旧区间或只剩终结预算时，不另购压缩调用。
4. 仍有必要时，使用 maintenance 绑定在它自己的窗口内压缩一个完整旧前缀，保留方法限制、反例、结果定位和未决项；不反复总结此前摘要。
5. 压缩调用以 `work_compression` 记入原工作，保存区间和目标 revision；没有形成可用窗口或发生错误，保留具体失败，不自动换协议或无限重压。

压缩不删除原工具资料、不增加读取资格、不清零费用。当前结果、最新目标和近期交换仍须判断；摘要中说“未完成”不证明保留在尾部的资料尚未读取。图片在恢复和压缩后仍使用同一容量规则。

工作工具附件使用已有 `image_manifest` 对象格式，归档仍只把实际图片块替换为资产引用。恢复只更新这些图片引用的装配状态，混合清单中的音轨说明原样保留，不能把没有图片块的音频改成“图片像素已丢失”。原前缀格式的旧检查点继续由已有解析入口读取，不新增另一份媒体状态或缓存。

方法正文仍沿原 read_skill 固定版本并保存观察，只有完整请求实际提供后才登记阅读范围；固定版本本身不等于正文已进入模型。候选只引用本工作实际提供过的资料，或 source_messages 中可定位的明确纠正；仅有纠正时允许不附工具结果，但两种来源不能同时为空。方法、旧摘要和 Bot 发言只作待核对材料，不能独立证明新方法正确。维护请求带来源工作阅读范围，仍受原工作累计账和维护窗口限制；不增加一轮审查、不为候选另建工作、不把面板回读记成模型已读。

## 7. 缓存与诊断边界

可选历史装填复用本次不变的基础请求与工具定义估算，每个新消息只计一次新增成本；失败仅回退本条及其引用原话的范围、引用登记和事件投影，不逐条深拷贝整个历史状态。估算直接跳过内部上下文元数据，真正出站时仍生成独立消息副本。当前来源片段与工具页的试装继续保留原回退路径，最终 messages + tools 的完整容量检查、图片、来源与预算边界不省略。这里不是跨轮缓存，也不据代码复杂度声称已测得加速倍数。

现有 Trace 分别记录 initial_source_reads_ms、initial_context_ms、context_plan.timings_ms 的 associated_source_reads/event_packing，以及各模型步骤的 request_preparation_ms、工具 execution_ms/tool_presentation_ms、提交与发布 timings_ms。event_packing 计已结束的装填调用并含媒体读取；initial_context 与 request_preparation 也包含各自等待、钩子或压缩，数值可能嵌套，不能相加冒充纯 CPU 耗时。模型等待沿原 latency_ms，真正发送仍查原行动回执的 queue_ms/send_ms；发布耗时不是平台送达耗时。

文件状态沿持久资产与原行动身份投影。当前可交付目录排除旧工作修订、未关联上传审查、已过期、已上传、已提交待核对或上传未知的资产；生成／下载不等于上传，模拟和 Shadow 不当真实 file_id。多个发起者同处一轮时不选择任意一人的授权代表所有工作，具体权限仍按原工作请求者在原事务与发送入口核对。状态增量留在运行事实尾部，不改变固定工具 Schema 或新增模型调用。

相同角色、资格和版本下，核心提案工具顺序、`respond` 参数与文件分支固定；工作、提醒、暂存回执和文件 ID 只在事实/回执中提供。对话上下文存在时同时提供 `read_pending_wakes` 与 `read_message_range`，不因当前待处理或部分原话为空而删工具。调用仍核对真实目标、截点、已读范围和资格；公开研究与插件工具子集不扩大。

终结阶段保留当前获准目录，使用原定向 `tool_choice`，并在任何工具执行前拒绝非终结响应。压缩之后重读额度和目录，更新实际请求的预算提示，再按最终 messages + tools 核对容量。对话、工作和维护的容量估算均包含这张完整目录；不再以仅终结工具的大小预估。

低频能力发现、权限撤销、角色差异和合法 hook 子集仍允许必要的目录变化。固定结构增加了部分无目标轮次的 Schema 开销，换取同资格下更少变化；真实协议兼容、调用结果、延迟与缓存收益仍需正常业务记录。窗口头稳定、消息目录相同，都不足以证明实际 token 前缀相同。

Trace 的 `context_plan.request.messages` 保存角色、类别、事件与范围、工具调用身份和省略记录，不保存完整请求正文或 base64。可从原事件回读，但不能据此补造历史完整请求；旧日志未记录完整 Schema 时也不能逐次还原其差异。

缓存统计区分正数、显式零和字段缺失；字段缺失不能还原上游是否报告零。命中率、上游账单、网关扣额与延迟分别解释。当前证据及未确认项统一在[当前任务](iteration.md)，不通过保温请求、扩大窗口或持续压测换取表面命中率。
