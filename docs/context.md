# 上下文装配

面向维护对话、工作与资料读取的开发者。本文说明当前源码如何装配、裁剪和恢复请求，不记录真实配置值或现场统计。行为边界见[架构](architecture.md)，参数保存见[运行手册](operations.md)，缓存结论口径见[缓存问题交接](serious-issue.md)，本批观察见[当前任务](iteration.md)，既往证据见[历史记录](history/README.md)。待实现目标与状态见[产品路线](plan/README.md)；源码改动与实际链路验收分开记录。

## 1. 对话与工作的生命周期不同

跨轮会话段的[结构设计与迁移约定](plan/s2-01-conversation-segment.md)已单独记录。当前接通原话窗口引用的保存与回读，并能在下一轮提供已存资料的定位级续读入口；段仍标记为 `source_window_only`，不表示保存了旧工具正文或原生交换。原生工具交换跨轮续接、固定材料持久版本和压缩交接仍未实现，不将完整设计视为已有能力。

- **普通对话**：每轮从事件、场景状态和持久资料重建请求，同时回读上一原话窗口保存的事件引用作为候选；不是跨轮无限累加的供应商会话。同一轮内保留原生工具交换，按需吸收新输入。
- **等待后的对话恢复**：沿 `ConversationResume` 保留原来源、资料、绑定、累计预算、消息数和期限；不是新预算，也不把旧原生轨迹当作一直在线的会话。
- **长期工作**：沿同一 job/revision 保存完整原生交换、已读范围和检查点；在原工作预算内外置或压缩旧材料。
- **历史维护**：按持久批次处理原话，产出的摘要用于连续性与定位；它不是工作上下文压缩，也不授予执行或发送能力。

## 2. 对话请求的来源与顺序

### 当前段的原话窗口引用

SceneSession 的可空 `conversation_segment` 保存当前段随机 ID、前段 ID、装配格式 1、开启时间与原因、无凭据模型绑定、知识修订、读取截点及有序事件 ID。只保存当前窗口引用，不复制原话、人格、工具正文或完整请求；没有新的段表。下一轮在同场景截点内回读这些原事件，与原近期查询候选合并、按保存位置排序，仍受 `conversation_history_limit` 和最终容量裁剪约束，不扩大查询数值限额。引用缺失时明确结束准备，不拿相近消息或摘要补造原话。

仅真实普通对话在最终裁剪后，通过原 Actor 队列与执行租约更新该字段；插件专用表达、工作和 Shadow 不写主段。保存校验预期段 ID、事件归属与顺序、非倒退截点，在原写锁事务内只更新该 JSON 字段及更新时间，不覆盖并发接入的 Session 其他事实。内存段在保存成功后采用；开启／换段在同事务记录 conversation_segment trace，context_plan.segment 同样标出 source_window_only。

同进程比较实际 system 内容、工具定义及已声明来源版本；这些比较材料只留在 Actor 内存，不写入段状态，也不是配置签名。模型绑定、知识修订或这些材料变化时开启 binding_changed 段；保留窗口移除旧事件时为 window_trimmed。首次为 initial，Actor 重新启动后首次装配为 process_restart，并可从原事件引用建立新段，不假装持久化了原人格／Schema。段身份不使用全局 rowid 取模；原窗口锚定算法仍是另一个装配规则，不被段 ID 替代。

保存位置在请求最终装配之后、模型额度准入和传输之前：已保存段不证明请求已发出、模型已读或来源已处理。取消、准入拒绝或后续发送失败仍可留下原话窗口候选，不自动执行或重发。pending_wakes、原话部分覆盖、累计预算、工作修订、提交和回执继续各自记录。本阶段没有保存窗外片段、摘要基线或原生交换，不能从段 ID 宣称跨轮工具经历已经恢复。

当前段还保存本轮已登记的 `result_aliases`（R → result_id）和 `job_aliases`（J → job_id），仅有身份，不含资料正文、工作状态或修订。下一轮先把它们装入独立编号预留表：同一对象重新登记时沿用原号，新对象不能占用尚预留的号；Actor 保存时也拒绝把上次保留的同号改指别的对象。每次保存只保留本轮已在请求中定位或重新登记的别名，不把已退出当前上下文的所有旧编号永久累积为全群目录。

预留表本身不填入本轮 `results`／`jobs` 可解析对象。普通对话在初始装配后，以段内 R 别名按本群范围核对已保存观察；在容量允许时追加 `saved_result_locators`，只列 R、原工具名及当前位置是否可用，不复制正文、不调用观察导入。最终模型请求仍保留该目录时，才使对应可用 R 成为本轮 `read_tool_result` 可解析位置；工具执行再次按本群范围读取，实际正文范围只在本轮最终呈现后取得阅读资格。目录因容量退出或资料已不可用，不恢复旧阅读资格；可用状态不代表已读、当前事实或来源未失效。旧段无别名时不从旧 trace 猜编号。工作 J 仍须重新取得当前快照后才能通过原引用入口解析；可操作状态、修订与发送资格独立核对。其他人物／认识／提醒编号、提案句柄及原生交换身份还未形成完整跨轮合同，当前覆盖仍是 source_window_only。

该目录的可解析编号还须与最终保留的原目录正文完全一致；正文若被合法入口改变，编号不作为本次可读位置。每次调用是否真的保留了这些定位项，由下述格式 v4 的逐消息清单记录，不用最终段状态倒推旧请求。

主要实现为 [context.py](../src/len_bot/cognition/context.py)、[projection.py](../src/len_bot/cognition/projection.py) 和 [input_window.py](../src/len_bot/cognition/input_window.py)。

| 来源 | 用途 | 主要容量约束 |
|---|---|---|
| `persona` | 人格、角色资料与当前对话合同 | 本轮配置快照、整个请求容量 |
| `original_input` / `related_original` | 窗外关联原话及未能完整装入的当前片段 | 优先装配，与近期历史共用文字预算 |
| `recent_history` | 本群近期连续完整原话，包含落在该窗口内的当前或关联来源 | `conversation_history_limit` 与 `conversation_recent_tokens` |
| `history_summary` | 已完成摘要及覆盖目录 | 摘要条数、摘要自身文字和整个请求容量 |
| `saved_result_locators` | 上段已存工具资料的本群可用位置，不含正文 | 可选；整个请求容量，不提供本轮阅读资格 |
| 偏好、媒体目录、表达样例 | 有范围的参考 | 各自上限及整个请求容量 |
| 时钟、运行事实、输入状态、预算 | 本次执行事实 | 不混入人类原话，不作为长期认识 |
| `tools` | 本次可见工具定义 | 独立请求字段，也参与容量估算和缓存变化 |

先保全当前与关联原话，再从最新消息向前装近期历史。近期历史遇到容量不足停止；当前长原话可按字符片段提供，其余部分仍待处理。完整原话与引用先用固定投影，只有必需来源装不下时才缩小片段；不能因本轮关联身份不同而改变完整原话的引用长度。摘要与原话窗口并列，不直接替换某条原文；摘要标为 `locator_only`，精确引述仍须回读。

`build()` 最后按以下顺序排放消息，随后核对容量、锚定和实际阅读集合：

```text
stable（当前只有 persona）
→ window（recent_history，按保存时序）
→ brought_in（窗外引用/取回原话、片段与当前像素，各自保留时间）
→ volatile（时钟、摘要、偏好、运行状态、预算、媒体目录等）
```

窗口归属与本轮关注来源分开：从原近期候选中确认最近一段连续保留的完整固定投影；尾部新输入尚未完整装入时保留在窗口之后，不因此搬走较早的完整窗口。窗内某条旧消息变为关联、邻居或召回来源时，原话仍只在原时序位置出现一次，关注关系留在 input_status。真正窗外取回的消息不会被插到近期窗口最前端。原话定位与成员编号沿真实身份生成；图片使用 `I:<asset_id>`，新增图片不重编号历史资产。原生工具交换不参与上述时序重排。

近期候选身份由入口的实际 get_recent_events 查询产生，作为独立的 recent_event_ids 传入普通对话与插件装配；不能从已经合并的 events 列表猜测。较早的待处理原话、等待恢复锚点和插件来源即使同时提供，也不自动成为窗内消息。插件只读 source/materials 时不为取得窗口身份额外查询群历史；同群、截点、当前来源优先级和原话已读资格仍分别核对。

这是减少前段变动的装配方式，不是供应商缓存承诺。人格、配置、原话、读取范围、工具定义和上游转换均可能改变实际请求。

### 当前互动与行动合同

`input_status` 为已定位的每项来源提供 `speaker`、`event_type`、`is_current_source` 与 `original_complete`。人物、事件类型和本轮来源身份只是索引，唤醒理由只是读取线索；都不代替原话、授予阅读资格或证明对方正在向 Bot 提问。

`runtime_facts.participation` 从本轮已有 Session 快照投影，带 `session_version`：关注只列本轮相关人物且在装配时尚未到期的记录，过期的 `observing_until` 显示为 null。新输入及成功提交后沿原刷新路径替换快照，不新增全群实时状态或持久账本。短期关注只影响读取机会，不是性格、委托或必须发言的义务。等待目录补充已保存的 `question_message`、`created_at` 与 `expires_at`；问话位置是 Bot 的实际发送记录，不是人类原话证据，也不改变等待生命周期。目录与新字段仍受原最终容量核对，省略不能读作空状态。

实际发言和等待资格同时核对回执来源、模式、未知标记及平台消息 ID。模拟、Shadow、仅提交／入队和缺可靠身份的回执不能激活真实等待，也不更新真实 Bot 发言／短期关注事实。旧问话定位仍可作为历史记录查看，但不因此取得当前等待或叫醒资格；对话不能把回执事件名称单独当作对方已收到的问题。

原话投影在原事件已标记模拟时携带 simulated=true；Bot 的 MESSAGE_SENT 记录另带 delivery.status 与 origin_mode，不能仅凭 assistant 角色当成真实发言。来源与回执分类不增加原话已读范围，也不为未确认发送补成功身份。认识操作须用真实原话；即使 Bot 已真实送达，它也不能独立支持群友事实或现实能力。

固定系统合同按当前互动、同一循环行动、读取与表达、提交与真实结果、跨轮记忆与自然结束分组。它要求按实际问题选择直接回应、短查询、回忆、计算、必要澄清或原长工作，而非强制顺序执行。时效/精确外部事实要取得对应资料；普通社交、一般解释和指定照发不强制搜索。纠正先影响当轮表达，持久修改仍沿原认识操作及提交；无必要后续动作时结束，不空转或固定追加追问。

当前循环与剩余预算内可完成的短查询、计算和必要续读直接处理，分页本身不是创建工作的条件。较长执行、跨轮保存进度或仅供工作调用的能力才按需使用 start_work；同一工作仍先读已有状态，不为重发成果重新执行。工具说明与无效 ack_ref 的错误提示采用同一边界：新建工作或提醒先取得对应暂存回执，再确认创建；普通短查询不填写创建句柄，不改变原提交和预算校验。

respond 的公开结构与参数解析来自同一组输入模型，不重复填写 intent。普通回复用 source 指定主来源，用可选 covers 声明同一答复覆盖的其他已读待处理人类原话。sources 只填 silent／incomplete 及具体原因或未完成部分；replied、delegated 和 waiting 从真实消息、创建提案和等待关系派生。仅仅读到的独立来源继续待处理，本阶段没有处理任何来源时用 note 说明结束或等待原因。系统触发交付仍沿原 delivery_ref 和已读原始委托处理，宿主关联本次已读运行来源，保留其系统类型与原人类证据边界。

answer_basis 按 kind 区分字段：social/general 只填类别，observed 提供直接已读依据，work_result／mixed 保留实际工作与资料关系，unverified 列出缺口。错误定位到 messages 索引及对应字段；不自动丢证据、换类别或把未完成来源变成旁听。显式 incomplete 的等待沿真实 expect_reply 消息关联保存恢复来源，仍共享原预算、消息额度与送达条件。

人工人格字段保持原样，与固定合同分别拼接为同一 `persona` 消息。插件 `include_identity=false` 只省略人格段，保留运行合同，再追加插件指令；不依赖对中文提示词截字符串，不更换模型绑定或增加调用。上述是输入合同，不是实际接话、查证或纠正效果的验收结论。

### 人物与服装参考目录

`runtime.character_reference_assets` 是运营确认的人物键、服装与已登记图片资产的对应表。普通对话及包含人格的完整对话插件，在历史摘要装配之后、反应表情目录之前，按本轮配置快照读取同场景／global-safe、启用的运营图片元数据，形成 `character_reference_catalog`。仅指定来源／材料的插件早返回路径不引入此目录。

每项只提供 character_key、outfit、image_ref、短描述及 catalog_only，归入原 `reference` 区和媒体 manifest，用途标为 character_reference。逐项核对总请求容量；装不下时恢复临时引用并记录省略，不挤走当前原话、改变历史锚定或装入五张像素。目录中的定位不授予视觉阅读、原话依据或最新事实资格。

需要辨认人物时沿原 read_media 读取相关参照，与当前群图像素及明确原话一起判断；图片数量、字节、实际已读重建和发送资格仍用原路径。固定表情目录在 LIMIT 之前排除“人物参考”标签，保留原表情频率、顺序和数量。目录配置保存不会上传素材、修改角色文字或读取像素；素材停用后后续目录不再提供该项。

### 图片讨论与纠正的对象关联

当前人类来源包含图片或真实消息引用时，`related_image_context` 从同场景、读取截点内的真实原话出发，沿平台引用和 Bot 实际 sent 回执的 origin_event_id／covered_source_event_ids 找回图片来源。引用只连接严格早于当前消息的原记录；同平台 ID 有多份记录时选最近的合法前项。排除模拟、Shadow、未确认发送、conversation_excluded 记录及其他场景，校验图片资产仍登记在本场景或 global-safe。仅指定来源／材料的插件入口不自动扩展这条路径。

找到具体图片后，按同一来源或完全相同的 asset_id，查询后续人类引用及其被引用的实际回答、原来源。查询先限定对象和真实关系，再按 rowid 倒序选取。原 retrieval_default_limit 分别约束向前追溯的新增原话数、后续人类回复数；每批回复共用其条数三倍的补充祖先／桥接回执额度，额度用尽标记 limited，不能据此宣称全部相关原话已经找到。它不会通过“这是某某”等词给原话贴上“正确纠正”标签，也不搜索图片相似度、URL 相等或新建认识。

选中材料沿原 pack_events 装配，当前来源保持其原片段；相关材料先尝试较新的人类原话，再尝试旧 Bot 回答，装配后仍按原保存时序展示。文字、引用与像素各自沿原容量和阅读确认处理，窗外材料保留 related_original，不搬到历史窗口头。续轮吸收新输入使用同一路径，不重排原生工具交换。

另有 `image_discussion` 短目录列出原图所在消息和 reply、response_source、covered_response_source 关系；它只提供 locator_only，不因存在关系就把未装入的原话、摘要或像素算已读。目录装不下则记录省略；原文仍以最终请求的范围集合为准。主对话读原话判断是否构成纠正及其对象，采用当前明确纠正，不把旧回答当作人物事实。关联事实与额度记录在原 context_plan.image_discussion，查找耗时记为 image_related_source_reads；这些是定位诊断，不是事实核实或表达效果结论。

边界：未明确引用的“上一张”等表达仍由已有群上下文判断；单凭这类文字不持久绑定对象。重传的图片通常会获得新资产 ID，不自动沿用旧图纠正。跨对象的人物知识继续依赖人工角色资料、实际参照像素和原认识修订，不从一次认图自动泛化。源码路径与实际采用效果分开验收。

## 3. 锚定窗口与摘要覆盖

`anchor_window_start()` 只处理本次 `recent_history`。设其最老全局 rowid 为 `oldest`、步长为 `step`：

```text
boundary = ((oldest + step - 1) // step) * step
边界前原话 = 本次窗口中 rowid < boundary 的原话
候选裁剪 = 边界前原话中非本轮必需的普通历史
```

每轮重新装填，再对齐边界；不是保存上轮窗口头。边界不变时尾部可增长，跨过新边界时裁掉一段，因此可能呈锯齿形。

裁剪必须同时满足：

1. `step` 非零、近期窗口非空。
2. 边界前原话不是空集，也不是整个窗口；否则保持原窗口。
3. 每条候选原话的真实事件 ID，都在**本次实际保留且未省略的已完成摘要**的 `_summary_complete_ids` 中。

条件满足后，边界前本轮必须保留的当前或关联原话改归 `related_original`，放入窗口之后的 brought_in；正文、引用和 `_original_ranges` 保持不变，不因锚定或普通可选上下文释放而丢失。这些原话仍实际提供，不要求摘要替代，也不单独取消整次锚定。边界及其后的窗口保持原时序，最后按实际载体重新核对已读范围。

第 3 条只检查将被删除的普通历史，使用维护批次保存的 `complete_event_ids`，不拿摘要 JSON 投影的字符偏移与 `event.raw_text` 的偏移相比较，也不是仅看 rowid 区间或假设后台已经概括过。摘要存在于数据库但未装进本次请求，同样不授予裁剪许可。

无边界前原话可能只是窗口头正好位于格点，不能一概解释为锚定失败。普通历史覆盖不足时记录 `window_anchor/summary_does_not_cover_original`，保留整个原窗口，不提前移动必需原话；最终保留哪些原文仍以请求装配记录为准。

### 历史维护期间的新输入与采用资格

历史批次使用原固定来源与完整原话覆盖，生成在 Actor 写入区之外进行，新消息仍可接收。采用前若已有普通对话租约，原 HistoryCommitDeferred 路径等待该对话结束，不重新生成候选；Actor 以届时的 Session 构造提交状态，批次之后的新输入不会被旧快照覆盖。相关认识的目标或主体／类别版本已变化时，仍沿原事务保留 stale_memory_candidates，不强行采用；无关认识变化不取消整批历史覆盖。

进入采用队列前及原 commit_history_batch 写入边界，复核同一个当前维护条件：运行时仍运行、维护入口可用且当前场景允许维护。运行停止保留取消语义；资格拒绝以 PermissionError 结束，原批次失败和诊断路径保留，不再写成已完成摘要或已采用认识。本事务的候选写入随拒绝回滚，Actor 不采用失败事务的内存状态；此前真实原话、调用及费用不删除。没有自动重试、换模型或改投其他场景。

这是现有历史维护合同，不是活动段完整原生交换的压缩交接；后者尚未实现，不能由历史摘要存在推断已恢复全部工具经历。

### 相互影响的参数

| 参数 | 影响 | 常见误判 |
|---|---|---|
| `conversation_history_limit` | 从数据库取得近期原料的条数上限 | 仅放大 token 预算不能突破原料条数 |
| `conversation_recent_tokens` | 当前/关联原话与近期历史的文字预算；也是摘要装填的独立文字上限 | 不等于每轮请求必定达到该值 |
| `conversation_window_step_rowids` | 窗口头的全局 rowid 对齐间隔 | 不是本群消息数，也不是每轮固定丢弃量 |
| `conversation_summary_limit` | 可尝试装入的最近已完成摘要数 | 数据库有覆盖不等于请求中有覆盖 |
| `history_target_tokens` | 维护批次目标原话量 | 不保证每批都能达到 |
| `maintenance_context_tokens` / `maintenance_output_tokens` | 维护请求输入余量 | 人格、认识、工具和续读也占容量 |
| `conversation_context_tokens` / `conversation_output_tokens` | 最终对话请求容量与输出预留 | 增大窗口不自动增大整个请求上限 |

全局 rowid 包含其他群和运行事件，同一步长在不同群的含义不同。条数上限、文字预算、步长与摘要覆盖应一起理解，不能规定任意群都必须由 token 上限先触发，也不能保证步长调小就有更高命中率。`recent_history/no_capacity` 只能说明本次装填受容量限制，要结合其他省略记录和实际范围判断。

维护容量影响批次覆盖，批次覆盖影响本次是否允许额外裁剪；不存在通用的“摘要条数 × 固定单条大小”裁剪公式。维护被未完成批次阻塞时，后续覆盖不推进，可能使当前窗口无法锚定。已有有限恢复与人工重试方式见[运行手册](operations.md)。

维护片段的 source_context 位于原文外层，按原事件给出类型、说话人、模拟与送达事实，新建及加载原批次均采用同一投影。history_source_text 不变，旧 start/end_offset、total_characters 与 complete_event_ids 不因新增标记重算；位置说明参与原输入容量估算，不追加免费调用。模拟片段可以在摘要中明确描述，但不能进入认识或当前 review_items 的真实来源。旧批次新增外层事实后仍须满足原容量检查，不以删标记或换坐标挤入。

## 4. 实际已读以最终请求为准

定位、取得、展示、已读与已处理是不同事实：

- `TurnReferences` 将短引用映射为真实身份；只有目录项不算已读。
- 提醒目录登记时另保留该记录的控制原值，修改／取消提案由宿主固定这份原值，在原提交事务核对；它不是原话／正文的阅读证明。装配省略项时原引用状态一同恢复，不从后来读取的值偷偷刷新已暂存提案的基线。工具定义不增加原值参数，原来源与可编辑资格仍须满足。
- 原文投影的贡献保存为 `_original_ranges`，包括正文及它引用的原文。
- `reconcile_original_reads()` 在容量裁剪和锚定后，按实际保留且未省略的载体重建范围并集；唯一载体被移除，就不再授予那部分读取资格。
- 工具页按原 `tool_call_id` 关联展示，完整字符串仍须匹配宿主采用的原投影。after_tool 的 notes/view 以独立 plugin_tool_view 放在整组原生工具回执之后，不重序列化原工具正文；说明不增加阅读资格，替换或删除正文也不能继承原有范围。
- `confirm_original_reads()` 在实际模型返回后确认本次提供范围，后续步骤及 checkpoint 沿同一 episode 累积；装配试算不算提供。
- 部分原话不能支持整条证据或完整处理；尚未覆盖部分保留在原 pending 生命周期。

工具资料的 characters 页须与已保存正文的相应片段相同；带本地引用的 records 页及带工作定位前缀的字符页，须与宿主最终采用的投影正文和范围一致。工作中的原始记录数组可按原 JSON 序列化规则确认，恢复后仍能识别原页。before_model 材料复制 result_id/displayed_range 却替换为摘要，不会继承原文已读资格。宿主试装、保存投影及插件说明均不等于实际提供，仍在最终请求保留且模型返回后才累积范围；不重写旧工作已保存的阅读记录。

模型输入中的 `chat_message` 独立保存发送者、原文、时间、引用、提及与范围。纯运行元数据使用 developer；外部资料、人类内容、认识、摘要及插件说明保持有类型的 user 材料，不提升为指令。

图片同时受 `max_context_images`、`media_context_max_bytes` 和整个请求容量约束，不计入原话文字额度。装不下像素时保留目录与未装配说明；已登记资产不等于已看见，指定发送资格与视觉证据资格分开。

对话和工作附件先核当前场景的登记类型。音视频只提供 `available / registered_media_reference_only` 清单与来源，不下载为图片、不消耗图片张数、不称已听过音轨或看过连续画面。即使工作没有确认视觉能力，音轨引用也不应被误报为缺视觉能力；采样帧仍必须满足原视觉条件。媒体总开关关闭时不继续提供可用装配说明，已有观察与资产身份不会因此被删除。

## 5. 需要时取回原话与资料

| 入口 | 当前职责 |
|---|---|
| `recall_chat` | 按词面、人物和固定时间范围定位本群原话，返回实际筛选条件及截点；按需展开底层读取 |
| `search_history_summaries` | 按主题寻找已完成摘要，以词面匹配为基础；语义候选受本群开关、检索绑定和索引约束，摘要本身只定位 |
| `query_memory` | 查询有范围、主体、类别与有效状态的认识及来源，不把旧版本当当前事实 |
| `read_context` / `read_message_range` | 实际回读原话及其字符区间 |
| `read_tool_result` | 按返回的 next_call 续读已保存资料，保留 result_id、offset、limit、coordinate_unit，不重新执行源端请求 |

有原话关键词时优先 recall_chat，人物和时间分别填写对应字段，不把整段检索要求当作词面查询。只有主题大意或需要摘要线索时使用 search_history_summaries，不因为超出近期窗口就强制先查摘要；语义能力不可用时不能宣称已做语义检索。摘要命中仍须回读原话并核对人物、时间和具体内容。

资料续读沿实际返回的 next_call 保留完整参数，不仅复制 next_offset，也不混用字符与记录坐标；初始正文因容量未装入时，定位提示使用相同规则。source_next_call 是源端尚未取得的下一批，不等于本地已保存正文的续读；错误处理仍按具体回执修正，不改分页器或读取资格。

`seed_history_recall()` 还会对有限字面线索进行预取，并说明匹配局限；它只是补充，不是每条消息自动语义检索。未命中预取不证明没有相关历史。

recall_chat 的 `time_range` 为两种互斥形状：absolute 提供 start_time／end_time 绝对 Unix 秒，日期含义沿当前业务时区；relative 提供 request_source 与 lookback_seconds。对话入口的 request_source 必须解析为本轮已完整读取、同群且在读取截点内的人类原话。宿主用该原话 timestamp 计算 `[timestamp-lookback_seconds,timestamp)`，继续同一来源不会跟随执行时钟移动；右端不含原请求时间。没有时间条件时省略 time_range，不推测日期或补造范围。

工作入口没有对话短引用表，relative 只接受该工作原始 request_source_event_id；工作事实显式提供此 ID，仍需核对它是同群、截点内的人类来源。此定位沿已确认的委托关系，不授予原话或检索候选新的证据资格。其他无原请求的入口使用明确的绝对区间；错误不会被自动改成当前时间或另一条消息。

原话查询在数据库内先应用场景、截点、关键词、人物和解析后的时间条件，再按保存时序排序并 LIMIT，不先截取全群结果再筛选。保存的原观察正文包含原输入形状的 time_range、time_anchor 中的原请求 ID／timestamp，以及 message_filters 中实际执行的人物、起止、through_rowid、limit。相对输入回显保留 request_source 和 lookback_seconds，不把扩展后的事实字段塞回输入形状。同一问题再次查询保留时间含义，每次实际读取截点分别记录；新提问明确要“现在再看”才选新的请求来源。

recall_chat 只返回符合条件的原话候选，不再附带未经人物／时间筛选的摘要，也不以摘要命中把原话空集改成 ok。主题定位继续用 search_history_summaries。候选和片段仍只是位置，须回读原话才取得精确引用资格；SQL 查询、人物过滤、排序、LIMIT 与特殊字符转义路径不变。

短于三个字符的关键词使用参数化 LIKE 查询，并显式指定 `ESCAPE '!'`；先转义 `!`，再转义 `%` 和 `_`，避免把用户字面内容解释为通配符。三个字符及以上继续使用原带引号的全文检索分支，不改变筛选范围、排序和数量上限。

已确认的有关称呼、偏好和群规则由互动偏好投影带入；其他认识按需查询。摘要、技能正文、Bot 发言或角色资料都不能替代真实来源。检索开关、索引覆盖与网络失败要分开说明，不能以“想不起来”断言历史不存在。

互动偏好在每次对话模型请求的最终装配前，沿原 interaction_preferences 重新读取本群及本轮相关人物的有效项，再执行原容量取舍；自然到期不会增加 knowledge_revision，因而不能只等新输入或成功提交才更新。这里只刷新既有本地投影，不自动调用 query_memory、向量检索或额外模型；只接收指定资料的插件入口仍不引入群偏好。投影仍是请求装配时的快照，不证明推理期间未变化，也不替换 Actor 的知识版本核对。

`query_memory` 的候选可能跨越嵌入和重排调用。返回保存结果前，沿原场景、主体、类别、创建时间与有效状态重新读取原表，只采用与所选候选相同的修订。期间变化的候选被移出，结果标为 partial 而不是冒充查无相关认识；不自动补查或再购重排。`memory_retrieval` 区分候选 ID/修订、返回 ID 与被排除的变化项；返回不等于模型实际读到，实际展示仍由原工具页记录。

认识查询的 fetched_at 固定在这次最终原表复核开始时，使用认识账本时钟，不采用复核后写 Trace 或序列化完成的较晚时间。因此记录在这些等待期间到期，后续展示仍能按原采样时间判断 stale_memory_result；不能把已经查到的旧快照伪装成到期后新取得的历史项。原查询条件、坐标、结果身份与显式续读方式不变。

新查询及 `read_tool_result` 的认识正文在展示前再次核对保存的修订；记录失效、修订变化或查询后到期，整份旧查询返回 `stale_memory_result`，由原循环在剩余预算内决定是否明确重查。字符和记录页都保留这个核对，不悄悄把保存正文替换为新记录，也不改变旧 result_id 或坐标。查询时已作为历史取得的到期条目仍可查看，不能当作当前认识；对话记录投影以 `effective_at_presentation` 区分当时有效性。面板仍能回读原保存资料。以上不撤回此前已经提供的历史交换，后续提交仍受原 knowledge_revision 检查约束。

### 认识旧页再次进入请求

普通对话、独立插件和普通工作的最终请求装配也执行同一认识修订核对，范围限于原 read_presentations 能关联已保存 query_memory 正文的工具页和插件资料。相同保存查询在一次装配内复核一次；修订变化、不再可读或查询后到期时，下一请求用 stale_memory_result 替换该页正文，账本不可用时用 memory_unavailable。原消息角色、原生调用配对及 result_id 保留，不带旧展示范围、证据引用或自动续读；实际阅读清单在替换后计算，错误不新增已读范围。

工作在原两处压缩准备前也复核保留认识页，不把当时已确认失效的页直接带入新压缩。有效页保持原样，不自动重查或替换为新认识。已保存观察、之前真实阅读和请求审计不回写；这不是供应商侧历史撤回，本页核对自身不追溯其他衍生材料；工作压缩条目的来源复核见下节。复核后的在途变化仍由各自原提交边界处理，完整段交接尚未接通。

### 历史摘要来源可用性

历史摘要仍以批次的 source_event_ids、同群与原 rowid 范围为依据。对话初始摘要、词法查询和语义候选在 LIMIT／排名前排除来源不完整的批次；对话摘要还在截取前限定本轮读取截点。不自动回读全部原话，不重建索引或重做摘要。候选在查询等待期间变化时，保存前再次复核并移出变化项，返回 partial 及覆盖说明，不自动补查。

新页、续读与后续请求复核当前批次完成状态、generation_version 和来源身份；失效的已存摘要页返回 stale_history_summary。直接历史摘要区块以仅在本次装配存在的批次／版本侧记复核，任一批次失效时整块正文及覆盖侧记撤下，保留不可用说明；不从自然语言拆出“仍有效的半份摘要”。同样适用于旧工具回执、插件资料和工作压缩准备前的摘要定位页，不为这些定位页授予原话已读。

原批次和已保存观察继续供审计，不改 completed 为 failed，不撤销此前真实已读。面板批次列表／详情的 sources_available 是即时来源位置可用性，历史摘要页在 false 时显示来源不完整提示；不能由 true 推断原话已读、当前认识有效或权限已授予。批次范围仍可定位并不证明其中历史断言尚未被纠正；现行认识仍沿原修订链及查询，工作压缩按下节复核已登记来源，不追补未登记的自由摘要依赖。各入口原执行授权与在途采用边界不变。

### 工作压缩条目的来源复核

新工作压缩条目的 result_ids 由宿主收集给定交换内成功工具回执及结构化插件资料中的实际资料编号，先限定为原工作资料集合；维护输出只填写 summary 和 unresolved，不再由生成响应挑选依赖列表。失败展示说明不会使已撤下正文重新成为有效依赖。压缩请求不附带全局 work_state，仍提供原目标、约束、所选交换及尾部数量；工作主请求的状态投影不因此被删除。

维护调用前和响应采用前，沿当前工作工具箱复核这些来源：认识查询检查原修订及查询后到期，历史摘要检查原批次及同群来源可用性。失效沿原压缩失败记录结束，不自动重做，不保存新摘要；已发生的调用和费用保留，权限／预算异常仍按原边界传播。

每次压缩准备先复核保留摘要，即使窗口尚未达到压缩阈值也不跳过；工作最终请求在钩子之后再复核。仅将与原已保存条目精确匹配的摘要载体撤下，换成区间、资料编号及不可用原因，不保留旧 summary 或 unresolved。原压缩条目和观察不回写，原已读事实不撤销，新说明不授予证据或自动续读。新来源列表的长度仍计入原窗口预算。

旧条目的 result_ids 可能是当时生成响应选取的子集；只复核已登记来源，不追补成“完整依赖”。自由表达、未关联资料的输入以及更早摘要未列出的认识依赖不由本机制猜测；全局工作状态的已登记来源按下节投影。升级不重写历史压缩或执行离线转换，也不声称能撤回已经发送的上下文。

### 当前工作状态与完成步骤依据

完成步骤的每个 result_ids 项须在该步骤的 evidence_spans 中有对应实际阅读范围，再由原事务核对坐标、总长和已提供记录。只取得工具观察不等于已经完成有依据的步骤。原 key_result_ids 仍可作目录定位，不为无须声称完成的计划强制逐项检索；目录和状态也不授予新的阅读资格。

工作事实使用唯一 work_facts 载体。两处压缩准备前以及最终请求在钩子之后，从同工作／修订的当前 processing 记录刷新 work_state；其余原话、图片、目标、约束和资料目录不因此重复装配。原窗口核对仍计算更新后的状态，不能以已保存状态为理由超预算。state_needs_revision 继续只表示状态所属目标版本与当前目标不同。

旧状态缺少完成步骤的逐项范围时，本次投影以 work_state_evidence_missing 说明；已登记资料中的认识修订／到期、历史摘要来源失效沿原资料错误说明。此时本次 work_state 为 null，work_state_error 给出资料编号及原因，数据库原状态不被删除。补齐读取或纠正之后须明确 update_work_state，不自动修改计划，也不把历史提案参数当作当前可用状态。未登记的自由文本依赖不由本投影猜测。

### 工作成果与状态采用时的资料复核

最后一次请求的来源快照不能替代提交时核对。complete_job 在原事务中按插件最终整理后的成果资料、成果／显式状态、方法候选及公共兴趣的引用去重，update_work_state 按本次状态和方法候选引用去重；运行器回调从本群保存观察重新读取，不以内存里仍有旧正文证明资料可用。

认识查询沿原修订和到期规则，历史摘要沿原批次及来源规则复核；失效拒绝本次采用，候选暂存与状态写入随原事务回滚。成果继续通过 JobResultRejected 给出终结参数说明，状态继续通过原工具参数说明；不自动补查或生成替代资料。其他外部资料只保留原归属和实际读取要求，不新增联网真实性审查。

失败／中断／取消记录携带的旧 work_state 作为审计保留，不重复要求新完成步骤的阅读证明；显式新状态不享有这个豁免。原真实调用、已读事实、预算消耗和退出原因保留，成功采用仍另受当前执行资格及原工作修订约束。时间到期按本次检查时钟判断，不宣称重写既往请求或已经发生的交付。

工具页使用 `characters` 或 `records` 坐标；本地 `next_call` 与尚未取得的源端 `source_next_call` 分开。`presentation_capacity_error` 表示本次没能呈现，不是源无结果；试算未采用的页不推进已读范围。

单条资料答复在 `answer_basis.event_refs` 关联完整已读的人类原话，在 `answer_basis.evidence_refs` 复制支持结论的资料页 `evidence_ref`；source 不自动填入依据。页引用是宿主分配的 E 开头不透明标识，局部映射到原 result_id、坐标单位和非空范围。公开输入不再手填 result_spans，内部 AnswerBasis 仍保存原 ResultSpan，原事务继续复核同群、实际阅读、资料类别与工作版本。目录、摘要、工作定位和群原话序列化记录不会因有页引用而成为直接资料依据。

页名与已读资格分开：试装时可分配页名，候选可能随后缩小或被裁掉；最终请求必须保留原正文，或匹配宿主登记的原投影，read_presentations 才记录其实际范围与页名，模型响应后由原 adopt_presentations 确认。外置正文时移除 displayed_range、evidence_span 和 evidence_ref，仅保留原回读位置；已经确认的范围仍沿原账本保存。保存原工具观察时清空输入携带的 evidence_ref，插件不能用这个字段自发授予已读资格。反复展示同一页可复用引用；同页的多个有效引用分别确认，不能让其中一个名字掩盖另一个已经展示的名字。

工作 `finish_work.evidence_refs` 同样选择已读页，宿主解析为原 JobResult.evidence_spans，并继续要求每个 result_ids 项有实际依据。原 observation_reads 的每个资料／坐标单位记录增加 evidence_refs 映射，保存页名到精确范围的关系；原 ranges 仍合并以核对覆盖，不因合并丢掉页名。该字段随原工作阅读事务保存，拒绝把同一个页名绑定到另一资料或范围。工作恢复先按场景装入原资料，再从已保存 ranges 与页名重建局部映射；旧记录没有页名时不补造，需引用时按 read_tool_result 取得需要的页。保存过但尚未收到响应的原生页，恢复后只有正文在最终请求中再次通过核对，才能在新响应后取得资格。

工作中的独立插件读取仍通过原 record_presentations 回调保存实际阅读，父工作随后采用相同页名与范围；不是凭导入资料 ID 或插件输出摘要授予资格。work_state 和公共兴趣候选保留原显式 evidence_spans 合同，页面的 evidence_span 仍供这些结构与诊断使用。独立对话恢复只有资料 ID 时仍须实际提供正文，不继承其他执行的局部页名。

工作答复依据另确认实际请求中的完整结果投影，或已保存工作详情的完整记录区间；省略／紧凑目录不计。页引用只定位实际已读内容，不证明每个结论在语义上得到支持。没有新增资料表、阅读调度器、摘要事实或内容指纹，也不改变原话与工作压缩的所有权。

导入 Python 的是本工作已保存资料或获准图片，不自动要求模型先逐字读完，也不因导入而增加模型实际已读范围。输入清单记录导出时工作修订、原资料状态、source_truncated 和 provenance，源端未取得部分不因复制到文件变完整。清单、程序读取、程序结果、模型读取与发送回执是不同事实；面板查看输入来源不会触发其中任何后续动作。

公共兴趣摘要只作为研究线索或已采用候选，不等于重新读取原始资料。分享入口按本群主题、有效期及匿名来源选择可发布项，不直接分享研究意图；近期表达材料只含当前 Bot 在原截点之前至多四条真实送达文字节选，每条前 300 字符。覆盖和 provenance 只列实际采用记录，模拟与未知回执不冒充已经说过，也不把 Bot 文字当作外部事实证据。

## 6. 长工作检查点与压缩

普通研究追加整理／导出时，start_work.reuse_work_ref 选择已经实际提供的原成果版本；仅 query_jobs 控制目录不算完整成果读取。对话及原 Gate 的 provided_work_results、提交事务的同场景实际快照共同核对选择。任务 payload 保存的 reused_work 作为新工作固定输入提供，不从父工作当前状态动态替换；原未完成项继续明确展示。正文仍通过原 result_ids 读取或作为 run_python 的 input_result_ids 导入，新工作 observation_reads 从空开始，不继承父工作阅读资格。

有人类申请者的工作初始事实同时提供原 file_delivery_facts，区分生成配置、持久资产登记条件、平台上传配置和当前申请者授予。它不额外探测 Gateway，也不把保存配置当成部署连通或执行成功。工作合同按用户新要求完成格式转换／导出，已有资料优先按范围读取；原摘要只作整理输入，引用外部事实仍须真实阅读。产物导出、持久资产登记和群上传各沿自己的工具及回执，缺少前置保留具体未完成项。

主要实现为 [work_context.py](../src/len_bot/runtime/work_context.py) 与原工作运行器。检查点保留完整 assistant/tool 交换及供应商原生续接字段，不能拆开工具调用与回执。恢复沿同一目标 revision、绑定和累计账，旧资料不自动变成当前版本的新证据。

`WorkCompressor.prepare()` 的当前顺序：

1. 按最终消息、保留段与工具定义估算，超过 `job_compress_trigger` 才处理。
2. 先外置较早交换中的长工具正文，保留 result_id、原显示范围说明和明确回读入口；近期两组完整交换及工作关键资料不按这条规则移出。
3. 外置后达到 `job_compress_target` 就停止；没有合适完整旧区间或只剩终结预算时，不另购压缩调用。
4. 仍有必要时，使用 maintenance 绑定在它自己的窗口内压缩一个完整旧前缀，保留方法限制、反例、结果定位和未决项；不反复总结此前摘要。
5. 压缩调用以 `work_compression` 记入原工作，保存区间和目标 revision；没有形成可用窗口或发生错误，保留具体失败，不自动换协议或无限重压。

压缩不删除原工具资料、不增加读取资格、不清零费用。当前结果、最新目标和近期交换仍须判断；摘要中说“未完成”不证明保留在尾部的资料尚未读取。图片在恢复和压缩后仍使用同一容量规则。

工作工具附件使用已有 `image_manifest` 对象格式，归档仍只把实际图片块替换为资产引用。恢复只更新这些图片引用的装配状态，混合清单中的音轨说明原样保留，不能把没有图片块的音频改成“图片像素已丢失”。原前缀格式的旧检查点继续由已有解析入口读取，不新增另一份媒体状态或缓存。

方法正文仍沿原 read_skill 固定版本并保存观察，只有完整请求实际提供后才登记阅读范围；固定版本本身不等于正文已进入模型。候选只引用本工作实际提供过的资料，或 source_messages 中可定位的明确纠正；仅有纠正时允许不附工具结果，但两种来源不能同时为空。方法、旧摘要和 Bot 发言只作待核对材料，不能独立证明新方法正确。维护请求带来源工作阅读范围，仍受原工作累计账和维护窗口限制；不增加一轮审查、不为候选另建工作、不把面板回读记成模型已读。

压缩准备中的 PermissionError、JobBudgetExhausted、AgentBudgetExhausted 与 JobChanged 直接保留原异常类型及预算维度，交由原工作运行器处理中断或修订；没有获得调用资格不等于生成了错误摘要，不写成 compression.status=failed。原工作上限、累计用量及之前成功的压缩片段不变。真正的压缩内容／窗口失败仍走原失败记录；取消不被转换成内容失败，旧数据库中的失败记录不自动清除或重新分类。

## 7. 缓存与诊断边界

可选历史装填复用本次不变的基础请求与工具定义估算，每个新消息只计一次新增成本；失败仅回退本条及其引用原话的范围、引用登记和事件投影，不逐条深拷贝整个历史状态。估算直接跳过内部上下文元数据，真正出站时仍生成独立消息副本。当前来源片段与工具页的试装继续保留原回退路径，最终 messages + tools 的完整容量检查、图片、来源与预算边界不省略。这里不是跨轮缓存，也不据代码复杂度声称已测得加速倍数。

现有 Trace 分别记录 initial_source_reads_ms、initial_context_ms、context_plan.timings_ms 的 associated_source_reads/event_packing，以及各模型步骤的 request_preparation_ms、工具 execution_ms/tool_presentation_ms、提交与发布 timings_ms。event_packing 在装填退出时记录，包含失败及媒体等待；initial_context 与 request_preparation 也包含各自等待、钩子或压缩，数值可能嵌套，不能相加冒充纯 CPU 耗时。模型等待沿原 latency_ms，真正发送仍查原行动回执的 queue_ms/send_ms；发布耗时不是平台送达耗时。

context_plan.event_packing_detail 细分原事件装配，不额外执行查询或模型调用：

| 字段 | 口径 |
|---|---|
| calls；required_candidates／optional_candidates | 装填调用数及各次必需／可选候选数，跨调用累计 |
| evaluated_candidates／fitted_candidates | 已进入候选循环数／该次装填接受数；不等于最终请求保留数或模型确认已读数 |
| phases | snapshot、restore、text_projection、request_estimation、media_preparation、optional_release 各自的 calls 与 elapsed_ms；包含试装和回退 |
| media | asset_checks／asset_lookup_ms；source_preparations／source_prepare_ms；preparation_failures；prepared_reuses／failure_reuses |

request_estimation 包含其触发的工具定义准备，optional_release 内部估算计在释放阶段。source_prepare_ms 包含文件读取、锁等待、解码和图片块准备；内层资产再核对不属于前置 asset_lookup_ms。媒体子计时包含在 media_preparation，阶段计时包含在 event_packing；上下层不能相加，也不是无重叠的完整耗时分解。该细分尚不覆盖所有工具页和工作装配。

面板的阶段耗时从同一已存轨迹按执行段和步骤读取，不增加计时器或新记录：

| 原字段 | 展示口径 |
|---|---|
| initial_source_reads_ms／initial_context_ms | 初始来源读取／上下文装配，仍可包含内部等待、媒体准备和容量核对 |
| steps.request_preparation_ms | 本次请求准备，包括循环内预算核对、装配、合法 Hook 和最后裁剪；可能包含压缩或其他嵌套调用 |
| steps.latency_ms | 网关登记完成后，客户端请求至读取响应正文；不是首字时间，不含全部登记和结算，失败时可能没有此字段 |
| tool_calls.execution_ms／steps.tool_presentation_ms | 逐工具执行／本步工具结果装配；不包含全部回执保存，工具可能并行或调用嵌套工作 |
| timings_ms.commit／publication | 本执行段内提交／发布累计，包含各自等待及失败前时间；不表示提交成功或平台收到 |

外层 elapsed_ms 只在原轨迹有字段时展示，不用已知子项补总数。缺少入场等待、失败请求细分或其他阶段时显示未记录；嵌套阶段、并行工具与运行段不能相加为一条消息的耗时。

AgentLoop 在每步准备已经开始、但尚未建立本步请求记录时失败或取消，将 step、state、elapsed_ms 和 error_type 保存在原审计的 request_preparation_failure。计时从该步预算状态读取前开始，覆盖装配、合法 Hook、最终核对和本步模型额度取得之前／期间的已耗时间；不添加虚构 steps 或 call_id，也不改模型次数。执行段的失败记录仅对应导致本次循环退出的准备，后续请求或工具执行失败仍沿原步骤记录；连准备都未开始时不补零。界面单列该准备失败／取消，不能据此宣称没有费用，因为准备可能已执行原压缩等嵌套调用。记录不代表整个运行或消息处理总耗时，旧审计不回填。

ModelGateway 的原传输记录另有 client_elapsed_ms：调用登记完成后开始单调计时，至客户端返回并完成本地响应解析，或异常／取消到达网关时结束，在结算写入前保存。它包含客户端内部等待、多次传输尝试及其间隔，但不包含先前准入／登记和后续结算；不把 HTTP 尝试耗时简单求和代替它。成功、失败、取消均沿原终态保存该字段，usage、状态和占用结算规则不变。调用详情将它单列为“客户端请求至解析／中断”，不是首字延迟、纯供应商处理时长或单条消息总耗时；上游在取消后是否仍执行／计费仍不可由计时证明。旧记录、登记前失败和未经过此网关的入口不补值；原步骤 latency_ms 与调用账起止时间仍保留各自口径。

独立插件表达和插件等待恢复，在原 `_model_slot` 实际申请共享对话槽位时，以单调时钟记录取得前的 cognition_slot_wait_ms；记录逐次追加到原执行 audit 的 model_slot_waits，不另建 trace 类型或计时表。取得槽位记 acquired，取得前取消记 cancelled，其他取得失败记 failed；异常继续沿原调用传播。取得后的模型／业务异常不改写为等待失败，也不把执行期间时间计入等待。记录随原插件／父执行审计保存，不额外发模型请求或改变信号量释放。

model_slot_owned 的调用沿用已有执行容量，没有再次取得对话槽位，也不补“等待 0 毫秒”记录。该计时不包含之前的 agent_lock 等待、资料准备、工作执行槽位或模型请求时间，不能当成全部排队耗时。阶段耗时投影同时展示原对话与插件记录的取得／取消／失败状态；等待项和嵌套运行项按所属轨迹分段列出，展示顺序不构成全局时间顺序。缺失记录仍为未记录，旧轨迹不回填。

插件 Agent 在同一父执行内原有的 agent_lock 串行入口，也逐次把 agent_lock_wait_ms 及取得／取消／失败状态记到父审计的 agent_lock_waits。计时从本次进入该锁前到取得或退出，取得后内部模型或工具异常不改写成锁失败，仍沿原传播；不改变锁的持有与释放，也不添加独立调用身份。父执行可在锁等待时取消，因此不能等子审计创建后才记。它与后续 `_model_slot` 等待是两个阶段，可能在同一父审计内出现，但均不是整条插件执行的独占总耗时；没有记录也不推断为零。原阶段投影分别显示，不将父子项相加。

信息工作在原列表选中 processing 工作之后、进入共享 `_slots` 之前，按已选 job ID／当时 revision 另记一条 `agent_job_wait` 到既有 traces：取得记 acquired，取得前取消／异常分别记 cancelled／failed，耗时为从本次选取后至结果的单调时长。此处既有 agent_job 审计尚未建立，所以不能把取消伪装成后来的工作步骤；新增的是一条有原 job 关联的审计种类，不是新工作状态、认领、预算或数据库表。审计写入失败结束本次路径；取消期间的审计写入若也失败，记录原日志并继续抛出原取消，不吞错执行工作。

取得 `_slots` 不等于工作仍具备当前修订／资格或已经完成，后续执行仍沿原读取和限制；取得后的失败不改写为槽位等待失败。该计时不包含先前目录读取、同群前一个工作执行、方法维护自己等待同一信号量、工作内模型请求或外部执行；不能把它称为工作从创建到启动的全部排队耗时。原查询投影和阶段界面区分对话与工作槽位，保留未观测字段为未知，不将历史记录补成零。

同一 `_slots` 也服务本群方法维护任务。`_learn_scene` 在选定候选前等待，因此它只把本场景调度的 maintenance_slot_wait_ms 与 acquired／cancelled／failed 写到原 traces 的 `skill_maintenance_wait`，ref_id 是场景，不是假定的候选或来源工作。取得槽位后维持原 maintain_candidates 循环；记录失败不绕过等待或继续执行。该时长只包含共享槽位等待，不包含候选读取、方法请求、工作预算或结束结算；即使取得槽位，也可能没有候选实际处理。旧轨迹和候选状态不回填。

同一个必需消息候选未改变时复用当次容量估算；释放可选内容后重建候选并重算。图片准备保留原单次 read_cache，复用前仍查当前资产；资产不可用时清除该局部项并记录 asset_unavailable，不装像素。最终容量、窗口锚定及原文／图片阅读核对保留。这些准备复用与供应商 cached_tokens 是不同指标。

文件状态沿持久资产与原行动身份投影。当前可交付目录排除旧工作修订、未关联上传审查、已过期、已上传、已提交待核对或上传未知的资产；生成／下载不等于上传，模拟和 Shadow 不当真实 file_id。多个发起者同处一轮时不选择任意一人的授权代表所有工作，具体权限仍按原工作请求者在原事务与发送入口核对。状态增量留在运行事实尾部，不改变固定工具 Schema 或新增模型调用。

相同角色、资格和版本下，核心提案工具顺序、`respond` 参数与文件分支固定；工作、提醒、暂存回执和文件 ID 只在事实/回执中提供。对话上下文存在时同时提供 `read_pending_wakes` 与 `read_message_range`，不因当前待处理或部分原话为空而删工具。调用仍核对真实目标、截点、已读范围和资格；公开研究与插件工具子集不扩大。

终结阶段保留当前获准目录，使用原定向 `tool_choice`，并在任何工具执行前拒绝非终结响应。压缩之后重读额度和目录，更新实际请求的预算提示，再按最终 messages + tools 核对容量。对话、工作和维护的容量估算均包含这张完整目录；不再以仅终结工具的大小预估。

低频能力发现、权限撤销、角色差异和合法 hook 子集仍允许必要的目录变化。固定结构增加了部分无目标轮次的 Schema 开销，换取同资格下更少变化；真实协议兼容、调用结果、延迟与缓存收益仍需正常业务记录。窗口头稳定、消息目录相同，都不足以证明实际 token 前缀相同。

Trace 的 `context_plan.request.messages` 保存角色、类别、事件与范围、工具调用身份和省略记录，不保存完整请求正文或 base64。可从原事件回读，但不能据此补造历史完整请求；旧日志未记录完整 Schema 时也不能逐次还原其差异。

经现有模型网关的调用另在原调用登记事务内保存一份 `model_call_request` 轨迹，以 `trc_model_request_<call_id>` 和原 scene_id/call_id 绑定。记录取自合法 Hook、最终裁剪和模型消息清理之后，客户端调用之前；准入拒绝或登记失败时连同调用行回滚，不继续传输。已登记而没有响应的调用仍可保留此清单，但清单不是请求已发出、材料已读或供应商已计费的证明。

普通对话及复用同一上下文装配的插件入口，通过私有类型传递已有事件／原文字符范围、省略标记及原因和图像块资产定位。该旁路元数据在网关估算和传输前移除，不进入消息正文、工具 Schema 或供应商请求，也不授予已读资格。其他网关入口只记录最终可观察的角色、类别、工具调用身份和图像位置；没有来源定位的字段保留空值，不从正文、图像 URL 或时间猜测。直接向检索／转写接口发起的调用没有此清单，旧调用不回填。

普通工作请求也在最终图片窗口同步和容量核对之后，把原工作 image_manifest 的图片序号映射到当前消息 content 的实际块位置，写入已有 image_assets 定位。只为本位置仍保留 image_url 像素块的资产登记；被移出或 included_elsewhere 的目录项不冒充本位置图片，也不把整轮 current_pixel_assets 集合填到每条消息。这里读取原窗口已有清单，不解析图片 URL、不重新读文件或下载、不保留 base64，不改变图片预算／已读资格；尚未接入的其他入口和旧记录仍保留未知。

调用详情在原消息顺序表内可展开每条消息的图像定位，显示内容块位置、图像类型与已记录资产 ID。界面位置从 1 开始，原记录 index／part_index 仍从 0 开始；缺资产编号明确显示未记录，不从当前资料补齐。展开只呈现原字段，不请求图片或媒体元数据，也不证明模型收到像素、资产当前可读或平台取得文件。保留原每次 25 条消息的展开范围与完整定位字段入口。

格式 v1 只保存位置和引用、消息字符串长度、图像块类别与已知资产、工具名称顺序、定向选择及实际模型／推理强度／最大输出设置。格式 v2 在同一记录中增加下列固定组件快照，不回填旧记录：

- `conversation.contract`：对话系统消息中由源码声明的固定合同，保存声明修订号、消息内字符范围和该片段全文。人格配置、表达偏好与插件动态指令不在快照中，消息顺序和实际发送内容不因登记改变。
- `core.proposals.<工具名>`：`respond` 与核心提案工具的声明修订号、当次描述和完整参数 Schema。私有定义对象沿原副本与 Hook 子集传递；其附属快照不参与容量估算，进入客户端前转换为普通工具字典。其他工具未接入时只保留名称和顺序。
- `core.retrieval.<工具名>`：核心本地读取、图片读取、工具发现、计算和有限枚举定义。读取页的数值默认值与上限先按原装配逻辑形成 Schema，再登记快照；插件定义在此之后拼入，不因工具名称相似继承核心快照。
- `core.work.<工具名>` 与 `core.skill_maintenance.<工具名>`：工作完成／进展／状态、方法发现／读取，以及方法保存／跳过的定义。方法发现的数值分页上限在快照前确定；不记录工作目标、候选正文或运行工具参数。

快照只从上述明确核心声明取得。传输前按明确字符范围／定义对象核对最终内容，符合时记 `retained`；声明后内容变化记 `changed_after_declaration`，不保存旧快照冒充当前内容，也不复制修改后的动态内容；没有声明的工具记 `not_recorded`。组件修订号由维护者随固定合同、描述或 Schema 修改递增，具体历史内容以当次快照为准，不是内容指纹、插件 API 世代或整条提示的版本。工具快照以 JSON 文本保存，避免面板通用字段脱敏把 Schema 中的参数名误作运行凭据删掉；此入口只接上述核心定义及已在其 Schema 中公开的数值限额，不复制配置对象或插件运行值。

新清单仍不保存动态消息正文、工具调用参数、媒体字节、运行地址、凭据或客户端序列化后的请求体。其他提示／工具定义、工具资料页完整范围与动态材料仍有缺档，不能逐字重建完整请求。组件快照随原调用轨迹保存，每次调用会增加存储量；没有新增表、跨调用版本库、清理任务或永久保留政策。

格式 v3 保留上述字段，并在宿主生成插件工具定义时附带所属插件 ID、当前实例自身版本及已准入的接口世代。最终调用登记只保存这些归属字段：与宿主声明一致记 `origin_recorded`，声明后定义被改动记 `changed_after_declaration`。动态插件 Schema、描述和默认值不落入固定组件快照；插件自身版本与接口世代均不等于该次完整 Schema 的内容版本。私有附属信息不参与 JSON 估算，进入客户端前仍转回普通字典。来源不能由工具名或描述文本猜测；目录筛选、Hook 子集和执行资格不变。旧 v1/v2 记录不回填，页面继续按原格式展示。

格式 v4 对 `saved_result_locators` 消息增加 `result_locator_status` 与 `result_locators`。仅最终内容与宿主装配的目录完全相同且未被省略时，状态为 `retained`，记录当次呈现的 R、原工具名、目录装配时可用性和可用项的原 result_id；整个目录被容量裁剪时记 `omitted`，声明后内容变化时记 `changed_after_declaration`，后两种都不保留旧编号清单。其他消息不增加空定位数组。定位元数据来自当前段别名和原同群观察元数据查询，不复制观察正文或模型请求正文；它不是资料页已读范围，也不表示当前时刻资料仍有效。旧 v1—v3 记录缺字段表示未登记，不能从现时段或整轮最终引用表补造。

工作压缩调用另登记源码固定的 `work_compression.contract` 提示组件和 `core.work_compression.summarize_work_segment` 工具定义，初始修订均为 1；后者 Schema 来自实际解析输出的 WorkSegment。沿同一请求记录比较最终内容，匹配才保存固定快照，组件改动时维护者递增其修订。压缩输入区间选定后才附提示定位，传输前移除私有信息，不参与窗口估算或改变原调用预算。动态目标、要求、归档交换与模型压缩回复没有因此复制进请求快照；原区间／来源与压缩结果仍沿原工作记录，本入口不证明完整请求可还原。旧压缩调用不回填，无新增表或清理策略。

下列维护与审查入口也复用同一机制，组件初始修订为 1，只保存源码固定文本及 Schema，不保存动态资料或动作值：

| 调用用途 | 固定提示组件 | 工具定义／输出合同 |
|---|---|---|
| history_maintenance | `history_maintenance.contract` | `core.history_maintenance.finish_history_maintenance` 与 `core.history_maintenance.query_memory`，Schema 分别来自 ReflectionOutput／MemoryLookup；没有认识查询工具时不虚增其记录 |
| skill_maintenance | `skill_maintenance.contract` | 继续使用已有 save_skill／skip_skill 定义快照，不重复注册 |

独立插件 Agent 的 result_only 分支还在原 developer 消息上标记源码固定的 `plugin_agent.result_only_notice`（修订 1）。在原最终裁剪及合法 Hook 后，仍由同一 _PromptComponent 定位和比较；文本改变则不把声明片段当本次快照。respond 分支不加这条通知，也不因为模板存在而取得发送资格。动态 `return_result` 输出 Schema 与插件指令仍未单独留存，来源和权限照旧归宿主。旧调用不回填。

历史维护在原最终容量核对后，为本次发送复制消息列表和固定首消息再附定位，不污染后续轮次复用的轨迹与估算。方法维护和动作审查在原输入容量核对之后附定位，原网关在估算、登记与传输边界取出它。动态批次原话、既有认识、候选方法、工作目标／要求和动作参数仍只在原所属记录中；缺少引用或正文的请求范围仍明确缺档。固定提示含 Schema 时，任一固定文案或 Schema 改变都应递增组件修订；旧调用不回填，登记失败仍随原事务／调用失败结束。

普通对话、独立插件表达及普通工作还在最终裁剪和合法 Hook 之后，逐消息复用 RetrievalToolkit.read_presentations 的原判定，向清单的 `tool_presentations` 写入 result_id、coordinate_unit、start/end/total 和已匹配的 evidence_ref。只有原正文片段或宿主已登记投影与保留内容一致才有范围；目录、搜索定位、失败结果和复制坐标的改写正文不能据此成为原文提供。原判定可确认已有原生页的引用名，但本批不调用 adopt_presentations，已读资格仍等待模型响应后的原确认入口。

资料范围来自各消息的最终保留内容，不使用整轮累计阅读账替代；同页在两个位置出现则两个位置各自记录。字段为 null 或旧记录缺字段表示该入口未登记，为空列表仅表示此位置没有匹配到原判定认可的资料页，并不说明工具没有执行。工作入口只补资料定位，未记录的省略标记仍为未知；原话来源与媒体字节不猜补。面板可沿原资料页入口查看该范围，资料被清理或当前不可见时仍按原查询边界处理。归属字段与页范围没有补齐动态正文或原生响应，不能据此宣称完整请求或跨轮交换可还原。

缓存统计区分正数、显式零和字段缺失；字段缺失不能还原上游是否报告零。命中率、上游账单、网关扣额与延迟分别解释。当前证据及未确认项统一在[当前任务](iteration.md)，不通过保温请求、扩大窗口或持续压测换取表面命中率。

调用材料记录另有 `request_order`：scope 为 binding_instance_preparation，binding_id 是当前 ModelGateway 实例的随机身份，sequence 在每次进入其 complete 准备入口时同步递增。它只在调用获准登记时随原清单保存；此前准备若在登记前失败，保存序号可有缺口，不能按序号推断真实发送或计费次数。新实例从 1 开始，内部传输重试不递增；它不是 scene、episode、job 或 conversation_segment 的身份，也不是群首问／会话段首轮。信息工作外层容量拒绝未进入此入口时不计入该序号。

调用账和工作预算页按这个明确范围区分首次、后续和未记录，使用相同筛选的全部调用，而非本页。平均输入只使用有效非负 prompt_tokens；每组缓存命中率仍只使用能够与输入量配对的缓存报告、按输入量加权，分母为零保留未知。清单缺失／无顺序字段或不支持的范围归未知，不以时间排序反推首轮。不同绑定、用途和版本可能共同出现；这些统计不能直接证明缓存带来的因果收益。汇总是同筛选的分别读取，不宣称正在变化账本的原子快照。
