# Plugin Runtime Sandbox, Sensory Decoupling, and Action Interceptor Pipeline

In a long-running social agent, third-party and custom extensions (plugins) must enhance bot awareness and agentic capabilities without compromising system stability, privacy, or conversational coherence. We decided to construct a sandboxed `PluginHost` governed by explicit permission grants (`EMIT_EVENT`, `REGISTER_TOOL`, `SCHEDULE_TASK`, `INTERCEPT_ACTION`). Plugins are strictly sensory inputs, agentic tools, or action filters—never independent chatbots. Sensory plugins emit raw events into the runtime event bus where SceneActor, Attention, and Cognition process them naturally according to bot persona (Goal 6). Tool executions are isolated with timeouts and complete exception catching, ensuring that broken or hanging plugins can never crash the runtime or stall cognition (Goal 7). Outbound messages pass through registered action interceptors in `ActionQueue` for safety filtering and sanitization before network dispatch.
