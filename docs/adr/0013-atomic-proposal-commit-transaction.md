# Atomic All-or-Nothing Durable Proposal Commit

In V1, independent durable state mutations (tasks, open loop resolutions, memory proposals) inside an `EpisodeOutcome` were committed via individual, uncoordinated database operations. If an evidence check failed or an error occurred midway, previous writes were permanently committed, leaving corrupted partial state. In V2, we decided to wrap all durable internal mutations (tasks, open loop resolutions, and scoped memory slot transitions with evidence provenance validation) in a single atomic SQLite transaction executed under `EventStore._write_lock`. If any mutation fails, the entire transaction rolls back cleanly with zero durable partial side effects. External side effects (TaskScheduler min-heap registration and ActionQueue enqueue with two-phase commit) are executed strictly after the database transaction commits successfully.
