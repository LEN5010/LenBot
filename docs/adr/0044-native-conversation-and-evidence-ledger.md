# ADR-0044：原生对话 Agent 与单一证据账本

- 状态：已采纳；实现与上线状态见 [实施记录](../implementation.md)。
- 日期：2026-09-06。
- 维护者：len_bot 工程与运营。
- 现行结构：[架构](../architecture.md)；前因：[实群运行审计](../research/20260906-live-run-audit.md)。

## 背景

8bb20a3 的实际运行把轻量闲聊、工作控制和整套社会状态更新放进同一大 JSON。格式修复增加延迟；Bot 自己提出的 MC 参与意愿进入持续工作认识，又被下一轮当作背景继续发挥。表情素材已经存在，但模型没有主动调用检索。审计同时记录了抵触反馈误读、能力和经历编造、数学错误，无法把问题全部归因于模型或措辞。

运营要求优先改善群聊自然度和可靠性，接受更高模型成本、供应商调整，以及切换时全部对话重新开始。此次选择替换对话与认识管线，保留事件、权限、事务、任务和真实发送边界。

## 决策

使用一个 `SocialCognitionCore` 对话 Agent，以自然顺序读取群友原话、真实已发送回复、原图和运行资料。模型通过窄原生工具暂存工作、提醒和认识提案，最后调用 `finish_turn`；消息为零至三条文字/图片片段，空列表表示沉默。普通正文不会发送，暂存提案也不会自行执行。

联网查询、解题、计算、核实和资料整理统一交给后台 `InformationJobRunner`，前台继续接新话。结果与有价值的进展回到对话入口，由它结合最新语境决定如何表达。工作执行没有记忆、人格或发送权限，受限 `calculate` 也不执行任意代码。

`ModelGateway` 与 `AgentLoop` 作为共同底座。每次运行固定提供商、型号、推理强度及客户端，原生 assistant 续接和工具回填顺序完整保留。不存在同轮换型、跨型号 fallback、独立视觉模型或固定 Planner/Replyer 多阶段流程。

| 配置 | 默认值与规则 |
|---|---|
| `conversation` | 3 个模型步骤、6 次工具、24K 文本上下文、4096 输出 tokens |
| `work` | 16 个模型步骤、24 次工具、300 秒、64K 上下文；默认每群 1 个、全局 2 个运行工作 |
| 参数修正 | 最多一次，计入原有预算；终结后不再吸收新输入 |
| 模型路由 | `conversation`、`work` 独立显式配置；Reflection 使用 `work` |
| 本次获准部署配置 | BotCF / `gemini-3.8-flash`；`conversation` 推理强度 `low`，`work` 为 `high` |
| 未配置模型 | 接收和保存事件，不自动创建提供商或调用模型 |

型号属于运营配置，不是源码默认值；之后的显式配置修改从新运行生效。工作修订保留当前运行绑定、资料与已消耗预算。

持续状态只保留事实 `SceneSession`、单一认识账本和实际执行账本。删除工作世界、自我兴趣、气氛、话题树、人物近况/关系容器、Retained Attention 与自动 episode 摘要。参与和语境解释留在本轮及审计 trace，不作为下一轮的权威背景。

认识记录主体、类型、`statement`、`reported/inferred`、原始 `evidence`、`expires_at` 和修订链。当前类型为 `address`、`preference`、`relationship`、`fact`、`group_norm`；`create/refute/supersede` 保留原始陈述和撤销依据。对话前台只即时记录明确称呼、偏好和相处要求；其他认识按需查询或由后台 Reflection 提议。Bot 自己说过的话不能独立证明现实能力、参与经历或群友事实，看到来源 ID 也不等于读过原文。运营撤销仅接受匹配目标与理由的真实操作事件。

原图直接装入对话/工作模型，`MediaService` 负责受控读取和图像处理。图片窗口最多六张，覆盖不足显式记录；运营目录最多 20 项，用短引用与编号总览帮助选择，实际发送仍读取获准原图。表达样例按固定顺序提供，支持文字、单图和混排。

## 保留的边界与取舍

`SceneActor` 仍是事实 Session 单写者，不等待模型；校验 lease、实际读取截点和 `knowledge_revision`。普通聊天可以提交已读部分，工作控制、提醒、履约和 OpenLoop 要求严格新鲜。认识发生变化后旧轮次中止，不假装读过新版；运营操作不消费未读群消息。

消息、认识和工作提案在 Actor/Gate 同一事务确认，冲突或失败全部回滚。Scheduler 持久认领任务；发送前复查素材、工作版本和运营配置。只有真实 `MESSAGE_SENT` 才证明送达、履约或激活 OpenLoop。历史和工具观察按本群及已读范围查询，global-safe 素材由运营显式发布。

这减少了闲聊维护状态和修复格式的负担，但把查询/解题拆到后台后，需要处理结果返回时话题已变化的情况。原生多模态和高强度工作模型会增加成本；复杂解释是否自然、事实是否可靠，仍需用真实群聊与具体来源检验。

曾考虑仅修提示与检索，无法消除自我生成状态的循环；也考虑默认拆成多个社会规划/表达模型，额外调用会加重轻量接话延迟。当前选择单一对话判断、按需后台工作，以及明确的事实和认识边界。

## 切换与验证

本次不迁移旧自动认识和会话。按已获准顺序停机、备份数据库与媒体，停止全部旧认知、反思、工作和投递，再完整 Reset 并切换结构。保留登录、OneBot、运行配置、人工样例和运营素材及来源。回退同时恢复旧源码与同批备份，不混用新旧结构；普通启动不会自动 Reset。

全局 Shadow 默认 true，初始名单为 `group:126300994`，运行时以运营保存值为准。本次重构不借修改源码重新开启 Shadow、清空名单或自动选择其他群；当前生产开关及名单见运行面板和 [运行手册](../operations.md)。

验证覆盖原生工具续接、图片范围、事实与认识来源、截点和租约、事务回滚、后台工作版本、发送/Shadow 以及 Reset。只运行受影响检查和前端构建；实际接话与附图回到实群确认，不增加固定消息数、打分或批量模型对照门槛。

旧 ADR 中的工作世界、大 JSON、`normal/deliberate/fallback`、独立视觉和终结续接设计均由本决策替代。仍适用的事件、场景隔离、任务认领及送达原则已纳入现行 [架构](../architecture.md)，历史索引见 [ADR README](README.md)。
