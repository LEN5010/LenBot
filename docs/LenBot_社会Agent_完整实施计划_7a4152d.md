# 1. 总体目标与完成范围

## 1.1 要得到的机器人

LenBot 应当能理解当前群正在讨论什么，适当地回应、接梗、反驳、提问或沉默；遇到明确研究与计算请求时，能建立可取消、可继续核对的工作；在获准情况下形成自己的公开兴趣，并选择适合的群与时机分享。人格表现可以自然、有趣，但不能制造现实经历或冒充读过未读资料。

Python、浏览器、B 站、媒体与 GSUID 是同一个 LenBot 可以使用的能力，不是第二套认知、记忆、预算或发送中心。保留现有 OneBot、SceneActor、SocialCognitionCore、AgentLoop、ProposalLedger、RuntimeGate、JobStore、MemoryStore、Scheduler、ActionQueue 和媒体资产链。[R02][R03][R04]

最终分三个可独立交付的层级：

| 层级 | 内容 | 不必等待的能力 |
|---|---|---|
| A：聊天与既有业务可靠 | 话题优先、纠正与记忆、卡片交付、能力发现、取消和上下文缺口收口 | 不等浏览器隔离、登录、心跳或 Core |
| B：社会自主性第一版 | 系统来源、授权、共享预算、公开研究、兴趣、心跳、睡眠与克制发布 | 不等点赞收藏、所有视频分析或 Core |
| C：扩展行动能力 | 独立执行、媒体片段、账号窄动作、文件上传、可选 Core | 各能力独立启用与验收 |

“全部完成”只用于本次明确纳入的模块。单个可选服务缺失，不阻塞其他已经完整交付的业务；反过来，普通计算成功也不能证明取消、任意网页或账号操作已通过。

## 1.2 必须保留的既有体系

- 原始事件 ID、场景身份、账号身份、历史投影与既有摘要偏移不变。已完成摘要不重新生成，旧认识不清空。
- 认识的 reported/inferred、证据、修订、撤销、替代、有效期与按场景过滤继续生效；向量索引仍是派生资料，不成为事实来源。
- Agent 的表达、工作与认识仍通过原提案与提交边界；工具不得直接越过 Gate 发 QQ 消息。
- conversation/work/maintenance 三类模型绑定保留；增加用途记账，不默认引入 Planner/Replyer/Critic 固定多模型流水线，不失败自动换模型。
- 根 `lenbot.config.json` 是唯一运行配置来源；面板保存和实际生效分开。保留旧人工人格、表达样例、Shadow 和群名单。
- 真实送达、未发送、拒绝和未知继续区分。进程重启或网络超时不授权重发、重复点赞或重跑 Python。

## 1.3 第一版不实施

常驻 notebook 内核、任意宿主 shell、通用多 Agent 编排平台、Python 任意调用所有 Bot 工具、自动修改 Bot 代码、自动安装任意第三方插件、跨群人物记忆、私人 Chrome profile、评论/关注/私信/投币/账号设置、所有网站登录、独立向量数据库迁移、多种执行后端同时支持、通用评分/防护/自愈平台，均不属于本版。

Hermes 式程序化工具 RPC、版本化脚本技能与有状态内核列入后置 TODO。能力缺失应明确显示，不能使用名称相似的半成品冒充完成。

# 2. 产品参数与冲突条款的裁决

## 2.1 沿用的已确认目标

原计划已给出以下数值和范围，本计划不擅自降低：[R01]

| 项目 | 目标 |
|---|---|
| 自主兴趣站点 | 第一版 B 站；不是任意网站自主探索 |
| 心跳机会 | 每 30 分钟最多一轮；上一轮未完成时跳过，不补跑所有错过的时刻 |
| 心跳时限 | 每轮最多 30 分钟；可以提前结束、无研究、无发布 |
| 心跳计费 | 独立系统账，不占用户工作额度，不额外设置每日 token 总上限 |
| 人类长工作 | 最大执行时限 30 分钟，累计模型输入与输出最高 10M token |
| 用户每日额度 | 默认每用户 30M token；群额度由该群授权用户的额度累计形成 |
| 文件发送 | 单文件 50MB、每群每天 10 个；具体 MIME/格式支持名单明确列出 |
| 叫醒 | 按群；30 分钟没有新的直接人类互动则恢复睡眠 |
| B 站账号 | 运营者提供 Cookie/SESSDATA，根配置保存、不回显、不写日志、不进入模型上下文 |
| 写操作 | 点赞、收藏分别授权；其他账号动作无入口 |
| 部署 | Linux VPS 分服务部署；LenBot 不挂宿主 Docker socket |

10M/30M 是累计调用量，不是模型上下文窗口。每次请求依然受其模型上下文与输出限制。只有依赖与配置记录，不能证明真实运行过这些上限。

## 2.2 本计划采用的推荐裁决

以下是对原文矛盾或未定义语义的推荐解法，需要随本计划一起写回产品文档；不要把它们说成用户此前已经逐项确认。其他代码不得自行采用相反解释。

| 编号 | 问题 | 推荐裁决 |
|---|---|---|
| D01 | 主动播报与文件发送是否自动相互授权 | `proactive_chat`、`interest_share`、`send_file` 独立；面板可以提供显式勾选模板，但开启播报不隐式授予上传 |
| D02 | Core 一处可选、一处成为完成条件 | Core 独立可选，社会 Agent 第一版不依赖它；配置后按单独支持矩阵验收 |
| D03 | B 站限制与 Python 任意公网冲突 | 自主工作只允许 B 站及经确认的必要资源域；人类授权联网 Python 属于另一能力与数据范围 |
| D04 | 系统工作没有 QQ 请求者 | 显式区分 human/system/plugin 发起者、授权主体和计费主体，不填假 QQ 号，不把真实群消息伪装成委托 |
| D05 | 30 分钟与暂停/继续的关系 | 本版按一次工作首次开始后的绝对 1800 秒期限实现；网络、模型与审批等待计入；排队未开始不计入；恢复不重置。需要延期由运营者明确修订，不自动延长 |
| D06 | 每日额度只在创建时检查可能超发 | 创建时原子预占该工作的预算，调用时结算；并发工作不能反复使用同一余额。授权撤销仍即时限制新操作 |
| D07 | 睡眠期间精确日历服务如何处理 | 推荐将“今日直播”等明确、只读、确定性卡片服务作为例外继续即时出卡；普通聊天、自动推送和主动分享服从睡眠。该例外不授予新权限 |
| D08 | 模型审查是否覆盖所有网络包 | 审查业务动作，不审查每个图片/CDN子请求；普通离线计算不依赖审查。已要求的启动、新目标、下载、解压、账号与文件提交审查保留为明确的业务检查点 |
| D09 | 模型审查 uncertain 如何处理 | 对要求审查的敏感动作，deny/uncertain/审查不可用都不执行；返回可操作状态。不得把 uncertain 当作 allow |
| D10 | 审查/技能是否能授权 | 都不能。授权由当前配置与服务端核验；审查只是额外条件，技能只是方法资料 |
| D11 | 系统插件是否重构全部核心 | 仅作面板分类和能力说明；必需核心不可热卸载，不为目录美观搬走 Actor/Gate/账本 |
| D12 | 普通长网页是否统一成万能 research 工具 | 统一观察合同和方法技能，保留清楚的搜索、HTTP、浏览器、媒体原语；不新增隐藏的第二个规划 Agent |

若用户对某项裁决有不同选择，只调整依赖该条的模块，不把整份计划退回未开始。未明确采纳的敏感扩权保持关闭，不能用模糊的默认配置先行开放。

# 3. 开源设计参考与取舍

以下参考来自项目官方文档或实际源码，不是按 Star 排名，也不声称整个开源生态只有一种“主流”。吸收责任边界，不整体迁移框架。

| 项目与来源 | 查到的设计 | 本计划采纳 | 不照搬 |
|---|---|---|---|
| MaiBot [O01] | Planner 处理时机/工具，Replyer 处理表达 | 明确“是否参与、回应对象”和“如何说”的职责 | 不默认增加每轮多模型调用、不采用其模型回退配置 |
| Hermes Skills [O02] | 方法文档逐层、按需加载 | 工具目录 → 技能正文 → 必需参考；沿现有技能版本 | 不让模型任意改人工技能、人格和服务代码 |
| Hermes Cron [O03] | 定时任务独立会话，可有不调用 Agent 的模式 | 心跳轻上下文；确定性卡片不用模型；执行与发布分开 | 不复制另一套 cron 存储、消息网关 |
| Hermes Code Execution [O04] | Python 通过 RPC 调工具，减少中间结果进入上下文 | 后置的程序化读取工具编排；底层调用仍计账 | 子进程不自动等于隔离；首版不开放全部工具 RPC |
| OpenClaw Heartbeat [O05] | 投递目标、活动时间、独立轻量会话可分设 | 一轮允许无发布、按群投递、减少重复上下文 | 不把心跳必然变成群消息 |
| OpenClaw Trust Model [O06] | 主要面向单一可信操作者/团队边界 | 主动识别其与多群、多用户 LenBot 的不同 | 不复制跨会话默认可见性，不共享用户可写工作目录 |
| LangGraph Persistence/Interrupts [O07] | checkpoint、长期资料、恢复副作用各自有规则 | 原工作恢复、平台副作用身份、unknown 不重做 | 不引入 LangGraph 替代现有 AgentLoop，不重放整个失败工作 |
| PydanticAI [O08][O09] | 类型化工具、用量限制、延迟工具；审批不是服务端授权 | 共用预算、动作绑定、参数与身份服务端验证 | 不把审批结果作为权限证明；不声称次数上限已过时 |
| OpenHands [O10] | 执行环境通过独立 Workspace/远端接口接入 | 窄 Worker Gateway、稳定执行接口、独立运行生命周期 | 不把另一个完整 AgentServer 的认知/会话也搬入 |
| AstrBot [O11] | FutureTask 与主动反馈，文档标为实验能力 | 使用调度事件唤醒原工作与原发送链 | 不整体迁移框架、不重复构建任务事实 |
| NoneBot [O12] | 匹配、权限、优先级和消费分开 | 精确命令与普通聊天分流、群级控制 | 不将全部含链接/引用的消息一律消费 |
| LivingMemory [O13] | 词面+向量候选、RRF 和召回分数明细 | 改进现有检索与可解释性，约束先于排序 | 不复制图谱与第二套认识库，不采用隐藏降级或读得多就更可信 |

多数上述系统保留多种资源边界，不存在“取消次数限制就更 Agent”的结论。LenBot 的选择是：次数不再是长工作的主要停止条件，但调用计数继续记录，deadline、累计 token 和外部资源必须先完整执行。[O08]

# 4. 总体架构、唯一职责与运行拓扑

## 4.1 认知与业务主链

```text
OneBot 原始消息 / 订阅事实 / Scheduler 系统事件
                │
                ▼
    EventStore + SceneActor（同群单写顺序）
                │
       ┌────────┴──────────┐
       ▼                   ▼
精确插件 handler       AttentionPolicy（只给观察机会）
       │                   │
确定性卡片/明确桥接        ▼
       │          SocialCognitionCore + 原 AgentLoop
       │              │              │
       │         读取与认识提案    工作/发布/平台动作提案
       │              │              ▼
       │              │       JobStore + JobRunner
       │              │              │
       │              │       工具 / Worker Gateway
       │              │              │
       │              └──── 观察、产物、范围 ──┐
       │                                      ▼
       └──────────► ProposalLedger / RuntimeGate
                           │
                   同一业务事务与真实版本
                           │
                即时 Action / 持久延迟意图
                           │
                      ActionQueue
                           │
           OneBot / 受限 B 站动作 / Core 回执
                           │
                    原事件与结果账本
```

同一 AgentLoop 实现可以以 conversation/work/maintenance 角色运行；“唯一社会入口”不等于全系统只有一个协程，而是没有多个组件分别决定同一个群的最终社会行为。Worker 不调用生成模型、不写认识、不直接发 QQ。媒体推理仍在 LenBot 的现有模型绑定和预算内执行。

## 4.2 部署边界

```text
外部访问 → 面板入口 → LenBot 控制服务
                        │
          ┌─────────────┼────────────────┐
          │             │                │
       OneBot         GSUID Core      Worker Gateway
    协议私网服务      可选私网服务      独立控制接口
                                         │
                              按工作创建短命执行环境
                              Python / Browser / Media
                                         │
                              受限公开网络出口（可选）
```

不要把所有服务放在一个“私有网”后就允许互通。至少区分控制平面网络与执行出网网络：工作代码不能访问 LenBot、Gateway API、OneBot、Core、数据库或宿主 Docker socket。Gateway 是高信任运行控制组件；它可使用专用/rootless Docker endpoint，但 socket 只属于它，不属于 LenBot 或执行容器。[O10][O14]

第一版只支持一个明确的 Linux Docker 后端。Python 工具的外部契约保持稳定；从当前本机 worker 切到 Gateway 是一次受控切换，不长期维护自动回落宿主的兼容通路。

## 4.3 边界矩阵

| 主体 | 可以读取 | 可以改变 | 永远不能因普通工具调用而获得 |
|---|---|---|---|
| 社会对话 Agent | 当前群原话、该群认识、允许公开兴趣、获准工具资料 | 暂存提案 | 根配置、跨群身份、直接平台发送 |
| 工作 Agent | 本工作源资料、后续合法观察、工作文件 | 工作步骤与结果候选 | 修改任务授权、重置预算、直接改其他工作 |
| 历史维护 | 已保存批次原文、必要旧认识 | 摘要与稀疏认识修订候选 | 发送、任务授权、合成真实经历 |
| 心跳工作 | 公共兴趣、干净的公共来源 | 兴趣候选、发布意图 | 人物记忆/私聊、默认向全部群发送 |
| Python | 导入资料和本工作目录 | 本工作输出 | 控制配置、凭据、宿主目录、默认无限出网 |
| Browser | 当前研究的页面与获准会话 | 临时页面状态 | 通用账号写权限、任意 Cookie 导出 |
| 媒体 worker | 指定资源/片段 | 派生帧与音频 | 自主选择观看范围、发表分析或发群 |
| 模型审查 | 脱敏动作描述及来源关系 | allow/deny/uncertain 建议 | 授权、工具、密钥、覆盖确定性禁止 |
| 功能插件 | 自己获准的业务资料 | 注册工具、事件、提案 | 第二套 Agent、发送队列、全局权限 |
| 运营面板 | 授权范围内的运行资料 | 经原服务保存配置和干预 | 直接编辑事实、伪造模型已读/真实送达 |

# 5. 数据、身份、事务与恢复合同

## 5.1 明确区分三种身份

建议在工作/提案内部使用以下类型；旧人类工作依原有确切字段转换，不从累积证据猜请求者。

```text
Initiator = Human(user_id, request_event_id)
          | System(agent_id, trigger_event_id, cycle_id?)
          | Plugin(plugin_id, source_event_id, run_id)

AuthorizationSubject = 获准的用户或系统能力主体
BillingSubject       = user:<真实UID> 或 system:<明确用途>
TargetScene          = 实际交付群；系统公共研究可没有目标群
```

公开研究可以落在明确的内部公共研究 scope，但该 scope 不是普通 QQ 群；不能把 `allowed_scopes` 一次扩成所有群。系统事件 ID 由 Scheduler/Runtime 生成，模型只能引用，不能自己构造一条“已获授权”的 system-origin。

## 5.2 最小新增数据面

| 数据 | 存放位置/建议实现 | 为什么需要；不负责什么 |
|---|---|---|
| CapabilityGrant | 根配置 `access` 的窄扩展、保存版本对应 OPERATOR_ACTION | 当前授权事实；不在数据库建立第二份可编辑 ACL |
| Job 的 initiator、预算配置快照、输入范围 | 原 JobStore 的工作与检查点结构；确需索引的字段再加列 | 保留工作归属与恢复，不重新建 ResearchJob 表 |
| 用量预占 | 建议仅新增 `usage_reservations` 于现有 SQLite | 原子处理跨工作并发的额度；实际模型用量仍来自 model_calls |
| 执行关联 | 建议 `execution_runs`，关联 job/revision/execution_id | 外部进程的生命周期与业务状态不同，需要可恢复定位；不重新保存整个工作结论 |
| Gateway 本地执行记录 | 单一小型持久日志/SQLite，记录启动身份、期限、终止与产物 | 控制服务断开时仍能停止和核对容器；不是另一个任务调度器 |
| InterestItem | 建议在原库新增公共兴趣表/受限类型，由 EventStore 管理 | 与群成员认识分离且可保留来源；不复制成员档案 |
| HeartbeatCycle | 原 Scheduler task + 类型化 payload/事件，稳定 slot_id | 防重和恢复；不增加另一个全局 cron 系统 |
| SleepState / 临时叫醒 | 原 SceneSession 的窄状态和对应事件 | 当前是否可参与；不停止原始消息存储 |
| 待发布意图 | 原 Scheduler 新 task kind `deferred_delivery`，载荷只存真实来源/成果/行动引用 | ActionQueue 目前是内存队列，不能靠在里面 sleep 数小时保证持久性；不新建并行发送队列 [R05] |
| 文件资产 | 原媒体/资产账本扩展为可保真文件 | 工作清理与延迟发送需要独立产物寿命；不接受任意宿主路径 |
| 审查结果/账号动作 | 原 Trace 与操作记录；动作 ID、版本、目标不可变 | 绑定具体动作、保存真实状态；不用模型文本代替平台回执 |

以上不是要求第一笔提交同时新增所有表。只有依赖模块进入实施时才引入。不能把 `ResearchSession`、`HeartbeatCycle`、`WorkState` 各自做成一套会发生矛盾的成功状态。

## 5.3 观察与证据合同

所有新工具沿 `ToolResult → 观察 ID → 预算化呈现`。观察至少能解释：来源资源、取得时间、版本或快照 ID、数据范围、内容覆盖、未完成部分、附件和后续入口。

- M：原事件定位；R：真实工具观察；I/P：媒体资产；批次 ID、工作 ID、execution ID 各自保持类型，不混装。
- 已取得、被代码处理、呈现给模型、模型生成结论、最终送达是不同事实。
- 网页刷新创建新观察；同一长文续读使用同一观察的偏移，不重新抓取实时 DOM 后假称连续。
- 视频分别记录 metadata、字幕时间段、音频转写时间段、采样帧时间点；没有统一的“整片已看”布尔捷径。
- 衍生内容继承输入限制；包含本群资料的结果不能仅因引用公共 URL 就进入可跨群分享的兴趣库。
- 不把模型原始长推理作为业务数据保存。保存短结论、已执行步骤、来源范围、失败和下一步。

## 5.4 并发、取消与提交顺序

模型、网络和 worker 等待均在 Actor 写事务外。真正提交时重新检查场景、工作修订、租约、授权、预算与实际资料范围。

```text
提交前检查 → 原子保存提案结果/资源预占/行动身份
          → 调用外部执行或发布
          → 保存真实回执
```

外部副作用前记录稳定身份。超时不是未执行的证明；重复收到同一执行请求只读取原身份状态，不能新建另一容器/上传/点赞。非确定性读取可以由 Agent 明确决定重新取得，但必须产生新的观察与预算记录，不自动静默切路。[O07]

取消：停止新工具入场 → 原执行终止 → 记录 confirmed_stopped/confirmed_absent/unconfirmed → 释放或保留资源资格 → 保存已有成果。未确认时阻止相同工作区复用；运营解除必须有针对该 execution 的核对记录，不能只删一个文件让它“变绿”。

# 6. 模块实施说明

## M01. 前置可靠性：取消、历史容量与确定性失败交付

**涉及现有模块：**`plugins/host.py`、`execution/workspace.py`、`execution/service.py`、`runtime/job_runner.py`、`memory/reflector.py`、`memory/history.py`、`tools/retrieval.py`、`plugins/builtin/asoul_calendar/`。

**目的。**先关闭上一轮仍未完成的真实业务缺口，不再重复已修好的 Unicode、FIFO、像素声明等任务。`docs/iteration.md` 中的日历连接失败和历史后续请求容量失败属于本地审阅记录，本次计划没有独立复验；实施前核对是否已有更晚修复。[R06][R07]

**取消逻辑。**区分父工作取消、插件停用、工具自身超时、worker 自身超时。父取消完成有界清理后继续向上传播；工具超时返回带 execution/termination 的失败结果。不要在宿主捕获所有 `WorkspaceCancelled` 后一律把它变成普通 ToolResult，让被取消 Agent 继续循环。外层总期限应涵盖输入准备、执行和明确的清理窗口，不与内层执行期限设成同一个数再相互争抢。终止状态要在不会被 `wait_for` 异常转换丢失的位置记录，所有清理子进程本身也必须被回收。

**摘要逻辑。**保留原批次、来源 ID、完整性标记、历史投影和事务。改的是维护期间的认识读取呈现：固定原文与终结 Schema 优先，旧认识使用少量完整记录、明确分页和回读入口；追加工具正文后仍按完整下一请求测量。不能强行截断认识中的否定与条件，不把只返回条目目录计为已经读过其原始证据。确实装不下时保留原批次失败，不能移动覆盖游标。

**日历逻辑。**成功与查询成功但无日程采用正常卡片；来源错误采用明确“日程暂未取得”状态卡，不表示今天没有直播，不多调模型、不切备用源。渲染本身失败则保留真实失败，不能声称发了错误卡。此处是确定性业务结果的呈现，而不是通用降级框架。

**数据流。**原请求 → 原读取/执行 → 真实状态与范围 → 原观察 → 正常成果或明确失败呈现 → 原提交/回执。

**验收。**普通取消不再变成后续模型步骤；超时保留清理身份；维护第一轮与工具返回后的请求都符合容量；日历来源失败不会静默消费后无结果，也不会给出虚假的空日程。

## M02. 社会参与与注意力

**涉及现有模块：**`runtime/attention.py`、`cognition/social_core.py`、`cognition/context.py`、`cognition/proposals.py`、`scenes/actor.py` 及现有 SceneSession/reducer。若类落在其他文件，按实际定义修改，不为本计划重命名。

**输入。**当前请求及引用关系、最近相关原话、真实 @、当前关注状态、已确认偏好、运行事实和获准能力摘要。AttentionPolicy 现有职责是提供观察机会，不是替模型决定应该发哪句话，应继续保持。[R03]

**逻辑。**

1. 精确命令先完成归属；普通消息进入既有注意力策略。
2. 强唤醒、正在交互、关键词和随机机会继续区分。公开话题参与只扩展弱观察机会，不把所有群消息变成确定请求。
3. 同一个 SocialCognitionCore 根据上下文选择直接回应、沉默、澄清、委托工作或提出发布意图；不增加固定前置分类模型。
4. 回复针对话题或真实对方。角色语气可以第一人称、玩梗、调侃或反驳；未经证实的换场、现实工作、离开/返回、参加活动不得作为当前事实。
5. 当前纠正立即影响下一句；长期称呼/偏好变化再走原认识修订，不等待 embedding 更新。
6. 弱机会导致的 Bot 发言不能自行延长注意力、叫醒窗口或触发新的心跳。沿用真实人类回应与已送达事实更新关系。

**输出。**继续使用现有 respond 的消息、逐来源处理、next/end/wait，不在群里展示规划步骤。为 Trace 增加必要的简短参与理由和对象关系即可，不保存模型长思维过程，不建立话题图谱/情绪数据库。

**边界。**公开话题原话可作为参与依据，但不是让该发言者支付自动研究的授权。主动参与使用系统社会额度；人类明确委托才建立对应用户工作。避免“谁说话，谁就被自动扣长工作额度”。

**借鉴。**MaiBot 的 Planner/Replyer 分工用于明确责任，不强制增加模型调用。[O01]

**验收。**不涉及 Bot 的技术或日常讨论得到相关回应；别人互相讨论时允许沉默；同名/称呼纠正不变成错误永久身份；直播样本只支持房间状态，不支持 Bot 自称刚完成现实直播动作。人格不因该修改被整体替换。

## M03. 上下文、摘要、检索和表达样例

**涉及：**`cognition/context.py`、`cognition/projection.py`、`tools/retrieval.py`、`memory/store.py`、`memory/index.py`、`memory/reflector.py`、`runtime/work_context.py`、`web/routes/voice.py`。

**保留。**原摘要自动提供连续性，原认识按需查询，原索引只辅助检索，原表达样例人工启用。embedding/rerank 沿已实现绑定使用，不为本轮替换供应商、泄露 key 或重新索引所有原话。

**改进。**当前请求/引用与必要运行事实优先；相关明确偏好、最近原文和连续性摘要次之；可选样例、素材目录最后。新工具正文按请求任务获得容量，旧无关工具正文外置为可回读 R。工具 schema 按 `tool_search` 展开，不每轮灌入全插件目录。

认识检索统一处理场景、主体、类型、时间、有效期和修订；约束先于向量 top-k，合并后再核对当前原表。记录词面候选、向量候选、最终选择、实际呈现，不能把 selected 命名为 presented。已否定记录不因旧向量存在而复活。

摘要搜索返回批次与原文定位；普通记忆建立时间、摘要原文时间、网络取得时间分别说明。不把摘要命中授予所有原文阅读资格。调用失败与无结果、索引不完整分开，不隐式只用另一条检索路线冒充全量成功。

表达样例从真实对话与确认送达的 Bot 发言进入现有编辑草稿，管理员确认后保存。按当前话题与人工 context/tag 选择少量样例，不额外跑风格评分模型，不自动修改人工人格。样例只提供表达形式，不能注入新人物事实或现实行动。

**能力提示。**对话模型应看到简短的可委托能力说明，例如“可以建立工作运行 Python/浏览网页”，而不是只有“不属于 conversation 的工具”。这不是把 work 的所有 schema 复制给对话，也不是把任何打开链接请求强制升级为长工作。

**借鉴。**Hermes 的渐进加载和 LivingMemory 的候选融合/解释；明确不照搬后者的隐藏降级或第二份认识库。[O02][O13]

**验收。**无需检索的闲聊没有新增 embedding 调用；语义查询严格满足人物与日期约束；样例多了不挤掉当前原话；纠正有原账本修订；大工具结果可续读而不丢失任务所需内容。

## M04. 来源身份、能力授权与当前权限

**涉及：**`events/models.py`、`cognition/jobs.py`、`cognition/proposals.py`、`plugins/models.py`、`config_store.py`、`runtime/scene_policy.py`、`runtime/gate.py`、`plugins/host.py`。可新增窄 `runtime/capabilities.py`，仅封装本项目能力检查。

**能力集合建议。**`long_work`、`public_research`、`network_python`、`proactive_chat`、`interest_share`、`send_file`、`bilibili_authenticated_read`、`bilibili_like`、`bilibili_favorite`。不把工具名称直接当权限，也不把整个 B 站插件启用等同于全部能力授权。

**Grant 最小字段。**grant_id、revision、operator_id、principal_type/id、scene 或明确系统范围、capabilities、有效期、并发与资源配置引用、enabled。额度数值可复用资源策略，不在每层复制可编辑默认值。

**检查顺序。**当前场景 → 真实来源与发起者 → 当前 grant → 原工作修订 → 工具/操作自身要求 → 数据范围 → 预算。定义可见性与执行入口用同一判断；真正网络外发、worker 入场、账号动作和发送前再次检查。验证过程只决定许可，不根据模型语气推定授权。

**群与用户。**既有普通聊天白名单保留；普通聊天不需要新授予 long_work。群管理员不是 LenBot 运营者；群消息中的“我是管理员”不能提升权限。请求者可取消自己工作，运营者可取消任意工作；任何人要求停止对其调侃，先影响当前社会表达，涉及永久策略才沿既有权限。

**系统来源。**心跳由 Runtime/Scheduler 创建真实系统事件。人类要求启动一次心跳可以成为另一个真实操作来源，但不改变长期系统 grant。不以 None/空 UID 绕过原请求来源验证，使用区分类型的验证分支。

**撤销。**保存配置成功后更新生效版本；撤销阻止未来入场、后续敏感操作和发布，正在执行的工作按能力策略停止并收尾。已经发送的字节无法撤回，不宣称“即时撤销”可消除过去副作用。

**验收。**未经授权无法执行对应能力；收发名单与系统主动名单不会相互隐式放大；授权过期/撤销发生在等待期间，下一次外发被挡住；旧人类请求仍沿原合同工作。

## M05. AgentBudget、用量预占与结束条件

**涉及：**`cognition/budget.py`、`agent_loop.py`、`gateway.py`、`call_store.py`、`runtime/job_store.py`、`job_runner.py`、`social_core.py`、`memory/reflector.py`、插件专用 Agent 入口及模型页面。必要的原子用量预占位于 EventStore 写事务内。

**资源维度。**绝对 deadline、每请求上下文与输出上限、每工作累计 token、并发资格、网络上传/下载字节、目录总字节/条目数、浏览器页数、媒体临时资源、消息/文件次数。调用次数保留为观测，可配置为有限或 None；不能保留未经检查的 `>= None`、减法或最后一轮判断。

**预占模型。**

```text
创建工作：在同一事务中检查 user/day + scene/day + 并发
        → 预占获准工作预算（不超过10M）
每次调用：检查工作余额 → 预留本次输入估算+输出上限
        → 发起绑定模型请求 → 取得 usage 或估算状态
        → 按唯一 call_id 结算，不重复扣除
工作结束：释放未用预占；保留实际/估算消费
```

缺少足额预算时不偷偷缩小用户目标、改模型或重置额度。允许明确提出一个较小预算工作，但要作为公开的工作参数，不在失败后静默改写。

**计量规则。**输入与输出各计一次；已含于输入的缓存 token 不再次相加，已含于输出的推理 token 不重复计算。审查、压缩、插件子调用都归同一工作。embedding/rerank 若提供真实 token 用量则按用途记录；不提供时保留估算/未知，不能编造 completion usage。账单费用与 token 额度分开，价格未配置时不假造成本。

供应商无 usage 时，记录估算方法和保守预留；本地估算不是服务商计费精确上界，界面不能把估算称为真实计费。[O08]

**每日规则。**用户额度按真实 UID 在账务时区一天内全局计算，跨群不重复得到 30M；每群另有由唯一授权用户集合形成的总额。跨日归属按工作预占日固定，直至工作结算；当天新增工作使用新日余额。授权变更不重写过去消费。不要给同一用户重复 grant 就把群总额叠加。

**系统额度。**心跳不扣用户账、不新增强制每日 token 总上限；仍有单轮期限、单轮并发、worker 容量和现有每请求限制。是否再设每轮 token 上限使用明确系统配置，原需求未指定就不隐藏套用个人额度。系统用量必须可见。

**停止。**预算接近结束时，使用同一个 Agent 的预算消息让其收束；终结本身预留必要的输出与时间。没有剩余模型额度时直接保存已取得结果与未完成项，不再启动“补一段总结”的免费模型。死循环由明确 deadline/资源耗尽结束，不增加无依据的进度评分器。

**恢复。**恢复保留原模型绑定、已用额度和 deadline；过期后不自动重启新工作。显式延期/续做是新的运营决策，过去消费仍累计，不重新赠送 10M。兼容旧记录只能读取其确切现有字段，缺字段不可当作零消耗。

**验收。**两个并发工作不重复占用余额；同一模型回执重放不重复扣费；None 次数模式有真实停止条件；审查和压缩收费；等待/重启不自动延长工作；绑定失效明确结束不换供应商。

## M06. 原工作生命周期与 Worker Gateway

**涉及：**`runtime/job_runner.py`、`job_store.py`、`execution/models.py`、`execution/service.py`、`plugins/builtin/workspace/`。建议新增 `execution/protocol.py`、`execution/client.py` 及独立部署的 `services/worker_gateway/`；只在该服务内保留 Docker 控制实现。

**对外工具不变。**`run_python`、`list_workspace_files`、`read_workspace_file`、`export_workspace_artifact` 继续由原工作 Agent 调用。改变的是执行位置，不是让用户重新学一套工具、把已有工作搬去另一种 Agent。

**请求合同。**Gateway 只接受宿主组装的 execution_id、job_id/revision、initiator、工作数据范围、worker_type、已登记输入资产 ID、预算/deadline、固定镜像配置引用、网络策略引用。模型能填写代码或业务参数，不能填写容器 owner、挂载、宿主目录、Docker 参数和任意镜像。

**窄接口建议（拟新增）。**

| 接口 | 语义 |
|---|---|
| `POST /v1/executions` | 接受已登记 execution_id；先持久化再启动；同 ID 不重复启动 |
| `GET /v1/executions/{id}` | 返回实际状态、资源用量、终止/清理情况 |
| `POST /v1/executions/{id}/cancel` | 取消该执行，结果可确认或未确认；请求取消不是已停止 |
| `GET /v1/executions/{id}/events?after=` | 顺序读取已保存事件，重复读取不重复采用 |
| `GET /v1/executions/{id}/artifacts` | 返回登记清单和归属，不任意遍历宿主 |
| `GET /v1/artifacts/{id}` | 受限文件传输；固定已登记文件、大小与类型 |

服务间认证与普通工作网络分离；密钥不交给执行容器。接口认证只能说明来自 LenBot，仍须核对 job/execution 归属和状态。Gateway 不接受自己生成新的系统授权。

**状态机。**建议技术执行状态为 accepted → starting → running → exited/failed/cancel_requested → termination_confirmed 或 termination_unconfirmed。终止确认后再进行 export/cleanup。业务工作 completed/partial/failed 独立：容器正常退出只能证明进程退出，不能证明任务答案正确。

**租约。**工作修订形成执行代次；旧修订回来的产物可保留为旧观察，但不得更新新修订进度或触发新副作用。Gateway 在控制服务失联后按本地绝对 deadline 停止执行，不依靠 LenBot 活着才能计时。

**资源回收。**稳定容器身份、完整取消原因、日志上限、执行总量与最终文件核对都复用已修思路。取消请求、停止确认、容器移除、产物清理分别记录；unconfirmed 保留目录并阻止复用。网关和 LenBot 重启后只核对旧 execution，不自动重放原脚本。

**验收。**客户端超时后能查询同一执行；重复提交不会创建第二容器；修订和取消后旧执行不能提交成果；LenBot 停止时 Gateway 仍能按 deadline 收尾；Bot 容器没有 Docker socket。

## M07. Python 执行、输入资料与产物

**涉及：**`execution/workspace.py`、`execution/service.py`、`execution/models.py`、`containers/workspace/Dockerfile`、workspace 插件、媒体登记与工作面板。

**执行形态。**保留“每次新进程、同工作文件持续”，不假装变量持久。依赖在镜像构建阶段安装并明确版本，保持已有 NumPy/Pandas/Matplotlib/Pillow/中文字体。需要 Excel 引擎、ffmpeg 或其他库时作为镜像能力单独增加，不把依赖缺失隐藏为代码自动安装。

**文件系统。**控制脚本与输入只读挂载；产物独立可写。明确 Linux 后端 UID/GID 及卷权限，禁止默认 root/特权容器解决权限。目录描述符、no-follow、非阻塞普通文件核对继续使用；产物读取/导出不能在检查后换路径打开。对同一工作执行与导出使用现有执行身份和互斥，防止导出过程中仍在改写文件。

**输入升级。**除现有工具正文外，增加已授权附件导入：从本工作来源中的 asset_id 读取真实字节，经归属、大小、类型检查后，生成只读 input manifest。manifest 记录原 R/M/资产身份和范围。模型不得把任意场景图片、主机文件、Cookie 或根配置路径填进输入。

**输出。**stdout/stderr 流式有界采集，截断标记与真实错误保留；文本文件分页；二进制字节下载。图片明确登记成功才返回附件。文件已经可下载但媒体登记失败，返回 partial 和原因。支持 Unicode/空格文件名，禁止绝对路径、穿越、链接和特殊设备。

**容量。**执行前、运行中、退出后检查总字节和条目数；异常结束也保留超限信息，不靠过滤清单假装成功。正式不受信执行使用可配额卷或等价有界存储；只有轮询监控时明确它不构成严格磁盘上界，不给平台提供虚假的安全保证。

**网络模式。**先迁移并验收离线 worker，再实现获准联网模式。网络 Python 只对有 `network_python` grant 的公共资料工作默认启用；群内私人资料工作保持离线。混合敏感资料与联网必须有额外明确数据外发授权，不因“能上网”和“能读群聊”同时存在就自动允许。

**验收。**从已取得 CSV/JSON 和图片生成中文图表；文件跨调用存在而变量不在；产物导出进入原发送链；无网运行不触达外部；超时/取消/超限如实结束；跨群/别的工作资产导入被拒绝。

## M08. 网络出口与执行安全边界

**涉及：**Gateway 后端、部署网络规则、浏览器/下载客户端、现有 `plugins/net_policy.py` 及相关公开资料工具。不得把底层隔离仅实现为 `validate_url()` 或环境变量代理。

**三类网络。**

1. 控制网络：LenBot ↔ OneBot/Core/Gateway，固定服务访问，执行容器不加入。
2. 匿名公开研究：B 站站点及经实际资料确认的必要 CDN/资源；禁止通用转发代理和用户自选出口。
3. 人类获准的联网 Python：公开 HTTP/HTTPS 与受控 DNS；不向控制网络、宿主和其他任务开放。

**执行。**由工作进程无法修改的网络命名空间/出口代理/防火墙强制控制。必须覆盖 IPv4/IPv6、解析后连接地址、重定向、子资源与 WebSocket；阻止直连绕过代理、未经核验的 CONNECT、QUIC/其他协议绕行。选择单一可维护实现，不同时做多个后端。业务域与资源域区分；不是把整个 CDN 共享域加入就允许任意账号跳转和外部上传。

**为什么两层。**应用层做业务 URL/来源检查并提供明确错误；底层出口保证实际连接目的地。域名预检后再让浏览器独立解析不构成绑定。容器工具白名单也不等于它发出的网络流量受限。[O06][O14][O15]

**数据外发。**公开地址不是安全接收者。工作输入有群资料时，上传到公网属于数据外发，需要单独范围；日志中保留目的主机、状态和字节，不保存 Cookie/token。模型审查不能证明脚本无外发行为。

**验收。**在获准环境中核对实际路由、worker 网络及网关访问边界；正常站点与资源能用，禁止目标明确失败；关闭网络授权后，排队和尚未发出的下一次请求停止。不给用户代码添加访问宿主控制口的“便利例外”。

## M09. 独立浏览器与可重复阅读的观察

**涉及：**`browser/models.py`、`browser/worker_v2.py`、`plugins/builtin/browser_agent/plugin_core.py`、Gateway 浏览器后端、`tools/retrieval.py` 和媒体输入装配。

**保持的工具入口。**`browser_open/snapshot/interact/capture` 和 work-only 归属不变。当前宿主 Chromium 功能试用不算独立浏览器完成；迁移后关闭该宿主执行入口，不静默回落。保留 `chromium_sandbox=True`，但不能把它当作宿主控制进程、网络和资源全部隔离的证明。[R08][O15]

**会话。**同工作可保留多个 page_ref，但页面数受预算限制；匿名工作独立 BrowserContext。不能把个人 Chrome profile 或多个群共享的可写 profile 挂进去。节点重启后旧 page_ref 应明确失效；保存的观察仍可读，重新打开是新执行，不声称恢复了旧页面状态。

**观察。**一次 snapshot 取得正文、标题、来源 URL、可见元素目录和页面状态；宿主将该观察保存为不可变 R。对同一 snapshot 的续读只读保存正文，不再次刷新 DOM；显式刷新创建新 snapshot。超出提取硬上限时保留截断与未取得范围。

元素引用绑定 snapshot_revision，过期时要求重新观察；定位器生成与实际点击必须属于同一页面和当前观察，避免把旧 e1 点击到新按钮。动态页面可变并不等于模型能凭旧引用获得新授权。

**截图。**保存图片返回 asset_id/attachments 及面积范围；像素是否装配交给原模型输入机制记录，不能在截图工具里写 `pixels_loaded=True`。完整页面截图有最大像素/高度与字节限制；无法全页时明确让 Agent 选择视口/分段，不自动声称全页已看。

**交互。**首版匿名观察可滚动和导航；输入/上传/下载/弹窗是否支持通过明确 Schema 暴露，未实现不要承诺。`click` 不是天然只读操作；带账号 profile 的浏览器不开放任意点击路径去绕过点赞/收藏之外的动作限制。

**错误和生命周期。**导航、DOM 提取、图片准备、取消、页面注册前失败都覆盖资源清理。上下文创建后立即纳入当前 execution 的资源登记，不等 `goto()` 成功才登记。页面错误保留阶段；超时和 Playwright 异常进入原 ToolResult，不伪装成空页面。

**验收。**在独立环境打开公开页、跨多页读取同一快照、观察变化后旧引用失效、截图实际进模型窗口；跨工作 page_ref 被拒绝；取消后页面进程结束；没有控制平面/个人 profile/非授权网络访问。

## M10. 公开研究与 B 站读取原语

**涉及：**现有 HTTP 搜索/读页工具、`tools/retrieval.py`、`plugins/builtin/bilibili_content/`、`link_parser/`、`asoul_dynamics/`，以及按需新增的 B 站字幕/评论读取模块。

**研究入口。**不再增加一个自动规划的万能 `research()`。对话需要较长工作时沿 `start_work` 建立目标；工作 Agent 按技能选择 HTTP、平台接口、浏览器和媒体工具。工具自行完成必要的协议步骤，不把每次 HTTP 请求拆成模型可见工具；但不同业务意图仍可分开调用。

**B 站工具建议（按现有名称复用）。**搜索/详情、读取已取得动态、读取字幕时间段、读取评论分页、定位分 P/时间轴、请求指定媒体片段。先核对现有工具可复用范围，不增加第二套视频详情客户端。工具返回资源身份、作者、发布时间、取得时间、查询条件和覆盖范围。

**逻辑。**取得线索 → 判断相关性与时间 → 读取必要正文/字幕/评论 → 保存观察 → 需要视频证据时选定时间段 → 得到片段观察 → 在同一工作形成结论。不是每个问题都必须搜索、浏览器、下载、ASR 全走一遍。

**平台协议。**B 站业务 ID 与临时播放 URL 分开；链接短期失效返回明确结果，允许 Agent 显式刷新同一资源定位，不自动替换成其他视频。具体 API、登录要求、字幕可用性、地域/会员/访问限制必须用目标版本与真实账号验证，不能用此计划中的工具名充当协议证明。

**来源与范围。**标题/简介只表示元数据；评论是评论者观点；字幕可能缺失；动态站提供的资料不自动是平台全文。来源失败不变成“没有相关内容”，获取全部字节不变成模型全部读过。

**浏览器选择。**已知结构化接口可回答时用现有读取；需要实际页面交互/视觉才用浏览器。这是 Agent 显式选择，不是失败后隐藏替换同一工具结果的 fallback。统一的状态、来源和范围格式比统一一个大工具更重要。[O02][O08]

**验收。**同一个问题能沿最短合法路径取得资料；不需要视频时不下载；公开兴趣研究不越出第一版站点范围；站点失败保留阶段；模型说“读过/看过”的范围与保存观察一致。

## M11. 公共兴趣与方法技能

**涉及：**原 `memory`、EventStore、现有索引与 `skills/store.py`、`skills/learning.py`；建议新增 `memory/interests.py` 作为公共兴趣的窄接口。

**三类兴趣数据。**

| 类型 | 例子 | 保存方式 |
|---|---|---|
| 公开资料事实 | 某公开视频讨论了一个主题 | 必须有真实观察 ID、来源与范围 |
| Agent 评价 | 觉得其中某种解释有意思 | 标明是评价，不升级为平台事实 |
| 研究意向 | 下轮继续核对某个疑问 | 保存未决项；不是未来一定执行的承诺 |

InterestItem 建议字段：id、topic、record_type、statement/summary、source_observation_ids、evidence_spans、observed_at、published_at（来源）、valid_until（适用时）、visibility、revision、status。现阶段不增加未校准的 0.97 可信度分数，也不建立完整知识图谱。

**写入。**心跳/公开研究工作提交候选，宿主校验来源、范围与可发布性后写入。群聊原文、群成员记忆、私人资料及其摘要不能进入全局兴趣。即使查询目标是公共视频，只要研究上下文混入群资料，整条研究的私有背景不能随结果一起跨群发布；可独立重读公共来源形成干净的公共记录，而不是由模型自动“去隐私”。

**读取。**群内调用只读取明确已允许公共发布的兴趣，并与该群本地资料分别标注。不要通过为 `query_memory` 增加全群 scopes 实现公共兴趣。

**维护。**新来源纠正旧记录时修订/撤回；时间敏感信息过期后不再作为当前邀请或热点。召回次数与点赞反馈不直接增加可信度。索引失败不回滚事实写入，覆盖不足明确呈现。

**技能。**B 站研究、文件分析等方法可作为现有技能正文，按需发现、读取固定版本。自动候选必须有实际成功路径或用户纠正，沿原候选/发布流程；不覆盖人工技能，不让技能携带权限或秘密。[O02]

**验收。**公共兴趣可在获准群复用，群成员身份和私聊不进入全局索引；能查到来源范围；撤回和过期真实生效；没有可靠新资料时正常不写入。

## M12. 心跳调度与系统工作

**涉及：**`scheduler/engine.py`、原持久任务存储、`runtime/agent_runtime.py`、`events/models.py`、JobStore/JobRunner、兴趣接口。可新增 `runtime/heartbeat.py`，不新建独立调度 daemon。

**运行。**配置启用后，每 30 分钟生成一个 slot。稳定身份由 agent_id+计划版本+slot 组成，使用已有任务认领和唯一约束确保最多一次入场；重启不依赖单个进程内 Lock 保证防重。上一轮仍活动或终止未确认，记录 skipped_busy，不并行新轮次。

**周期流程。**检查全局睡眠/授权/资源 → 保存 system-origin → 构造轻量公共兴趣上下文 → 同一 work Agent 选择研究或结束 → 提交可采用兴趣 → 形成零到多个发布候选 → 周期结束。

每轮最多 30 分钟是硬上限，不是必须使用的时间。一轮可以只整理未决问题、可以没有新研究、也可以完全不产生群消息。没有现成话题不以填充套话作为完成证据。[O03][O05]

**上下文与账。**独立系统计费，不继承某群最近对话或某个用户预算。携带必要主题、已处理公共资源身份、仍有效来源和未决项；不把所有历史兴趣拼进每次请求。模型使用既有 work 绑定，`purpose=heartbeat`，不引入新角色供应商回退。

**重启/错过调度。**只处理当前应运行 slot；错过的周期记 missed，不在启动时补跑一整夜。崩溃时核对已登记工作与执行，不自动重跑未知平台动作。没有合法目标群时仍可保存公共兴趣，但发布为零。

**并发。**心跳全局最多一轮，使用系统资源池；不得长期占满普通用户工作的 worker 位。资源不足跳过或等待到本 slot 的明确期限，不能无限延后形成积压研究。

**验收。**同一 slot 重复触发不重复研究；忙时跳过；停止配置后无新外发；无发布的一轮仍有正常终态；重启不会补发旧 slot；系统用量与用户用量分开。

## M13. 睡眠、叫醒与持久延迟交付

**涉及：**SceneSession/reducer、`runtime/attention.py`、`scene_policy.py`、Scheduler、`runtime/gate.py`、`actions/queue.py`、`runtime/plugin_interactions.py`、直播/提醒/报告插件。可新增 `runtime/sleep_policy.py` 作为纯规则与事件投影。

**状态。**全局计划按配置时区计算；各群有 `awake_until`、确认叫醒来源、最后直接人类互动时间。UI 展示全局计划与本群临时状态。修改时区/窗口产生配置版本变化，不重写原事件时间。

**睡眠不等于停止接收。**原始消息继续存储，历史维护继续按既有条件进行；停止的是普通社会回应、新心跳和自主发布。已启动长工作继续遵守原 deadline，结果入持久待发。确定性只读卡片按 D07 例外即时响应。

**叫醒。**真实 @ 或直接匹配称呼仅创建本群叫醒请求；不扫描引用旧文本当新叫醒。当前有资格用户明确确认后，本群临时清醒；Bot 自己发言、定时事件、无关群的互动不续期。同群重复请求合并，不能让叫醒确认刷屏或修改工作权限。

**延期实现。**在已有 Scheduler 保存 `deferred_delivery` task，载荷引用真实来源、成果/资产、原定时间、有效期和交付模式。不要让内存 ActionQueue 长期挂着睡眠消息，也不要再开一条睡眠发送队列。[R05]

尚未生成的普通闲聊不在夜里预生成成百回复；醒来依据当前上下文决定是否仍需处理原请求。已确认的提醒和工作成果需要保留待交付关系。发送入队后才进入睡眠的竞争，在 `validate_before_send` 前返回 defer 结果，保存原行动身份，不记录为已发送或虚假失败。

**醒来规则。**

| 内容 | 处理 |
|---|---|
| 普通聊天 | 不逐条补答；仍有明确未解决请求时重新依据当前语境处理 |
| 日历精确请求 | 按 D07 即时；不在醒来后发送昨日“今日直播” |
| 提醒 | 保留原定时间，过期提示按事项策略处理；晚发明确晚发 |
| 直播推送 | 重新读当前场次；已结束不发“刚开播”；可以合并为过去通知 |
| 工作结果/报告 | 使用已保存成果；重新检查当前群授权后交付，不重新计算 |
| 兴趣分享 | 可过期/合并/不发，不保证补齐每一候选 |
| 文件 | 资产必须仍存在、未过期，额度在实际发送日核验 |
| 拒绝/错误提示 | 只对真实待反馈请求保存，不能把一夜内部错误逐条发群 |

**合并和回执。**按同一事项/场次/工作/来源 ID 关系合并，不新增内容指纹体系。合并后的行动要携带它实际履行的各原始事项关系，真实送达后才确认相应交付；未采用的候选显式过期/替代。unknown 结果不自动再合并重发。

**验收。**午夜、跨日、叫醒超时、重启和手动修改窗口均保持来源；文件不因工作临时目录清理而丢失；一条延期消息不会卡住整个群的即时卡片；醒来不刷屏、不发过时直播邀请。

## M14. 主动参与、兴趣发布与统一卡片

**涉及：**SocialCognitionCore、Gate、Scheduler、原提案/行动、`cards/`、`plugins/builtin/asoul_calendar/`、`bilibili_live/`、`group_summary/`、`asoul_dynamics/`。

**两种社会行为。**事件参与读取本群话题；定时原创/分享读取公共兴趣及当前目标群必要语境。二者共用社会判断入口、当前群权限和发送额度，但计费与来源保留类别。不同群根据相关性分别生成表达，不共享人物记忆。

**发布逻辑。**候选兴趣 → 是否仍有效 → 本群当前话题/近期已发内容 → 睡眠与额度 → 同一社会 Agent 决定说什么或不说 → 原提案与 Gate → 原 ActionQueue。候选不是消息，研究完成不自动授予发送权。

**反刷屏。**沿既有冷却、消息条数、群发送和 @全体限制。新增主动每日次数是独立可配置预算，面板显式设置，不能凭新功能默认给所有群扩权。发布去重使用原资源/场次和已送达关系；不是用户明确“再发一次”也被永久拦掉。

**卡片输出矩阵。**

| 请求/事件 | LLM | 对群交付 |
|---|---|---|
| 今日/明日/本周直播精确命令 | 不调用 | 对应日程图片；不加角色台词 |
| 日历来源失败 | 不调用 | 明确状态卡，不声称无日程 |
| 新直播场次 | 原邀请调用一次 | Agent 文案 + 同场次事实卡 |
| 群聊总结工作结束 | 复用原分析与 comment | 有序报告图片；可选短点评，不重复分析 |
| 动态/二创卡片 | 渲染不调用模型 | 原资料渲染的卡片；是否附话由正常入口决定 |
| 普通兴趣分享 | 社会表达调用 | 有根据的短表达；有对应卡片才附图，不强制所有话题卡片化 |

**视觉。**沿共享亮色 tokens 和 Pillow，继承网站参考的白卡、粉色强调、灰蓝文字与轻边框。公共组件只负责测量、留白、作者/时间、来源、引用块、页脚与分页，不包含 B 站业务。长内容按真实字体测量分页；每页标题/日期/页码完整；“本页没有金句”不写成“本次没有金句”。GSUID 返回图片先原样交付，不宣称它内部已统一主题。

**版式与信息完整性。**直播状态不能用日程代替；无封面时采用无封面版式；长标题有截断说明或展开页；群报告保留统计范围与未分析部分；动态支持头像、源媒体与转发独立区域的条件以实际取得字段为准。图片生成不需要浏览器或模型临时写代码。

**验收。**确定性命令仍零模型调用；直播不重复发两条事实邀请；报告分页全部有序进入原交付，不偷偷突破现有消息限制；引用卡片提问回到普通 Agent；发布与实际送达有完整来源。

## M15. 有限模型审查与确定性授权

**涉及：**`cognition/providers.py`、`gateway.py`、`call_store.py`、提案、Gateway 入场与平台动作。建议新增小型 `cognition/action_review.py`，不得扩成通用风险平台。

**范围。**按已确认需求，对公开研究启动/新目标、显式下载与解压、带登录态的动作、文件发布等业务检查点使用 work 绑定的无工具审查；普通离线计算不依赖审查。常规同域页面子资源不逐包审查。审查计入当前工作或系统账，不使用额外免费隐藏模型。

**输入。**确切 action_id、job_revision、动作类型、资源 ID/域名、目标范围、计划数据类型、资源限制、必要来源关系。不含 Cookie、根配置、OneBot 凭据、完整私人群史或文件秘密。模型看到的描述不足以证明所有代码/文件安全，应在说明中明确这一限制。

**输出。**allow/deny/uncertain、短 reason_code、运营详情及可公开概述。敏感动作只有确定性许可和 allow 同时满足才执行；uncertain 或审查失败不运行，保留可继续的条件或待运营决定。已经允许的动作不能被模型更改参数后继续套用原结果；批准绑定不可变动作 ID 和修订，不用自建内容签名/指纹。

**用途边界。**审查不能解锁任何权限、覆盖被禁网络、降低文件检查，也不能把来源内容提升为系统指令。人工审批与模型审查都不能取代服务端授权。[O09]

**调用成本。**同一不可变动作不重复审查；目标、资源或权限级别改变才创建新动作与审查。审查结果存原 Trace，不建平行审查调度器；关闭可选审查也不能关闭确定性边界。

**验收。**allow 不导致越权；deny/uncertain/超时无副作用；修改已批动作参数会重新核对；模型/日志中无凭据；群反馈只说可公开概述，内部技术错误不按每个子请求刷屏。

## M16. 视频片段、音频与视觉分析

**涉及：**B 站读取/解析插件、Gateway 媒体后端、`media/`、工作观察与模型绑定。建议在 `containers/media/` 定义 ffmpeg 等镜像依赖，处理逻辑放独立 worker，不在 Bot 进程解码大型媒体。

**步骤。**取得视频和分 P 身份 → 读取元信息、可用字幕/时间轴 → Agent 选择明确时间范围 → 下载指定资源/片段 → 校验容器、字节、时长、像素与音频轨 → ffmpeg 生成采样帧/音频 → 保存资产及时间轴 → LenBot 调用获准模型分析 → 保存同一研究的结论与覆盖。

时间区间使用明确 start/end 与单位；资源身份与临时 URL 分开。计划不得承诺“指定 30 秒就只下载 30 秒流量”：协议、索引和关键帧可能导致额外取得数据，真实下载字节都计账，超过限制返回不足，不悄悄下载整片。[O16]

**模型。**帧分析优先使用现有 work 绑定的视觉能力。只有模型确实支持时才装配图片；不支持返回 capability_missing，不凭标题推断画面。字幕存在就按需使用；无字幕的音频转写可增加同一 ProviderRegistry 的转写能力绑定，不是再新增一个 Agent 角色。该绑定默认未配置，模型名称与费用需在部署时验证，不能猜网关能力。

**结果。**采样策略、帧时间点、字幕/转写段、未覆盖区间、音轨与资源来源都在观察中可见。ASR 是派生识别，不能无条件当作精确原话。抽帧摘要不能称逐帧看完全片。

**资源与取消。**并发与临时卷受同工作预算；ffmpeg 及子进程由具体 execution_id 终止，取消后不生成“分析已完成”；已取得片段可保留，过期 URL 的刷新为新的显式读取，不重跑整场研究。

**验收。**同一视频的选定片段与生成帧时间一致；缺字幕可明确选择转写或结束为部分结果；模型不能引用未呈现帧；过长/异常媒体失败不拖垮 Bot；最后仍由原工作返回群结果。

## M17. B 站账号、登录资料与受限外部动作

**涉及：**RootConfig/面板凭据字段、B 站专用 connector、Gate/操作记录、当前授权与预算。建议将账号写动作实现为明确的插件提案，不塞进通用浏览器点击。

**凭据。**Cookie/SESSDATA 只由运营者配置。根文件权限 0600、备份同级保护、UI 只显示配置状态，不把原值回传。真实请求所需鉴权字段按已核对协议提供，失败即记录；不猜字段、不自动登录。必要时将短命受限会话交给专用账号读取 worker，绝不交给自由代码 worker。

**最小权限操作。**建议 `set_bilibili_like(resource_id, desired_state)` 与 `set_bilibili_favorite(resource_id, collection_id, desired_state)`，名称为拟新增。每个调用先作为提案绑定账号、资源、目标状态、授权、job/revision 与审查；实际执行由平台动作适配器完成。不能用 toggle 造成重试后反向操作。

**浏览器边界。**匿名浏览器可以导航不代表登录浏览器可以任意点击。即使不暴露评论工具，带 Cookie 的无限点击仍可能完成评论/关注/账号设置；因此账号写操作通过窄 API 实现，通用页面交互不能借用该权限。

**结果。**已确认成功、已确认没有执行、被拒绝、结果未知各自保存；平台动作回执与 QQ 消息回执分开。未知后先通过平台可用状态读取核对，不能直接再次点赞/收藏。撤销授权阻止未来动作，不自动取消用户原有收藏；显式取消收藏是新动作，不是数据库回滚。

**并发。**同账号同资源的写动作串行并带稳定行动身份；每日额度按账号与能力计算，同时核对目标群/发起者。系统心跳没有默认点赞权。无 Cookie、权限或合法目标时工具不可执行。

**验收。**明确对象和目标状态正确、两种权限可分别撤销；取消/重启不重复副作用；Cookie 不在模型、日志、图片元信息、工作文件里；其他账号动作没有可绕行入口。

## M18. 普通文件资产与 OneBot 上传

**涉及：**`media/models.py`/资产服务、`execution/service.py`、`actions/models.py`/`queue.py`、`adapters/onebot.py`、提案与 Gate、工作面板。

**资产链。**工作产物完成安全读取后，转成持久文件资产：asset_id、原工作/修订、源执行、大小、实际 MIME、展示文件名、授权范围、有效期。先登记后才允许文件提案；不能直接发送模型自拟的宿主路径。

支持范围应在 Schema 与面板列出。建议第一版 TXT/CSV/JSON/PDF、常用图片、ZIP，以及明确配置支持的无宏 DOCX/XLSX/PPTX；其他类型明确 unsupported。源码可以放进 ZIP，但独立脚本或编译可执行文件不自动开放。格式扩展是可见能力变化，不凭扩展名泛化。

ZIP 检查条目路径、特殊文件、嵌套深度、展开字节数/文件数和敏感来源；密码保护或无法检验的包明确失败。禁止控制输入、凭据、根配置和数据库进入可导出的工作文件。敏感名称检查只是辅助，不能保证任意字符串里不存在秘密；核心保证是秘密从不进入自由代码输入。

**上传。**新增明确的文件行动类型/参数而非伪 `file` 消息段。OneBot 适配器根据已确认能力调用 `upload_group_file`。分服务部署时，文件通过专用只读导出卷或受限资产获取接口提供给 OneBot，不共享整个工作区。具体协议、路径形式、返回字段以实际 OneBot 实现核对，不假设通用。[O17]

**额度。**`send_file` 独立授权；单文件 50MB、每群每天10个，发送前原子预占。同一 action 不重复扣次；确认未发可释放，未知暂保留占用等待核对。额度日期按实际上传日的配置时区；睡眠期间生成不提前消耗当天发送次数。

**回执。**文件上传成功只按真实协议结果记录 file_id/文件列表身份等；不能伪造普通消息 message_id。需要群内文字通知时是后续独立消息，上传与通知各自记录，通知失败不重传文件。

**留存。**待发送/unknown 的文件不得在工作结束时清理。发送不支持时保留面板下载并明确未发群，不假装自动替代了原交付。

**验收。**同群工作生成 ZIP 并在已确认支持的 OneBot 上传；跨群资产拒绝；超过50MB或当日次数明确拒绝；重启/超时不重复上传；只读导出权限与文件生命周期正确。

## M19. 插件分类、GSUID Core 与公共接口

**涉及：**`plugins/base.py`、`models.py`、`host.py`、插件目录规范、`plugins/builtin/gscore_adapter/`、前端 PluginsView。

**系统模块分类。**Agent、预算、权限、工作、认识和统一发送可以在面板归为“系统能力”，但不因此变成可由模型卸载的插件。现有核心运行时不用搬目录。功能插件仍是一目录一 PluginSpec，独立业务模块注册自己的工具/handler/hook。[R09]

**接口增量。**工具可声明 required_capabilities、可用角色、输入/输出数据范围和副作用类别；schema 可见性与执行处统一校验。`read` 只描述业务作用，不意味着工具没有 CPU/网络消耗；账号写操作和上传必须走提案。所谓“小卡片”在 UI 中明确区分“功能项”和“渲染图片”，避免一个开关混合两种含义。

**Core。**只转发明确 `/gs` 或已确认的精确前缀，不上传全量群聊、不新增第二个普通聊天入口。保留 onebot 平台身份与实际 bot_self_id，不因更换品牌破坏旧绑定。连接生命周期沿已修锁实现，不重复做连接器。

支持矩阵逐项列出：文字/图片、媒体、文件、合并转发、按钮、撤回、私聊、登录提示。首版仅承诺已实现并联调的项目，其他明确拒绝。Core 数据进入插件事件后由原资产与发送链处理；真实 `after_delivery` 才回传逐帧送达身份，echo 不当作整次业务完成信号。

Core 重连只恢复连接，不重放未确认的签到、绑定或其他命令。Core 没有配置时保持 unconfigured，不在每条群消息中报错，也不阻塞其他插件。

**借鉴。**NoneBot 的匹配/权限/传播分工，以及 AstrBot 将主动能力建立在明确任务与反馈上的设计。[O11][O12]

**验收。**普通消息不被 Core 抢走；同一帧不重复发送；目标群受限；插件停用后所属任务结束；未知回执不伪造成功；卸载 Core 不影响卡片、记忆与 workspace。

## M20. 面板、观察与错误呈现

**涉及：**`web/query_service.py`、原路由、`web/frontend/src/views/` 下现有 Jobs/Scenes/Models/Plugins/Memory/TasksLoops/Settings 与 Trace 组件。

每个能力提交同时更新相关页面，不最后一次性建设巨大新面板。界面读取仍通过 RuntimeQueryService，不在 Vue 或路由中维护第二份数据库事实。

| 页面 | 必须回答的问题 |
|---|---|
| Jobs | 谁发起、谁付额、哪个修订、目前执行/暂停/取消、有哪些真实产物、还有哪些未读/未完成 |
| Models | 当前绑定、各用途真实/估算用量、预占与可用余额、发生费用是否可计算 |
| Scenes | 普通聊天/确定性命令/主动分享/文件/账号权限、睡眠与本群叫醒状态 |
| Plugins | 配置已保存与当前生效、可发现与可执行差异、缺少后端/模型/平台能力 |
| Memory/Interest | 人物认识与公共兴趣分开，来源、修订、有效期、召回原因和实际呈现 |
| TasksLoops | 当前心跳 slot、跳过理由、延迟交付、原定时间与实际送达 |
| Trace | received / selected / presented / proposed / committed / attempted / delivered 分开 |
| Artifacts | 文件下载、图片登记、群上传三种状态与失败原因 |

敏感字段在序列化出口遮蔽，不能只靠前端隐藏文本框。查看 trace 不重新执行工具；刷新页面不重新渲染所有历史报告、不重新调用模型。错误对用户简洁，对运营保留准确阶段；技术失败不能被包装成泛泛的安全拒绝。

未确认终止的解除动作必须明确列出 execution、检查证据与后果，并进入 OPERATOR_ACTION；不提供“强制标成功”按钮。

**验收。**页面值可追到真实记录；已选择但未装配资料不显示“模型已读”；已上传与已通知不混同；没有服务器端凭据回显；生产静态产物随提交生成且人工检查实际页面。

# 7. 端到端业务流与异常分支

## 7.1 普通群聊：不依赖研究平台也能改善

```text
真实群消息 → 事件保存/插件归属 → 注意力机会
→ 当前群上下文与偏好 → 社会 Agent
→ respond（回应/沉默/澄清）→ Gate 同事务提交 → 原发送 → 真实回执
```

无需资料时不检索、不启动 worker、不先审查一遍情绪。当前参与对象与否定由原话确定；强请求暂未完成要保留来源状态，不能“本轮沉默”就把所有待处理请求清空。

## 7.2 用户要求“分析这份资料，画图发出来”

```text
请求原话 → 对话提出工作 + 明确资料/预算
→ Grant 与额度预占 → 原工作创建
→ 读取资料并保存观察 → 导入被本工作授权的文本/附件
→ Gateway/Python → 真实执行结果 + chart.png
→ export 登记图片资产 → 工作保存结论与资产
→ 对话/准备交付沿原 Gate → 图片实际送达
```

缺依赖是明确 worker 错误；图片登记失败是可下载但不可发图的 partial；发送失败不重跑分析；终止未确认不继续读取/复用目录。工作结果只有保存后才回到对话，不能先说“发好了”。

## 7.3 “今日直播”与直播推送

```text
明确命令 → 精确 handler → 原日历读取 → 同日期资料
→ 确定性日历/空状态/错误状态卡 → 仅图片 → 原提交回执

真实新开播事件 → 核对订阅与场次 → 原 Invitation 文案
＋同场次事实卡 → 睡眠/额度/当前状态 → text+image → 原回执
```

引用卡片的自然问题转普通对话，不再宽泛消费。首次监测已有直播只建立基线，不把旧场次当新开播；此行为沿现有实现保留。延迟后已结束的直播不能继续使用旧“刚开播”文字。

## 7.4 系统心跳：研究与发布分离

```text
当前slot → 原任务认领 → 系统grant/睡眠/容量
→ 公共工作（无群成员资料）→ B站公开观察
→ 兴趣候选 → 宿主验证写入
→ 各获准目标群的发布机会
→ 该群社会 Agent 判断相关性/是否发言
→ Gate/ActionQueue → 真实送达（也可能零条）
```

心跳的正常结果可以是没有新兴趣或没有消息。候选引用同一个公共兴趣，不把多个群当前对话回写成全局资料。重启不自动重新研究所有已跳过 slot。

## 7.5 睡眠中的工作完成与文件上传

```text
工作完成 → 持久报告/文件资产 → 保存延期意图与原定时间
→ 清理不再需要的 worker 临时文件，保留待发资产
→ 醒来 → 当前授权/资料新鲜度/额度/原工作版本
→ 适当合并 → 原发送/文件上传 → 每个原事项的真实回执关联
```

延期不等于失败；unknown 不再延期自动重试。只有队列里没发出的意图才能安全重新评估；已经尝试但无回执的动作必须先核对。

## 7.6 点赞/收藏

```text
Agent 提议明确账号＋资源＋desired_state
→ 当前grant与原工作修订 → 必要审查/运营条件
→ 保存操作ID → 专用连接器请求
→ 成功/拒绝/未执行/未知 → 原操作记录
→ 必要时生成群内表达（不是账号接口直接发群）
```

平台网络超时不触发相同动作重放。未知状态读取是核对，不是新授权；确认目标状态后才把结果记成完成。

## 7.7 工作、插件或服务取消

```text
真实取消事件 → 原工作不再允许新操作
→ 定位所有相关 execution_id → Gateway 有界终止
→ confirmed / unconfirmed → 保存终态与保留资料
→ 释放可释放的预占 → 对已提交/未提交/已发送分别处理
```

真实取消继续向父循环传播；内部工具超时可以形成失败观察，但不能吞掉用户取消。重复取消可读取同一清理状态，不能创建第二轮执行。

## 8.3 不得出现的半提交

- 只让 `AgentBudget` 接受 None，却未修改所有循环终结判断与恢复字段。
- 工具声明 `send_file`，Gate、资产或适配器尚不支持，但面板显示已可用。
- 新 system-origin 能绕过人类检查，却没有系统 grant/计费/来源验证。
- 添加 Gateway 客户端后继续在失败时回落宿主 `docker run`。
- sleep UI 有开关，真正发送队列却未检查，或睡眠时任务只存在内存。
- 账号 Cookie 已挂给浏览器，而任意 click 仍可执行所有平台操作。
- 后端字段已变而提交旧 `web/static/dist`，或只在临时目录构建。

# 9. 配置、结构迁移与版本规则

## 9.1 配置组织建议

以下是结构索引，不是现版本可直接粘贴运行的 JSON；新增配置必须先有 RootConfig、统一解析、页面和当前能力事实支持。

```text
lenbot.config.json
├── runtime                     原运行参数；扩展统一预算，不重置旧参数
├── models
│   ├── providers               原提供方与凭据
│   ├── routing                 conversation / work / maintenance
│   ├── retrieval               保留已实现embedding/rerank绑定
│   └── media                   可选transcription等能力，默认未配置
├── access
│   ├── operators               真实运营者白名单
│   └── capability_grants       明确主体、群、能力、期限、资源策略
├── autonomy
│   ├── heartbeat               enabled、周期、deadline、系统scope
│   ├── interest                启用范围、公开来源策略
│   └── system_budget           独立账；daily_token_limit=null
├── scenes.<scene>
│   ├── 原enabled/chat/plugins等字段
│   ├── proactive               发布类别、冷却、每日消息额度
│   ├── sleep                   窗口/继承关系/确定性服务例外
│   └── file_delivery           独立授权与50MB/10次额度
├── time                        原业务时区，增加必要账务时区说明
└── plugins
    ├── workspace               Gateway地址/固定worker策略引用
    ├── browser_agent           受限独立browser策略引用
    ├── bilibili相关             现有业务参数＋专用账号字段
    ├── group_summary/calendar  原业务参数，保留
    └── gscore_adapter          未配置即unconfigured
```

每个参数只有一个编辑来源。worker/Gateway 所需的启动配置由部署阶段从根配置生成最小只读投影，不可包含 LenBot 全部凭据，不作为另一份可手工修改的业务配置；明确投影版本和服务是否已生效。容器内部 PATH/HOME/MPLCACHE 等进程环境可以固定设置，但不得用 env 覆盖 LenBot 的授权、人格、模型或预算。

## 9.2 默认值与启用

旧的聊天、摘要、原插件行为不因新增字段自动变化。新自主权限、账号操作与文件上传默认关闭，未配置后端保持 unconfigured。原本已批准的本地 browser/workspace 试用状态由运营者选择保留或切换，计划不自动改你的本地根配置。

新参数不要默认继承另一个能力的权限。例如打开直播播报不自动打开文件上传；设置 B 站 Cookie 不自动授予点赞；设置模型提供方不自动上传所有历史到 embedding。

缺模型、缺网络策略、缺平台协议能力必须在模型能力摘要和面板中显示，不等调用失败后才假装“今天没有结果”。

## 9.3 数据迁移

新增字段优先追加；必要表仅在依赖阶段引入。真实旧事件、认识 ID、批次投影/offset、已发 action 和 message_id、工作模型绑定不改写。

旧工作能从明确 requester/source 字段形成 Human initiator；缺乏确切来源的旧记录保留 legacy_unknown，可读不可直接扩权恢复。没有预算信息不能填零；先核对已保存 model_calls/工作计量，无法可靠转换的旧未终结工作保持待运营处理，不伪造成功。

公共兴趣与系统工作只对新事件生效，不扫描所有旧群聊建立全局资料。现有向量只在编码配置或来源版本确实变化时重建；单纯增加社会功能不重嵌全部历史。

配置结构变更使用一次性离线转换：停机、普通备份、明确转换列表、人工核对，再启动。转换脚本不接触真实群、模型和外部账号，不增加内容签名/校验清单平台。

## 9.4 回退

优先停用新能力并停止新入场，结束或隔离已有 worker 后再回退代码。新添加事实与已完成外部动作必须保留；不能为回到旧版本而恢复过时数据库并丢掉上线后消息。

若旧代码不理解新记录，保留新版本只读查询能力或执行一次明确的离线兼容处理；不能谎称任何版本都能无损回退。已发文件、点赞、收藏不能靠数据库回滚撤销；需要运营者明确的新平台动作。

# 10. 验收与交付证据

## 10.1 核对方式

遵守当前 AGENTS：不新增/修改/运行测试、fixtures、断言式探针、自动评分、覆盖率或自动 QA 截图。只做阅读、正常编译/构建，以及获准环境中的正常启动与人工业务操作。业务浏览器截图属于用户请求的实际工具产物，不是擅自新增自动截图测试。[R10]

正常静态核对可使用项目指定的 uv、Python 编译、`git diff --check`；涉及前端执行既定 `npm run build` 并提交实际静态产物。运行任何生产服务、真实模型、Cookie、Core、下载或群发送，需要对应授权；不得因为“验收”就自动调用它们。

| A15 | 明确点赞/收藏 | 对象状态正确，独立授权，unknown不重复动作 | action、账号结果、审查 |
| A16 | ZIP/文件上传 | 50MB和次数执行；OneBot真上传，不伪造message_id | asset、上传action、平台回执 |
| A17 | 服务正常重启 | 不自动重放不明操作；待发资产可恢复 | execution journal、task、action |
| A18 | 可选Core明确命令 | 不抢聊天，帧与真实回执关联，不重复回复 | Core帧、plugin事件、OneBot回执 |

人工验收不要求消耗满10M/30M，不要求为了证明上限真向群发送10个大文件。用获准的小额真实业务核对链路，再结合配置/事务实现说明额度逻辑；没有运行证据的边界明确写未确认，不能用“没报错”代表全面通过。

## 10.3 每提交的固定交付模板

```text
Commit / Parent / 审阅HEAD
涉及模块与新增持久字段
本提交实现了什么、没有实现什么
输入 → 状态/资料 → 外部操作 → 结果/回执

已完成正常业务观察（来源/Trace/工作/行动ID）

```

不要只写“编译、diff、文档均通过，因此功能完成”。同样，没有实群验收不等于否认代码确实存在；统一使用“实现完成”“部署就绪”“实际链路通过”三种状态。

# 11. Linux VPS 部署、运行与恢复

## 11.1 服务与卷

| 服务 | 挂载/状态 | 网络 | 不应拥有 |
|---|---|---|---|
| LenBot | 根配置、原SQLite、媒体/文件资产、必要日志 | 面板入口与控制网络、获准提供方/资料接口 | Docker socket、所有用户可写任务卷 |
| OneBot/QQ | 自身运行数据、只读专用导出区 | LenBot协议连接 | Bot根配置、SQLite、自由工作目录 |
| GSUID Core | 自身状态，按是否启用部署 | Core桥接私网 | LenBot认识和发送权限 |
| Worker Gateway | 执行journal、专用runtime endpoint、任务卷控制 | 内部API与执行管理 | 平台账号/OneBot/模型完整凭据 |
| Python worker | 本任务只读input/control＋可写output＋限额tmp | none或受控public出口 | 宿主home、socket、其他工作、根配置 |
| Browser worker | 当前工作临时会话与资源 | 对应站点/资源出口 | 任意个人profile、控制网络 |
| Media worker | 指定媒体输入、限额临时输出 | 下载阶段受限，解码阶段优先无网 | 账号操作和QQ发送 |

Compose 网络与容器参数属于部署静态事实，业务授权仍由根配置和运行核验决定。不要在生产用自动拉取 latest 镜像改变已验收环境；记录实际版本并在普通升级流程中更新。当前本地已构建镜像和 Playwright 安装不证明目标 Linux 架构、字体、UID映射和Chromium sandbox已经可用。

## 11.2 资源规格不在信息不足时猜成已知

本计划不虚构目标 VPS 的 CPU、内存、磁盘、架构和内核条件。第一轮部署记录实际值，再配置用户工作并发、心跳单例、浏览器/ffmpeg数量和卷配额。优先保证普通聊天与SQLite不被长工作占满；大型媒体任务不能绕过系统工作容量。

缺少目标机器数据不阻塞 C00—C09 的代码和接口工作，但阻塞独立执行后端的正式放行。网关、容器和浏览器的健康检查只确认就绪，不触发业务模型或真实群发送，不建设探针平台。

## 11.3 启动与停止顺序

部署时先准备授权和配置、备份，再启动依赖服务与 Gateway，确认受限网络/卷，再启动 LenBot；新能力保持未放行，逐模块在指定群人工核对后由运营者启用。OneBot forward_ws 已有实现，复用它，不再开发新的连接模式。[R11]

停止时先阻止新工作与新心跳，保留入站/已保存事实，取消或等待当前执行到明确结局，保存未交付资产/意图，再关闭 worker 与协议连接。遇到无法确认的执行不靠“进程没了”判定安全。

## 11.4 恢复矩阵

| 中断点 | 恢复行为 |
|---|---|
| 工作已登记、worker尚未确认接受 | 查询同execution_id，不新建另一个 |
| worker运行、LenBot重启 | Gateway按原deadline运行/收尾；LenBot读取已有事件 |
| 模型请求结果未知 | 保留已用/预留状态，记录未知；不自动重新付费请求同一步 |
| 动作提交、未开始发送 | 当前授权/睡眠核对后可按原身份继续 |
| 已开始平台请求、回执未知 | 保存unknown并人工/受限状态查询；不自动重放 |
| 文件已登记、睡眠尚未交付 | 恢复延期task与持久资产，不重新生成文件 |
| 账号动作已成功、消息通知失败 | 保留平台成功，只处理明确后续通知，不再次点赞 |
| 向量索引不完整 | 原认识有效；展示覆盖，按批准的维护继续，不丢账本 |

## 11.5 备份与回滚

沿现有运行手册做普通备份：SQLite、媒体/持久文件、真实根配置、待交付资产、Gateway执行状态和匹配部署文件。只复制一致状态；不能只备份数据库而忽略其引用的文件。工作临时缓存可清理，未确认终止或未发送成品不可提前删除。

恢复先关闭新外发，再核对记录和依赖身份。根配置备份含凭据，仍按敏感文件管理，不上传Git、不送模型。无需新增checksum/配置签名/备份验证平台；实际恢复核对写入操作记录。

# 12. 暂缓能力与触发条件

| TODO | 为什么暂缓 | 何时值得做 |
|---|---|---|
| Python程序化工具RPC | 容易绕开现有权限、计账、取消和来源呈现 | 先证明多步结构化读取确实造成大量无效模型往返，再仅开放当前工作已获准的读取工具 |
| 常驻Python/Jupyter内核 | 多了变量状态、崩溃恢复、并发污染 | 文件持续已不足以满足真实反复分析需求，且用户明确选择状态语义 |
| 技能中的可执行脚本包 | 来源、发布、依赖和工作执行需联合管理 | 先让现有文档技能与人工发布稳定；脚本仍在原worker内运行 |
| 通用多Agent/分工模型 | 成本、重复上下文、提交权冲突 | 有具体无法由当前单loop达成的业务，不因其他框架有就增加 |
| 更多网站与登录 | 每站读取、动作和凭据边界不同 | B站能力完整且有明确新增业务，逐站插件扩展 |
| 向量库/图谱替换 | 当前没有足够容量/延迟证据 | 实测表明SQLite索引与候选过滤成为瓶颈 |
| 任意浏览器账号操作 | 极易绕过窄动作授权 | 单独产品授权与可验证执行合同后再设计 |
| 全局语气/好感度/情绪状态机 | 容易将模型猜测持久化并影响事实 | 只有真实产品需要和可解释数据，不作为社会性必需 |

程序化RPC参考Hermes，但必须每个底层调用照常计预算、保存观察与执行身份；脚本print返回模型的少量结果不意味着其他资料自动成为已读证据。[O04]

# 14. 给执行者的工作约束

本计划作为模块合同使用，不是让执行者一次改完全部仓库。

1. 开始前核对真实HEAD、当前AGENTS、已完成修复与本阶段依赖；不覆盖用户更晚提交。
2. 每次只实施第8章一个可独立运行的提交边界；范围超出时先记录具体原因，不能趁机迁移整个框架。
3. 保留已有摘要、认识、模型绑定、人工样例、OneBot与真实回执。新增参数在根配置统一解析，禁止env/备用文件覆盖。
4. 不能通过吞错、隐藏fallback、改模型、重置预算、恢复旧数据库或直接平台发送制造成功。
5. 确实需要新增状态/表/模块时，说明它承担的唯一事实及与已有账本的关系。不要为日志、目录、工具发现重复建系统。
6. 只做本阶段允许的编译/构建和获准正常业务观察；不新增自动测试框架、断言探针、评分模型或QA截图。
7. 交付代码、文档、必要前端静态产物与真实核对结果。完成但未运行、运行但未送达、部分完成各自说明。
8. 实际根配置、生产启动、外部模型、Cookie账号、Core与真实发送分别服从当前授权；制定计划不等于已授权部署。

**实施原则：让能力逐个接入原执行链；让成功、失败、已读和送达逐个有据可查；先交付会聊天的机器人，再增加受控的自主行动。**
