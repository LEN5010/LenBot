## 4. P0-C：代码任务明细

### P0-C01. 修复纯 Gateway 配置的插件加载和面板下载

**源码事实。**`WorkspacePluginConfig` 规定 `worker` 与 `gateway` 互斥，纯 Gateway 时 `worker=None`；插件描述符的 `call_timeout` 却仍使用 `config.worker.timeout_seconds`。`PluginHost.load_plugin()` 在构造 manifest 时调用它，所以纯 Gateway 配置会在加载阶段发生空对象属性访问，尚未到真正执行。[S04][S05][S06]

面板也没有完整切换：`read_workspace_artifact_bytes()` 总是经 `_workspace_service_for_panel()`；该工厂只构造旧 `WorkspaceService(WorkspaceWorker(setting.parsed_config.worker, ...))`。即便启用后的列表和文本预览经插件进入 Gateway，原文件下载及插件未加载时的读取仍可能选错后端。[S06]

**实施范围。**workspace 描述符、插件生命周期、`PluginHost` 的产物入口和服务构造。不得在每个读取方法里再写一份后端选择逻辑。

**工作要求。**以当前明确配置确定唯一执行／读取服务；超时从实际后端和原工作期限推导，执行与收尾窗口分开；纯 Gateway 配置下所有入口不再解引用 worker。面板读取只走该服务的只读产物接口，不因为查看文件而启动 worker、执行脚本或新建任务。

**验收。**源码证明纯 Gateway 的加载、执行、列表、文本预览、导出与下载都指向同一服务；插件未加载／停用时只读能力有明确处理。获准环境再完成一次非 root 正常离线计算与对应原文件下载。不能仅凭配置模型接受 gateway JSON 就判定完成。

### P0-C02. 嵌套凭据在 API 层脱敏，保存时不丢失

**源码事实。**Gateway 的服务令牌是 `workspace.config.gateway.token`。`status_snapshot()` 提供保存的配置；`RuntimeQueryService.plugins()` 只扫描、删除配置第一层的敏感字段，`gateway` 对象及其内部 token 不在该第一层集合中。插件列表和保存响应直接使用这份投影；前端把对象变成普通 JSON 文本。[S06][S09][S14][S15][S17][S18]

这是**已认证管理接口回显敏感值的合同缺口**，不是本次已经证明匿名访问或实际密钥泄露。不要把它夸大成未证实的外网漏洞。

**实施范围。**插件配置 Schema、配置公开投影、配置保存合并、`PluginConfigFields` 与草稿序列化。先修响应，再修视觉遮挡。

**工作要求。**沿已声明 Schema 路径识别嵌套敏感叶子，公开响应只返回“是否已设置”；不得在普通 JSON、Schema 示例、错误文本、复制配置或高级详情中带原密钥。编辑非敏感 Gateway 字段时保留未修改凭据；“保持／替换／清除”是不同操作，必填凭据不允许无提示清除。不得把显示占位符当真密钥写回。

只支持项目已经使用的对象、列表、引用及可空结构，不为此新建全能秘密管理平台。凭据仍以根配置为唯一来源，前端不保存到 localStorage、URL 或长期草稿缓存。

**验收。**源码检查所有插件列表／详情／保存响应的嵌套路径；在获准面板中编辑端点后凭据状态仍为“已设置”，不需回显旧值。取消编辑不改变密钥；明确替换保存后读取响应仍不带新值。

### P0-C03. 补齐提交全程取消、错误分类与对账责任

**源码事实 A：取消只覆盖轮询。**`GatewayWorkspaceService.run_python()` 先写宿主执行行并 `await client.submit()`，之后才进入带 `CancelledError` 收尾的 `_await_result()`。如果请求已经外发但提交响应尚未返回时取消，当前入口不会经过 `_cancel_execution()` 和终止 park。网关可能继续执行到自己的期限。[S07]

**源码事实 B：把未知误记成没有执行。**提交分支将 `GatewayConflict` 与已拒绝一起标记宿主 `FAILED`；`_reconcile_workspace()` 捕获所有 `GatewayRefused`，统一写“请求从未到达”。认证失败等 4xx 不证明服务从未收到旧执行；即使 404，只能证明被查询的日志此刻没有记录，不能证明历史上从未产生副作用。[S07][S09]

**源码事实 C：未知终止被跳过。**对账跳过所有宿主终态，而 `termination_unconfirmed` 也属于终态；虽然镜像函数允许它更新到 confirmed，但该入口不会主动读取它。对账遇网关不可达又继续返回，未明确把工作区保持不可新用的结果交给调用者。[S07]

**源码事实 D：修订身份来自再次读取的最新行。**服务获得锁后重新读取工作，把当时的 `job['revision']` 写进 ExecutionRequest，没有接收原调用所归属的预期修订。旧工具调用等待锁期间工作被修订时，不能把旧脚本自动贴上新修订身份。[S07]

**工作要求。**

1. 从拥有 execution_id、开始外发，到轮询与最终收尾，采用一条完整取消路径。外发前取消可确认未发送；外发后不能确认时保留同一 ID 并请求取消／核对，不重新提交脚本。
2. 明确区分已拒绝且未启动、同 ID 冲突、工作区占用、认证错误、传输未知与日志暂无记录。状态写入不得推断未发生的事实。
3. 对账须给出“可新用／仍占用／未确认”三类可执行结论，不能只循环写日志。未知终止继续承担复核责任，确认后追加事实并释放资源资格。
4. 调用携带运行时绑定的原 job_revision；取得锁后和真正提交前复核该修订与工作状态。取消／修订失败不能授权跨修订继续。
5. 原工作绝对 deadline 是上界；网络传输、提交重试或 poll 等待不重新赠送执行时间。清理期限不授权继续运行用户脚本。

**验收。**静态逐入口说明取消和修订在哪里检查，所有错误如何影响占用；正常获准的执行、人工取消和正常重启能回查同一身份。没有故障注入许可时，不为验收主动制造网络故障；未观察的时序分支单列，不写成运行通过。

### P0-C04. 列表、读取、导出和下载使用一致的产物身份

**源码事实。**`_latest_artifacts()` 返回最近一个可查询执行的列表；`_artifact_by_path()` 却从最新执行一直搜索旧执行。若新执行删除 `report.csv`，列表可以没有该文件，按同一路径读取却从旧执行找到它。另一方面，最近执行只是被拒绝或未完成，也可能让现有产物列表突然为空。[S07]

`_artifacts_summary()` 在网关错误时返回空列表，结果固定写 `artifacts_truncated=False`；所有条目又固定 `over_limit=False`。这把“没有产物”和“产物尚未取得／清单未知”混为一谈。`_artifact_text()` 看似分页，却先下载全部字节、解码全文件，再截取一页。[S07]

**实施范围。**Gateway 产物查询合同、宿主服务、`WorkspaceArtifact`、工作详情与下载入口。复用现有 artifact_id／execution_id，不生成第二套文件事实。

**工作要求。**明确两种读取：当前工作区已确认快照，以及某次执行的历史产物。当前路径读取只查同一个已确认快照；历史读取必须携带明确 artifact_id 或执行选择，不能隐藏回退。读取失败保留失败与来源身份，不伪装成空目录。目录完整性、超限和截断从网关实际结果传递，未知就显示未知。

文本预览应从拥有文件的一侧进行有界读取，或在已有限额的统一传输层中取范围；offset／limit 的坐标单位保持明确。中文 UTF-8 不能按任意字节边界切开后声称字符分页连续。图片导出和普通文件下载用同一稳定身份，但图片另经原媒体登记链。

本项修复 C11 已开放接口的正确性，不提前开发 C12 全部媒体导入和格式处理。

**验收。**同一产物在列表、预览、导出、下载上身份一致；新执行删除文件后不会偷偷返回旧文件；历史文件仍能通过明确历史入口读取；无法获取清单显示“暂不可读”，不是“0 个文件”；小页预览不会每次完整读取大文件。

### P0-C05. 统一无上限、缺少历史快照与真实零余额

**源码事实。**当前旧 `held` 记录会补存 `limit_tokens=reserved_tokens`；但 `work_budget_facts()` 只读新 `budget_json`，没有它就返回无限／未知的 `(None, None)`。同一旧工作已知的额度上限可能留在预占表，却未用于新的调用准入；`work_call_admission()` 遇到 ceiling=None 直接不施加 token 维度。[S10][S26]

无上限工作由 JobStore 传 `tokens=0, limit_tokens=None`，底层又把 `None` 理解成未提供参数而用 tokens 代替，导致预占行记 0、工作快照记 None。不能因为首轮主要读快照就忽略两份持久事实的矛盾。[S10][S12]

**工作要求。**为“明确不设限制”和“历史上没有记录”作可识别区分；原累计上限只有一个权威解释。能从确切旧事实还原的内容在一次明确转换中补齐；不能还原原期限、身份或上限的记录，不按当前默认值补造，也不在运行中默认为无限继续。

不能用两套长期兼容分支处理旧工作。保留原事件和用量，转换后统一进入同一套读取；需要运营处理的旧工作列明原因。恢复遵循已修复的日账与并发准入，不退回无日账重开。[S11][S12]

**验收。**创建、结算、恢复和启动后的同一工作对上限给出一致答案；无上限不变零，缺历史不变无限；后改默认策略不改变旧工作预算。真实 usage 与估算继续分开，不能把本地估算称为供应商精确计费硬边界。

### P0-C06. 输入和输出收尾要有可追踪结果

**源码事实。**当前 Gateway 会先逐个落盘 `input_files` 再登记 execution；后续输入坏 base64 或合计超限时会拒绝，但此前已写文件没有在该拒绝路径撤销。输入目录不属于已登记执行，却已占磁盘。[S08]

输出读取虽然已经提前启动，但在停止分支收集完结果后仍直接返回，没有在这条路径统一写入 stdout／stderr；目录权限应用失败记录为 warning 后仍启动，也没有把“能不能读取本次脚本和输入”明确变成启动条件。[S08]

**工作要求。**输入接收先在本次未发布临时区完成解码与总量校验；完整成功后关联执行身份，拒绝清理本次临时文件，不删除其他运行资料。取消、超时、执行异常都保存已经取得的有限日志和截断信息；原进程退出、资源终止和产物超限是不同事实。

权限准备不要求一味以 chown 成败替代可用性：UID/GID 已一致时不需要多余 chown；真正无法取得所需权限必须停止并给出部署错误，不能继续后再把 PermissionError 描述为脚本问题。不改成 root，不用 777。

**验收。**静态检查输入拒绝的回收路径和停止日志出口；获准普通执行可读取输入、写文件、产生并读取日志。目录和输入限额不能只是登记条目上限。没有压力测试许可时，以源码约束与普通业务证据交付，不制造磁盘耗尽或攻击文件。

### P0-C07. 初次配置草稿不能构造出无效配置

**源码事实。**`blankConfigDraft()` 对复合对象填 `{}`、数组填 `[]`、其他值填 null，忽略 Schema 的合法默认值和可空对象的含义；保存遍历草稿中的所有字段。workspace 首次配置因而会同时出现 worker={} 和 gateway={}，与后端“只能配置一个”的合同冲突。其他有默认布尔／数字的插件也可能被显式 null 覆盖，后端正常默认值无法生效。[S04][S17][S18]

**工作要求。**草稿区分未设置、使用 Schema 默认值、显式 null 和实际输入。默认值可用于可见草稿，但不在用户保存前写入根配置；也不是运行期混合样例与根配置。互斥对象有明确选择器，未选择的后端按协议省略／置 null，不同时提交空对象。嵌套凭据使用 P0-C02 的独立编辑语义。

**验收。**首次配置和编辑已有配置都能在不手改 JSON 的基本表单中产生有效候选；未填写可选字段不被擅自改成 null；开启／关闭群插件不重置其余参数。服务器依然进行完整验证，前端只帮助输入。

### P0-C08. 混策略账户不得显示默认策略推导的假余额

**源码事实。**当前已修完整日账汇总，也能为单一 Grant 引用的账户显示具名策略；但同日混用多个引用或策略无法解析时，仍回到默认策略算 available。默认无限时，实际受有限 Grant 约束的下一项工作可能被显示为无限；历史使用过哪条 Grant 也不等于当前请求适用哪条 Grant。[S13]

**工作要求。**全日已用／占用是账户事实；可新建工作额度是“当前主体＋能力＋范围＋当前有效策略”的准入结果，分开展示。混策略场景不给无条件单一 available，而是显示各适用范围的额度或明确“需选择能力与范围”。失效、撤销和未配置不能退化成无限。

日账页同时区分实际用量、本地估算、在途占用；不要把同一份整工作预占和内部调用预留重复相加。字段 `policy_name` 当前可能存 Grant ID，应在输出中区分授予引用与策略名称，不把技术字段含义错误地翻译成用户标签。

**验收。**单策略、混策略、跨群查看和撤销后，页面与同一准入解释一致；明细分页不改变汇总；配置页用量不依赖抓取新模型账单或额外模型调用。

### P0-C09. 校正 C11 完成条件，收口正式单后端

**当前边界。**代码保留 worker／gateway 互斥选择，且没有网关失败后自动回落到本机执行；两者不能混为一谈。没有运行时 fallback 是已经存在的优点，但保留两个可选实现、示例仍选 worker，也不等于已经完成“唯一正式 Gateway、LenBot 无 Docker socket”的最终切换。[S01][S04][S07]

**工作要求。**保持保护计划中的最终单正式后端目标。先解决 P0-C01—C06，明确一次性配置／部署转换和旧产物处理，再在获准切换时移除正式插件里的旧本机执行选择及宿主 runtime 依赖。旧实现保留在 Git 历史，而不是作为隐藏备用入口。切换前记录“C11 源码接线／合同待补齐／部署待验”，不要改写总计划来追认双后端为完成。

目标 VPS 的用户、架构、网络和卷没有被本次观察到；镜像、Compose 或部署说明缺少的部分作为 C11 部署交付，不拿 C12 的未实现功能填充。C12 需要的输入／产物契约可以明确，但不宣称 C12 已做完。

**验收。**正式配置只有一个后端，LenBot 不需 socket 或 Docker CLI；断开网关不会执行宿主命令；所有只读产物入口仍遵守同一归属。回退是明确停机和代码／配置操作，不是业务失败时自动换实现。

## 5. 前端诊断：问题主要是配置路径，不是缺少装饰

以下判断来自 Vue 组件和 API 阅读，不是浏览器实测。当前界面已有未保存提醒、按页草稿、部分保存值／生效值区分、群名搜索、状态标签以及移动布局规则，应保留。[S16][S19][S20][S21]

| 当前入口 | 已见交互／信息问题 | 使用者承担的额外工作 | 改进方向 |
|---|---|---|---|
| 系统设置 | 十个标签，默认从人格开始；连接、发送、群、授权分散 | 想让某群正常使用，先要知道配置在哪一页 | 首次配置按依赖引导，日常从群进入；保留高级设置 |
| 群设置 | 顺序展开所有插件，每个插件先“添加本群设置”再编辑 | 在大量停用插件中找一个目标；不知道全局还缺什么 | 已启用／可添加／未就绪分组，依赖原因和跳转 |
| “填为仅播报群” | 只设 enabled=true、chat=false | 容易以为已经配置播报，实际没有来源；白名单仍可互动 | 清楚表述行为，并列出已选播报来源；不隐式开插件 |
| 插件全局详情 | 长对话框先展示入口、事件、hook、源状态，参数靠后 | 改一个端点要穿过实现细节 | 配置与开放群在前，诊断信息折叠 |
| 插件复杂参数 | 嵌套对象／列表直接是 JSON textarea | 必须懂内部键、null、数组与互斥关系 | 结构化常用字段，JSON 仅高级入口 |
| 新配置 | 默认草稿全部 null／{} | 即使只用合法默认值也可能保存失败 | P0-C07 先修 |
| 能力授予 | 手填 ID、版本、主体标识、能力枚举、Unix 时间和策略名 | 记忆内部词汇，重复查字段和复制 ID | 选择主体／群／能力／策略，日期选择，ID 只读 |
| 额度策略／运行参数 | 10 行／24 行 JSON 是主要编辑方式 | 改一个超时也要保存完整对象 | 单位清晰的分组数字表单，不更改后端预算含义 |
| 全局“成员” | 实际是成员名称＋B 站 UID＋直播间 | 容易与群详情的 QQ 参与者混淆 | 改名“主播与订阅对象”，群成员仍在群里 |
| 生效原因 | 分别显示保存、启用、源状态，但缺统一的当前使用解释 | 配置已保存却不能用时要逐层排查 | 显示阻断原因、当前范围、配置应用状态与最短下一步 |

证据：[S16]—[S22]。以下改进是针对这些已见结构，不进行全站换肤，也不迁移前端框架。

## 6. P1-U：界面实施任务

### P1-U01. 按任务重组入口，保留诊断能力

**目标信息架构。**

| 主入口 | 日常任务 | 高级／诊断内容 |
|---|---|---|
| 概览 | 当前连接、发送模式、需要配置的依赖、最近失败 | 原状态时间、详细运行记录入口 |
| 群聊 | 找到一个群，调整聊天、命令和播报 | 原话、注意力、历史、工作和回执 |
| 插件 | 配置连接／来源，查看可用性，管理开放群 | 工具名、Schema、事件、hook、目录、任务 |
| 工作与文件 | 查看工作结果、执行状态、读取／下载产物 | 原修订、执行日志、观察范围、费用 |
| 模型与额度 | 模型绑定、用量、策略与主体准入余量 | 原调用行、真实／估算分类 |
| 系统设置 | 人格、注意力、连接、发送、业务时间、主播、账户 | 高级运行参数与危险操作 |

不必为了这个菜单重建路由体系。复用既有页面、组件、查询接口和对象链接，主要调整默认视图、标签与内容顺序。旧事件和 Trace 深链接继续能打开；不能把工具目录、错误记录删掉，只把它们移到诊断层。

**首次配置流程。**用可见状态清单串联模型、OneBot、必要业务时间、目标群和所需插件；每项连接到真实配置页。缺省可以保持停用，首次配置不能自动打开实发、语义检索、联网或账号动作。检查状态只读现有事实；涉及请求外部服务的检查单独按钮明确其行为，不随刷新自动执行。

**涉及模块。**现有前端导航与 router、OverviewView、ScenesView、PluginsView、SettingsView、既有 app state。先定位导航实际定义再修改，不按猜测新建文件。

**验收。**从概览能看见为什么目标群不能使用；从群详情到对应插件配置可直接到目标，不再找长对话框中的隐藏段落；原诊断链接不丢失。

### P1-U02. 让群配置成为日常操作中心

群列表显示“群名＋群号”，可搜索、查看启用状态和聊天／播报摘要。只使用现有接口能返回的群名，缺失时显示群号；未出现过的群允许手填群号，不为此强行增加 OneBot 群发现联调。[S20]

群详情默认分为“消息”和“配置”两个主要操作区域；注意力、历史批次、认识和回执保留为诊断或次级标签，不挤占配置流程。群设置包含三个明确部分：

**基本行为。**启用本群、允许普通聊天、白名单例外提示、全局 Shadow 对本群的影响。快捷填充只修改既有字段并列出改动，不创建一套与 enabled/chat 冲突的模式字段。

**本群插件。**首先列已配置插件，停用也保留参数；添加插件用搜索选择器，只展开选中项。每项显示本群开关、全局保存／运行状态、依赖缺失、有效参数；全局未就绪时可保存停用草稿，但不得显示为已可用。移除本群配置不删除全局插件参数。

**播报与提醒。**从已实现插件的场景配置读取可用选项，例如开播公告、订阅对象、@全体；明确每项的依赖及当前是否实发。尚未实现的心跳／睡眠／文件发送等显示“未实现，当前不能启用”，不放一个能保存却无执行效果的假开关。

“仅播报”应显示类似：“普通成员不参与闲聊；当前已配置 1 项播报，白名单例外保留；全局 Shadow 开启，暂不实际发送。”没有播报来源时明确说没有，而不是暗示已经会推送。

**涉及模块。**SceneSettingsForm、ScenesView、群设置查询与保存、ScenePolicy 的只读解释、插件场景 Schema。权限逻辑仍在后端，不把前端判断当授权。

**验收。**设置聊天群或仅播报群无需读源码；能解释白名单、全局关闭和 Shadow 的作用；给 A 群开插件不影响 B 群；未授予的 send_file、账号操作或 @全体不会随“播报群”隐式开启。

### P1-U03. 插件列表与配置按“用途、配置、开放范围”组织

列表增加轻量搜索及状态筛选，采用面向人的用途分类，沿现有插件定义提供名称和简述；不按分类把底层插件重新合并或改成新框架。

卡片摘要只呈现：插件做什么、全局保存状态、实际加载状态、开放群数量、需要处理的问题。源成功时间只对有源监测语义的插件显示；Python 计算不能因为没有“最近成功获取源”而看起来故障。

详情默认打开“配置”，其次“开放群”，最后“诊断”。工具函数名、事件、hook、优先级、Schema、来源目录放在诊断区域。开放群用群名＋群号，可跳到同一个群设置表单，不维护另一份本群开关存储。

对 `restart_plugin` 显示保存影响：“该插件会重新装载，未提交工作可能中断”；只有会改变运行或发送资格时才要求确认。不要为编辑说明文字等无风险字段层层弹窗。

**有效状态不要压成一个绿色开关。**至少分别表达：配置是否完整、全局保存是否启用、运行时是否加载、本群是否开放、此能力是否已实现／满足依赖。模型是否会选择调用是 Agent 决策，不应被显示成“一定回复”。[S06][S16]

**验收。**查找并配置一个插件不需穿过全部注册入口；全局启用但某群未开放有具体原因；源不可用与插件未配置区分；详情诊断仍能追溯原错误。

### P1-U04. 通用表单只支持当前需要的 Schema 子集

复用现有 Vue／Vuetify 与 PluginConfigFields，补齐常用字段，不开发完整 JSON Schema 编辑器。

| 配置形态 | 默认控件与语义 |
|---|---|
| bool | 清楚标签的开关；需要三态时明确“未设置”，不把 null 当 false |
| enum | 中文选项名，保存原枚举值 |
| 数字 | 单位、上下限、合法步进；“不设限”与 0 分开 |
| 可选字段 | “使用默认／自定义／未设置”只出现真正支持的语义 |
| 小对象 | 分组子字段；仅实现项目已用的嵌套结构 |
| 简单列表 | 可添加／移除的行或多选；不要求手写 JSON 数组 |
| 已登记对象引用 | 下拉或搜索：群、插件、主播、资源策略 |
| 互斥对象 | 明确单选，切换展示影响并清理非选中分支；不同时提交两份默认对象 |
| 凭据 | P0-C02 的保持／替换／清除，明文不从服务端读回 |
| 长文本 | textarea，保留换行和字数提示 |

未知复杂结构保留明确标注的高级 JSON 编辑，不把它当常用入口。表单和高级 JSON 共用一个草稿与同一服务器校验；切换模式不丢配置、不复制运行配置来源。

中文标题与描述优先维护在所属插件 Schema，前端只维护通用控件与少量已知引用选择。字段错误通过服务端错误路径映射到控件，包含具体可修复原因；不能只有页面顶部的一句 Python 异常。[S17][S18]

**验收。**当前内置插件中常用布尔、数字、主播订阅和 Gateway 连接不需要 JSON；高级入口仍可表达完整合法配置；服务器拒绝时保留草稿并定位字段；默认值不在未保存前生效。

### P1-U05. 授权和额度改成可选择的业务表单

授权日常顺序调整为：“谁”→“哪个群／明确系统用途”→“允许什么”→“有效期”→“使用哪项额度策略”→“影响确认”。

人类主体填 QQ 或从已有参与者选择；插件主体从已登记插件选择；系统主体只能从当前有实现且合法的用途选择，允许高级诊断查看原 ID，不鼓励手填不存在的系统主体。能力采用多选项和简短说明，标出未实现项，不因为枚举存在就允许实际启用。

Grant ID 由服务端生成并只读展示，版本由现有修订过程递增，签发者来自认证，不要求运营者编辑版本号。有效期用日期时间选择器并明确业务时区，后端仍存绝对时间；资源策略用现有策略选择器，可以跳到策略编辑，不手抄名称。[S22]

额度策略是三项数字与可空语义的表单：单工作累计 token、主体日额度、可选群日额度，明确 token 不是货币。可用易读单位显示，但保存前精确换算到原单位。调用次数、单请求上下文、输出预留和工作期限不要全部命名为“额度”，分别解释。

保存前只对权限变化提供简短影响摘要：影响哪个群／主体、是否增加能力、是否撤销、如何影响在途工作。不能承诺撤销能收回过去发送的字节。当前工作快照不因改默认策略自动改变。[S12][S13]

**涉及模块。**SettingsView、ModelsView、授予请求类型与保存路由、CapabilityAuthority、配置 Schema、query_service；复用现有 Grant、revision、operator event，不新建权限数据库。

**验收。**普通授权无需输入 capability 枚举、Unix 时间或版本；只修改白名单不重写其他授予；编辑额度不自动重开工作；混策略账户采用 P0-C08 的明确准入口径。

### P1-U06. 统一保存、生效和错误反馈

保留当前未保存提醒、刷新不覆盖脏草稿和返回原对象定位的行为。保存需要在用户可见的位置分别表达：未保存草稿、已写入根配置、运行时已应用、等待插件重载／服务重启、应用失败但配置已保存。[S15][S16][S19][S21]

按钮命名说明实际动作，例如“保存本群设置”“保存并重新装载该插件”，不要把保存写成“已成功启用全部能力”。配置预览只给出规则计算与已观察状态，不自动发消息或调用模型。

错误顶部提供摘要，并链接到对应字段；字段旁显示相同解释、格式或范围要求。所有状态同时有文字，不只靠颜色。对话框支持键盘进入、关闭后回到触发按钮；移动端保留主要保存动作，避免长内容使按钮不可发现。上述是待人工核对的交互要求，不是当前界面已经失败的截图结论。[U01][U02]

“重置全部对话”移入账户／高级危险区，列清真实删除与保留范围。执行记录和额度记录的清理没有核定前，不把 Reset 推荐为修复路径。不能为了文档清理擅自修改或触发 Reset。

**验收。**保存失败不丢草稿；配置已保存但应用失败不会被误写成未保存；重启待生效有明确说明；从字段错误能定位并修正；键盘与窄屏人工检查有记录；常规编辑不会产生多层无必要确认。

## 9. 升级、历史数据和回退边界

文档删除可以通过 Git 查看和恢复；它不授权恢复过时数据库，也不是密钥清理操作。固定历史链接优先使用本计划锁定的 SHA，避免指向会继续移动的分支。

预算记录转换只能使用真实已有事实，保存原 job/revision、用量、来源和回执。新字段缺失不是自动无限的依据；无法还原时限制恢复，不构造假首次开始时刻。

Gateway 切换须先核对仍占用的执行和旧产物。宿主、网关和模型请求的未知结果分别保留，禁止使用新执行 ID 重跑来“验证成功”。确认清理与追加真实回执不是新业务执行，不应因业务权限撤销而被一起阻断。

配置更新使用现有根文件和发布锁；运行中通过面板保存。面板表单与高级 JSON 最终进入同一服务端验证，不用 env、CLI 或数据库另存一份运行配置。

若需要回退代码，先停止新能力进入并处理现有执行；保留升级后产生的消息、消费和回执。不能通过恢复一份旧库丢弃这些事实。后端替换没有自动 fallback，未授权切换时保持当前真实运行配置不动。

## 10. 最终交付格式

每批交付仅写：固定审阅 SHA 与父提交；修改文件；对应任务；解决的真实路径；未解决项；实际执行的编译／构建命令与结果；获准人工业务观察及其对象 ID；必要的一次性转换；配置保存和生效边界。

状态使用三个维度而不是一句“都完成”：

| 维度 | 可用取值 |
|---|---|
| 代码合同 | 待实施／已知缺口待修／源码闭合 |
| 运行证据 | 未运行／已核对具体正常路径／指定边界仍待验 |
| 启用资格 | 不可启用／限获准环境核对／已满足本能力放行条件 |

最后应交付：精简后的文档树；完成与未完成任务映射；当前代码缺口清单；群、插件、授权、额度的实际操作结果；没有运行证据的边界。不能只报减少多少行或“前端构建成功”。

本计划结束后，不再把整份计划、完整执行日志与逐轮复审报告同时留在 docs。保留保护计划、必要当前手册和短当前任务；详细过程留在 Git 历史中。
