# 在群里使用 LenBot

面向普通群成员，不需要先读架构或产品路线。本文描述当前源码支持的交互，不表示所在群已经开放这些能力。安装和面板配置由运营者按[运行手册](operations.md#初始化与启动)处理；群管理员身份不等于运营权限。

## 开始一次对话

1. 先确认这是运营者已开放的群。使用平台真正的 @ 提及或回复 Bot 的消息，说明想做什么；手打“@名字”不是平台提及。
2. 给出必要范围，例如要讨论哪条消息、哪段时间或哪份资料。图片随原消息提供，引用片段只在实际可取得范围内使用；看见图片名称不代表已读到图片内容。
3. 看实际回复或后续进展。读取优先不保证必须回复，Bot 可以沉默；没有回复也可能是未开放、睡眠、额度或执行问题，不宜连续重复发送。

不知道本群开放了什么时，请运营者从“本群设置”和“工具能力”核对。不要把自报身份、改写命令或换个问法当作绕过权限的方法。

## 查资料与委托工作

短查询可以在当前对话完成；涉及多步分析和整理时，Bot 可以提出后台工作。说明目标、时间／资料范围和希望得到的结果即可，不需要输入内部工具名或自己分配工作编号。

- 查询结果以实际取得资料为准；没有资料时，生成文字不算检索成功。
- 委托被接收、工作建立、研究完成、文件生成和最终送达是不同阶段。
- 如果需要文件，先确认本群文件能力与申请者资格。返回本地路径不代表文件已经上传，实际以平台收到的消息或文件为准。
- 日程、动态、群报告等按本群插件配置开放；直播订阅开关由运营者在面板保存，不把查询订阅状态理解成已完成订阅修改。

## 修改、停止与继续

尽量回复原工作的确认或结果消息，说明是哪项工作以及新的要求。存在多个相似工作时明确指出对象，不让一句“继续”自动指向猜测的目标。

- **修改要求**：说明哪些目标或约束改变；后续结果以实际采用的工作版本为准。
- **停止工作**：说明停止哪项委托。控制已提交不等于外部执行已停止，已发送内容和费用不会被撤销。
- **继续原工作**：沿原身份、模型和剩余额度继续，不会自动增加预算。已完成的研究只是需要再次表达时，不应重新执行来制造一份新结果。
- **复用结果做新工作**：给出新的目标并指出旧成果；这是新工作，不继承旧工作的读取范围、额度或发送权限。

当前工作控制合同是创建、修订、取消和恢复；没有独立的“暂停”控制按钮。具体能否采用请求由现有权限、状态与版本决定。运营者的处理入口见[日常查看与处置](operations.md#日常查看与处置)。

## 纠正错误与报告问题

如果 Bot 误认称呼、偏好或事实，指出错误及真实依据，尽量关联原话。认识可以被撤销或修订，但不是原始事实的替代；角色设定、摘要和 Bot 说过的话不自动成为证据。

出现以下情况请交给运营者核对，不直接重复操作：

| 看到的情况 | 提供什么信息 |
|---|---|
| 一直没有回应或工作未完成 | 原消息、发生时间、想完成的事情，以及已有确认／进展 |
| 修改或停止后结果不明 | 原工作确认、具体修改要求和发生顺序，不仅提供当前状态截图 |
| 文字／文件未送达或重复 | 平台实际收到的内容和时间，由运营者对照行动与回执 |
| 引用资料或认识有误 | 错误片段及原资料位置，区分本人明确表达和他人推断 |

只提供解决问题必需的内容，不公开完整群历史、密钥或无关个人资料。运营者可沿原事件预览并下载受限诊断材料；它仍需人工核对，不是自动匿名化的全量日志。问题记录格式见[缺陷报告模板](../.github/ISSUE_TEMPLATE/bug.md)。
