## B. 五个页面按标签拆出子组件

五个页面：SettingsView、JobsView、ModelsView、ScenesView、AgentSettingsView。

**共同做法**

- 每个标签的模板移到 `components/<页面>/` 下的渲染组件。
- 标签专属的状态、读取函数和各自的请求序号移到同目录的组合函数。组合函数仍在页面 setup 里创建，所以：
  - 切换标签时草稿照旧保留；
  - `useRequestGuard`、`useUnsavedChanges`、`onBeforeRouteUpdate` 仍在页面组件的生命周期里注册。
- 标签组件只接收 `state`（本标签组合函数的返回值）和 `page`（页面共享的 ref 与函数）两个对象，解构后原样使用。组件不发请求，也不向外发事件，因此不存在没有接收方的 emit。
- 移动的模板和脚本逐行保持原样。
- 路由、URL 查询参数、标签值都没有改。

**样式迁移规则**

- 一条 scoped 规则复制到子组件的条件：最后一段选择器能命中子组件模板，且它的祖先类名在子组件内或挂载链上。
- Teleport 出去的对话框不计祖先。
- 页面保留仍命中自身模板的规则，也保留原本就没有命中任何元素的规则（死规则不在本批删除）。

**自检方法**：每次拆分都用 `/tmp` 里的脚本做三项对照。

1. **名称解析**：编译页面和每个子组件，模板里没有落到 `_ctx.x` 的未定义名称，没有 `_resolveComponent` 的未导入组件；模板 `ref="x"` 都编译为 ref 对象，没有退化成字符串 ref。子组件解构了但没有用到的名称已删除。
2. **行对照**：拆分前后，页面加所有子组件的模板行多重集相同。差异只来自新增的挂载行和挪动的 `v-if` 根。脚本行多重集的差异只来自下表列出的调整。
3. **调用对照**：`api(`、`window.confirm`、`router.push`／`replace` 的调用条数与参数文字，拆分前后逐条相同。

## C. 受请求守卫约束的读取流程（`306b913`）

新增 `composables/useGuardedRead.js`，流程如下：

1. 取守卫；
2. 清错误，置 loading；
3. 响应仍新鲜才采用；
4. 错误只在仍新鲜时写入原始 `message`；
5. loading 只在仍新鲜时复位。

九处形状完全相同的读取改用它：

- 概览的统计与插件清单；
- 媒体列表与表情目录；
- 方法列表；
- 认识列表；
- 任务与等待列表；
- 模型额度预占；
- 表达样例列表。

认识列表和任务列表原来在 fresh 判断后还有一个条件（详情模式下不写列表）。这个条件移进 `apply`，先判新鲜再判条件，结果相同。

以下三类读取没有改，保持原样：

- 请求前有前置判断的；
- 错误文案带前缀的；
- loading 在请求前另有分支的。例如概览的 `loadIssue`，它的数据来源是响应式参数。

**核对**：`npm run build` 退出 0，页面与子组件名称全部可解析。这项改动的产物本来就会变，所以没有做逐字节对比。
