# 运行手册

面向运营者。本文是从初始化到停机、备份、升级和故障处置的可执行最短路径；行为含义与边界见[当前架构](architecture.md)，插件开发见[插件开发](plugins.md)，当前实施状态、实际核对与未确认项见[当前任务](iteration.md)。

待实现的设计、批次与人工验收见[完整改造计划](LenBot_群聊体验与可靠执行_完整改造计划_20260920.md)。操作仍服从当前源码合同、真实配置、部署前置及当次授权；计划、历史成功记录和配置开关都不能替代现场证据。旧资料仅用于辨认旧版本，不继承其机器状态或运行授权。

本群设置可为全局已配置的插件添加独立记录。没有群专属参数的插件使用 `{}`，新增草稿默认关闭；添加动作不执行工具，也不授权其他群。有必填参数时需补齐对应字段才能保存。全局停用、部署缺失和运行失败仍需分别处理。群列表合并已保存群、已有原话的群和 OneBot `get_group_list` 读到的已加入群；刚发现的群在保存前不启用聊天或工具。群页「设置」是唯一的本群配置表单：本群启用/聊天、旁听覆盖、表情倾向、能力开关、文件申请者和语义检索一次保存。旁听区显示本群普通周期观察是开是关、观察间隔、名称与关键词冷却，以及本群这一小时已发条数与上限；按钮「开启并将观察间隔减半」把这三项算成具体数值写进草稿，而不是每次再乘一次。本群覆盖可分别填写 `observation_enabled`（继承／开启／关闭）、`observation_interval_seconds` 与 `keyword_cooldown_seconds`。关闭周期观察不关闭真实 @／回复／私聊、名称与关键词机会以及短时观察期。未填 `scenes[group].attention` / `expression` 的旧群继承全局，不会自动变得更积极。

能力页按真实插件 ID 展示状态。全局参数从系统设置进入插件页，本群能力统一在群工作台的“设置”编辑，授权仍在现有权限入口维护。能力读取失败显示原因，不当作已就绪。旧群设置书签重定向到同一表单，不再保留第二套保存入口。

选择群和申请者后，能力卡同时展示当前入口用途、工作用途、条件型用途与具体缺项。条件型用途中的授权列表是原入口检查项，不表示全部未授权；工作开关或模型未配置时保留缺项。页面不创建临时工作、不探测外部服务，已有运行状态也不保证当前工具一定可执行。

## 插件启用前置

启用 `gscore_adapter` 前确认 Core 的 WebSocket 端点、认证方式、bot id 和 Core 版本协议；连接身份 `core_bot_id`、上行平台身份 `platform_bot_id` 与 `bot_self_id` 分开配置。该适配器只桥接明确 `/gs <命令>` 到独立 Core，未知消息段保留在观察中但不假定为可发送内容；它没有搬运 AstrBot 插件运行时，也不会自动安装游戏插件。

启用 `workspace` 前先确定唯一执行后端：`worker` 需确认宿主容器运行时、可取得的配置镜像、无网络和工作目录权限；`gateway` 需另外部署网关进程（见下文），两者不能同时配置。`browser_agent` 需先填写域名白名单并核对执行隔离：旧 worker 配置保留同进程试运行；workspace 选 Gateway 后只走独立 browser worker，构建和 seccomp 安装见[浏览器部署](../containers/browser/README.md)。白名单与源码存在不替代部署验收，最新现场记录见当前任务。`runtime.heartbeat_enabled` 与 `time.sleep_start`/`sleep_end` 默认关闭，改后需重启。

## 初始化与启动

从项目根目录运行，不在其他目录搜索配置。首次部署先执行 `uv sync`，仅在尚无实际配置文件时复制样例：

```sh
cp lenbot.config.example.json lenbot.config.json
```

编辑根文件中的实际连接、账号初始化信息、模型、插件和运行参数。样例中的 `runtime.bot_qq=0` 是占位，必须填写实际 Bot QQ 账号；启动要求正整数。样例不含生产凭据与群名单，不参与启动时合并。已有部署沿用一次导出的实际文件，不能用样例覆盖。文件含凭据，保存在本机并排除 Git。

| 配置节 | 内容 |
|---|---|
| `runtime` | 数据库与监听地址、身份与表达、注意力、预算、并发、媒体和维护参数 |
| `models` | 提供商连接、各角色 routing 与可选 retrieval embedding/rerank；未配置能力明确为 null |
| `delivery` | 全局 shadow |
| `access` | 全局 QQ 回复白名单，仅用于已启用群的普通对话资格；`capability_grants` 是自主能力的唯一可编辑授权来源，默认空列表 |
| `resources` | 具名额度策略；未配置额度维度为 null，明确引用不存在的策略拒绝保存／使用 |
| `scenes` | 每群 enabled、chat、semantic_retrieval 与按 plugin_id 保存的插件 enabled/config；命令和订阅由各插件 Schema 定义 |
| `time` | IANA 业务时区、自然周起点与下午范围；尚未填写为 null |
| `members` | 成员名称与别名、bilibili_uid、房间号；与 QQ UID 分开 |
| `plugin_directories` | 明确的本地插件根目录列表；空列表仍发现内置目录，变更需停机后重启 |
| `plugins` | 已配置插件的 enabled 与完整 config；未配置目录仅展示元数据 |

配置解析错误会报告具体位置，缺失必需项由运营补齐。env、dotenv、CLI 和数据库不覆盖根文件。三个模型职责单独设置，不需要为启动面板强行配置所有模型；未配置能力的含义见[架构](architecture.md)。样例开启 Shadow，群列表和模型供应商为空，插件中仅 web_search_tool 启用；样例不能直接收发群消息，实际状态以根配置及面板为准。群管理员不是运营者，群消息里的自报身份不提升权限。

语义检索先在“模型设置”中保存已确认的 embedding 绑定，再在目标群的“本群设置”开启 `semantic_retrieval`；两个条件缺一不可。首次开启后在认识页按场景执行显式索引重建。rerank 还必须填写实际确认的协议，未确认时保持空值。模型设置页不会因为刷新或保存而自动请求检索模型。

索引请求在每个嵌入批次取得并发位、发起网络请求和写入派生表前重新核对场景开关；重建期间关闭语义检索会停止尚未开始的批次并记录 `memory_index_cancelled`，原认识和历史摘要不受影响。认识索引的覆盖量按当前有效记录、修订号和模型代次连接核算，重建结束清理按当时的原表状态执行，不使用重建开始时的旧 ID 快照。

认识页先筛选一个场景，列表下方的索引卡独立显示该场景整体数量、当前修订/绑定覆盖和采样时间；人物/内容筛选不会改变索引范围。未初始化的覆盖显示“未取得”，不读作 0；关闭、缺绑定和客户端不可用分别说明。索引状态读取失败不清空认识列表，历史错误不表示当前仍失败。点击重建前核对卡片所示场景与绑定，确认后才会发送相关文本并产生嵌入调用；未配置的请求明确拒绝。切换页面不等于取消服务器上的请求，异常后查看最新覆盖与 `memory_index_rebuild` 原记录，不自动重复购买调用。

认识列表与群内记忆默认排除已撤销、替代和到期条目；选择“全部原始状态”或对应旧状态可回查。认识详情的“此修订链当前采用什么”仅按该次样本解释有效版本，创建/修订提交和原话可分别打开。维护页的“已采用认识操作”是当时真实回执，不等于当前仍采用；“候选待核对”不通过重试已完成摘要来强制写入。遇到 `stale_memory_result`，保存查询已经变化或到期：旧资料仍在，不能当作当前认识；需原循环在已有预算内明确重查，不能通过回读旧字符页规避。

Embedding 客户端显式要求浮点响应格式。每次检索操作在记账等待后、实际发起 embedding 或 rerank 请求前复核本群语义开关；关闭后的操作返回明确中断，不回退成成功的词面结果。向量候选先应用与词面查询相同的人物、类别、建立时间、状态和有效期条件，摘要检索还受本轮读取截点限制并保留词面与语义候选的并集，其日期范围在向量 top-k 前筛选；摘要批次 ID 不伪装成工具资料引用。

链接解析插件的媒体下载必须通过已保存的 `parse_link` 结果和明确下载入口。解析只读取 metadata；下载时校验实际容器字节，HTML、JSON 或无法识别内容不登记为视频/音频资产。工作中的公开片段使用明确 bvid/cid、时间区间与媒体 Gateway，不借用完整视频下载入口。内部 `audio` 在 OneBot 11 映射为 `record`，发送仍需真实回执。

确认配置和结构就绪，并取得当次生产启动授权后，在根目录执行：

```sh
uv run len-bot
```

使用启动信息与文件指定的地址打开面板。初次建号使用文件中的初始化账号，已有登录记录继续由 SQLite 保存；不要把旧文档或样例凭据当作生产登录。查看 OneBot 连接状态及当前发送设置后再进行原群操作。

## 运行中修改

运行中使用面板分节保存，保存成功才更新显示；手工编辑根文件前先正常停机。监听地址等需重启的字段显示“已保存，需重启”，不自动重启。新轮次使用新模型设置，已启动工作保留原模型绑定，恢复时原绑定不可用就明确失败。

面板产物 `src/len_bot/web/static/dist` 不入 Git，本机和部署镜像分别构建，命令见下文“Reset 与前端构建”。缺少 `dist/assets` 时后端仍提供 API，但面板不可用；升级或跨版本切换后应重建对应产物，不能按目录非空判断版本匹配。

调用详情的“调用登记时的请求材料”读取原 traces 中与当前场景、调用编号绑定的 model_call_request 记录；已有调用不回填，检索／转写等未接入此记录的调用也显示缺失。新增记录不需要表结构转换，沿原数据库备份保存。材料记录写入失败时原调用登记事务回滚，不能丢弃记录后继续传输。登记成功仍不证明已发出或被接收，须分别看调用状态与传输记录。

材料格式 v1 没有提示或工具定义版本；v2 可展开固定对话合同与核心提案、读取、工作和方法维护工具的声明修订号和当次快照。读取页和方法目录已装入 Schema 的数值限额随当次快照保留，不代表保存完整配置。页面逐项说明未留存或声明后变化，不能把名称或修订号当成完整请求。人格配置、插件动态指令、其他未接入定义及动态正文仍缺档。升级时重建同版前端；旧页面不能解释 v2，不能因显示不支持就认为记录为空。快照保存在原调用轨迹中，会增加逐调用记录体积，备份沿原范围；没有新增保留期限或自动清理任务。

排查响应慢时，从消息详情展开关联处理轨迹，分别核对初始读取、装配、逐请求、工具、提交与发布；从对应行动的结果回执核对发送排队和适配器返回。排队包含准备、校验与等待发送名额，发送计时包含尝试登记与适配器处理；缺少字段的失败、模拟或 Shadow 记录不补成零。原 event_to_delivery_ms 的起点可能是整轮最早来源，不是当前消息的独占起点，计时本身也不证明送达。

需要提供诊断材料时，在已登录面板的“活动 → 原始事件”打开具体事件，点击“读取并预览诊断材料”，核对 JSON 后下载。文件只保留固定身份、状态、用量、计时及缺档标记；不含正文、工具参数、错误原文或请求快照，详细原因仍在受控原对象中阅读。文件仍含场景和业务编号，分享前人工确认接收范围。下载采用当前预览，不重新查询或触发执行；换事件、换场景或重新读取时清除旧预览，读取失败不提供旧文件冒充新结果。

诊断接口为 `GET /api/cockpit/events/{event_id}/diagnostics?scene_id=...`，使用现有 Cookie 登录且响应 `Cache-Control: no-store`。文件包含读取起止、各类关联上限与截断标记，不承诺数据库原子快照。关联可能含同轮其他请求，不能据它分摊单条费用；字段缺失不补成成功或零用量。它不是备份、完整请求重放或匿名公开材料，下载不表示已经上传给任何平台。

排查“为什么没回”时先看具体来源的已提交处理说明和未完成项，再展开同来源的关联问题：Gate 拒绝、预算用尽、协议错误或取消以保存的类型和理由为准；不能把整轮问题当本条最终失败。已有提交后发布失败，继续核对原行动入队及结果回执，不重新提交原候选。只有发送尝试而无终态回执时保持 unknown，不点击其他路径重发来补证明。完整对应关系见[状态判读表](architecture.md#来源处理提交与送达的判读)。

调用账与工作预算页显示缓存命中及覆盖。命中率的分母仅为同时报告有效缓存数的输入 token，总计使用当前筛选的全部调用；输入量覆盖率以所有已知非负输入 token 为分母，调用覆盖率以全部匹配调用为分母。字段缺失、无法配对和输入未知次数单列；零分母显示无法计算。压缩、维护与子调用继续按原工作身份及用途计入，不混成供应商费用，也不为补统计发起新请求。

OneBot 显式选择主动／反向 WebSocket 与发送通道，保存后需正常重启生效。插件参数保存按描述符声明原位应用或正常停用、重载该插件；保存失败与运行应用失败分别显示，代码更新仍需停机重启。HTTP 检查只检查当前正在使用的接口，不证明尚未生效的新连接可用。模型能力检查由运营主动发起，会产生真实模型请求，浏览或刷新页面不会。

插件运行应用失败时，页面保留错误并重新读取当前状态；若根文件已经保存，详情明确显示保存开关与当前启用状态。排除原因后可“重新启用”，也可“停用”已保存为启用但运行失败的插件。不要把保存成功当成采集、模型或发送已经恢复。

配置冲突返回具体字段并保留草稿；刷新不会悄悄把旧草稿变成新基线。先核对最新保存值，再明确选择保留改动或采用现值。调用方须遵守 baseline/values 合同，插件另带公开配置基线或原启用值。

本群设置和插件参数的冲突条会显示重读时间。尚未取得冲突后的保存值时，两个选择按钮均不可用，使用“重读保存值”先核对；失败原文保留，不以之前的样本继续提交。“保留我的改动”只保留自己编辑过的字段，其余采用现值，列表按整组处理；JSON 对象不因空格／换行不同而整段覆盖。若对方切换了互斥后端，而本页仍有原分支改动，保留后先核对明确显示的后端，再保存。选择本身不保存、不重启、不重新装载；“采用现值”须确认放弃已有草稿。

系统设置与人格页也提供此处理入口，冲突按标签分别保留并标注“待处理冲突”。返回标签会重新读取，可展开“查看本次读取的保存值”核对；未取得快照时不能选择，取得后也不会自动套用。选择只处理当前标签，其他标签未保存的修改保持原样。运行参数的 JSON 须先修正到可解析对象，非法额度字段须先修正；不能为完成合并而补默认数值。

处理能力授予冲突时，白名单与授予列表分别判断是否实际改变。保留授予改动会使用刚读到的同一 ID 的 revision，再由保存端重新核对。若提示旧 ID 已不在当前列表，可从草稿移除该项或采用现值；要重新授予，须明确点击添加，不把被删除的旧 ID 自动改成新项。并发上限 0 会保留为待校验的 0，不等于留空；有效期 0 是具体日期，格式错误或超出日期控件范围会明确说明，未编辑的原到期值不被改成长期有效。

模型页的供应商、职责、检索和每份常用目录各自处理冲突。在对应弹窗或卡片展开本次保存值，明确选择保留实际改动或采用现值，再另外保存；对照不含输入中的新密钥。新增供应商重名时不能直接保留新建草稿覆盖旧接口，应改名或采用现值后重新编辑。已观察到原供应商删除时，旧编辑不能恢复它；删除本身若冲突，先重读，再回到该供应商另行确认删除。

切换职责绑定的供应商或模型会清空旧推理强度与视觉确认；切换检索绑定会清空旧维度和协议，须按实际接口重新填写。并发换绑与参数编辑冲突时，先采用现值或明确选择整项绑定，不能把旧参数接到新模型。检索只填一半、维度为 0 或非法值会阻止保存，不再被解释为关闭或留空。目录来源改变或供应商消失时，未保存选择仍可核对但不能继续提交；取消旧选择后，才可明确获取新接口目录。普通刷新只读本地保存／运行配置和额度账，不发起目录请求或能力检查。

凭据按 Schema 路径保存：留空保持、非空替换、显式清除才删除；OneBot 令牌使用 keep/replace/clear。替换和清除要匹配 credential_revision，冲突后保留草稿并核对最新修订，不能用占位值覆盖真实秘密。人格/样例/参与/睡眠在 Agent 入口编辑；模型页分开显示保存路由和运行绑定，不用重复购买能力检查代替配置核对。

### 面板读取与保存结果

总览各列表、能力状态、模型额度账和人工样例分别标示读取结果。一处读取失败不代表其他列表为空；刷新失败时旧内容只代表所示采样时间。“已记录失败请求”不等于当前故障，可选插件未配置／未启用也不要求全部开启。延期交付的未知回执从对应列表核对，不在普通提醒里寻找。能力页选择群和账号只预览授予；成员列表没有该账号时不自动替换，也不据此证明真实发起者。

设置保存中切换标签或离页，只停止界面跟踪，不撤销服务器已接受的操作；回到原配置正常刷新核对后再提交。页面不会把旧操作的成功反馈写到后来打开的标签。普通设置的未保存草稿在同页标签间保留，关闭页面后不持久保存；模型／样例弹窗切换标签会先确认放弃。退出登录清空共享样本和临时浏览位置，不取消工作或发送。

连接页的当前状态说明使用运行连接投影，下方表单是已保存配置，两者可能不同。时间／订阅对象页显示的重启提示来自系统全局标记，不证明某个插件已经按新值采集；仍到对应插件或运行记录核对。配置冲突对照区不会展示输入中的新令牌。

看到“已保存，尚未读回保存值”时，配置已经取得写入确认，但当前表单还没有新的基线。先使用刷新或弹窗内“重新读取保存值”，不要重复提交，尤其不要再次提交替换令牌。读回成功才更新基线；未取得确认的网络／JSON 错误不能按保存失败重试，也不因状态码为 409 就认定未保存。普通配置冲突仍保留原草稿，刷新不自动改基线；模型弹窗也须明确选择冲突处理，或确认放弃后重新编辑当前值。保存和运行应用不同，仍须按重启提示操作。

人格与人工样例列表独立加载。模板批量新增样例遇到首个失败即停止后续项；离页也停止尚未提交的后续项，已提交项仍可能完成。返回后先刷新已保存列表，核对逐项结果，再决定是否继续，不直接重复添加整批。样例图片只从所选样例范围的运营素材中选取，重新筛选期间不保留可误选的旧列表；没有读取成功不能显示“没有素材”。

### 执行预算、恢复与 Gateway

`workspace` 与旧配置 ID `python_workspace` 指向同一实现，不应同时启用。共享后端采用唯一启用项；都停用时，只能有一份已配置项用于读取连接信息。多份停用配置不自动取第一项。能力卡显示已保存的配置来源和后端，不替代实际装载、群级开关或部署核对；媒体始终需要 Gateway，浏览器无共享 Gateway 时才保留原本机试用入口。

修改共享 Gateway 或切换配置 ID 后，原浏览器／媒体实例拒绝借用新后端。按原流程结束工作并确认资源，再在面板保存浏览器／媒体自身参数，使其按 restart_plugin 重新装载；只刷新页面或只切换启用按钮不等于重建实例。不要为重新装载改域名、权限或人工资料。submission_refused 表示本地登记后、网络提交前拒绝，保留该执行日志，不据此寻找不存在的上游成功回执；已发送或未知执行不重放。

运行参数页分别显示已保存配置和当前进程发布值，EXECUTION_BUDGET_FIELDS 包含对话次数、工具次数、对话窗口、工作次数、工作工具次数、工作时长和维护工具次数。热更新会同步 EventStore.budget_config，新工作预占读取已发布值；已有工作的执行段与恢复仍使用创建时写入的快照。已有模型绑定不会因保存默认路由而改变。

实际次数与时限以根配置及当前发布值为准，样例不参与运行合并。有限调用上限包含失败尝试，终结占模型步骤但不占普通工具次数。单次超时、上下文、输出和并发另有配置，不随调用次数一起放大。次数可填 null；次数与单工作 token 上限同时为空且未设日额度时，该工作没有 token 维度，由期限和消息上限结束。若只设有限日额度却算不出单工作预占，创建会拒绝。历史维护的模型次数仍必填。

工作首次开始时写入绝对期限，排队不计时，之后的等待和停机都计入。没有该字段的旧工作仍按累计活动时长换算。对话恢复沿用已存窗口，循环受剩余期限包围。继续工作保留累计次数、资料、原模型绑定和创建时的累计上限；没有存档上限的旧已结算行不能自动恢复。恢复前核对工作记录和完整调用账，不能为重送完整结果而恢复分析。

workspace 插件在根配置 `plugins.workspace.config` 里二选一：`worker`（LenBot 调宿主容器运行时）或 `gateway`（独立 Worker Gateway）。必须恰好一个非 null，网关失败不会回落宿主执行。样例保持 worker 且 `gateway: null`。把真实根配置改成 gateway、部署网关服务与镜像，才是生产切换。macOS 开发配方见 [deploy/dev](../deploy/dev/README.md)：Gateway 容器里的工作卷路径必须与宿主 Docker 看到的路径相同，否则 `run_python` 会报找不到 `/lenbot-control/task.py`。

选用 gateway 时，根配置只保存客户端字段，容器运行时不在 LenBot 进程里：

| 根配置字段 | 含义 |
|---|---|
| `base_url` | 网关 HTTP 地址 |
| `token` | 服务间认证密钥，至少 16 字符，不交给执行容器 |
| `image_ref` / `network_policy` | 网关部署配置里已有的引用名，不是镜像或 Docker 参数 |
| `network_python_enabled` | 默认 false；明确开启后仍需公共研究来源、当前授权与逐动作审查 |
| `request_timeout_seconds` | 单次 HTTP 超时，默认 30 |
| `execution_timeout_seconds` | 单次执行期限，实际提交时不超过该工作剩余期限，默认 30 |
| `poll_interval_seconds` | 查询终态间隔，默认 1 |

网关进程使用自己的 JSON 配置（`--config`），含 listen 地址、同一份 token、`database_path`、`workspaces_root`、容器运行时路径，以及 `images` / `network_policies` 引用表。该文件不进 Git，也不从根配置合并。启动：

```sh
uv run python -m len_bot.services.worker_gateway --config /绝对路径/gateway.config.json
```

`image_ref` 与 `network_policy` 必须能在网关自己的表里解析，否则请求被拒绝而不是换成默认镜像。`mode` 只有 `none` 和 `proxy`；`proxy` 须已核验部署、代理在跑且宿主授权联网，否则拒绝，不会改成离线跑完。Linux 部署需让 Gateway 把控制目录组拥有者设为 worker GID。停机后备份还要包含网关库、工作卷与出口记录。

出口网络由运营者在目标 Linux 上部署，样例 `gateway.config.example.json` 只供人工初始化，不参与运行合并。以下命令仅在确认子网无冲突且获准部署时使用：

```sh
docker network create --internal --subnet 172.31.9.0/24 lenbot-egress
```

`--internal` 让 worker 没有默认外网路由。网关进程跑在宿主上，出口代理监听该网桥地址（常见为 `172.31.9.1:8799`），worker 只加入 `lenbot-egress`，`HTTP_PROXY` 指向该地址。核对后再把对应策略的 `deployment_verified` 改为 true。未核验前不要改真实根配置。worker 不得加入 LenBot/OneBot 所在控制网络，也不能用 `host`/`bridge`/`none` 当 proxy 网络名。环境变量代理不是限制：实际隔离看网络与代理。

执行输入由宿主导出，网关只落盘。各层上限针对不同事实，不是同一数字再写一遍：

| 上限 | 针对 | 超限 |
|---|---|---|
| 观察+附件合计 8 份 | 一次 `run_python` 导入条目 | 拒绝该次调用，不截断后继续 |
| 导出合计 24 MB | 宿主导出的真实字节 | 同上；不删原始资料 |
| 网关 `input_files` 字段 | 线上传输的文本/base64 | 协议拒绝，不落半成品 |
| 工作目录字节/文件数 | 执行中的可写产物 | 停止并标记超限，保留已有文件 |
| Pillow 可解码 | 导入图片的内容 | 按内容拒绝，不把非图片当附件 |

图片附件必须是本工作来源已登记媒体，且媒体能力已启用。目标镜像需包含 Pillow。`manifest.json` 是输入事实，不授予网络、发送或跨群访问。控制目录按 worker GID 只读。

“工作 → 执行记录”可展开原执行的输入来源、失败说明、停止回执和本地事件。该入口只读取宿主数据库，不联系网关；读取时间和事件序号不代表实时容器状态。输入清单不返回脚本、正文或媒体字节，可沿原 R／媒体／事件链接核对。旧清单缺版本显示未记录，格式或身份不符显示无法投影，只有明确空 inputs 才显示零导入；导出不证明容器已经执行。

“进度与资料 → Python 工作空间产物”区分 Gateway 的已确认 Python 快照与宿主 worker 的当前目录。同工作浏览器或媒体执行不替代 Python 快照；目录刷新不会运行脚本。Gateway 的后续文本页和下载保持原 execution_id；宿主没有不可变执行快照，逐页查看不拼接，后续运行可能改变文件。指定错误执行、停止未确认或读取被拒绝时按页面原错误核对，不切到其他文件或重复执行。

工作进展冷却由 runtime.job_progress_interval_seconds 决定，正常等待回应的存续时间由 runtime.open_loop_ttl_seconds 决定。原话和工具资料共用现有字符页参数；消息检索、原文邻居、待处理目录、工具发现、摘要／发送事实候选与媒体检索的条数也从 runtime 读取。Schema 展示与实际查询使用同一组值，越界请求明确失败；具体参数和分页坐标见[架构](architecture.md)。

### 方法版本公开

在“方法技能”详情核对正文、来源与版本后，点击“公开 vN”；确认窗口固定显示方法 ID、来源场景和版本。仅当前版本可提交，后来出现的新版本不会替换确认对象。公开只改变这一版本的可见范围，不运行方法、不直接发群，也不扩大所引原话和工具资料的读取权限。

公开回执在当前详情内显示，不与原详情采样混为一谈。“已公开，保存值待读回”表示写入已经完成，使用“重读原版本”，不能再次公开来修复读取。网络／响应异常或回执身份不符时显示结果未知，当前详情停止再次提交；刷新只读取原版本，既不取消旧请求，也不把当前范围追认成旧请求的结果。切换或关闭页面后应回原版本核对，不依赖离页撤销。

前后端须同版：公开成功仍返回 success 与 skill，但 skill 固定为本次指定版本，不再返回恰好更新的最新版本；409 使用 skill_published 和原对象身份区分事务明确拒绝与已公开后读回失败。没有数据迁移或历史回填；单独一条公开请求事件不是完成回执。

### 场景、授予与额度策略

从“群聊”进入唯一工作台，在同群的对话、记忆、工作、设置间切换。目录支持名称/号码、群聊/私聊和已保存状态筛选；旧 `/groups` 书签仍能进入对应目录或设置。注意力、摘要、参与者、互动偏好与发送记录在“更多诊断”，原深链接继续可用。

点击消息、工作、认识或能力记录后，可用“返回群聊原位置”回到来源筛选与定位。当前页面内存最多保留八个离开位置：消息页保存已加载窗口与原分页截点，旧采样时间仍保留；目录、记忆、工作和诊断子页保存位置、参与者筛选与展开项，返回仍重新读取业务记录。原项不在本次页面时提示核对，不把旧位置套到另一条记录。设置页只恢复读取后的滚动，不保存草稿。

读取期间主动滚动、点击或按键会取消迟到的滚动恢复。刷新消息只提示新内容，不强迫跳到末尾。退出登录清空这些临时位置，硬刷新或关页后仅按 URL 定位；未写入 URL 的筛选、展开项和旧窗口不能由此恢复。实际宽窄屏和键盘体验仍待人工核对，见[当前任务](iteration.md)。历史摘要重试离页后停止界面跟踪，服务器可能继续原维护，应回到该区间正常刷新，而不是据此重复提交。

本群设置区分未保存草稿、已保存规则与“当前运行、能力缺项与最近结果”。折叠事实来自独立只读请求；选择实际发起者后才能进一步核对其资格。“工作插件已开启”不表示部署、授权或上传均可用。“保存本群设置”仍一次提交原基线合同，不自动重启、执行工具或发送；离开未保存编辑继续要求确认。目录不再提供另一套批量即时模式保存按钮。

能力分类内同一插件只保留一个编辑入口；未列入固定卡片的外部插件在“其他已声明插件”中，仍按原群 Schema 填写。缺全局配置可进入对应插件详情，返回原群继续编辑；添加按钮只加入本群草稿。保存缺字段时点击错误列表可展开并定位该插件参数。全局缺参数不妨碍停用本群已有启用项，不能借停用再自动启用。未改变文件申请者时保存其他群规则不提交授予变更，首次填写群规则也不会默认清空已有申请者；恢复旁听继承仅取消本群覆盖，不修改全局。

“媒体与素材”按登记类型展示消息媒体、工具产物及运营图片；音视频列表只显示类型，打开详情后手动播放，不自动播放或转码。消息及引用内的媒体采用相同预览。预览不增加模型阅读范围，非运营媒体只读；取得失败保持原来源，不从浏览器错误推断链接过期。上传入口仍只收 PNG/JPEG/WEBP/GIF，字节上限取列表响应中的运行配置，不固定为 10 MB，也不直接发群。

素材用途可筛选反应表情、人物参考和一般媒体，不改变场景范围。人物常服上传时使用“人物参考”标签；在详情将固定目录顺序留空，保存后选择“加入人物参考草稿”。页面上方“人物与服装参考”填写人物键和服装，再单独保存绑定；也可填写已有资产 ID。人格页只链接到这一入口，文字人格与参考图片各有唯一保存位置。人物键使用小写字母开头的字母／数字／短横线／下划线，最长 32；服装名去首尾空白后 1—80 字；最多 40 项，不接受重复人物与服装组合或重复资产。

绑定属于根配置，但不会扩大素材作用域：本群图只提供给本群，global-safe 才可跨场景。保存前核对运营图、启用状态、人物参考标签及空目录顺序；已绑定图可停用，去掉人物参考用途前先解除绑定。停用项保留在配置列表并显示具体原因，后续模型目录不提供它；媒体总开关关闭时也不提供目录。页上预览、配置保存与实际模型读取分别记录。

绑定草稿在同页筛选或打开素材详情时保留，收起卡片不清空；保存发生冲突先重读，再明确保留整份绑定列表或采用现值，最后另行保存。保存成功须读回基线，读回失败暂停再次提交；请求结果未知时保留提交值，读当前值不追认旧请求成功，也不直接重发。采用当前值重新编辑须人工确认。配置接口为已登录的 `GET/POST /api/settings/character-references`；POST 沿 ConfigEdit，只提交 character_reference_assets，不改其他人格或额度。

固定表情目录独立加载，错误不显示成空目录，读取时间与实际配置限额单列。顺序可填非负整数或留空，不限为 1—20；“当前目录限额内”不是某轮已装配证明。媒体详情保留原列表范围及采样时间，同对象刷新失败保留旧内容与表单；切换对象后不采用旧保存响应。离开上传页面只停止采用旧响应，不证明服务器取消；结果未确认时回原范围刷新，不能用重复上传替代核对。

刷新素材详情不再要求先丢弃未保存草稿。描述、标签、启用和目录顺序按原值保存，未编辑字段不覆盖别人的修改；发生冲突时先重读并展开当前值，再选择保留实际改动或采用现值，最后另行保存。公共素材的启用／目录变更会影响所有场景，确认窗口显示真实保存范围。前后端须同版更新：`POST /api/media/{id}` 及原服务编辑入口要求 baseline，旧请求不由后台补造基线。

上传成功后先显示已登记的 asset_id 和范围，可明确进入详情或登记另一张图片；这不是平台群文件／消息送达回执。若显示“已入库，但事件登记／保存值读取失败”，使用返回的原素材与事件身份核对，不重复上传来修复后续阶段。编辑已有素材遇到此状态，先读回再继续；能读到保存值不证明原事件阶段已恢复。HTTP／JSON 或网络结果未知时，当前上传表单停止再发，可确认关闭后查看原范围素材列表；没有已确认 asset_id 时不能只因列表相似就认定本次成功。

“已入库”响应若不属于本次范围／素材，或缺少应有的事件与阶段信息，仍显示本次结果未知，不开放重传。已有素材的编辑请求未知时也暂停保存：保留原值与提交草稿，通过“读取当前保存值”核对；当前值不是原请求回执。需要继续编辑时须明确“放弃旧草稿，采用当前值重新编辑”，不把旧草稿自动套到新读取值，不由这次选择取消或重发旧请求。

全局暂停实发使用 Shadow；停用一个群则关闭“本群设置”的启用字段。聊天群/播报群快捷操作只填写实际字段，不保存另一份 mode。QQ 回复白名单只在系统设置维护，不强制每条回复，也不授予运营权限。恢复配置只修改运营明确选定的值，不从文档复制群号。

能力授予保存主体、范围、能力、有效期、策略引用和 enabled。面板只提交可编辑字段，签发者由当前登录账号在认证后写入；只改白名单不重新签发授予。主体类型切换时丢掉不适用范围。到期控件按本机时区支持秒精度，未改时保留原始 epoch 的更细精度；版本冲突保留草稿。非人类 create/revise/resume 与执行期都核对当前授予，撤销后下一次执行应被拒绝。

“额度策略”按名称保存单工作、账号日和可选场景日上限。账务日按 time.timezone，未配置则按 UTC；创建准入的账号日账跨群聚合。留空策略不再套用 10M/30M，各维度为不设上限；根文件里写出的数字才是限制。授予引用失效的策略名称会拒绝。保存 resources 会重新应用预算配置；已有工作按自己的快照执行，结束后恢复也使用原上限，不会按新默认策略补造。

创建期预占与工作行原子提交，失败会回滚创建。业务结果完成时，若还有技能候选则保持原预占直至维护请求结束；取消在仍有在途调用时不先释放。模型页账户合计按全日聚合，明细最多 100 条；账户全天只在同一具名策略下运行时按该策略显示日上限与余量，混用多个策略时说明需要选定范围，无具名策略按默认策略说明并把用过的策略引用名单独列出。不能单独批准追加额度。费用核对查看完整 model_calls，区分真实 usage、估算和未确认。

工作详情的“预算与压缩”先显示本工作原次数、期限、token 和上下文快照，再折叠当前默认值。缺字段为未记录，不等于不设限；有绝对期限时不能用累计活动时长推算余量。下方调用账按同一 job_id 全部版本分页，汇总包含压缩、方法整理及子调用，保留 usage 未完整记录数；不要用关系页最多 50 条记录算总费用。公共研究会标“无需群交付”，实际逐群分享另查发布行动，不把工作 completed 当送达。

核对方法时，从候选打开其实际保存的版本，再回到来源工作、纠正原话和保存时的阅读区间。旧方法没有区间快照时保持未记录。工作详情另分固定版本、已保存正文与实际提供范围；候选、已保存和正确复用不是同一状态。打开方法详情仍保留原列表范围，刷新失败显示旧采样时间。工作产物按目录的执行快照读取、续页和下载；切换工作后不合并旧响应，快照变化需重新选择，不重新执行来补页面内容。

已记录的候选不自动补发，unknown 不重试或更换通道。按每个 checkpoint 查看提交、行动和真实回执，后阶段失败不抹掉前阶段事实。等待页的“待核对”表示旧挂起请求跨越进程重启，可按实际情况处置，不自动取得新预算或重发。

提醒在执行未结束时重启会进入“待核对”（review_required），旧到期事件不恢复发送资格。按当前需要在面板取消或重新安排；群内也可由明确的人类请求调用原提醒控制。模型看到该提醒仍需保留未完成事实，不能把它与新的独立工作一起当成已到期交付。已提交发送但没有确定回执的提醒保留未知状态，不按待核对提醒重发。

人格页点击“查看嘉然模板”，选择需要的字段并填入人格草稿；关闭预览后使用“保存人格”。表达样例另行勾选并逐条新增，每条分别显示成功或错误；缺少图片引用的样例须先补充对应素材。模板不会自动识别或替换旧默认值，不停用已有人工样例。人格文件与人工样例分属配置和数据库两个保存动作，界面分别显示结果。角色原始资料与表情索引保留在[persona](persona/diana/README.md)。

## 停机、备份与结构切换

图片对象关联版本在现有 events 表增加两个定向索引：idx_events_scene_message_id、idx_events_scene_reply_id，不改原事件或业务身份，也不新建纠正数据。按正常停机、备份和获准启动流程，由原初始化入口建立索引；首次建立的时间与文件增长须按实际记录观察。本路径使用 SQLite 的 MATERIALIZED CTE，需要 3.35 及以上版本，继续要求原 JSON／FTS 能力；版本读取不是业务查询验收。索引不重编号历史，不赋予素材可用或像素已读资格。

正常出现带图引用或人物纠正时，核对同版 Trace 中 context_plan.image_discussion 的原事件、图片资产、实际关系与 limited，再结合原请求装配清单、已读范围和媒体 manifest 看哪些材料真正提供。查找耗时单列 image_related_source_reads，属于初始关联读取的组成部分，不与外层总计时相加。只看到目录或锚点不等于已经记住；只看到道歉也不证明后续采用。重新上传取得新 asset_id 的图片不自动匹配旧对象；无明确引用的纠正仍依赖当前原话语境，不补造永久人物关系。

阅读与调用诊断修复不新增 SQLite 表／列，不需要业务数据转换。正常升级仍先停机并按下列步骤备份，前后端保持同版；不通过重启重放未知工作或发送。新模型调用的传输信息在原 traces 表中，以 kind=model_call_transport、ref_id=原 call_id 查询，也由调用详情返回 transport。attempts 表示客户端发送尝试，其 requests 包含重定向等实际请求阶段；started 只说明尝试开始，headers_received 不等于正文完整或上游只处理一次。缺少诊断保持未记录，不能以一条 model_calls 推断只有一次上游处理或费用。

模型调用分页查询同样返回已关联的 transport，不再仅在详情查询中读取。其他关系简表若没有 transport 字段，表示未在该投影加载，请打开原调用详情；明确查询后的 null 才表示没有保存诊断。尝试数量不参与原 usage 汇总，重定向条目也不变成新的逻辑调用。

分析慢响应时，先查看原 Trace 的初始资料读取、上下文装配、逐步请求准备、工具呈现和提交／发布耗时，再关联模型调用与原发送回执的 queue_ms/send_ms。装配和准备阶段包含自身等待，部分计时嵌套；不要相加或据此给出未经实际观察的加速倍数。前缀正文比较仍须另获授权使用现有短时诊断，不默认长期保存群聊全文、图片或凭据。

新记录可继续查看 context_plan.event_packing_detail 的 phases 和 media：先区分文字投影、容量估算、可选释放和媒体准备，再区分资产查询与源文件准备。候选／接受计数包含试装阶段，不代替最终阅读清单；source_prepare_ms 含等待和解码，不能直接称为磁盘或 CPU 耗时。上下层计时不相加，旧记录缺少细分就保留未知，不回填。prepared_reuses 是本次准备复用次数，不是模型缓存命中率；asset_unavailable 表示本次自动装配时资产已不可读，沿原素材状态核对，不以旧准备结果补像素。字段定义见[上下文诊断](context.md#7-缓存与诊断边界)。

答复依据改造不新增 SQLite 表/列或运行参数：旧消息缺少 `answer_basis` 仍可读取，新提交/行动在原 JSON 中保存该可选字段及已确认阅读关联。字段存在不证明答复正确、已发送或已部署。旧版本的严格 MessageProposal/ActionItem 可能拒绝新字段（含 null）；写入新记录后不能宣称直接切旧版本兼容。回退先停相关入场并保存新事件、费用与回执，再确定具体旧版本的只读兼容方案，不能删依据或恢复旧全库消掉新业务事实。

页引用版本将公开 answer_basis.result_spans 改为 evidence_refs，普通工作 finish_work 也使用 evidence_refs；内部消息和 JobResult 仍保存原坐标。工作实际已读记录在原 observation_reads JSON 内追加页名与范围映射，不新增表或执行数据库结构转换。升级须整体采用同版定义与消费者，先处理在途执行并停机备份，不把旧待提交参数自动翻译成新引用。旧工作仅有 ranges 而没有页名时，读取需要的原资料页以取得当前引用；不能根据目录或正文总长伪造已读页。

1. 前台进程使用 Ctrl+C；后台部署向当前明确的主进程发送 SIGTERM。等待认知、维护、工作、投递和 OneBot 正常退出，再确认该实例的监听和数据库句柄已关闭；已有容器的终止结局另行核对，进程退出不代表未知容器已停止。
2. 在新的备份目录保存当前代码提交或源码归档、实际根配置、指定 SQLite 数据库及其完整媒体目录。若 workspace 已改选 gateway，同批保存网关自己的配置文件、`database_path` 指向的日志库和 `workspaces_root`。数据库使用 SQLite 的普通备份，媒体普通复制；不生成文件指纹或哈希清单。
3. 只对已确认的当前结构执行本次必要的离线转换。旧结构由对应旧版本处理，不在启动时猜测补列、补 JSON 或自动 Reset。
4. 获得当次启动授权后，使用匹配的代码、根配置与当前结构启动，按约定人工查看数据和操作。未完成转换或发生错误时保持停机，查看具体错误并决定是否恢复同批备份。

停止后的普通数据库与媒体备份示例，路径由本次部署填写：

```sh
sqlite3 /绝对路径/len_bot.db '.backup /绝对备份目录/len_bot.db'
cp -R /绝对路径/media /绝对备份目录/media
cp /项目根目录/lenbot.config.json /绝对备份目录/lenbot.config.json
# 若已改选 gateway，另备份网关 --config 文件、database_path 与 workspaces_root
```

媒体目录位于数据库同目录的 `media`；使用持久文件时同批备份 `file_assets/`，使用本地插件数据时备份 `plugins/`。保留资产 ID、原路径、来源和权限，不重新下载、批量编号或改写历史事件；运行数据不移入插件代码包。

运行目录是本机运维位置，**不在仓库内也不进 Git**：日志、`.backups/` 和现场记录都放在本机运维目录。`.backups/` 里的根配置副本含真实凭据，需要人工清理，不能把仓库当作这些文件的备份。

### 更新当前实例

更新前记录实际代码版本、数据库结构、根配置及未结束调用/工作，按上文停机备份后再更新同批代码、文档与前端产物。备份整个库，包含预占、调用、执行/命令、兴趣、平台动作和文件资产身份；独立 Gateway 的日志库、产物与工作卷另行保存，不只备份消息表。

**仅从仍含旧观察键的版本升级时，执行离线配置转换。** `attention_sample_probability` / `attention_sample_window_seconds` 已由 `attention_observation_enabled` / `attention_observation_interval_seconds` 取代，`scenes[group].attention` 下的旧键对应改为 `observation_enabled` / `observation_interval_seconds`。`RuntimeConfig` 的 `extra='forbid'` 会拒绝旧键。已使用新结构的实例无需因文档更新再迁移；确需转换时，停机备份后在项目根目录执行：

```sh
uv run python scripts/migrate_observation_config.py          # 只报告将改动的字段并按新结构校验
uv run python scripts/migrate_observation_config.py --write  # 确认无误后写回 lenbot.config.json
```

脚本只改这些键（概率 >0 转成 `true`，=0 转成 `false`，窗口秒数原值保留），顺带删除上一轮已退役的 `attention_engagement_step` / `attention_engagement_recovery_seconds`；其他配置值原样保留，不打印任何配置内容或凭据，转换后再按新 schema 校验一次，校验失败即不写入。新增的 `addressed_debounce_idle_ms` / `addressed_debounce_max_ms` / `observing_debounce_idle_ms` / `observing_debounce_max_ms` 有默认值，旧配置不必手工补；默认值是首轮调参起点，不是已验证的最优值，也不是回复延迟承诺。转换动作记入本次升级记录。

旧配置中的插件列表、群顶层业务字段与当前描述符结构不兼容时，先按其实际版本核对并离线转换。这需要辨认旧结构时，用 Git 提交 `d1fd37e` 的 `docs/archive/operations-before-doc-cleanup.md` 对照，不是所有版本通用的升级命令。不得从样例补生产模型、人格、Shadow 或群名单；新增本地插件用法见 [业务时钟](../local_plugins/local_clock/README.md)。

旧工作缺独立来源、绑定、原额度或首次开始时间时保留原记录，不用当前默认值补造可恢复预算或身份。新增结构与旧记录处置按[完整改造计划](LenBot_群聊体验与可靠执行_完整改造计划_20260920.md)第 8、10 节逐批说明；未结束容器和在途模型请求另行核对。

方法来源改动不新增表或离线转换。旧已保存方法不改写；旧 pending 候选若没有实际提供记录、有效来源或只引用模型投影，在维护调用前明确失败并保留原因，不补造区间、不自动重查。仅纠正的新候选允许空 result_ids，旧版本的严格类型不接受这类记录；回退前须核对现存候选，不能仅凭无结构迁移宣称旧代码可直接继续维护。

回退先停止新能力入场，确认原执行资源和发送状态，再选择能读取现存数据的代码/配置。上线后若已收到新消息或产生新回执，不能直接恢复旧数据库丢弃它们；旧代码不理解新结构时先设计明确的离线兼容处理。只有能够确认没有丢失后续事实的恢复，才可使用对应同批备份；不能将数据库回退当作撤销真实发送的方法。后端替换没有自动 fallback，未授权切换时保持当前真实运行配置不动。

取得当次启动授权后，使用匹配的代码、配置和当前数据启动。备份、转换、启动和实际核对分别记录在 [当前任务](iteration.md)。

## 插件接口世代升级

当前描述符必须声明整数 `api_version=1`，与插件自身 `version` 分开。发现目录中的任何包缺少声明或世代不匹配都会终止发现，停用插件也不能跳过；这是配置解析前的明确错误，不是启用后才出现的运行状态。目录导入先于世代判定，继续只装载可信代码。

1. 升级前处理在途执行，按上节停机并备份；保存部署版本和外部插件代码版本。
2. 同批升级宿主、内置插件与前端；外部插件逐个按[开发迁移说明](plugins.md#接口世代-1-与迁移)核对实际接口后补声明，不修改根配置、历史事件、工作归属或版本来绕过拒绝。本变更不涉及数据库结构转换。
3. 在另行获准的正常启动中核对发现错误及插件面板的“插件版本／接口世代”；它们不替代原配置、启用、命令、取消和送达验收。当前交付仅完成编译／构建，尚无本批启动记录。
4. 不兼容时保持停机，修正对应外部代码或整体回到先前宿主、插件与前端版本；不删目录、删配置或改业务版本来静默继续。数据恢复仍按原备份流程与当次授权，不自动重放未知行动。

## 日常查看与处置

认识或历史维护若拒绝模拟来源、非人类消息身份或未确认的 Bot 送达，先沿原事件／回执核对；不要更改 simulated、origin_mode 或补造消息 ID 来让提案通过。事件类型名不是送达证明，reported 也不代表客观核实。此版本只收紧新提交的来源资格，不自动扫描、撤销或重写旧认识、摘要和事件。

需要撤销既有错误认识时，仍通过原认识详情填写原因，或在对话中给出真实纠正；保留原记录和修订链。撤销验证本次依据和原目标，不要求把错误记录重新证明为真；若要保存替代认识，须满足新的主体、类别、原话和有效期要求。未知或模拟输出不能代替本人对称呼／偏好的明确要求。

首次开放新功能时，先确定一个聊天群和一个仅播报群、QQ 回复白名单与真实成员身份，填写业务时间和各来源参数。若该群仍有旧 AstrBot 同类日程／直播入口，在本次迁移授权内先停用旧入口，再开放 LenBot 对应插件与类别；同一功能同一群只保留一个负责人，不监听旧 Bot 或自动抢占。

插件页的全局启用与“场景消息 → 目标群 → 本群设置”中每个插件的启用和参数分别保存。全局启用后，还需在目标群加入相应插件，Agent 才能取得该群的工具：自然询问日程需要 `asoul_calendar`，动态查询需要 `asoul_dynamics`，按时段总结需要 `group_summary`。**“已保存”“全局启用”“插件加载成功”和“本群已加入该插件”是四件独立的事实**，不能把其中一件当成另一件；全局启用不会自动修改任何群的开放列表，运行日志中的“加载插件成功”也不代表本群已开放。加入插件也不自动开放精确命令或订阅公告，继续按下述字段分别保存。

日程读取根配置 `plugins.asoul_calendar.config.source_url` 指定的单一 ICS 来源，来源说明见[日程移植说明](../src/len_bot/plugins/builtin/asoul_calendar/SOURCE.md)。命令词在日程插件中映射 calendar_today、calendar_tomorrow、calendar_week，再由 `scenes.<群>.plugins.asoul_calendar.config.commands` 开放。评论日程时引用实际日程响应；要提问 Agent 或修改、取消工作时另发明确消息。无引用的“好耶”等内容不作隐藏语义分类。源返回空日程和请求失败含义不同，失败时先看源状态；不换来源或改发文字。

排查来源时对照同一配置 URL、请求身份和实际代理路径，分别记录 HTTP 状态、响应类型与解析结果。客户端不继承终端代理变量；系统 TUN 仍可能影响出口。403 或 412 本身不能确定缺 Cookie 或某种封禁；验证页 HTML 不算取得 ICS。历史成功请求记录不再作为当前依据，新的实际结果只记当前任务。

直播配置的 source_timezone 用来解释源给出的无偏移开播时间，业务时区独立保存。成员订阅选择已填写的真实主播；群聊可读当前订阅状态，添加或退订仍在登录后的“本群设置 → 哔哩哔哩直播监测”保存。其 config 中的 live_subscriptions、announcements 和 mention_all 分别定义订阅、公告与全体提及；@全体的账号条件由运营在实际群确认，不自动修权限或去掉提及重发。首次采样只建立基线，不补报当时已经开播的场次。是否实际生成、发送和送达分别看 PLUGIN_EVENT 来源、plugin_run Trace 与 action 回执。

自然询问日程、动态与已配置监测状态可直接使用短工具；当前群“今天”“昨天”、指定日期或明确区间报告由 Agent 提出工作，日期以请求原话的业务时区为准。group_summary 2.0 需要 render_font_path，本仓库可填写 `../asoul_calendar/resources/font.ttf`，复用已随源码保存的字体；只使用该字体资源，不要求日历服务启用。新增字段需停机后离线保存，运行中由插件面板保存。

启用 `link_parser` 后，可在目标群单独开放 B 站原生链接解析。纯 BV/av 链接或明确的“解析链接 URL”命令会被确定性处理；`parse_link` 默认只返回 metadata，下载媒体时必须使用同一场景已保存的解析结果引用。命中缓存但已保存字节不可读或类型不符时，cached_media_unavailable 表示本次在缓存读取边界失败，没有因此重新下载来源；不将其当作源端无视频。下载完成仍需由正常 Agent/插件提案决定是否发送，视频或音频的 unknown 回执不自动重发。

工作详情分别显示范围与快照、本工作实际已读、成功分析、复用和未完成数量；批次、JSON 和图片均可回读，结果页显示成品图片。渲染失败时先核对字体、图片限制及具体错误，再显式恢复原工作，只消费已保存 JSON；模型绑定和累计计数保留，仍需核对原绝对期限与原累计额度余量。发送失败或未知看交付行动与实际回执，不恢复分析来重发。工作已生成但等待原请求者的新话处理时仍保留 result_ready，原话处理后再核对首次交付。

查询“已有日报／历史群总结”会读取本群精确范围内已经保存的报告，不新建分析、不渲染、不直接发送。修改焦点或附加要求会按新要求重选可复用批次；不同时间范围不能仅改日期标签来复用成品。旧 1.1 的分页工作保留原始结果和回执，只读查看，不能用 2.0 的类型猜测恢复。当前不提供定时广播。动态详情仍仅指源已提供的记录，不据图片链接声称看过像素。

历史动态关键词搜索与最近动态都直接列入本群已开放的动态工具，仍由模型按请求选择。核对“搜历史动态”时查看是否实际调用 search_asoul_dynamics，以及该次筛选、正文范围和源续页；网页搜索、群消息搜索或呈现容量错误不能作为动态站无结果的证据。

插件 Trace 展示保存的插件版本、入口、触发来源、父运行与父工具调用，分别列出直接读取、Agent 步骤、钩子变化和提交阶段。沿关联记录查看实际观察、工作、调用账及行动回执；旧日程命令和开播邀请只保留历史显示，不用当前插件版本补写旧记录。

### 历史维护阻塞

- 限额、连接、超时、上游内部错误、进程重启及 pending 可由下一次维护沿原批次有限恢复，日志为 `History maintenance resuming blocked batch in <群>`；每批每进程最多自动一次，再失败会阻塞。
- 发现摘要长期不增长时查 `History maintenance blocked in <群>` 的批次、错误和范围。处理具体原因后，在群历史页显式重试；不删失败记录或用 Reset 绕过覆盖。
- 已有对话进行时，重试持有维护位等待其结束。提示“该群的历史维护正在进行”表示已有操作，不需反复点击。
- 摘要停更可能令本次窗口缺少裁剪许可，影响可复用前缀；不能据此断言所有缓存失效或具体费用。
- 摘要完成但“认识候选待核对”时，读取维护回执中的来源与版本变化，再走原认识操作。候选未被采用不是现有事实，不重试已完成摘要或强改版本采用旧候选。

## Reset 与前端构建

Reset 是独立的破坏性管理动作，需要当次明确授权。操作会先停止认知、维护、工作与投递，再清理原话、Session、摘要、自动认识和技能、任务、工作及检查点、调用账、工具资料与聊天媒体；保留登录、根配置、人工样例和运营素材及来源，追加管理记录。它不改变 Shadow、群设置或白名单。当前 reset_conversation_data 的清理表列表未包含 usage_reservations、execution_runs 和 execution_events；不能用 Reset 清理新额度/执行记录或证明外部容器已结束。在这些数据存在时需单独核对归属与处置方案，不直接删除残留行。

修改前端后，在 `src/len_bot/web/frontend` 执行：

```sh
npm ci
npm run build
```

产物位于 `src/len_bot/web/static/dist`，与同批 API 一起交付。按改动范围人工核对页面，检查方式遵循[工程约束](../AGENTS.md)。

## 心跳、睡眠与延期

heartbeat_enabled 默认 false，heartbeat_topics 默认空列表，在运行参数页保存，改后手动重启。每项主题最多 200 字、最多 20 项；种子还包含有限的当前有效公共兴趣，无种子可零研究。心跳使用 system:heartbeat 用途的系统授权与原 work 模型，必须开放 public_research、配置可用的公共工具，并留出至少两个工作位置。开关不授予网络 Python 或发布权限；每次联网脚本另需 network_python_enabled、network_python grant 和动作 allow。purpose=heartbeat/action_review 的请求均在原调用账可查，未知 usage 不当作零消费。

time.sleep_start/sleep_end 成对设置。具备聊天资格的人类叫醒时先等待本群五分钟内的自然语言确认，提问实际送达后的答复才可确认；确认后 30 分钟的直接互动续期。场景事实页显示确认来源、提问阶段、到期与清醒截止。日程确定性卡片可以睡眠期间响应，直播/普通公告和其他模型表达仍延期。

在“提醒、等待与周期 → 延期交付”查看原 action、original_due_at、delivery_phase、原请求者／回应对象与实际回执；可回到原请求、工作、提醒或文件资产。延期从普通提醒列表分开，只读展示，不提供改时间、立即触发或重发按钮，API 和提醒事务也拒绝这类修改。管理请求跨对象的迟到响应不更新新对象；离开页面不证明原请求在服务器被取消。

同批同请求的前序消息失败或未知时，后序保存拒绝回执；前序仍未尝试时继续等待原 Scheduler，无关请求不受影响。旧闲聊过期，工作成果不重跑，直播重取原场次。queued 不等于已发送；attempted 无可靠回执、旧领取不明或 Gateway 终止未确认均需人工核对，不自动重发/重开。适配器称成功但未给 message_id/file_id 时按 unknown 处理；“模拟回执”和“本槽已结束”都不是实群送达。页面核对本身不授权启动生产。

提醒内容或时间在调度认领前发生变化时，原堆条目不会带旧正文取得认领；下一次原 Scheduler 同步读取当前任务，不另设补发队列。旧来源和原事件不被覆盖。叫醒需确认提问的真实消息回执和其后的本群请求者答复；旧会话提示字段、模拟或 Shadow 不能单独通过确认。

升级继续先停机和普通备份宿主/网关数据库、根配置与产物卷；新增命令表由现有初始化入口建立，不重编号历史事件。新延期阶段明确未尝试的记录可恢复，旧 claimed/processing 缺少依据保留未知；无 provenance 的旧兴趣不会自动变成公共证据。明确 token_limit:null 的工作可按原无限维度恢复，但当前有限日额度无法预占时仍拒绝；真正缺少原上限的记录不补造。

### 配置公共兴趣分享

通过面板填写并启用 `interest_share` 全局插件，再为明确目标群填写主题、每日次数与冷却并启用该插件；在全局能力授予中向插件主体 `interest_share` 授予该群的 `interest_share` 能力。普通聊天、公共研究与发送文件各自授权，任何一个开关都不替代此 grant。不要手工修改运行中的根文件。

TasksLoops 中的“公共兴趣分享机会”只表示调度阶段；Trace 的“公共兴趣分享机会”给出候选/跳过原因，“公共兴趣表达”记录模型用量。实际是否发送以原 ActionQueue 的消息回执为准；发送尝试的 `interest_publication` 保存候选版本与公共资源 URL。未知结果不重发，也不释放当日次数；明确未发送不计入已用次数。默认每半小时一个机会，睡眠、连续消息上限、冷却、额度或无相关内容均可零发布。被小时限额挡下记为 `skipped_hourly_limit`，只跳过当前槽，仍然启用的插件照常续排下一槽；错过的分享不补发。停用插件会取消其未领取槽，重启不重新执行已领取机会。「公共兴趣分享考虑」trace 保存每次实际考虑的候选 ID、修订与结果，候选顺序按本群最近考虑时间轮换：被沉默拒绝的候选让位给其他候选，修订后重新获得机会。

### 配置媒体片段

按 [media worker 部署说明](../containers/media/README.md) 构建固定镜像，Gateway 登记 `media` 类型及已核验公共出口策略，再通过面板配置 `media_analysis` 的 `image_ref`、`network_policy`、`max_download_bytes`、`timeout_seconds`。它使用同根配置的 `workspace.gateway` 连接，不会回落到宿主解码。此插件默认未配置；运行中继续只通过面板保存。

模型配置页新增“已确认此绑定支持图片输入”，默认关闭。确认真实模型能力后才打开；已有工作保持原冻结值，不用当前配置覆盖。转写在媒体插件的 `transcription` 字段单独绑定同一供应商，默认 null，填写已核对的 model、`protocol=openai_verbose_json`、`estimated_tokens_per_second` 和 `max_text_chars`。估算只用于工作预算，不是价格。缺字幕时 Agent 可显式选择转写，也可提交部分结果；不自动猜模型或切换型号。

片段的工具资料保留 execution_id、实际帧坐标与音轨范围；运行轨迹中的 media_segment 保存回收记录，audio_transcription 保存转写调用关联，模型账的“音频片段转写”保存实际供应商 usage。失败或超时后查看原执行与清单，过期 URL 需要新的显式片段读取，不自动重跑整项工作。目标环境的镜像、流量与时间轴、取消终止和真实模型协议尚未完成运行核对，状态见当前任务。

资料页可直接查看浏览器 DOM 版本、当次正文页与完整受限正文的保存情况，以及视频采样帧、音轨、ASR 区间。DOM 偏移不是 R JSON 字符偏移；采集截断或源端续页不等于本地资料尚未展开。登记截图不表示模型已看图，转写区间也不保证每个词已识别。旧记录缺少对应字段时保留原文并显示覆盖无法投影，不补造历史已读范围。

### 持久文件资产

普通研究已有完整／部分成果而新要求只是排版或文件导出时，后续工作应引用已读原版本，使用新请求创建，不把已完成旧研究改成可恢复状态。工作详情“成果复用关系”显示固定的原摘要、未完成项与资料位置；“查看原工作当前详情”可能已经是另一个版本，须以固定输入版本区分。原工作页面只列最近 20 项已保存的后续复用关系与总数；旧工作没有该字段时不推测补齐。新工作的计费、执行、文件资产及实际交付仍独立核对，不能靠这条关系继承旧上传资格。

持久文件登记支持 TXT、MD、CSV、JSON、PDF、PNG／JPEG／WEBP／GIF 和 ZIP。独立 `.md` 使用 text/markdown，沿原 UTF-8 文本解码、字节上限及控制字符检查，不渲染或执行 Markdown／HTML，也没有增加脚本或 Office 格式。字节和展示名仍由原文件检查核对；普通本机 worker 导出的下载产物与 Gateway 持久资产登记继续是不同路径。

根配置 `runtime.file_delivery` 默认 `enabled=false`，`max_file_bytes=50000000`、`daily_group_limit=10` 可调低，`retention_seconds=604800`。运行中通过面板运行参数保存，需重启生效。授权 `send_file` 不自动启用上传后端。普通产物仍可下载；工作页另列持久资产、有效期、尝试和独立上传回执。

在工作“进度与资料”先看文件资产，再展开原执行／产物、审查、提交、尝试和回执。消息详情可直接定位指定资产，不按文件名或时间猜关联。状态“已提交，尚无尝试”不证明当前队列仍在运行；“上传结局未知”可能是已尝试无终态，也可能是回执缺真实 file_id，均不重传。旧失败不关闭另一条行动，曾上传成功也不能抹掉另一条未知；模拟和 Shadow 不算实际上传。点击“下载已保存资产”仅读取副本，不改变这些状态。

能力卡的工作空间字段来自已保存配置，平台协议／文件开关来自运行时。worker 可以生成工作产物，但 prepare_workspace_file 需要 Gateway 已确认的不可变产物；尚未选择目标群与真实申请者时，只能看平台配置，不能称上传授权已具备。登记工具等待互斥锁后会重新核对原工作，发现修订、取消或期限变化时拒绝，而不是返回旧资格下的资产。

停机备份数据库和数据库同级 `file_assets/`，保留文件权限。资产采用宿主生成身份，目录 0750、文件 0440；待发送和 unknown 文件不因工作结束或有效期到达而自动删除，有效期仅阻止新上传。首版保留所有登记资产供运营核对后按现有备份/留存流程处理。跨群、工作修订变化、权限撤销和超限均拒绝上传；不能把面板下载当成已发群。

### 配置 OneBot 文件上传

面板运行参数新增 `onebot_file_upload`（默认 null）。当前支持配置示意如下，版本必须替换为现场值，核对前保留 false：

```json
{"implementation":"napcat","version":"填写实际版本","protocol":"upload_group_file_data_file_id","deployment_verified":false,"export_mount_path":"/lenbot-files"}
```

SnowLuma 现场示例（版本换成实际值）：

```json
{"implementation":"snowluma","version":"填写实际版本","protocol":"upload_group_file","deployment_verified":false,"export_mount_path":"/lenbot-files"}
```

连接页的「读取平台实现与版本」按当前发送传输只读调用 `get_version_info`，返回现场 app_name、app_version、protocol_version，并与已声明的 `onebot_file_upload` 对照实现名与版本。该按钮不发送任何群消息，也不改配置：填 `deployment_verified` 前先用它核对现场版本，不要用发布目录反推现场。

只将数据库同级 `file_assets/` 只读挂入 OneBot 的 `/lenbot-files`，不得共享完整工作区、控制目录、配置或数据库。宿主运行账号应能创建资产，OneBot 账号通过部署文件组获得 0750/0440 读取权限；核对挂载确实只读。`deployment_verified` 只表示版本与挂载已人工核对，不要求先有成功上传；授权后的第一次正常文件操作才产生真实 `data.file_id`。现有 HTTP/WS 连接模式不变。不要把一种实现填成另一种，也不自动改协议。

生产开启须同时具备 `file_delivery.enabled`、当前用户与群的 `send_file`、资产审查以及已核对协议。unknown 保留原尝试、资产及额度供现场核对，不提供再次发送按钮或强制标成功；面板下载仍可用。

### B 站账号配置与动态读取

`bilibili_content` 的 `account_uid` 默认 null，`authenticated_read_enabled` 默认 false。即使旧配置有 SESSDATA，也不自动开放登录资料；须保存 UID/开关，并为人类请求者和群独立授予登录读取能力。SESSDATA/bili_jct 只在原根配置，面板仅显示设置状态。根配置须 0600，备份同级保护；权限不符时 connector 拒绝，先停机再修改。账号配置变化后重载插件，运行调用不能继续借用旧配置。

首次请求会读取 nav 核对实际 UID；未登录、身份不符、重定向、超出 2MB、格式变化和平台错误码明确失败，不自动登录或修参数。账号错误记录只保留阶段和错误码，不记录 Cookie 或上游原始响应。

### 专用账号写入开通与未知状态

`bilibili_content` 的 `daily_like_limit`、`daily_favorite_limit` 默认 0；`allowed_collection_ids` 默认空。运营停机配置真实账号 UID、SESSDATA、bili_jct，并为点赞提供文档要求的真实 buvid3；保持根配置和备份 0600。仅在根配置 access 中分别授权 bilibili_like/bilibili_favorite 后，当前人类工作才可发现对应提案。额度按账号和能力聚合，不能靠切群或换请求者绕开；一天以 time.timezone 为准。未取得现场账号与协议证据前保持关闭。

工作页平台动作显示 confirmed/not_sent/rejected/unknown、账号、资源、收藏夹、期望状态、修订、尝试时间和原因。unknown 保留额度；原调用不重试，下一次新提案先通过相应窄状态接口核对。点赞状态 0 不证明取消成功，不能据此解除占用；相反状态也不证明原请求未执行。没有“强制成功”或自动重试按钮。撤销权限只阻止未来请求，不删除已有收藏。备份数据库时包含 platform_actions 和 PLATFORM_ACTION_* 原始事件。

能力卡的“账号操作”另列已保存 UID、登录读取开关、三类凭据存在性、每日写入上限和允许收藏夹；有凭据不等于有效登录，上限不是今日余量。最近平台动作可回到原工作，时间是记录更新时间，不会因刷新而查平台；历史记录不按所选授权主体过滤。工作详情分开目标状态、尝试与确认记录，不再将历史确认称作当前实时状态。

插件详情的配置／开放群／诊断标签随 URL 切换，保存成功和配置冲突显示在当前弹窗内。冲突后先重读当前保存值，再选择保留草稿或采用现值；重读失败时先重读，不能使用旧凭据世代覆盖。切换插件或离开页面后，旧请求不会清除新对象草稿；服务器可能已经接受原保存／启停，应回到原插件正常刷新核对，不把离页当作撤销。

### Core 现场核对

地址使用无 query、fragment、userinfo 的 ws/wss 端点；认证令牌只填 writeOnly 的 access_token，由客户端按明确 token_query_parameter 注入。`core_version` 记录现场核对的版本/提交，默认空；`platform_bot_id` 固定 onebot，bot_self_id 必须与当前 OneBot QQ 身份一致。保持 Core 默认可选，不自动安装游戏插件。

首版下行必须有逐帧 echo。部分上游普通回复默认不带 echo，这类帧在 LenBot 明确不支持，须先核对实际 Core 游戏命令的输出模式，再开放对应群。不要为解决此差异把 msg_id 当帧 ID，也不使用内容指纹去猜重复。原消息命令、下行帧和 recall_message_id 回传分别登记 CORE_BRIDGE_ATTEMPTED 与 gscore_* 观察；已转发不等于已完成，回传中断不触发命令重放。现场仍需逐项观察支持矩阵和真实 OneBot 回执，未取得前不标记运行通过。


Core 回填 ID 采用完整发送回执的统一判定。模拟、Shadow、未知、矛盾回执与缺平台身份不作为成功 ID 回传；原 echo 尝试与未知不重放规则保持。能力卡中的消息／文件回执同样采用该判定，历史缺字段不会显示成新取得的成功。

### 跨模块核对入口

“能力与插件”上方可进入系统能力页面。“认识与记忆 → 公共兴趣”按主题/内容查找，核对事实/评价/意图、版本、有效期、匿名来源证明、采用工作与修订原因；查看记录不会抓取来源或调用模型。“提醒、等待与周期 → 心跳与兴趣分享”显示预定槽、真实触发、关联研究及跳过原因，不能在普通提醒入口手动取消/提前系统槽；启停仍走所属心跳/插件配置。

公共兴趣详情另列最近 50 个逐群发布行动，分开显示当时采用版本、发送尝试和终态回执，可回到原场景记录；没有群表达正文。只见尝试时可能仍在处理，不据此重发；published_at 不是群发送时间。没有发布记录也不证明没有被考虑或没有保持沉默。来源覆盖沿原资料展示，同对象刷新失败保留带采样时间的旧内容。

工作详情页首显示真实发起主体与预占账户，“预算与压缩”显示原工作快照和结算，“进度与资料”显示已持久化呈现范围，“执行记录”显示外部执行仍否占用及停止回执。termination_unconfirmed 需要核对原执行服务，面板没有“强制清零”占用入口。文件上传、B 站状态和 QQ 回执分别查看原记录。调用页将供应商报告的音频秒数单列；token 缺失仍标记未知，不把音频秒数当 token 或价格。

修订工作发生拒绝或版本变化时，先刷新成功，再选择“保留实际改动，采用新基线”或“放弃草稿，采用现值”。保留按自己原先增加／移除的要求重建，不删除别人后来新增的要求；目标没改时采用现值。插件业务参数可展开原参数、当前参数与修订草稿对照，也可只放弃参数修改而保留目标／要求。旧修订接口已经改变时不套用原参数；重新确认后仍须另行保存。读回失败不能用旧样本更新基线，离页不撤销已提交控制，取消反馈不是外部执行停止证明。

撤销认识收到成功回执后，页面仍重读整条修订链。出现“尚未取得一致的修订链读回”时，先重读并核对原记录，不能因旧样本还显示有效而直接再次撤销。请求未知或原对象暂不可读取时查看原错误；未提交的撤销理由／工作修订仍在本页保留，可核对或明确放弃，不会转移给别的记录。返回同一对象会重新读取，不沿用离开前尚未完成的界面请求。

提醒修改、取消和立即触发会携带本次读取的原对象、事项、时间、状态及触发条件；后台在原事务内再次核对，已被调度认领或被其他操作修改时可能正常拒绝。修改冲突后先重读，再明确保留实际改动或放弃草稿；取消／立即触发须核对后重新选择并确认，不自动重复。成功回执之后仍要读回当前对象，待读回提示消失前暂不再次提交。等待结束仍只适用于 active／review_required，不等于收到群友答复。

提醒时间采用页面标明的浏览器时区，并同时显示绝对时间。没有编辑时间时保留原 Unix 秒值的精度；冲突重建也不把自己改过的整数秒换成他人的同秒小数值。超出日期控件范围的保存值明确说明，不按空值清除；非法日期和夏令时跳过的本地时间不会被自动修正。重复时段的改动须核对确认窗口中的绝对时间，原时间未编辑时保持原时刻。

升级须让面板与后端同版构建。`/api/cockpit/tasks/{id}/update`、`cancel`、`trigger_now` 现在均要求 baseline；旧页面或调用方缺少原值会被拒绝，应重新加载／读取原事项，而非由后台补当前值。既有数据库无需转换，旧已提交事件保留可读，旧尚未提交的提醒控制不能自动重放。


### Linux 发布材料

具体部署配方、目录/权限、配置映射、起停顺序、普通备份与恢复见 [deploy/linux](../deploy/linux/README.md)。LenBot 使用无 Docker socket 的 Compose，Gateway 保留独立宿主服务和日志库；配置挂整个父目录，支持原面板原子保存。离线 Python 与尚未核验的 public 网络分别准备，模板不改现场根配置，不自动启动或登录平台。

升级记录要同时保存源码/镜像、LenBot 与 Gateway 库、完整媒体/文件资产/插件数据/任务卷以及实际配置。发布时使用 [现场记录模板](../deploy/linux/release-evidence.template.md) 在本地运维目录记录真实聊天群、播报群及可选项，阶段结果归纳到本轮状态；模板存在、构建通过均不能写成部署或实群通过。
