# 运行与实群迭代

面向运营者。日常操作是配置、群聊和查看具体问题；不需要评分、导入报告或凑够消息数。

## 启动与发送

使用 `uv run len-bot` 启动，面板默认地址为 `http://127.0.0.1:11307`。配置、管理员登录、OneBot、人格和素材都以 SQLite 保存值为准。没有默认模型提供商；未设置 conversation 时继续保存输入，不发起对话；work 和 maintenance 各自未配置时不运行对应能力，面板明确标示未就绪。

实发只由群名单和全局 Shadow 控制。代码默认 Shadow 开启，初始名单为 `group:126300994`；重启恢复运营保存值。关闭 Shadow 后仅名单内可发送，名单外保持 Shadow。源码、模型或人格变化不清空名单，也不自动隔离既有任务。

开启 Shadow 可暂停实发，移除某个群可单独暂停该群。候选不会补发；发送 unknown 不重试、不换通道。失败或 unknown 停止同组后续片段。任务到期、工具完成、工作结果就绪都不等于送达，最终看真实 MESSAGE_SENT。

## 模型与工作

模型页分别设置 conversation、work、maintenance 的提供商、型号和推理强度。maintenance 负责历史维护、工作压缩和技能整理，必须由运营显式选择，不能自动沿用 work。修改在新轮次或新工作生效；已运行工作修订保留原绑定和已消耗预算。没有跨型号 fallback 或独立视觉路由。

已有运行配置为 BotCF / `gemini-3.8-flash`，conversation 使用 low，work 使用 high；2026-09-08 另获准以同提供商/型号 low 做 maintenance 的少量隔离供应商验证，这不等于已修改生产维护配置或已上线。这是此次运营选择，源码不会在启动时覆盖后续手工修改。模型页原生能力检查使用合成图片和工具续接，不向群里发送测试消息。

普通聊天默认 3 个模型步骤、6 次工具、24K 文本上下文、4096 输出 tokens。联网查询、解题、核实和资料整理作为后台工作执行，聊天可以继续处理新话。工作默认每群一个、全局两个，预算为 16 步、24 次工具、300 秒、64K 上下文、16K 单次输出；输出预留同样计入上下文预算。工作页显示进度、依据、目标版本、预算、压缩及检查点，可以检查资料、修订、停止或显式恢复；中断工作不会因重启自动从头执行。已完成/partial结果即使发送失败也不能重新执行；已取消工作不能恢复。

工作页分开显示执行结局和回应阶段。“结果待回应”也可能是一份失败记录，不能视作查询成功。失败或中断可按当前条件恢复，已用预算不清零，暂停期间不消耗运行时间；原模型绑定缺失或不可用时明确拒绝，不能猜测使用当前默认型号。失败说明不能作为成功履约。运行记录按真实工作 runs 汇总模型次数、工具执行次数和错误；提交失败时优先显示拒绝原因，模型候选中的“已经完成/已经提交”不作事实展示。

新建工作的确认绑定实际暂存回执；只有确认消息真实送达才算对用户作出承诺。有限计数和极值问题可用枚举工具查找反例，工具结果同时保留变量范围与条件；仍需核对这些条件是否覆盖原题，不能把简单算式或搜索摘要当作完整证明。

网页搜索使用无需密钥的 Bing 公开检索，并丢弃与原查询词项不匹配的 RSS 行；`site:` 约束也在本地校验返回域名。资料页保留图表入口，工作可继续读取原图或PDF页面；读不到、截断和没有文字层会明确显示。搜索服务不可用时，本次工作停止重复尝试该服务，未核实项应保留。Trace 中“调用结束”和“资料已读取／读取失败／服务或格式不可用”分别显示。

## 注意力、维护与技能

设置页的关键词与抽样参数只控制观察机会。默认每 300 秒新旁听内容最多一次抽样、概率 0.2；关键词有独立短时冷却。明确呼唤、连续互动和有效工作参与者的新要求不受这两项限制。真实送达建立默认 120 秒关注，在途回应的同一来源仍可继续输入。没有唤醒时，普通消息保存而不产生对话调用。

场景页显示扫描位置、待处理唤醒及摘要状态。扫描不是已读，摘要不是原话证据。长原文按字符范围续读，完整原文未覆盖或本轮预算不足时，来源继续待处理，不能假装整条已读或已完成工作。历史维护默认约 8K token 成块；至少 2K 的尾块在安静 150 秒后处理，更小尾块继续保留。失败/未确认范围不会因新消息自动重试；查明原因后可点明确的维护重试，当前对话正在运行时会提示稍后操作。

工作页按需展示技能目录与正文、来源工作及版本。只有工作提出候选才启动技能维护；普通完成没有额外学习调用。自动技能只供来源场景，人工方法不会被自动覆盖。运营公开操作针对当时版本；后来形成的新修订仍先限来源场景。技能中的工具名称和步骤不授予权限。

模型页按用途汇总供应商 token、未知 usage、取消和未确认请求，本地估算单独呈现。推理 token 可能已包含在输出中，不能再次相加。取消只代表客户端停止等待；没有价格记录时不填零费用或节省比例。

## 人格、认识与图片

设置页提供短角色卡和人工表达参考。预设先预览再显式应用，已有人工编辑和启停保留，启动不自动应用。六组嘉然参考包含自然接话、接受纠正、留出空间、工作资料表达、单图与混排；角色资料和样例不进入群友认识。

“呼唤昵称”可填写额外叫法，默认“然比、小然”，用逗号或顿号分隔。机器人名字、实际 @、引用它的消息和私聊也会提供直接交流线索。昵称命中不强制回复，普通群聊默认旁听，正在接着聊时不必反复叫名字。保存空列表只清除额外昵称；昵称配置与群友偏好称呼独立，预设应用保留已有值。

决定参与后可以只发一张表情，也可以图文混排。减少主动插话和选用表情分别判断，不设置固定发图比例。模型输出格式已简化，面板里的人工样例编辑方式保持。

认识页展示有原始证据的陈述、reported/inferred、有效期和修订链。运营撤销必须填写理由，保留原文、原始证据和此次操作来源。昵称、群名片是协议事实，偏好称呼单独记录。

图片页可上传 PNG/JPEG/WEBP/GIF、编辑说明与情绪标签、调整启停和目录排序。只有明确运营发布的素材可设为 global-safe；群聊输入图片保持本群范围。固定目录最多 20 项，以文字索引提供短引用，模型选定后先用 read_media 读取像素，完整库仍可搜索。实际发送始终读取获准原图。

当前和引用图片直接进入同一次多模态对话请求，窗口内去重，最多六张、最长边 2048；额外图片可按需读取。动图只提供首帧，未装入和移出范围在 trace 中说明。下载受 10MB/20MP 和网络权限限制，读取图片不会隐藏调用另一个视觉模型。

媒体文件在数据库同目录的 `media`，按原始内容哈希保存；当前嘉然库为用户提供的 49 张图片，完整 GIF 也原样保存。`JOBS_ENABLED=false` 或 `MEDIA_ENABLED=false` 可停用对应能力并保留账目和文件。素材与人格说明见[嘉然表达与表情库](persona/diana/dialogue-and-stickers.md)。

## Reset、升级与回滚

设置页“Reset 对话数据”停止认知、历史/技能维护、工作和投递后，清理全部群聊/私聊原话、Session、摘要、自动认识与技能、任务、工作检查点、调用账、资料和聊天图片。运行配置、登录、人工样例、运营图片及来源保留，重置追加一条管理记录。Reset 不改变 Shadow 和实发群名单。

本次 ADR-0045 转换保留全部业务事实，**不得执行 Reset**。先停止当前运行进程，等待认知、维护、工作与投递退出，并确认面板端口无监听。保存当前旧代码提交或代码归档；数据库与完整媒体由下面的命令在修改前备份并哈希核验。备份目录必须不存在，且在媒体目录之外。

```sh
uv run python -m len_bot.migrations.attention_work \
  --database /绝对路径/len_bot.db \
  --media-dir /绝对路径/media \
  --backup-dir /绝对路径/.backups/adr0045-本次时间
```

命令只操作离线结构，不连接 OneBot、不发模型请求、不启动 Runtime。它把旧未处理原文转成持久唤醒，记录升级截点之前没有新摘要的事实，保留原始事件、认识、任务、工作、工具观察、登录、配置、人工样例和媒体。旧 reflection_cursors 缓存退出，不能把旧反思当成已有摘要。

检查 `upgrade-result.json` 的 `facts_preserved` 和 `integrity_check`，再启动新代码。升级期间发生错误时，未完成标记会阻止普通启动；保持停机，检查备份和错误，必要时恢复同批备份，不能清除标记后盲目启动。已消耗预算但旧记录缺少准确模型绑定的工作不能猜测恢复；结果和资料仍保留，当前版本已有结果不重做。

在模型页显式配置 maintenance。当前分支只实现配置入口并进行已授权隔离验证，不预设生产型号，不改变保存的 Shadow、群名单、人格或人工样例。上线后依原群真实原话核对旁听、呼唤连续追问、工作追加/取消、结果事件唤醒、长资料压缩与明确纠正；只有真实 MESSAGE_SENT 能证明交付。

回滚必须一起恢复旧代码、旧数据库与旧媒体备份；不要用旧代码打开新结构或只还原数据库。生产运行日志、PID 和备份位于本地 `.runtime`、`.backups`，不进入 Git。

## 排查具体问题

记录群、时间和原话，按事件、conversation/work/maintenance trace、工具资料、Gate 与发送回执追踪。trace 展示真实型号、工具、终结候选、读取截点、媒体覆盖和拒绝原因，凭据与像素保持脱敏。失败或冲突不发送候选，也不通过清空未读输入掩盖问题。

修改后只做相关检查；涉及前端运行 `npm run build`，实际页面按本轮约定由运营查看。模型在具体题目中的错误与协议测试通过是两件事，原始失败记录继续保留，修复后回到真实群聊确认后续互动。
