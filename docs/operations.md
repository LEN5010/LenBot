# 运行与实群迭代

面向运营者。日常操作是配置、群聊和查看具体问题；不需要评分、导入报告或凑够消息数。

## 启动与发送

使用 `uv run len-bot` 启动，面板默认地址为 `http://127.0.0.1:11307`。配置、管理员登录、OneBot、人格和素材都以 SQLite 保存值为准。没有默认模型提供商；未设置 conversation/work 时继续保存输入，不发起模型调用。

实发只由群名单和全局 Shadow 控制。代码默认 Shadow 开启，初始名单为 `group:126300994`；重启恢复运营保存值。关闭 Shadow 后仅名单内可发送，名单外保持 Shadow。源码、模型或人格变化不清空名单，也不自动隔离既有任务。

开启 Shadow 可暂停实发，移除某个群可单独暂停该群。候选不会补发；发送 unknown 不重试、不换通道。失败或 unknown 停止同组后续片段。任务到期、工具完成、工作结果就绪都不等于送达，最终看真实 MESSAGE_SENT。

## 模型与工作

模型页分别设置 conversation 与 work 的提供商、型号和推理强度，Reflection 复用 work。修改在新轮次或新工作生效；已运行工作修订保留原绑定和已消耗预算。没有跨型号 fallback 或独立视觉路由。

本次已批准的部署配置为 BotCF / `gemini-3.8-flash`，conversation 使用 low，work 使用 high。这是此次运营选择，源码不会在启动时覆盖后续手工修改。模型页原生能力检查使用合成图片和工具续接，不向群里发送测试消息。

普通聊天默认 3 个模型步骤、6 次工具、24K 文本上下文、4096 输出 tokens。联网查询、解题、核实和资料整理作为后台工作执行，聊天可以继续处理新话。工作默认每群一个、全局两个，预算为 16 步、24 次工具、300 秒、64K 上下文、16K 单次输出；输出预留同样计入上下文预算。工作页可检查资料、修订、停止或恢复；中断工作不会因重启自动从头执行。

工作页分开显示执行结局和回应阶段。“结果待回应”也可能是一份失败记录，不能视作查询成功。失败或中断可按当前条件恢复，已用预算不清零；失败说明不能作为成功履约。运行记录按真实工作 runs 汇总模型次数、工具执行次数和错误；提交失败时优先显示拒绝原因，模型候选中的“已经完成/已经提交”不作事实展示。

## 人格、认识与图片

设置页提供短角色卡和人工表达参考。预设先预览再显式应用，已有人工编辑和启停保留，启动不自动应用。六组嘉然参考包含自然接话、接受纠正、留出空间、工作资料表达、单图与混排；角色资料和样例不进入群友认识。

认识页展示有原始证据的陈述、reported/inferred、有效期和修订链。运营撤销必须填写理由，保留原文、原始证据和此次操作来源。昵称、群名片是协议事实，偏好称呼单独记录。

图片页可上传 PNG/JPEG/WEBP/GIF、编辑说明与情绪标签、调整启停和目录排序。只有明确运营发布的素材可设为 global-safe；群聊输入图片保持本群范围。固定目录最多 20 项，编号总览帮助模型选择，完整库仍可搜索。实际发送始终读取获准原图。

当前和引用图片直接进入同一次多模态对话请求，窗口内去重，最多六张、最长边 2048；额外图片可按需读取。动图只提供首帧，未装入和移出范围在 trace 中说明。下载受 10MB/20MP 和网络权限限制，读取图片不会隐藏调用另一个视觉模型。

媒体文件在数据库同目录的 `media`，按原始内容哈希保存；当前嘉然库为用户提供的 49 张图片，完整 GIF 也原样保存。`JOBS_ENABLED=false` 或 `MEDIA_ENABLED=false` 可停用对应能力并保留账目和文件。素材与人格说明见[嘉然表达与表情库](persona/diana/dialogue-and-stickers.md)。

## Reset、升级与回滚

设置页“Reset 对话数据”停止认知、反思、工作和投递后，清理全部群聊/私聊原话、Session、自动认识、任务、工作、资料和聊天图片。运行配置、登录、人工样例、运营图片及来源保留，重置追加一条管理记录。Reset 不改变 Shadow 和实发群名单。

普通升级先停机，备份 `len_bot.db` 和 `media`，再更换代码并启动。VNext 是已明确批准的一次不兼容切换：旧场景和认识结构不能直接启动新引擎，也不会自动迁移或抹除。切换顺序为停止旧运行时、备份数据库与媒体、执行获准完整 Reset、建立新结构和配置、应用本次角色卡与目录、启动新运行时。执行记录和配套提交见[实施记录](implementation.md)。

回滚必须一起恢复旧代码、旧数据库与旧媒体备份；不要用旧代码打开新结构或只还原数据库。生产运行日志、PID 和备份位于本地 `.runtime`、`.backups`，不进入 Git。

## 排查具体问题

记录群、时间和原话，按事件、conversation/work trace、工具资料、Gate 与发送回执追踪。trace 展示真实型号、工具、终结候选、读取截点、媒体覆盖和拒绝原因，凭据与像素保持脱敏。失败或冲突不发送候选，也不通过清空未读输入掩盖问题。

修改后只做相关检查；涉及前端运行 `npm run build`，实际页面按本轮约定由运营查看。模型在具体题目中的错误与协议测试通过是两件事，原始失败记录继续保留，修复后回到真实群聊确认后续互动。
