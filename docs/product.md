# 当前产品行为

LenBot 面向群聊参与者与运营者。本文说明已有功能对用户意味着什么；实现方式见[架构](architecture.md)，操作方法见[运行手册](operations.md)，本轮未完成目标见[当前任务](iteration.md)。

## 聊天与旁听

所有接收到的原话先保存。群是否启用、普通成员能否聊天、开放哪些插件、命令与公告，由本群设置决定；没有启用的群不产生新认知或发送。chat 关闭时，普通成员消息只保存；全局 QQ 回复白名单中的用户仍有普通互动资格。白名单不强制每条回复，也不授予管理员、跨群读取或全体提及权限。

有对话资格的输入经过实际 @、回复 Bot、呼唤昵称、连续互动和有效工作的参与者线索提供唤醒；关键词和时间窗口抽样只提供一次观察机会。获得机会后仍由对话入口决定是否参与。未唤醒的旁听不逐条调用模型，也不记成“模型决定沉默”。仅播报群不做闲聊历史维护，明确工作的压缩仍使用该工作的预算。

既有私聊继续保存与观察，沿原 Shadow 语义不实发；本轮分群规则不另行开放私聊插件或发送权限。

新的一句话不会自动替代仍在继续的前一个问题。多人可以分别回应，玩笑沿前文中的具体对象继续；共同玩的设定仍是聊天语境，不能成为 Bot 真实经历或能力的证明。真实送达会建立短时关注，同一参与者可以继续追问；正在处理或尚待回执的同一来源也能继续输入。

一次表达可以是文字、单张图片或图文混排，也可以保持沉默。消息数量和工具、模型预算受当前配置与终结协议约束；普通模型正文不直接发送，只有已提交的表达进入发送流程。参与频率和表达形式分别判断，不设固定发图比例。

普通新输入不会取消正在等待的模型请求。在完整工具交换后，尚未提交的轮次可以在原预算中继续接收新输入。控制工作、提醒或等待回应时必须看完有关的新要求；因新输入尚未读完而未提交的候选不会产生消息或任务。失败不通过清空未读来源掩盖，也不以新预算无限自唤醒。

## 信息工作、提醒与等待

联网研究、陌生概念查证、解题、计算和复杂资料整理使用后台工作，前台聊天继续接收新话。短日程、监测状态和动态查询可在对话中直接读取。新建、修改、停止或恢复工作都要基于实际请求与当前版本。修订保留已消耗预算和已取得资料；工作只有只读执行权，进展与结果回到对话入口决定如何表达。

工作确认关联本次真实创建的工作。不同轮次中相同的短编号不会把一条新确认串到旧工作；只有确认消息真实送达才算向用户作出承诺。

| 显示状态 | 含义 |
|---|---|
| 执行完成 | 工作按当前目标形成完整结果，仍需结合原问题与来源判断结论是否正确 |
| 部分完成 | 保留已取得结论及明确未决项 |
| 失败／中断 | 本次执行没有成功完成，保留原因、资料与预算；符合条件时可显式恢复 |
| 结果待回应 | 已有终态资料等待对话处理，可能包含失败说明，不代表查询成功或已送达 |
| 待核对 | 运行中断等情况需要运营或当前对话明确处置，不自动从头重做 |
| 等待送达／送达未知 | 表达已进入交付阶段；未知不能推断成功，也不能自动补发 |

已经完成、部分完成或取消的工作不重新执行；完整结果发送失败也不能作为重跑工作的理由。失败说明可以解释情况，不能冒充成功履约。恢复需要原绑定仍可用，不能改用当前其他型号继续旧工作。

提醒保存具体来源与触发时间；到期只证明触发发生，实际履约仍取决于交付。等待回应只在真实发送后激活，结束或过期各有明确记录。

## 原话、资料、认识与技能

当前群的按需总结先固定带时区的 `[start_at,end_at)` 范围、请求者与取得截点，提交后沿原工作链统计和分页读取。日程命令及引用评论属于群友原话，可在明确总结中读取；机器人回声和内部运行事件排除。结果分别展示匹配记录、实际阅读覆盖与未完成部分，只说明 LenBot 已保存的本群记录，不能据此声称取得 QQ 全日全部消息。总结不自动广播到其他群，也不生成长期认识或方法技能。

资料被取回、已保存、能定位、实际展示给模型，是不同状态。多份资料共享同一次请求的剩余容量；装不下的内容保留续读位置，原始内容完整保存。未展示的原话和图片不计为已读，长原话可按实际范围继续读取。当前工作信息仅在变化时更新，旧查询结果不会使目标版本倒退。

历史摘要是带原始范围的非权威缓存。摘要与来源位置帮助找原话，不能替代实际阅读，也不能独立授予认识或工作证据。维护失败不推进覆盖，未覆盖历史与失败范围继续可见。

认识保留主体、陈述、原始证据、有效期及修订链。“有人明确报告”和“从互动推断”分别显示，均不等于客观核实。撤销或替代保留旧陈述及理由。账号昵称和群名片属于协议事实；偏好称呼独立保存，缺省字段不清空现值，同名不合并身份。

方法技能包含适用条件、步骤、不适用情况、来源与版本。工作可以按需读取；有实际结果或明确纠正依据的候选才进入维护。自动技能限来源场景，人工内容不被自动覆盖，公开范围针对运营选定的版本。技能不授予工具权限，不自动创建工作或群消息。

## 图片与人格

当前及引用图片直接进入同一次多模态请求，按实际像素窗口记录覆盖。窗口外图片或被移出的旧图可继续读取；历史上看过不等于当前仍装入。动图向模型提供首帧，发送保留获准原文件。网页图表和 PDF 文字层分别读取，文字提取不代表图表像素已看过。

运营素材有说明、标签、启停和固定目录顺序，完整库可以检索。模型选择后读取原图再提出发送；运营明确标为表情包的素材使用 QQ 自定义表情类型。聊天输入图片保持所属场景；跨场景素材由运营明确发布。

人格与人工表达参考影响说话方式，不构成群友事实、真实经历或实时资料。启动不会自动应用人格模板或重建已删除样例。运营可以独立维护文字、单图和混排参考，来源资料见[人格资料](persona/diana/README.md)。

## 日程、动态与开播邀请

日程使用唯一 ICS 来源，返回源事件身份、明确时间、取消状态与取得时间；缺少结束时间显示未提供，团体署名不强制展开成员。日程未收录不表示确定没有直播，排期不证明实际开播。缓存到期后刷新失败就是本次失败，旧快照仅在面板标注时间查看。

根文件中的精确日程命令直接生成图片，不调用社交模型。原命令、实际响应和通过真实引用关系识别的评论不进入普通对话、轮中新输入或闲聊维护，送达不建立聊天关注；QQ 白名单也遵守这一归属。没有引用关系的短评不通过关键词或额外模型分类，运营用法见运行手册。图片生成或发送失败不改发文本。

动态工具读取指定站点已抓取的最新项目、搜索、历史同日与二创，明确发布时间和取得时间。成员无法识别时失败，不改查全员。搜索片段、已取得的源记录与真实像素分别说明；不存在的详情接口不编造，源失败不转其他来源，查询不会触发自动动态广播。

共享直播采集在第一次成功读取时建立基线。之后出现新的真实房间号与开播时间，才为订阅群建立一次公告事项。相同场次不反复生成，采集错误不视作下播。公告沿同一 conversation 模型的窄入口生成正确指认主播的邀请；Runtime 固定目标群，并按当前群设置添加真实全体提及。公告不激活普通聊天关注，源明确下播、订阅取消或群停用时停止旧邀请。生成失败、发送失败和未知回执均不自动改写或补发。

## 发送、运行状态与面板

| 发送结果 | 含义 |
|---|---|
| `sent` | 具有真实发送回执，证明实际送达 |
| `not_sent` | 已明确未发送 |
| `rejected` | 候选或发送被当前业务条件拒绝 |
| `unknown` | 结果不确定，不自动重试或更换通道 |
| Shadow／模拟 | 候选或隔离运行事实，不证明真实发送、履约或正常短时关注 |

真实发送由当前群的启用与对应 chat、command、announcement 字段和全局 Shadow 共同控制；独立实发群名单已退出。类别由实际入口绑定，模型不能自行选择。源码、型号或人格变化不重设群设置。一次发送失败或结果未知会停止同组后续片段。

面板提供场景原话、工作与资料、提醒与等待、认识与技能、媒体、模型、插件、设置及运行记录。写入等待服务端结果，不因刷新自动恢复工作、补发或发起模型请求；尚未保存的草稿与失败反馈明确显示。

对话、工作和维护分别配置模型。未配置对话时仍接收保存输入；其他角色未配置时对应能力明确未就绪。每个真实请求保留用途、实际绑定、usage 或未知状态；本地估算单列，失败、取消与未确认不能按零用量计算，没有价格依据时费用保持未核实。

显式 Reset 会清理会话与自动产生的资料，保留运行配置、登录、人工样例和运营素材及来源。它是单独管理动作，本轮重构不执行；操作范围与步骤见运行手册。
