# S2-01 会话段与最小持久状态设计

面向内核与存储维护者。依据 2026-09-23 已确认的[宿主所有权方向](s0-02-product-positioning-and-decisions.md)，核对源码基线 `a0d07c8`。本文给出结构选择与后续实现约束，**不是当前已具备的持续会话能力**；状态只见[产品路线](README.md)，现有装配仍见[上下文](../context.md)。本批不转换数据、不改变保留期限。

实施增量：当前已在原 state_json 接通 `ConversationSegment` 的原话窗口身份与引用回读、最终请求保留的摘要批次引用，并保存 R／J 编号预留；普通对话可把上一轮已存 R 资料作为同群、定位级候选放入新请求，正文仍须本轮重读。运行覆盖仍为 source_window_only，见[现有合同](../context.md#当前段的原话窗口引用)。具体保存字段使用 id、previous_id、through_rowid、event_ids、summary_refs、result_aliases、job_aliases；下文的有序材料、固定材料持久版本、其他稳定别名和完整原生交换仍是后续设计，并非都已落库。新程序保存 Session 后即可能出现可空新字段，旧程序回退约束已经实际适用；本轮未运行服务，因此没有修改真实业务数据。

## 1. 四种身份不得合并

| 名称 | 身份与所有者 | 不能替代什么 |
|---|---|---|
| 场景主会话 | 原 scene_id 对应一条 SceneSession，宿主拥有 | 不按用户×群另开窗口 |
| 会话段 | 主会话当前保留的一段有序上下文，宿主分配独立随机 ID | 不是全局 rowid 取模，不是处理进度或事务版本 |
| 单次运行 | 原 episode_id；一次执行及其等待恢复共用身份和累计预算 | 换段不创建新预算，不复活已取消执行 |
| 长期工作 | 原 job_id/revision，原工作检查点与结果 | 不把主会话段当工作状态或新的发送入口 |

一段可经历多次运行，一次等待恢复可能遇到主会话已换段；此时仍从原 ConversationResume 取得来源、模型绑定、计数和期限，不用当前段生成新的恢复资格。

## 2. 现有结构能做什么

| 真实入口 | 已有事实 | 对新设计的约束 |
|---|---|---|
| [SceneSession](../../src/len_bot/scenes/models.py) | 每场景一条严格类型状态，包含 version、knowledge_revision、pending_wakes、观察截点 | 可以增加一个可空的当前段字段；不得借用观察截点充当已接入截点 |
| [SceneActor](../../src/len_bot/scenes/actor.py) | 串行处理事件、执行租约、提案和历史提交 | 段更新也由它拥有，不能从模型协程直接保存旧 Session 覆盖新输入 |
| [EventStore](../../src/len_bot/events/store.py) | scene_sessions.state_json 与事件提交一起保存；原话已有事件身份和范围 | 原话继续只在 events，段只存定位及顺序；不得人为生成聊天事件来保存检查点 |
| [SocialCognitionCore](../../src/len_bot/cognition/social_core.py) | 每轮新建 ConversationContext；普通对话没有传 exchange_checkpoint | 仅保存段 ID 不会产生跨轮工具延续，须接通真实完成交换的保存入口 |
| [TurnReferences](../../src/len_bot/cognition/context.py) | snapshot 包含编号、阅读范围，也混合工作／提醒／文件资格 | 不能整份恢复为当前授权；稳定编号与本次实际阅读、当前权限必须拆开处理 |
| [AgentLoop](../../src/len_bot/cognition/agent_loop.py) | 原生 continuation 与工具回复按顺序组成轨迹，部分终结路径直接返回 | 不能认为已有回调覆盖所有终结；提交成功、拒绝及中断分别核对 |
| [工作上下文](../../src/len_bot/runtime/work_context.py) | exchange_spans 按调用 ID 核对完整交换，工作有独立压缩／检查点 | 复用分组规则，不调用工作保存方法、创建虚假 job 或改变工作预算 |
| [历史维护](../../src/len_bot/memory/history.py) | history_batches 保存摘要、覆盖范围、generation_version，提交核对知识版本 | 摘要仍引用已完成批次；新段不另建记忆库或第二个原话压缩器 |
| [S1 请求清单](../../src/len_bot/cognition/request_record.py) | 保存位置与部分明确固定组件，未保存所有动态消息和原生响应 | 不能拿清单当完整交换检查点，也不从审计文字猜供应商续接字段 |

## 3. 最小持久结构

首先使用 `scene_sessions.state_json` 中一个可空、严格类型的 `conversation_segment`。目前没有需要跨段全文检索或独立生命周期的业务，因此**不新增 transcript 表或段历史表**。它只保存当前有界段；关闭段的身份、原因和引用写原 traces，历史业务事实仍在原所属表。不得把 traces 改为恢复所必需的唯一业务状态。

拟定字段及归属如下，具体类型在接通消费路径时加入，不先铺设未使用模型：

| 字段／内容 | 用途与范围 |
|---|---|
| segment_id、previous_segment_id、opened_at、open_reason | 宿主分配身份，明确初建／容量换段／装配变更；前段 ID 仅定位，不要求永久保留旧段正文 |
| assembly_version | 源码维护的渲染合同版本，不是 hash、配置签名或知识版本 |
| model_profile 与固定材料引用 | 复用原无凭据 ModelProfile；定位本段固定合同、工具定义和基础摘要，不能把整份根配置写入段状态 |
| admitted_through_rowid | 已考虑接入的场景事件位置上界；配合实际事件范围／省略项判断提供了什么，不表示这个范围内每项都读完或处理完 |
| summary_refs | 已完成 history_batch ID、generation_version 和原覆盖范围；摘要正文仍归原批次 |
| ordered_items | 按接入顺序排列的事件范围、资料页、媒体引用及完整交换；只覆盖当前容量内的段 |
| stable_refs | 渲染所需的事件／成员／资料别名对应真实身份；不保存一份可跨轮复用的权限表 |

当前 `summary_refs` 只收录最终请求未被省略、未被改写且经过本次来源可用性复核的 history_summary 批次；每项保留批次 ID、字符串 generation_version 与四个位置值，不存摘要文本。Actor 将这些引用的变化视为装配变化并换段；旧段无此字段时读取为空列表。下一轮仍由原 history_batches 和当前读取截点重新选取与核对摘要，不能把保存引用当成本次已读或永久可用的正文。这是摘要基线的窄身份增量，不是 `ordered_items`、压缩或完整段恢复。

`ordered_items` 至少区分以下材料，不能用一个任意消息数组混装事实和草稿：

- **原话／真实回执**：原事件 ID、场景、位置与字符范围；原话不复制，回执不由提案文本替代。部分提供和省略必须显式保存。
- **工具资料页**：原 result_id、原页范围及实际渲染版本；跨轮只是材料候选，需在本次最终请求提供后才形成当前已读依据。正文继续从原观察读取。
- **完整原生交换**：必要的原生 assistant continuation（含工具 ID、参数与供应商要求的续接字段）和一一对应的 tool 回复定位。已有观察可定位的正文不重复存；无法从权威资料还原的协议回复才保存必要原文。它是模型／工具执行经历，不是 Bot 群发言。不得从旧 trace 重造这部分。
- **固定组件与媒体**：有明确版本的组件引用、媒体资产 ID 和装配范围；不持久化 base64、临时下载地址、客户端或凭据。像素是否本次提供仍由原媒体装配确认。

这是活动运行状态所需的最小新增内容，不是整条群聊请求永久归档政策。原生交换会增加活动状态体积；不能把理论 token 上限当实测 SQLite 文件大小。后续若真实实现证明单行重写成为具体问题，再带实际范围重新讨论窄存储，不预建分片或归档系统。

## 4. 更新、提交与失效边界

1. 普通群聊获得原场景执行租约后取得当前段；插件专用表达、后台工作和维护不写入普通群聊主段。
2. 新输入按原场景位置接入段尾，已在段内的原话不会因为本轮变成引用或当前来源而移动。时钟、资格、工作状态和预算仍按本次权威状态装配，不冻结成永久事实。
3. 只把完整 assistant/tool 交换交给宿主保存；模型返回但工具尚未结束，不能持久标为完整。现有交换分组规则保持调用 ID、顺序及供应商字段，不拆断、不拼接推测的回复。
4. 保存命令携带原 episode、预期 segment_id 与段内追加位置，由 Actor 在原租约边界核对；存储在原写锁／事务下仅更新段字段，保留 Actor 最新待处理来源、注意力与 Session 状态。没有成功落库就不推进内存中的已保存位置。
5. 业务提案仍由原 Gate 和事件事务决定。原提案提交成功而段保存失败时，报告两者的真实结果，不能撤销既有提交或重新执行。拒绝的提案可保留为明确拒绝的原生经历，不能投影为真实回复。
6. 段内材料不授予未来执行资格。新请求继续核对场景范围、插件启用、工作修订、素材状态和实际阅读；失效材料不从旧像素／旧资料副本补回。
7. 格式错误、引用归属错误、写入冲突在所属边界结束并记录。不得吞错后悄悄清空段重试；正常容量换段和明确旧数据初建是有原因的生命周期动作，不是通用降级。

## 5. 迁移输入、输出与回退

| 输入 | 输出与动作 |
|---|---|
| 旧 Session 没有段字段 | 读取为未建段；在下一次获准普通群聊运行中，由已知原事件和摘要建立新段，原因标明旧数据无原生轨迹 |
| 已有事件、工作、等待、调用或回执 | 全部保留原 ID、状态、版本和预算，不从成功日志推导旧交换，不补发、不重新读外部源 |
| 新段格式及材料引用完整 | 只恢复可读本地材料；本次范围、预算和最终阅读仍分别核对，恢复本身不执行工具或发送 |
| 新段缺少无法重建的必要材料或绑定依据 | 记录缺口，结束本次续接准备；不拿相似模型、当前提示或缺页文本假装原样续接。明确换段须通过所属生命周期，而非在解析异常里自动替换 |
| 段格式版本不受支持 | 明确拒绝，不猜字段或丢掉未知字段继续 |

当前设计不需要 SQL 表／列转换，也不批量回填旧场景。上线仍先停机备份，同版更新消费者与生产者。**旧 SceneSession 使用 extra='forbid'，新字段一旦实际写入，旧程序会拒绝它**：届时回退须使用该版本写入前的同批备份，或在另行授权下离线定向移除仅活动段字段并记明丢失的续接状态；不得删原事件、改预算或重置业务状态。原设计批次未新增字段；当前原话窗口增量已经新增该字段，回退按现有运行手册执行。

## 6. 下一步必须先补齐的实施细节

以下是沿已确认方向可继续的源码工作，不是要求用户再次选择所有权：

- 固定材料的版本依据：当前人格、动态 Hook 与插件定义并非都有不可变定位；不能把 S1 部分快照直接当全覆盖。逐项建立明确装配变化入口，未具备依据的路径不声称稳定续接。
- 活动交换的可还原表示：复用原资料范围和分组逻辑，明确哪些协议回复必须原样保留；不得把通用审计投影作为正文来源。媒体同样需要重建原资格而非复用内存标记。
- Actor 保存与终结覆盖：普通循环的成功终结、拒绝、取消和提交后发布失败分别接通段记录；不把已有 exchange_checkpoint 的部分覆盖当全部完成。
- 容量与压缩交接：沿原历史维护互斥与知识版本提交新段，宿主从 pending_wakes、JobStore、open_loops 和出站事实附带未完事项。摘要不能结案或清预算。
- 当前段设计可编译实现后，人工核对多轮追加、部分原话、真实工具交换、正常重启、权限撤销与提交／送达分离。禁止用测试、伪造回执或另起未授权服务代替。

数据保留期限、公开稳定承诺及发布操作继续等待维护者决定／授权；不因本设计交付而自动通过验收。
