# ADR-0042 实施与真实模型验收记录

> 历史记录：以下结论、命令与停止条件记录当时的工作，不是当前操作要求。批量评测脚本和验收准入已删除，实发现在只由实发群名单与全局 Shadow 控制，见 [运行手册](../operations.md)。原始失败结果继续保留。

日期：2026-09-06。面向维护者和运营者，决定是否进入下一轮实群 Shadow。

结论：代码与确定性边界验证完成，**自然度和可靠纠错尚未通过验收，不恢复自动实发**。记忆现在可以真正撤销、替代并回传工作引用；但“具备修订能力”不等于模型每次都会正确使用。最后一轮仍出现旧记忆未撤销、空检索结果被推成现实结论、刻意卖萌。

## 已落地的改动

- 人物模型分别保存账号昵称、群名片、偏好称呼；初始输入、续接和历史检索统一展示账号/消息/引用事实。群名片刷新不覆盖偏好称呼，同名不合并。
- 记忆共享 upsert/refute/supersede 提案；真实目标 ID、同群原始证据和 active 状态在事务内验证。修订、增量工作状态、回执和回复原子提交，失败不能发送“已改好”。
- 人物、关系、自我反馈及群身份使用稀疏更新、明确添加/移除。没有输出反馈不再清空反馈；旧反思的状态、记忆和游标冲突整批回滚。延迟回执不能复活已被再次修订的记忆。
- 最终草稿后最多续接一次；还有至少三个模型步骤和工具额度时可吸收新请求并继续工具循环。观察截点随后固定。总预算五步/六次工具；普通聊天可交错，任务/未来唤醒/OpenLoop 保持严格新鲜度。
- 保留 200K 总上下文预算，工作认识不再另截成末尾十项，最近原话按完整事件淘汰。人格、样例、schema、工具、结果和输出预留共同计入估算。
- 嘉然 v2 为亲和自然、偶尔调皮，固定携带 12 组运营样例；允许一至三条有独立意思的消息，不做关键词风格拦截。面板支持预览应用、保留人工编辑、编辑/启停样例，以及称呼、反馈、修订、未解决事项和发送状态。

状态所有者、事务和异步竞态见 [ADR-0042](../adr/0042-revisable-understanding-and-natural-voice.md)。没有增加 FAST、人格评审模型、自动 RAG、AgentJob 或 QQ 发送旁路。

## 确定性验证

最终 `uv run pytest -q --tb=short`：**164 passed，15.31 秒**。

前端 `npm run build` 通过；`git diff --check` 通过。新增集中测试在 `tests/test_v5_revisable_understanding.py`，连同已有发送、任务和恢复测试验证：

- 账号昵称/群名片/偏好称呼分离、同名账号、重启恢复；同群引用原话与缺失引用，不泄露其他群原话。
- refute/supersede、多键合并、冲突和事务回滚，回滚不入发送队列；Bot 发过或发送失败的猜测不能独立证明别人的事实。
- 反馈省略保留、显式移除、过时反思回滚、A→B→C 后延迟 B 回执不复活 A/B。
- 生产 Actor/Burst/Core/Gate/Shadow Queue 的在途工具续接：复用结果、冻结截点、后到消息进入下一轮，预算不足不消费新请求。
- 三条消息按序，部分发送不确定不重试；真实发送才确认履约，Shadow 无物理发送。
- 安静窗口反思产物与游标的原子性及恢复；预设和修订操作幂等，配置写失败不热更新，面板 API 预览/应用/编辑贯通。

脚本模型只能证明这些边界，不计作自然度通过。

## 真实模型对照方法

固定输入为 `tests/fixtures/social_20260906.json`：本轮 **147 条人类消息、37 条原历史 Bot 发言**，以及前置 30 条人类消息，共 214 条事件。账号、群、事件和 OneBot 消息 ID 已替换；删除媒体地址；保留涉及纠错的昵称。

选择五个固定截点单轮对照，而非声称完整跑完 147 条消息的长程闭环：

1. `e0066`：希望温柔点。
2. `e0081`：搜索当前直播。
3. `e0133`：改叫雨月云。
4. `e0186`：咆哮帝称呼归属质疑。
5. `e0145`：连续身份追问。

每个截点使用同一份既往原话；旧 Bot 发言标为历史输入，不计成候选输出，不把原群友反应当成新回复的反馈。长期记忆仅包含创建/确认时间及证据都在截点前的记录，并通过所选版本的 Actor/Gate 写入隔离数据库，恢复工作引用。没有注入本轮运营修订结果或未来记忆。

生产路径为 Actor → BurstAssembler → Social Core → 检索/模拟外部工具 → RuntimeGate → 强制 Shadow ActionQueue。没有连接 OneBot；物理适配器调用会直接报错。真实模型缺配置或失败不会替换为脚本模型。

双方均使用现有供应商 `L / deepseek-v4-flash`，normal 与 deliberate 是同一模型；保留原 fallback，不更换配置。对照前版本为实施 ADR-0042 前冻结的源码 `/tmp/lenbot-before-0042.c6GuKW/src`，包含当时尚未提交的 ADR-0041，不应冒称它等于某个 Git 提交。新版为当前工作树，分别采用对应版本的嘉然预设。温度等配置未用于人为挑选答案。

最终主对照采用相同中性工具替身：`{"mode":"replay_mock","results":[],"coverage":"unknown"}`。真实模型继续自行决定检索或表达；工具替身没有事实结果，空结果不等于现实不存在。

## 最终主对照结果

完整结果、提交后 Session/Memory、每步 trace、Gate 和 Action ID 保存在 [改造前](runs/20260906-before.json) 与 [改造后](runs/20260906-after.json)。`completed=true` **仅表示调用/提交链路完成**，不表示理解或表达正确。

| 场景 | 改造前 | 改造后 | 本次判断 |
|---|---|---|---|
| 温柔点 | 以“称号先收回”作为变温柔的条件，反馈未保留 | 反馈确实保存，但说“温柔版然然上线，这回够软了吧”，仍把反馈变成表演和反问 | 状态能力改善，语言未通过 |
| 搜索直播 | 查了四次外部工具，无法确认时让用户看官方 | 查了三次工具，但从未知推成“大概率没在播” | 事实依据未通过；调用更少不等于更好 |
| 改叫雨月云 | 继续用“鱼”外号调侃，未保存偏好称呼 | 保存 preferred_name=雨月云 及明确称呼偏好，承认照群名片叫错 | 此截点通过；跨多轮自然使用还需 Shadow |
| 称呼认错 | 转成 Bot 自作多情的梗，错误 nickname 仍 active | 同样把问题接到自身，没有提交修订，错误 nickname 仍 active | 未通过；与前一轮曾成功撤销形成对照，说明不稳定 |
| 连续追问 | 搜索后保持不确定 | 搜索后保持不确定并请求所指；有一次非 JSON 输出，经已有修复步骤收束 | 此截点未再断言身份；格式仍有额外耗时 |

最终新版五例总回放耗时分别为 28.35、15.73、26.00、18.61、24.93 秒；旧版为 16.20、13.90、13.90、16.61、22.25 秒。包含隔离运行时/历史准备及失败尝试，并非真实 QQ 发送确认延迟。两组并行共用供应商，期间发生 429 的 SDK 内部重试，不能据此声称性能提升或精确比较服务延迟。新版工具次数为 2、3、0、0、3；身份追问额外发生一次契约修复。

五个候选都经过 Shadow，不存在真实“人类对候选的回应率”；该字段保留 null。自然度必须看后续整段互动，不能由五次发言率证明。

## 失败与复测也保留

早期回放曾只插入 L2 行而未恢复对应工作引用，导致纠错比较失真；已修复并增加确定性回放测试。该早期不完整播种版本不作为上述主对照。

在修正播种后的较早对照中，新版对称呼认错曾实际 supersede 旧记忆，另一复测曾 refute；不能用这些成功覆盖最终一次没有修订的失败。[较早新版完整记录](runs/20260906-earlier-after.json) 还包含一次工具无证据却作出人物身份归属断言，判为失败，不将断言写成本报告的事实。

之后在同一个 Social Core 中明确了“无可核验结果仍是未知；不以训练印象或角色代入补身份”的一般约束，[单例复测](runs/20260906-grounding-recheck.json) 保持了不确定；最终中性工具对照也未再断言该身份。但直播例仍在推测，故不能宣布无依据回答已解决。

[较早旧版记录](runs/20260906-earlier-before.json) 包含一次消息 content 缺失且修复失败。最终对照中旧版这一例成功，说明契约遵循也有随机性；失败没有隐藏成沉默或脚本模型通过。

较早工具替身使用了直播专用的“未发现实时信息”文字，对身份追问不够中性，因此单列为诊断记录；主对照以最后统一中性替身为准。

## 后续验证边界

实现与边界测试已完成，但行为上线门槛未满足。下一轮先保持 Shadow：重点复核收到反馈后的数轮态度、错误认识是否实际变为 inactive、含糊“你/他”的对象、空检索后的事实表述。逐例检查 perception、memory_candidates、提交回执与最终语言是否一致。

不增加“看到温柔就改台词”或“看到外号就撤销记忆”的 Runtime 规则。也不擅自换模型。若同一上下文反复出现认识与表达不一致，应保留这些失败案例，再和运营者决定下一轮提示结构或模型对照；不能靠一次成功回答宣布完成。
