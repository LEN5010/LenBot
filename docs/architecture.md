# 当前架构

面向维护者，2026-09-06。实施与切换状态见[实施记录](implementation.md)，操作见[运行手册](operations.md)。

## 事件、对话与表达

OneBot、感知插件和 Scheduler 提供事件。SceneActor 是事实 SceneSession 的唯一写入者，将原始事件与事实状态原子保存；它不等待模型。BurstAssembler 只做时间聚合。唯一社会认知入口 SocialCognitionCore 使用自然顺序的群友原话、真实已发送回复、当前工作和明确相处要求。

参与提示要求识别当前仍在继续的具体话和各自对象。新来的一句话不自动取代前一个问题；多人可分别回应，玩笑沿着前文中的具体对象继续。共同玩的设定只属于聊天语境，不转化为现实经历或实际能力证据。

对话 Agent 通过原生工具选择读取或提案。`finish_turn` 只接受零至三条由文字或图片片段组成的消息，空列表表示沉默。模型片段恰好填写 `{"text":"一句话"}` 或 `{"image":"P01"}`，不填类型字段；ProposalLedger 严格校验后解析本轮图片引用，转换为内部带 `type/text/asset_id` 的片段。content 由运行时生成，普通模型正文不会发送。工作、提醒、认识修订与 OpenLoop 关闭暂存在本轮 ProposalLedger，终结时经 Actor/Gate 原子提交。任何校验失败都会回滚，确认消息也不能入队。

终结工具使用内联基础 Schema，不向模型暴露 Pydantic 的判别联合；本地校验仍为权威，拒绝多内容字段、旧字段拼写和不可用引用。模型只收到有界的错误路径与修正提示，脱敏 Trace 保留具体失败。人工样例和在途表达在模型上下文中投影成同一格式，存储与管理 API 的内部消息结构保持。

普通文字或目录表情的成功路径可以一次模型调用完成。默认对话预算为 3 个模型步骤、6 次工具执行、24K 文本上下文、4096 输出 tokens。最后一个步骤指定终结工具，参数修正最多一次且计入预算。工具步骤之间可读取新增输入；终结草稿后不再吸收或改写。

强制收尾时请求只暴露终结工具，同时保留明确的工具选择和最后一步提示；供应商仍返回其他工具时拒绝该响应，不增加预算或执行未提供的能力。

普通轮次默认提供九个本地读取工具、三个新建提案工具和终结工具，共 13 个；修改、取消、恢复、认识修订、关闭等待与撤回暂存等管理工具，仅在本轮有已提供的对应对象或暂存提案时出现。每次模型调用前重新计算；读取和暂存可以让下一步看到相应操作。可见性不授予额外权限，终结与新建提案同批提交的能力保留。

主提示保留角色、参与、证据和表达原则。工作、提醒、等待及发送事实初次为空时省略；同一轮已经展示过的状态后来消失时，用空项明确更新。工作摘要、执行结局和未决项保留，详细约束与预算按需读取，不能将 result_ready 或中间观察解释为成功结论。

群聊以旁听为默认。运营配置的呼唤昵称、实际 @ 和已读 Bot 引用作为输入线索，私聊明确标为直接消息；昵称检测排除 CQ 片段与引用原话。命中不强制表达，未命中也不截断持续互动或工作回应。所有输入仍按原路径保存、读取和提交，不新增基于词表跳过认知的游标或调度旁路。

Actor 校验 episode lease、实际读取截点与 knowledge_revision。普通聊天按已读截点提交，后来输入留在数据库与待处理集合；工作控制、提醒、履约和等待回应要求没有未读输入。认识版本改变会拒绝旧轮次。对话模型仍在处理时若有新的人类输入，运行时取消这次未完成轮次并保留输入，让下一轮合并最新语境，避免旧结果在严格新鲜度拒绝后反复插入。运营操作走同一个 Actor/Gate，但不会消费尚未认知的人类消息。

工作提案被提交冲突拒绝后，下一轮在相关输入尚未消费时看到明确的“未提交”记录。它不是任务，不自动执行或恢复；对话 Agent 结合新输入重新判断。已提交的轮次不会因后续 trace 写入异常而被当作未提交。

下一轮可以读取最近已批准表达的发送状态：CONVERSATION_COMMITTED 按批次及片段关联同场景、同 Bot 的回执。尚无回执、已发送、未发送、拒绝、未知及 Shadow/模拟分别标注；晚于输入截点的真实回执作为独立运行时事实提供，不推进已读游标，也不授予消息证据引用。这样新输入到来时能看见在途表达，避免因上一条仍在发送而重新作答。@ 提及与引用原话统一使用本轮人物 U/BOT 引用。

## 事实与认识

| 持续数据 | 权威与更新方式 |
|---|---|
| events | 追加且不可变，带场景与来源 |
| scene_sessions | Actor 事实投影：身份、昵称/群名片、读取游标、版本、必要收发事实 |
| memories | 主体、类型、陈述、reported/inferred、原始证据、有效期、修订状态 |
| tasks / agent_jobs | 调度、工作目标版本、持久预算、资料引用及交付状态 |
| open_loops | 真实 MESSAGE_SENT 后才能激活 |
| tool_observations / media_assets | 受场景限制的资料、原图与来源 |
| runtime_dynamic_configs / voice_exemplars | 运营配置与人工表达参考 |

不再持久化气氛、发言欲望、兴趣、话题树、人物近况、关系容器或 episode 摘要。临时理解只进入 trace。角色资料和运营样例也不构成群友事实证据。

称呼和明确偏好通过窄 `remember` 提案提交，下一轮可直接提供仍有效的明确相处要求；其他认识由模型按需查询。记忆修订保留旧陈述、原始证据和撤销原因。看到来源位置不等于读过原话，引用须在本轮真正读取后才能用作证据。Bot 自己说过某句话不能证明实际能力、共同参与或群友事实。

后台 Reflection 复用 work 模型与 AgentLoop，只能查询认识并提出版本化修订和核对事项。提交时校验反思游标、来源和认识版本，将认识、核对事件与游标同事务保存；它不能创建工作或发送消息。

## 独立工作与模型底座

对话入口只开放本地历史、认识、媒体、已有工作资料与提案工具。联网查询、解题、计算、核实和整理通过 `start_work` 交给 InformationJobRunner。新建工作与提醒由工具生成暂存引用；拿到回执后，`finish_turn.ack_ref` 只列出当前有效的新建提案，确认消息与提案仍原子提交。未提交的协议错误和冲突只在对应输入尚未消费时作为失败记录提供，不创建任务、不自动重试。

模型工具能力以注册的只读工具定义为准；`calculate` 核对数值算式，`finite_check` 对整数范围、条件和目标做完整枚举，返回数量、极值和见证。最多八个变量、25万组合、两千万估算节点访问及五秒执行时间，在线程中运行；超限或超时明确失败。表达式只允许受限算术、比较、布尔组合与 min/max，无任意代码、文件或网络访问。枚举只验证所给模型，不证明模型覆盖原题；未核实的假设与矛盾仍须保留。

网页搜索通过 Bing 公开 RSS 返回标题、来源和摘要；结果会按原查询的词项做最低相关性筛选，并在查询包含 `site:` 时再次校验返回域名，避免把结构正常但偏题的 RSS 行当作资料。服务不可用时只对当前工作停用该搜索工具，后续可读取已知原始来源；参数填写错误不因此停用。`read_page` 保留最多24个图片与12个PDF链接，并可提取PDF的文本层；`read_web_media` 按需读取公开原图或指定PDF页面，走相同网络限制和场景隔离。外部图片与工具观察在同一事务登记，来源指向观察事件，curated=false，不进入运营图库或global-safe。

PDF处理使用独立可终止进程：下载最多10MB、100页、20万文本字符；渲染一次一页、最长边2048，CPU最多8秒、进程等待最多12秒。没有文字层或发生截断均明确标记，原图覆盖仍由六张原生图片窗口限制。文本层不是图表像素，图表结论需读取对应图像。

工作终结与进展检查引用是否来自本工作，以及资料是否可用。已尝试外部查询却只有失败、搜索摘要或本地聊天，不能标为全部核实；有已验证算式的给定数据计算可以独立完成。此检查验证来源可用性，不声称证明结论语义正确；原对象与同名候选仍由认知按原始请求和来源判断。Trace 同时记录调用状态和观察资料状态，调用结束不代表读取成功。

准备回答陌生概念、外部事实或时效信息时，对话 Agent 主动建立查询工作，无需额外收到“搜索”指令；不会通过重复检索群史来替代外部查证。工作上下文带当前时间，来源需核对对象、日期与适用范围。

工作使用 tasks 和 agent_jobs 的同一 ID。Scheduler 持久认领后执行；默认每群一个、全局两个运行工作，预算为 16 个模型步骤、24 次工具、300 秒、64K 上下文，单次输出上限使用 work_output_tokens（默认 16384），计入上下文预留。补充和取消继续由对话 Agent 处理，修订保持预算和已取得的资料。工作结果含总结、资料引用和未决事项，经 AGENT_JOB_PROGRESS / FINISHED 回到对话入口；结果完成与实际送达分开。

模型的 finish_work 只提交 summary、result_ids、unresolved；未决项为空时形成 completed，否则形成 partial。失败和中断由运行时记录，不让模型重复填写与未决项相矛盾的状态。持久化 JobResult 与查询 API 仍保留完整状态。

tasks.status=result_ready 表示终态资料等待对话处理，不表示执行成功。查询与模型上下文另外提供 execution_status 和 can_resume。失败／中断可在保留预算和资料的前提下显式恢复，partial 不因此重开；失败可以通过 work_ref 说明，但只有 completed/partial 执行结果可关联履约。单次算式与检索记录仍是中间观察，不能代替完整结论。

重启保留已持久化结果的待回应阶段；只有尚无执行结果的在途工作进入 review_required，等待显式恢复。旧待核对状态若已有当前版本执行结果，按该事实恢复 result_ready，再唤醒对话核对；不会因此重跑工作或自动确认送达。awaiting_delivery 仍恢复为 delivery_unknown，不自动重发。

ModelGateway 固定一次运行的提供商、模型、推理强度及客户端。conversation 与 work 独立配置，Reflection 使用 work；热更新在新轮次或新工作生效，同一工作修订仍保留原绑定。没有同轮型号切换、跨型号 fallback 或独立视觉路由。

AgentLoop 使用非流式原生调用，模型返回的完整 assistant 续接记录原样保留，包括未知供应商扩展、签名、参数字符串及调用顺序。只读工具可并发完成，回填仍按原调用顺序。终结和读取工具不能出现在同一批，以免未读工具结果就提交；终结与暂存提案可同批原子确认。

历史、工具资料和媒体的场景范围由存储查询执行。历史检索额外在 SQL 中限定实际读取截点；资料内容、网页和图片不是新的系统指令。只有运营显式发布的素材能进入 global-safe。

## 原生媒体与发送

MediaService 负责受控下载、文件校验和缩放，不调用视觉模型。当前及引用图片直接进入对话模型请求，同一窗口内按资产去重，当前图片窗口最多六张、最长边 2048；额外图片或已移出的图片可通过 `read_media` 换入窗口，未装入或被移出的范围在 trace 中明确记录。动图仅覆盖首帧。下载仍受 10MB/20MP 和网络边界限制。

运营目录固定最多 20 项，提供短引用、说明和标签；按场景、素材版本、顺序和启停状态缓存。完整素材库通过 search_media 检索。模型选定图片后必须调用 read_media 读取像素，实际发送始终读取获准原图。表达样例按固定顺序提供，可包含文字、单图或混排。

运营明确标记为 `表情包` 的素材以 QQ 自定义表情类型发送，普通图片保持原类型；原图字节不改动。先判断是否参与，再选择文字、单图或混排。单图可以完整回应，不要求附加解释，也不因近期连续用图就普遍转向文字；不使用硬性比例或随机开关。

Gate 校验素材可用范围，ActionQueue 在真正发送前再次核对素材、工作版本与运营配置。同群保序，跨群可并发；失败或 unknown 停止同组后续消息，unknown 不重试。sent / not_sent / rejected / unknown 保持不同事实，只有真实 MESSAGE_SENT 确认送达、履约或激活 OpenLoop。

实发群名单与全局 Shadow 是唯一运营发送控制。默认 Shadow 开启，初始名单为 group:126300994；沿用运营保存值，源码、模型和人格变化不会清空名单或重置任务。Shadow 只形成候选记录，不伪造真实发送。

## 控制面板与验证

读取统一经过 RuntimeQueryService。场景页显示近期对话、参与者事实、明确偏好、实际工作和回执；认识页展示账本和修订链。设置页可编辑额外呼唤昵称，默认“然比、小然”；保存值优先，省略字段保留，空列表清除额外昵称。Bot 的呼唤昵称属于运营配置，与群友偏好称呼分开。管理干预记录 OPERATOR_ACTION 并走 Actor/Gate，撤销认识需明确理由。模型凭据只在保存配置中使用，响应和 trace 脱敏。

trace 记录实际提供商和模型、每步开放工具、呼唤线索、原生工具调用、终结候选、媒体来源、读取截点及具体拒绝原因，不记录原始图片或供应商签名。运行记录页同时显示新模型格式和历史内部格式的图片提案，不改写旧 Trace。模型失败保留原因和输入游标，不无限自动重试。

生产问题以原话、时间、工具结果和发送回执定位。内部 ReplayLab 使用隔离库和生产路径，始终输出 Shadow；没有日常评分、报告导入或固定消息数要求。真实效果仍回到群聊确认。
