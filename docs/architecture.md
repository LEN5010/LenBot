# 当前架构

面向维护者。产品语义见[产品行为](product.md)，起停与切换见[运行手册](operations.md)，本轮实现状态见[当前任务](iteration.md)。

## 正常链路与所有权

运行参数进入 Runtime。OneBot、感知插件和 Scheduler 产生事件，SceneActor 在同一场景写序中先确定交互归属，再保存事实与注意力进度。普通消息进入注意力和 SocialCognitionCore；精确日程命令进入确定性图片处理；真实新开播进入同一个 AgentLoop 的窄公告模式。三种表达都由 Actor 和 RuntimeGate 提交，再进入 ActionQueue 与真实回执。`start_work` 和 `summarize_group_chat` 暂存的工作由 InformationJobRunner 执行，资料与结果回到原请求群。

| 模块 | 唯一职责与边界 |
|---|---|
| `events/store` | 追加事件、持久事实和事务；数据库保存持续状态，模型上下文不作永久存储 |
| `scenes` | 事实 reducer 与 SceneActor；Actor 是 SceneSession 单写者，不等待模型 |
| `cognition` | 临时上下文、原生循环、短引用和暂存提案；SocialCognitionCore 是唯一社会判断入口 |
| `runtime` | 生命周期、Gate、信息工作、预算与调用账；工作和维护不能直接发送 |
| `scheduler/actions` | 持久认领、到期事件、队列、显式传输与回执 |
| `memory` | 单一认识账本与增量历史维护；不持久化模型生成的气氛、兴趣或工作世界 |
| `skills` | 有来源、场景与版本的方法文档；没有额外执行权 |
| `plugins/tools` | 真实资料读取或工作提案、工具观察和范围查询；不直接调用模型或发送 |
| `media` | 原图读取、解码与窗口装配，运营素材及其来源；不调用独立视觉模型 |
| `adapters` | 协议归一化、唯一消息连接与获准传输 |
| `web` | 读取经过 RuntimeQueryService，干预使用事件与提案接口，不直接读取私有容器或数据库 |

事件追加且不可变。Session、认识、任务、工作与等待状态由事件或获准提案更新；原始证据、撤销记录与历史身份保留。认识、工作状态、回执关联和行动提案同事务提交，冲突回滚后确认消息不能入队。运营干预记录 OPERATOR_ACTION，不确认未读的人类输入。

## 配置与持续数据

ConfigStore 从当前项目根目录的固定 `lenbot.config.json` 读取 RootConfig。runtime、models、delivery、access、scenes、time、members、plugins 各节在配置入口解析，插件保留已解析类型供构造使用。未配置插件为 `enabled=false, config=null`，业务时区未配置为 null；不能启用缺少必需时间或成员资料的能力。样例、环境变量、CLI 与数据库不参与覆盖。模型连接取得实际凭据与端点，网络客户端显式禁用环境继承，连接参数变化时更新客户端。

面板保存持有 Runtime 的 config_update_lock，先验证完整候选并替换根文件，保存成功后发布内存设置。人格、注意力、发送与新轮次模型设置按对应入口生效；需要重新建立运行组件的参数记录需重启，不自动重启。文件失败就是保存失败，没有数据库替代写入、配置指纹或文件监听合并。

SQLite 继续保存事件、账号、认识、人工样例、素材与来源、工作模型绑定、技能、资料、检查点和运行结果。它退出运行参数覆盖源，不迁出上述业务记录。人格模板只返回候选字段和参考；操作者选择字段填入草稿，再正常保存配置，样例另经现有数据库接口逐条保存，结果分别呈现。

## 输入、注意力与实际阅读

事件保存、注意力扫描、摘要覆盖、本轮原文读取分别持久记录。AttentionPolicy 在事件事务前提供观察机会，扫描位置与待处理唤醒和原话同事务保存；BurstAssembler 只按到达时间聚合获得机会的输入。它们不替模型判断发言。

Actor 提交时校验 episode lease、实际读取集合、读取截点和 knowledge_revision。普通聊天可按实际读过的快照提交；工作控制、提醒、履约与 OpenLoop 还须读取待处理确定唤醒及快照后的有关场景输入。未装入、只有定位或片段不完整的来源继续待处理。认识版本或租约失效结束提交，不进入通用重试循环。

TurnReferences 将本轮短编号映射到真实 ID。历史目录只授予定位，持久记录使用真实事件 ID，跨轮回读重新绑定短编号。长原话与引用按字符范围提供；范围并集完整之前，不能使用整条原话作证据或确认对应唤醒。历史查询还在 SQL 中限制场景与允许读取截点。

MESSAGE_SENT 为实际回应来源建立正常短时关注；在途来源单独记录。最新发送状态以批次、action_id 和片段关联到原提交，晚于输入截点的回执作为独立运行事实，不推进原文读取位置或授予证据权限。

ScenePolicy 直接读取当前根文件中的群字段与全局 QQ 回复白名单。群停用时继续保存接入的原话，但不进入认知或发送；chat 关闭群只有白名单请求者获得普通对话资格。请求人以独立 requester_qq_uid 随工作、提醒与完成事件保存，系统 actor 不能替代其来源。插件是否开放由具体群和当前全局插件状态共同决定，定义展示和实际调用都检查当前值。

精确日程命令、实际响应及经真实 reply message_id 找到的评论在事件中记录 interaction 与 conversation_excluded。同一归属用于注意力、Mailbox、默认近期原文、轮中新增原文、历史维护和回应关注；明确的总结查询仍可读取这些人类消息。控制提案只要求补读尚属普通对话的新增输入，日程交互不构成未读控制阻塞。没有引用证据时不作语义评论分类。

## 对话循环与提案

ModelGateway 和 AgentLoop 供对话、工作与维护共用。一次运行固定提供商、型号、推理强度与客户端；三角色分别配置，没有继承、同轮切换、跨型号 fallback 或独立视觉路由。新配置用于新轮次，已启动工作保留原绑定。原生 assistant 续接、供应商扩展与工具调用顺序保留在私有运行数据中。

模型通过窄原生工具读取与暂存。`finish_turn` 接受零至三条消息，空列表表示沉默；片段恰好填写 `{"text":"一句话"}` 或 `{"image":"P01"}`。ProposalLedger 在提案入口校验，转换为内部 `type/text/asset_id` 片段。MessageProposal 与 ActionItem 以必填 segments 为唯一消息主体，content 只读派生；Gate、MediaService 和 OneBot 不按 content 重建发送正文。普通模型正文不发送，消息及工作、提醒、认识和等待提案共同提交。

只读工具可并发取回，按原调用顺序回填；读取工具与终结工具不能同批，以免尚未读到结果就提交。管理工具随已提供对象和暂存提案展开，可见性不改变执行权限。最后一个模型步骤只开放终结工具，仍受原预算约束。非法协议、未知工具、无法解析参数和无效终结候选直接结束本次并记录错误，不追加格式修正请求；正常工具失败仍以标准错误观察返回，在原有后续步骤处理。

完整工具交换后才能吸收新输入。`FreshInputConflict` 表示候选因晚到输入未提交：保留匹配工具结果，在同一运行和同一预算内续接。它不等于供应商失败、非法协议或版本失效后的自动恢复。成功提交后不再吸收新输入；未提交记录只帮助后续真实输入重新判断，不创建工作或自动重试。

### 整组工具页与容量

ConversationContext 按实际消息、动态工具 Schema、原生图片估算和输出预留装配每次请求。稳定人格与人工参考前置；原文、当前事实优先于辅助目录与摘要。有效输入容量为配置的总上下文扣除输出预留。

原始工具观察先完整保存，ObservationPage 只描述本轮展示位置、偏移及已知结构。完整工具组共享下一次请求的剩余额度：先保留匹配工具回执、新事实与新原话，再分配资料页，同时计入最终提示。装不下的正文保留定位与续页；试算后未采用的页、片段或图片不更新实际读取集合。`pack_tool_pages` 的容量试算、状态撤销和回执配对仍承担这些职责，不为了缩短代码改写。

插件 handler 每次接收不可变 PluginCallContext，包含 scene、请求者、时钟、快照、episode/job 与当前 Ledger；共享插件实例没有可变 current_scene。读取定义声明角色与是否延迟发现，返回 ToolResult；提案定义只暂存到现有 Ledger。Toolkit 不按相同参数盲目复用旧结果：源的有效缓存由具体服务维护，原观察按 result_id 显式续读。conversation 与 work 的整组展示共同复用 pack_tool_pages，实际展示后才更新原文覆盖。

运行事实只追加变化类别，已提供类别消失时显式清空；保存观察本身不重复装入相同工作列表。历史查询中的旧工作版本不能覆盖当前目标版本。分页不追加工具执行或模型步骤，不引入额外压缩模型。

## 工作、任务与交付

InformationJobRunner 使用现有 tasks 与 agent_jobs，同一工作共用实际 ID。任务存储读写 TaskItem，固定列在存储边界解析一次；payload 必须是 JSON 对象，可选 wake_match 区分 SQL NULL 与坏 JSON，不用行长或任意对象猜旧形状。Scheduler 持久认领后追加 TASK_DUE。恢复时只把匹配任务、场景与本次触发的待投递事件视为该次认领；已执行却没有持久结果的工作进入待核对，已有当前结果保留待回应，未知送达不自动重发。

新工作与提醒返回当轮暂存引用，确认只引用实际新建提案。确认动作通过事务内保存的唯一 `ack_action_id` 定位对应工作，再校验实际 ID 与版本；不能按跨轮重复的 `S1` 等短编号搜索历史任务。

工作保存目标版本、已用预算、原始资料和简短 work_state。完整 assistant/tool 交换形成检查点，图片只保存资产引用；查询接口只暴露元数据，不暴露供应商私有续接。显式恢复使用最后完整检查点与原绑定，暂停时间不算执行时间，已取得结果不重做。

长结果先换成可续读资料引用；仍需压缩时，maintenance 只整理确定的旧完整工具组，保留近期原生交换、目标与未决项。压缩使用同一工作预算；失败或未缩小不发布覆盖，原交换和观察不删除。

`finish_work` 提交总结、资料引用和未决项，运行时据未决项形成 completed 或 partial，失败与中断由执行层记录。`tasks.status=result_ready` 只表示终态资料待回应，另以 execution_status 表达执行结局。资料必须属于本工作且可用；搜索摘要或失败观察不能冒充外部查证完成，来源可用性也不证明自然语言结论正确。

群总结只在原 task.payload 增加 work_operation、requester_qq_uid、summary_range 和 summary_coverage。绝对范围与快照由提案固定，修订沿已有 revision；统计与分页复用同一 scene、时间半开区间和 rowid 上界条件。默认只读本群非 Bot 的真实人类消息，保留日程命令和评论。分页位置是存储顺序，引用来自原事件；资料取回不等于模型已读，展示范围决定实际覆盖。预算用尽或尚未读取全部匹配记录时结果明确 partial，不新增调度器、模型流水线、群史库或自动技能维护。

## 认识、维护与方法技能

认识账本保存主体、陈述、reported/inferred、原话证据、有效期与修订链。前台即时记录明确称呼、偏好和相处要求，其他认识按需读。角色资料、模型摘要和 Bot 自己的发言不能独立证明群友事实或现实能力。

HistoryMaintainer 只处理新增原始范围，同批生成摘要与稀疏认识提案，由 Actor 原子保存摘要、认识和覆盖。长事件使用稳定字符分段，文本维护中的图片只记定位和未解读范围。失败、中断或认识冲突不推进覆盖，失败范围由显式操作重试，不因下一条新消息自动重做。

技能目录按需读正文并绑定版本。有实际工作结果或明确纠正的候选才触发一次 maintenance；自动内容限来源场景，人工内容不能自动覆盖，公开针对指定版本。同一场景、工作和目标版本下完全相同的候选正文复用已有 ID，不同正文可分别保存；新候选使用随机身份，历史身份和来源引用不重算。历史维护、工作压缩与技能整理均无创建实际工作、任务或发送的权限。

## 工具、媒体与传输

插件生产者、Host、Toolkit、工作与维护读取使用 ToolResult；外部协议在生产者解析，持久观察从已知 JSON 结构读回，不使用任意字符串成功包装、包含判断或文本猜状态。工具执行失败由工具边界形成错误结果，供应商失败由 Gateway、事务失败由提交处负责。原始观察、ObservationPage 与读取授权保持不同职责。

内建插件由一个显式目录注册表加载，日程、动态和原有网页/B站工具没有旧单文件 alias。ICS 仅用配置来源，保留源 UID、时间、取消与更新时间，未支持的源结构明确失败。动态服务只使用原站实际接口，详情只读已取得且仍有效的源记录。公共缓存不按群重复采集，进入 Agent 的观察仍属于调用群；到期刷新失败不延长旧数据有效期。

直播只有一个公共采集循环，首次样本建立基线，之后以真实 `(room_id, started_at)` 识别新场次。每群通知使用源场次与 scene 组成的事件身份，由现有事件唯一键在进入模型前去重；生成状态与失败在 trace，提交与发送状态沿原事件和 action 回执，无第二套投递库。窄公告只装人格、明确主播/标题/链接/场次与公告参数，仍使用 conversation 绑定和 AgentLoop；不装整群历史或 pending wakes。

命令与公告的 output_kind、来源事件和订阅对象由 Runtime 绑定，模型只提交正文。Actor 对这种原生输出核验实际命令或场次来源，不取得普通聊天租约，也不冒用 operator；它只能提交表达，不能夹带工作、认识或其他控制。群、插件、命令、订阅和当前场次在提交与发送前复核。全体提及是 Runtime 专用 ActionSegment，普通 MessageProposal 不接受它；OneBot 固定编码为 `at` 的 `qq=all`。

历史、工具观察和媒体的场景隔离在 SQL／存储层执行，global-safe 素材由运营显式发布。现存网络策略限制可访问目标，本轮不扩建或放宽其权限。

网页搜索返回标题、来源和摘要；read_page 提取正文并保留图表与 PDF 入口，read_web_media 按需读公开图片或 PDF 页。受限计算与有限枚举只执行所提供模型，范围、条件与未核实假设必须保留。外部原图与工具观察同事务登记为来源场景资料，不自动进入运营库。

MediaService 读取获准文件并解码、缩放，不计算内容校验和。新文件使用随机文件名；已登记资产继续使用原 path，不重新编号、下载或拆开历史共享文件，同一资产复用已有文件。当前像素集合从实际消息块同步，压缩或恢复不会把历史读图永久占作当前窗口；换出图片仍保留来源与覆盖记录。缺失、未装入、截断和只覆盖首帧各自明确。运营目录只提供定位、说明与标签，发送使用获准原图；无人调用的目录联系表渲染已退出。

ActionQueue 在实际发送前复查素材范围、工作版本、当前群及输出类别；全局 Shadow 单独维持观察语义，独立实发名单退出。同群保序、跨群可并发；失败或 unknown 停止同组后续片段。真实 MESSAGE_SENT 才确认送达、履约与聊天 OpenLoop 激活，命令和公告不建立社交关注，Shadow 和模拟不产生这些事实。

OneBotAdapter 管理一个消息连接，显式选择主动或反向 WebSocket；发送单独选择 WebSocket 或 HTTP。HTTP 不成为第二事件源。连接断开使在途 echo 请求明确结束，主动连接按现有间隔重连；一次发送只尝试选定通道，结果不确定不跨通道重试。令牌不在读取 API 中返回。

## 面板与记录

Vue Router hash history 管理页面、对象、筛选与分页，Vuetify 提供控件。正文与凭据不进入 URL 或浏览器持久存储。管理列表返回 `{items,total,page,page_size}`，消息时间线使用原始 rowid 游标和首次 snapshot_rowid；有限配置目录和固定素材目录明确完整返回。

RuntimeQueryService 统一生成有场景范围的公开投影；原话安全显示，媒体走鉴权接口，磁盘路径、凭据和私有续接不外露。写操作经现有事件／提案边界，保留具体失败，不自动重试。迟到响应不覆盖新对象，未保存草稿和旧读取时间明确显示。

ModelGateway 在真实请求前创建唯一 model_calls 记录，成功、失败或取消结束同一账目；中断留下未确认。供应商原始 usage 与本地估算分开，推理 token 不重复加算，费用无价格依据时未核实。Trace 记录 call_id、tool_call_id、真实 result_id、observation_event_id、状态与 usage，不计算续接、结果或错误参数的内容摘要；私有续接原样留在检查点，大段资料留在原观察。Trace 不能代替原始事件、资料或送达回执。

## 必要术语

| 术语 | 边界 |
|---|---|
| Scene | 群聊或私聊的持续隔离范围 |
| SceneSession | Actor 保存的身份、游标、版本与收发事实投影 |
| Read Cutoff / Original Read Set | 快照上界／实际提供原文的集合；上界不表示以前全部已读 |
| Attention Scan / Pending Wake | 调度扫描位置／尚未成功提交确认的观察来源 |
| Episode Lease / Mailbox | 本轮执行权／新输入通道 |
