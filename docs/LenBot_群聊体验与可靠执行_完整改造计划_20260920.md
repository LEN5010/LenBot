# LenBot 群聊体验与可靠执行：完整改造构建计划

> 日期：2026-09-20；源码审阅基线：`6b115aa`。  
> 状态：待实施的设计与施工合同，不是已实现清单。  
> 目标：让运营者能管理清楚，让群聊参与有分寸，让回答有依据，让纠正确实影响下一次行为。  
> 范围：现有全部业务模块的职责、接口、页面、数据、实施顺序、正常人工验收与发布。覆盖全部模块不等于重写全部模块。

本计划替代此前的社会能力总计划和文件交付/群配置计划。用户已明确解除旧总计划的文件保护并授权移入系统回收站。旧编号不是本批待办；已实现能力保留，未确认部署条件不得因为换计划而自动放行。当前行为以[架构](architecture.md)、[上下文](context.md)、[运行手册](operations.md)和[插件合同](plugins.md)为准，实际观察只记[当前任务](iteration.md)。工程限制以 [AGENTS.md](../AGENTS.md) 为准。

## 1. 产品目标与范围

### 1.1 必须交付的结果

| 编号 | 用户能够观察到的结果 | 不能用什么替代 |
|---|---|---|
| U01 | 找到某个群、看懂当前状态、在唯一入口修改本群设置，返回原消息不迷路 | 新主题色、更多卡片、另一个配置向导 |
| U02 | 看清一条消息未回复、查询中、失败或送达的实际阶段 | 统一显示“处理中”、模型事后编写理由 |
| U03 | 直接问题能接住，别人互聊不乱接，话题继续能跟上，没有新内容能潜水 | 更高发言率、定时刷存在感、永久情绪值 |
| U04 | 短事实问题按需查来源、读正文或计算后回答；不能核实时保留具体缺口 | 搜索过就当核实、失败当无结果、凭旧知识冒充最新 |
| U05 | 旧事可按人物、时间和内容找回原话；有效偏好在互动中生效 | 仅增加窗口、摘要条数或向量库规模 |
| U06 | 明确纠正立即改变下一句；必要的认识修订在下一次取用时仍生效 | 只说“记住了”、仅新增一条与旧认识冲突的记录 |
| U07 | 长工作有原目标、资料、进度、累计预算，能明确取消/修订/恢复 | 每一步新建工作或子代理、恢复后重新计算额度 |
| U08 | 资料整理能形成成果，文件能沿已确认平台协议实际交付 | 本地路径、已生成资产、文字声称已发送 |
| U09 | 每次模型/工具/压缩费用和执行失败能归到实际互动或工作 | 只看最终回答、只看缓存命中率 |
| U10 | 主动分享、睡眠、订阅、账号动作和可选服务保持各自资格与真实状态 | 因改善聊天而隐式打开全部插件或权限 |

### 1.2 本批不做

- 不更换数据库、Web 框架、Actor/Gate、登录、原事件和送达账本。
- 不自动修改人工人格、角色原始资料、表达样例、模型绑定或实际群名单。
- 不新增通用情绪/好感度数据库、永久话题树、真假评分、审查模型或权限平台。
- 不为每条消息自动语义检索、反思、搜索、创建工作或维持缓存保温。
- 不实现无限递归代理树，不接入两个外部循环，不整体迁移 Harness。
- 不扩大联网、账号、文件格式或跨群信息范围；没有场景需求的不新增能力。
- 不运行测试、夹具、断言探针、自动回放、自动截图、压力任务或模型评审。

## 2. 当前基线与问题性质

### 2.1 已有基础，禁止重复建设

| 领域 | 当前源码已存在 | 本批要补齐 |
|---|---|---|
| 社会参与 | AttentionPolicy、短期观察、focus、输入合并、沉默、轮中增量输入 | 对象与未完事项的清晰呈现、自然结束、阶段可解释 |
| 认知执行 | 对话/工作/插件/维护共用 ModelGateway 与 AgentLoop | 稳定工具接口，减少本轮数据进入 Schema，区分行动与表达 |
| 原话与回忆 | EventStore、历史摘要、同群检索、语义索引、明确偏好投影 | 需要时正确选择回忆入口，正确使用范围与有效版本 |
| 认识纠正 | remember/refute/supersede、版本、来源和有效期 | 即时采用与下一次取用连贯，UI 能查看修订链 |
| 工作与方法 | JobStore、原生 checkpoint、WorkCompressor、技能候选 | 工作类型边界、恢复解释、来源与方法的实际使用 |
| 资料与执行 | ToolResult、分页、Python、Gateway、浏览器、媒体 | 取得/展示/读取不混淆，部署条件在面板准确可见 |
| 交付 | Gate、ActionQueue、文件资产、消息/文件回执 | 完整流程的正常人工确认，清楚呈现结果与送达区别 |
| 面板 | Vue/Vuetify、六组导航、SceneInspector、实体链接、能力事实 | 唯一群工作台、稳定返回路径、简明说明和主动作 |

### 2.2 已确认的具体设计问题

1. `/groups/:sceneId` 和 `/scenes/:sceneId?tab=settings` 都编辑同一表单；群级、全局和技术配置入口不统一。
2. 群列表帮助与本群旁听覆盖表单不一致；workspace enabled 推导的“工作”标记不代表部署及请求者资格。
3. 提案工具、部分读取工具和 `respond` 参数随本轮资料增删；终结阶段再次缩工具表。工具集合变化已观察到缓存代价。
4. 普通回复的 `source` 表示回应哪条原话，不是答案依据。已有工具日志不等于已关联每条回答的材料。
5. 字面回忆预取只覆盖有限线索，不替代模型主动回忆；大窗口不证明旧事能正确取回。
6. 对话即时认识修订、历史维护、工作技能学习是不同路径。普通短对话的纠正不能被当成已经发布了方法技能。
7. 一些文档把历史观察、当前机制与未来要求混写，甚至存在“Schema 已稳定”等与代码不符的描述。

具体遗忘、误接或幻觉仍须定位实际轮次；本计划不把以上静态问题当作所有失败的统一根因。最新缓存及部署观察见[当前任务](iteration.md)，不据旧报告宣布固定 TTL、容量淘汰或当前运行成功率。

## 3. 总体设计与所有权

### 3.1 唯一业务主链

```text
OneBot / 感知插件 / Scheduler
  → 原始事件与交互归属
  → SceneActor：本群单写者、阅读机会与轮次身份
  → SocialCognitionCore：判断参与，按需读取/计算/委派，形成提案
  → ProposalLedger + RuntimeGate：同事务核对和提交
  → ActionQueue：发送前再核对 → 平台真实消息/文件回执

已提交的工作 → JobRunner → 工具/执行/资料/结果
                                 ↓
                     原完成事件返回 SceneActor

历史维护 / 认识修订 / 方法候选 → 各自原存储与版本
面板 → RuntimeQueryService 读投影；管理操作仍走原配置锁或 Actor
```

模型决定社会含义，宿主负责身份、范围、版本、额度和真实状态。面板和模型可以读取同一来源事实的不同投影，不能互相将展示文本当权威，也不能用 UI 聚合结果回写业务状态。

### 3.2 本批继续有效的边界裁决

| 编号 | 裁决 |
|---|---|
| B01 | 普通聊天、主动研究、兴趣分享、文件发送、账号写入独立授权；开关不隐式产生 grant |
| B02 | human/system/plugin 来源、授权主体与计费主体分开；不伪造 QQ 请求者 |
| B03 | 群管理员不等于面板运营者，自报身份和模型文本不能提升权限 |
| B04 | 原话、摘要、认识、工具资料、工作结果、方法和送达回执各有用途，不相互冒充证据 |
| B05 | 绝对期限从工作首次开始计算；等待与停机不延长，恢复不清零；实际数值只来自根配置/原工作快照 |
| B06 | 预占及工作创建同事务；所有实际调用归原账，取消和晚到 usage 不擦除费用 |
| B07 | worker/Gateway 后端明确二选一；未知执行、未知发送和未知账号动作不自动重放或切后端 |
| B08 | 自主公共研究不读私人群资料；联网 Python 与账号能力沿原明确范围，不以脚本能力扩大授权 |
| B09 | 既有敏感业务动作审查保留；不扩展到所有网络包或普通离线计算，allow 不替代当前授权 |
| B10 | 睡眠保留消息与维护；既有确定性只读服务例外不扩大到所有 handler 或模型调用 |
| B11 | Core 独立可选；系统模块分类不意味着必需核心可热卸载 |
| B12 | 保留搜索、读取、浏览器、媒体等清晰原语；不引入隐藏规划器或万能 research 黑箱 |

这些裁决承接旧计划的职责边界，不继承旧计划尚未确认的额度数值、生产名单或操作授权。

### 3.3 术语与判定范围

- **观察机会**：允许考虑读取，不是已读、请求或发言义务。
- **已读**：内容实际进入请求且有确认提供记录，不是目录命中。
- **已处理**：本次来源有明确处理结局；读取不自动等于解决。
- **潜水**：不发言但继续按资格接收、记录及观察；不是失败状态。
- **记住**：来源和范围正确的信息能在需要时取回，且修订后不会沿用失效版本。
- **查证**：取得并实际读取支持当前对象与结论的材料；搜索标题不等于完成。
- **学会方法**：保存有依据的适用步骤与限制，不是改模型权重或人格。
- **工作完成**：形成与目标对应的完整/部分结果；**交付完成**只由真实回执确定。

## 4. 前端产品与交互设计

### 4.1 信息架构与路由收敛

主导航收敛为“群聊”“工作与交付”“记忆与方法”“系统设置”；运行概览保留为首页。高级诊断从当前对象或系统进入，不再与日常操作争夺第一入口。

优先沿用已有 `/scenes` 作为群工作台，减少 EntityLink 与消息定位改动：

| 现有入口 | 目标入口/处理 | 必须保留 |
|---|---|---|
| `/groups` | 跳转统一 `/scenes` 群目录 | 搜索、权限筛选；不能在跳转时启用新群 |
| `/groups/:sceneId` | `/scenes/:sceneId?tab=settings` | 群身份、未保存草稿提示 |
| `/scenes/:sceneId` | 唯一群详情 | event 定位、分页快照、滚动位置 |
| 原 messages/settings | 对话/本群设置 | 原配置事务与读取接口 |
| 原 history/attention/participants/preferences/deliveries | 更多诊断或消息侧栏；旧深链接继续准确打开对应内容 | 不把旧链接全部粗暴回首页 |
| `/jobs`、`/jobs/:jobId` | 全局列表及唯一工作详情 | scene、原请求、来源和返回上下文 |
| `/memories`、`/skills` | 同一资料区的认识与方法页 | 各自数据合同，不合并成一个可任意编辑的对象 |
| `/agent/settings`、`/models`、`/plugins`、`/settings` | 系统区子页 | 人格、模型、连接和插件的原保存端点 |
| `/agent/capabilities`、`/activity` | 本群入口可直达的能力详情/高级诊断 | 场景与请求者筛选、原始记录 |

路由转换集中在 router，不让每个按钮各自拼一套迁移逻辑。已存在的外部书签和 EntityLink 保留兼容 URL；兼容仅为导航，不新增第二套业务 API。返回链接只允许应用内路径，不携带秘密。

### 4.2 群工作台布局

桌面布局：左侧群列表；中间当前群消息/子页；右侧按需展开的对象详情。右侧默认不挤占正文，窄屏改成全页详情，关闭返回原定位。

群头固定展示群名/群号、聊天模式、保存与当前运行差异、待处理问题摘要。主子页为“对话”“本群记忆”“工作”“设置”；临时原始 Trace、摘要覆盖、参与者身份等不常驻成一排同权按钮。

消息区保留发送者、时间、引用、图片/文件与真实发送状态。当前选中消息明确高亮；加载更早内容不能跳走；新消息提示不抢正在查看历史的滚动位置。失败保留旧数据及采样时间，不能把读取失败渲染为空列表。

侧栏默认用简短阶段列表呈现：触发/未触发 → 实际阅读 → 本轮处理 → 资料或工作 → 提交 → 发送。原始 ID、完整载荷和调用账展开查看。一个阶段允许未开始、进行中、完成、失败、未知；不得把所有等待映射为“思考中”。

### 4.3 页面逐项合同

| 页面/组件 | 必须回答的问题 | 主要动作 | 技术入口 |
|---|---|---|---|
| OverviewView | 当前是否连接、有哪些明确待处理事项 | 进入具体群/工作/配置 | overview/status/capability 只读接口 |
| ScenesView + GroupsView 合并路径 | 哪些群已加入/配置、我在看哪个群 | 选群、配置新群 | `/api/cockpit/scenes` |
| SceneInspector | 这条原话实际怎么被处理 | 查看依据或关联工作 | 现有 event/relations/Trace |
| SceneSettingsForm | 本群将发生什么变化 | 保存本群全部改动 | 原 settings GET/PUT + baseline |
| JobsView | 做到了哪里、还缺什么、是否已经送达 | 查看资料；符合状态时修订/取消/继续 | 原 job/control/asset 接口 |
| TasksLoopsView | 谁提出、何时触发、在等谁 | 更新/取消/明确处置等待 | 原 task/loop 操作 |
| MemoryView | 当前采用哪条认识、依据与旧版本是什么 | 查看原话、沿现有合同修订/撤销 | 原 memory/history/index 接口 |
| SkillsView | 方法适用什么、由什么结果支持 | 查看版本/来源；人工内容仍由人工维护 | 原 skill/candidate 记录 |
| MediaView | 素材来自哪里、可以在哪使用 | 查看/登记/管理现有素材 | 原媒体权限与原始来源 |
| CapabilitiesView | 开关、部署、请求者资格、最近实际记录是否一致 | 跳到唯一缺项配置位置 | 原 capability_status |
| PluginsView | 全局参数、保存状态、运行加载哪里出错 | 原配置保存、明确启停 | PluginHost 的原应用机制 |
| ModelsView | 路由、单次限制、usage、可选检索绑定是什么 | 保存；显式发起实际能力检查 | 原 provider 与模型 API |
| AgentSettingsView | 人格、参与和睡眠各自如何影响行为 | 原字段保存 | 不自动改人工资料 |
| SettingsView/LoginView | 连接、发送方式、认证是否可用 | 登录、保存具体配置 | 原认证、CSRF/请求防护 |
| NotFoundView | 链接失效还是对象不存在 | 返回原群或所属目录 | 不重定向到无关设置、不触发写入 |
| ActivityView/TraceDetails | 哪次调用失败、费用归哪里 | 查看原记录与关联对象 | 原 model_calls/Trace |

卡片渲染、URL 状态、空态、错误态、加载态与请求取消共同收敛到既有组件/composable，不为每页复制状态逻辑。首次进入不进行真实工具、模型、账号或发送操作。

### 4.4 按钮、保存与状态规则

1. 每个工作区域只有一个主要提交动作；使用“保存本群设置”“取消这项工作”等具体词，不使用无对象的“应用/执行”。
2. 刷新只读；编辑只改草稿；保存只执行其明确合同；授权、启用、启动和实际发送互不暗含。
3. 统一未保存离开提示、保存中禁重复提交、成功回执与错误定位。不同页面改同一配置仍受原 baseline/credential_revision 校验。
4. 展示四种事实：草稿、已保存、当前运行、最近实际结果。能力开关标签不得写成“已验证可用”。
5. 群级继承与覆盖能看清来源；“恢复继承”只清本群覆盖，不能改全局。
6. 高级参数可折叠但仍可操作；取消/修订与“未知结果”的人工处置说明必须在动作旁，不靠长篇警告遮住按钮。
7. 键盘焦点、抽屉关闭返回、读屏标签、窄屏触达和长 ID 换行纳入人工页面检查。颜色不作为唯一状态线索。

## 5. 群聊、查证与记忆的目标行为

### 5.1 注意力与自然参与

保留直接 @/回复/私聊的读取优先级，名称与关键词只是机会。普通群消息按既有合并窗口和周期观察处理；不为改“更像人”恢复随机决定是否看见原话，也不把所有消息当作委托。

同一轮从已有事实明确：当前来源、实际回应对象、直接引用、自己近期说法、待处理要求和当前工作。不新增持久社会推断字段。模型在同一循环中判断是否有值得补充的信息、观点、关心或玩笑；没有增量时正常沉默，不回“我在听”证明在线。

连续性使用原 focus、observing_until、Mailbox 和新输入：真正的后续问题可跟进，旁观者的新消息可读取；过期弱机会不拖成义务。用户要求停止或纠正误接时，当前判断立即调整，必要时提交 release_focus；不因一句玩笑永久建立群规则。

不使用假延迟模拟思考，不以固定多轮规划增加响应时间。直接问题、短资料查询和长工作分别看从读取到真实回应的耗时；普通观察可以合并，不能为省钱饿死明确请求。

### 5.2 同一循环选择行动

| 信息状况 | 首选路径 | 结束条件 |
|---|---|---|
| 当前原话足够、社交表达或一般解释 | 直接回应/沉默 | 没有新内容即结束 |
| 指向旧聊天、认识或未完事项 | recall_chat/query_memory/现有工作查询 | 找到正确范围的原话/状态；找不到明确说范围 |
| 最新、精确或指定来源的外部事实 | 已开放搜索/读取/专用来源工具 | 读到支持结论的内容，或明确未核实缺口 |
| 数据齐全、需要运算 | calculate/既有计算工具 | 结果与输入、单位、条件一致 |
| 缺少会改变答案的必要条件 | 一个聚焦澄清问题 | 实际答复后沿原身份继续 |
| 多页、多步骤、耗时或需保留进度 | start_work 或专用工作 | 真实完成/部分/失败事件回到原场景 |

这是一组行动语义，不是新增预分类服务。网页、插件结果、摘要和记忆不提升为指令；没有工具资格就准确说明缺口，不编造可执行路径。短查询不强制建工作，已完成工作不为重发结果再执行。

### 5.3 查证的最小流程

1. 保留问题中的对象、时间、版本、单位与所求结果；同名候选不能替换原目标。
2. 优先使用指定来源或适用的专用工具；搜索摘要仅用于找到正文。
3. 在现有展示预算内实际读取所需内容；必要时分页或查看图表/PDF 像素。
4. 区分取得时间与来源所述时间，区分完整覆盖、片段和未取得附件。
5. 回答先给结论及适用条件，再按群聊需要附少量来源。推断与未核实部分明确，不把工作草稿塞进群。
6. 失败保留具体阶段；源端 no_results 不等于所有来源没有；没有取到价格不能给旧价格冒充当前值。

对一般知识解释不强制联网；对任意自由文本也不承诺确定性真假判定。人工检查重点是必要时是否补足资料，以及回答是否超出了实际依据。

### 5.4 普通资料答复的依据合同（拟新增）

**业务缺口：**普通对话虽有工具资料，但单条最终答复缺少独立的依据关联。新增的是现有消息合同中的小型字段，不是新证据数据库或通用审查层。

在 TurnMessage / MessageProposal / 原提交 payload 中设计可选 `answer_basis`，固定 Schema：

| 字段 | 语义与约束 |
|---|---|
| `kind` | `social` / `general` / `observed` / `work_result` / `mixed` / `unverified`；是模型声明的依据类别，不是真假评分 |
| `event_refs` | 实际已读的本群原话引用；宿主解析为真实 event_id，不能把 source 自动填进来 |
| `result_spans` | 复用 ResultSpan 的资料身份、start/end/coordinate_unit，限定实际展示范围 |
| `unresolved` | 与当前答复有关的具体缺口，不存长推理过程 |

`work_result` 使用本条已有 work_ref/delivery_ref 关联的真实工作结果与 revision；宿主保存其来源关系，不要求对话把工作全部材料重读，也不能把结果摘要登记成新的原始证据。`mixed` 保留已有工作关系与直接资料；由解析后的明确字段区分，不按正文猜测。

旧记录缺字段表示“未记录”，不得补成 general 或 observed。新闲聊/照发允许省略；`observed` 必须有有效资料或原话关联，`work_result` 必须有可用工作结果。检查范围、身份、版本和阅读覆盖，不检查自然语言结论真假。普通回复仍按原 source/请求者/权限提交。`event_refs` 只接受已完整读取的原话，部分原文不在本批扩展新证据坐标；`result_spans` 使用非空区间并核对 coordinate_unit 与原观察一致。

字段穿过 Ledger、Gate、提交事件、Action 与面板的关联读取，OneBot 只接收原 segments；不把内部依据 JSON 发到群。记录本身不能替代正文中的必要不确定性。若最终容量不足，不扩大已读范围或伪造依据；缩小结论、续读或明确未完成。

模型可见合同要求资料性回答填写依据，宿主只验证可确定的结构与范围；选择 general 或省略字段不能证明没有幻觉。因此 P04 的数据贯通不单独完成 U04，必须同时交付 P06 的行动合同并观察 A09—A11 的真实回答。字段只放短引用和必要缺口，不复制全文；列表与文本沿本轮展示/终结容量限制，不新增免费总结调用。

### 5.5 回忆与纠正

已确认称呼/偏好/群规则按当前主体自动投影；其他认识及旧事按需读取。现有字面预取只作有限辅助，不扩成每条消息自动向量检索。记忆查询中的场景、主体、日期、有效期和状态在候选选择前生效，呈现前再核原表修订。

摘要负责定位，原话负责精确引述。用户记错时间时可在其问题允许范围内明确扩大查询，不隐式跨群或改成无范围扫描。索引缺失/未完成、查无结果、服务失败是三种结果，不能互相冒充。

纠正顺序：当轮调整 → 确认是否有需要改的持久认识 → 原 refute/supersede 与提交回执 → 后续读取当前有效版本。人类对本人称呼的明确要求可直接用于偏好修订；对外界客观事实的纠正保留 reported 身份，仍按需要核实。

短对话中的问题、解决资料与纠正由原事件及观察保留，下一次可按需回读；不把“还没发布技能”误报成“完全没记住”。工作中有可复用方法时才提交现有 SkillCandidate。若实践证明短对话也必须自动发布方法，另作受限来源合同扩展，说明 episode 的来源、预算、版本与候选寿命；本批不伪造工作承接它，也不增加隐式免费维护调用。

### 5.6 人格、图片与情境表达

人工人格、原始资料和样例不自动重写。当前纠正和实际请求优先于表演；不声称未经证实的现实活动。样例按已有标签/语境少量选择，只提供表达形式，不证明群友事实。

运营表情按目录标签、短描述与近期使用选择；合适时可以一张表情结束，不强制配长解释。需要判断图中事实时必须取得像素。指定照发、准确数值、文件行动和严肃技术错误不随机塞图。素材导入、图片/音频/视频处理仍保留真实来源与范围。

### 5.7 三条必须完成的使用流程

以下是设计情境，不是实测记录，也不自动写入人工表达样例或发到群里。

**流程一：群友问一个需要外部资料的小问题。**

1. 适配器保存原话，Actor 给出本次来源、被问对象与既有相关上下文；旁人的话不被合并成同一个请求者。
2. 当前资料不足时，在同一循环调用已开放搜索/专用工具，读取实际正文；同名或版本不清且会改变结论时先澄清，不先建立无目标长工作。
3. 最终答复保留必要条件与缺口，answer_basis 关联实际已读资料，source 仍指提问原话；Ledger/Gate 按原事务提交。
4. ActionQueue 保存真实回执。面板从该消息可查看“读了什么→答复引用什么→是否送达”，不能用一次工具 ok 把整条流程标成功。
5. 查不到、源失败、展示容量不足分别结束或在剩余预算内继续；不能编数值，也不另买无预算收尾调用。

**流程二：当场纠正，隔几天又提到同一个问题。**

1. 当轮先停止错误称呼或修正解释。确定需要持久修订时，读取现有认识并提交 refute/supersede；临时玩笑不扩大为永久偏好。
2. 回执能确认修订是否提交；没有持久修改时只说明当前已调整，不宣称已删历史或已学会技能。
3. 后续关于同一人物/时间/问题的表达，优先使用当前有效偏好，其他旧事按需检索摘要/认识并回读原话及已有资料。
4. 上次技术办法只有实际步骤、条件和结果可复用时才采用；版本、时效或关键条件变化时重新读取来源，不把“以前这样做过”当本次验证成功。
5. 符合现有工作候选合同的经验才能发布为方法；普通短对话仍能回忆原过程，不为发布方法伪造 job。

**流程三：运营者从一条没回复的群消息排查到可解释的结果。**

1. 在唯一群目录进入对话，选中原消息；侧栏展示原身份和已有阶段，而不是跳入另一套设置导航。
2. 未取得机会看注意力/额度/睡眠事实；已经读取则看来源处理；工具/模型失败看原错误；已提交则看发布与发送。没有关联记录时显示未记录，不补写模型理由。
3. 点开对应工作/资料/设置再返回，保留 scene、event 定位、分页与筛选；读取失败保留上次数据及时间。
4. 需要修改本群参数时在唯一设置入口保存并显示保存/运行差异；重启、授予、模型检查和真实发送仍是独立操作，不由排查按钮隐式执行。

## 6. 上下文、工具接口与预算设计

### 6.1 固定结构，动态事实后置

保持现有三类输入职责：稳定的人格/规则；按时序的原话或工作轨迹；本次状态、预算、引用目录和其他易变事实。优先保全当前与关联原话、必要材料，再考虑可选历史/样例/媒体目录。布局稳定不是放弃相关性，也不是把 200k 上下文当每轮必须填满的目标。

conversation 继续按本轮重建消息窗口；work 沿原生交换持续追加、恢复与压缩。不要为了统一接口，把两种生命周期改成一套永远增长的会话。

### 6.2 稳定工具 Schema 的实施细则

1. 核心对话提案工具在相同角色、资格和版本下保持目录与字段顺序；无当前工作时，引用目录为空，不通过删除 cancel/revise 表达业务状态。
2. respond 的 intent、关系互斥、文件独占与参数结构固定；具体 M/U/J/T/S/文件 ID 在原事实/回执内提供，不写枚举。
3. 同步核对 RetrievalToolkit 的 pending/range 工具与插件发现变化；不只修 proposals 而遗留另一半目录抖动。
4. 高频已获准读取入口保持可见，低频插件仍可渐进发现。不一次性塞入全部插件；发现新能力或权限撤销时接受必要的目录变化。
5. 模型可见目录与宿主可执行性不能混为一张名单。无合法目标、当前无额度或已撤权时，原执行边界仍拒绝；固定定义不授予权限。
6. 终结阶段优先保留目录，用已有定向 tool_choice 收尾；先核对实际协议支持。若无法确保不执行额外调用，保留正确性优先的终结限制并记录缓存代价，不自动切协议。
7. 压缩后重新读取账户，按最终 messages + tools 估算容量并准入；不要按压缩前的工具表核算。
8. 不引入内容指纹或缓存代理。现有 Trace 记录目录和调用事实；需要完整定义对照时采用获准人工阅读，不永久保存群聊完整请求/base64。

### 6.3 窗口与压缩

保留锚定窗口与已装配摘要覆盖条件，优先修已确认的 Schema 变化；不先重新放大窗口或修改真实参数。消息数上限、token 预算、全局 rowid 步长和摘要覆盖共同影响装配，不能拿一个群的经验推广所有群。

所有裁剪后重建实际读取资格；唯一载体被裁掉的引用不再算已读。图片既受张数/字节限制也受总请求容量约束，未装像素保留定位说明。

工作压缩只有一个所有者：先外置旧大工具正文，再压缩旧完整交换，保留可恢复的原生配对、结果定位、未决项和必要近期交换。压缩不授予新证据、不重置预算。原始资料不因摘要形成而删除。

### 6.4 预算、协议与故障

ModelGateway 保留原生 assistant continuation、工具 ID、供应商扩展和真实 usage。协议在入口解析一次，不猜字段、不自动换模型、参数或协议。调用失败、输出截断、工具参数错误、业务无结果、提交冲突和发送失败分别落在所属边界。

模型/工具调用、压缩、既有敏感动作审查、插件子调用、方法维护都走原账户。共享预算的并发调用先原子预留，结算与 call_id 关联；失败尝试和未知 usage 不算免费。缓存 token 与推理 token 不重复累加，缓存命中与网关费用单独展示。

预算不足时保存已取得资料与具体未完成项，不额外调用模型“写一句结束语”。授权撤销、工作修订和 deadline 要在真正请求/执行前再次核对。取消客户端等待不证明上游停止计费。

## 7. 全模块实施合同

各条的“核对”指阅读、编译/构建或获准正常人工操作，不授权新增测试。既有模块没有明确缺口时保留其接口，不为凑重构范围改名、拆包或建表。

### M01 输入适配与事件：adapters / events

- 保留 OneBot 身份、原始段、真实 @/reply、时间、附件、交互归属与不可变事件。
- 面板阶段关联从已有 event_id、episode_id、action_id 等明确身份查询；不按文本相似猜关联。
- 扩展答复依据时只增加既有事件 payload 的明确可选结构；原话永不改写。
- 协议错误在适配入口结束；未知回执保留未知，不把连接成功算成操作成功。
- 核对：原话、引用、多人身份、插件消费与出站消息关系可以回查，旧事件仍可读。

### M02 场景与轮次：scenes / cognition.mailbox

- SceneActor 继续单写 Session；模型、网络和维护等待不占用场景写入区。
- 保留 lease、cutoff、knowledge_revision、逐来源处理和完整读取校验。
- 当前互动投影由实际输入、focus、等待与工作组成；不持久化模型对话题/情绪的猜测。
- 无关新消息不阻断已独立完成的事项；有关确定输入按原 FreshInputConflict 在同一预算内处理。
- 核对：多人同时说话不串请求者，取消/修订后的旧结果不提交，异常后租约释放。

### M03 注意力与睡眠：attention / scene_policy / sleep_policy / wake_confirmation

- 区分搭话、观察、工作回执、确定性服务，保持普通机会合并与原限额。
- 修正面板术语与帮助，不调整真实群参数；调参须另获授权并记录旧/新值。
- 沉默、限额未入场、睡眠、服务失败分别显示，不把“没发消息”都算故障。
- 既有群级叫醒确认需要真实提问及答复回执；不因 UI 操作改成全局醒来。
- 核对：自然话题结束、停止调侃、睡眠期间收消息与原例外服务的边界。

### M04 社会认知：social_core / context / input_window / projection / diana

- 在原循环内清楚呈现对象、当前要求、已知资料和缺口；保留短查询直达与长工作委派。
- 提示合同按来源/行动/表达分组并去重，不堆叠新的规划模型；不修改人工人格原文。
- 新增依据元数据不进入实际群文本；一般解释不被迫搜索。
- 对话不以记录沉默为代价清除尚未处理的明确请求。
- 核对：已读但不说、确需查证、正常接梗和明确照发均可正常结束。

### M05 提案与提交：proposals / cognition.models / runtime.gate

- 固定 Schema，保持 ack/operation/work/delivery/file 的互斥与真实句柄派生。
- 增加 answer_basis 的类型解析、范围校验与持久关联，不把 source 改成资料来源。
- 认识、工作、提醒、等待及表达继续同事务提交；提交后发布失败不倒写成未提交。
- 仅未提交的可纠正参数错误返回 committed=false；失效版本或协议故障不自动修复。
- 核对：当前引用非法、同轮控制与旧结果冲突、文件混入文字等不能被稳定 Schema 放宽。

### M06 模型与账户：gateway / providers / budget / call_store / metrics / rate_limit

- 固定本轮/原工作绑定，统一最终请求估算、逐次预留和真实 usage 结算。
- 验证新固定 Schema 与当前协议的实际表现；仅编译不能证明提供方接受。
- 调用详情展示类别、归属、输入/缓存/输出/推理及未知字段，不推算未配置费用。
- 协议失败单独呈现，不能伪装成潜水；不新增自动重试或备用路由。
- 核对：压缩/子调用计原账，取消后晚到回执不丢账，最后一步不超支。

### M07 读取与发现：tools.retrieval/discovery/observations/results / retrieval_models

- 保留搜索、读取、计算等原语及 ToolResult 的类型；查询条件在入口一次解析。
- `tools.http/pdf_reader/calculator` 等沿所属取得/解析边界保留时间、页码、单位与错误；PDF 文本不代表图表像素已读，计算不隐式取得缺失输入。
- 稳定核心定义；渐进展开只影响确实新增的能力，不因没有结果自动隐藏工具。
- 本地 next_call 与源端 source_next_call 分开，字符页与记录页不混用。
- 空结果、取得失败、展示失败分别传给模型和面板；不能将部分文字授予全文资格。
- 核对：读正确来源、真实正文进入窗口、只引用已读部分、工具失败后不编答案。

### M08 认识与历史：memory.models/store/writes/gate/history/reflection/reflector

- 保留一份认识账本、reported/inferred、scope、主体、有效期、修订和原始证据。

- 历史维护保留批次身份及已实现的有限恢复规则，不在本批推广通用自愈。
- 面板分开摘要覆盖、已采用认识和待核对候选；维护失败定位到阻塞批次。
- 核对：失效认识不再用于当前互动，维护候选冲突不伪称全部采用。

### M09 检索索引：memory.index / retrieval clients

- 词面与语义查询共享场景/主体/类别/时间/有效状态约束；候选与最终呈现分开记录。

- 显示原表有效数量、当前修订覆盖与失败原因，而不是只有一个绿色“已开启”。

## 8. 数据、接口与兼容设计

### 8.1 改动清单及必要性

| 对象 | 拟变更 | 必要性 | 不做 |
|---|---|---|---|
| TurnMessage / MessageProposal / Action 关联 | 可选 answer_basis，固定类型 | 将普通资料答复关联实际依据 | 新建全局知识真值表 |
| 原提交事件 payload | 保存解析后的真实依据身份与范围 | 重启后仍可解释答复 | 保存隐藏推理、完整供应商请求或秘密 |
| QueryService 的消息详情 | 返回实际阶段、资料/结果关联、未知状态 | 单条消息能读懂 | 新增可编辑阶段账本 |
| 前端 route/query | 唯一群入口与兼容映射 | 不迷路、不丢定位 | 并行两份配置页状态 |
| 技能/认识/工作表 | 本批默认沿用 | 已有身份与版本足够 | 无明确缺口先建新表 |
| ConfigStore | 默认不改配置结构；如新字段必先列清语义与发布方式 | 避免隐式行为变化 | 修改真实参数、隐藏默认额度 |

在编码前核对 Action/事件序列化的具体承载位置：优先使用现有持久 JSON，不为只读展示复制新表。若严格模型或数据库固定列必须变化，同批列出精确列、缺省、读写入口和离线处理；不得只改前端而丢持久依据。

### 8.2 旧数据与新数据

- 新字段缺失的历史消息显示“未记录依据”；不从当轮所有工具结果推断它引用过哪些资料。
- 原事件、任务、job/execution/action ID、revision、预算和送达状态不变。
- 原生 checkpoint 必须继续配对；新字段不写入供应商原生 assistant 消息。
- 原认识/摘要/技能不因页面归并而重新提炼或重嵌；旧来源不重新变成新授权。
- 新枚举/字段若旧版本无法读取，升级前明确最低可读版本；回退不能恢复旧库抹掉新事实。

### 8.3 API 责任与错误

读取使用现有 `/api/cockpit`、overview/capabilities、settings/models/plugins 等边界。返回对象携带 scene/真实身份、sampled_at、分页截点或版本；客户端不得靠显示名串关联。

保存仍提交 baseline 与 values，秘密替换/清除仍需要 credential_revision。API 成功保存与运行应用失败分开，错误保留字段位置与具体阶段。管理操作需要当前认证，下载/资产读取复核归属；不要为前端方便提供直接写状态或任意 SQL 端点。

消息阶段解释只使用原始事件、提交、Trace、工具观察和回执的已保存关系。没有明确关系就显示未知/未记录；禁止时间邻近猜同一互动。完整原始记录仍可展开，但普通用户路径不用理解每个内部 ID。

### 9.1 每批必须交付的内容

- 修改的业务缺口、涉及符号、未改的边界；新增字段/层/状态的必要性。
- 来源 → 输入/资料 → 判断/执行 → 提案 → 结果/回执的完整路径。
- 实际阅读/编译/构建结果，实际人工操作及其 event/call/job/action 身份。
- 失败原文、是否已提交、是否发生外部动作、是否仍未知。
- 所属文档同步、真实配置变化范围、迁移与回退限制、下一批依赖。

### 9.2 停止扩大范围的条件

如果新增抽象只为统一命名、界面美观或框架接入而存在，停止该抽象；若必须绕过原预算、取消、权限或送达边界才能继续，返回接口设计，不靠自动降级完成。一个批次出现业务回归时先停止该能力的新入场并保留已发生事实，不推倒整个项目重新跑。

## 10. 迁移、构建与发布

### 10.1 文档与源码阶段

计划编写阶段只交付文档，后续各实施批次的实际状态见[当前任务](iteration.md)。实现使用 uv；前端修改在 `src/len_bot/web/frontend` 执行 `npm run build` 并人工查看实际改动页。`web/static/dist` 不入 Git，镜像由 Node 阶段自行构建。没有前端改动的文档批次不为了声称核对而运行构建。

不运行仓库测试或新增检查任务，不通过自动截图、断言脚本、回放语料或评审模型绕过限制。静态阅读和正常编译不是运行验收。

### 10.2 升级前

1. 明确要发布的提交、启用能力、目标环境以及是否允许模型/平台调用和真实发送。
2. 正常停止相关服务，按运行手册备份根配置、SQLite 与相关媒体/文件/工作卷及 Gateway 数据。
3. 若只有可选 JSON 增量字段，明确验证新旧读取合同；若需要结构转换，提供单次离线转换说明和原始副本。
4. 核对模型绑定、原 grant、在途调用/执行/行动及其未知结局；不得清库、清失败或 Reset。
5. 构建所需前端/镜像，只在实际使用的后端确认路径和网络；不因发布 UI 改全局运行参数。

### 10.3 运行应用与正常观察

保存参数、进程发布值、部署组件、真实业务结果分别确认。先用获准小范围的正常业务观察，不为覆盖边界制造满额、并发、断网、未知回执或压力。使用者没有授权某条链路时标记未确认，不能用模拟或静态结果顶替。

旧工作沿原绑定/版本/预算恢复；新代码不理解其旧记录时保留待核对原因，不静默换模型或从头执行。已保存配置需要重启的字段明确展示，不自动重启服务。

### 10.4 停用与回退

先停止受影响能力的新入场，确认实际执行/发送结局，保留新产生的事件、费用和回执，再决定代码或离线兼容处理。对新字段不兼容的旧版本不能直接声明可回退；必要时保留当前只读查询能力。

平台已发文件、消息、点赞收藏不因数据库恢复而撤销。新旧记录必须保留，不通过恢复过时全库获得“干净版本”。回退是运营动作，不新增运行时自动切后端或自愈。

## 11. 正常人工验收矩阵

下面是业务观察目标，不是测试脚本或强制制造的场景。已有合适真实记录可只读核对；没有记录且未获相应操作授权则写未确认。特殊竞态在禁止测试的约束下只能说明源码核对范围，不能冒称实测。

| 编号 | 正常业务/操作 | 应观察到什么 | 主要证据 |
|---|---|---|---|
| A01 | 从目录打开群，再打开消息/工作后返回 | 群、筛选、定位保持；只有一个配置入口 | 实际页面与 route |
| A02 | 编辑本群设置及离开草稿 | 草稿/保存/运行差异准确，离开不静默丢失 | 保存回执、根配置对应节 |
| A03 | 正常配置冲突或凭据已有新修订 | 冲突保留草稿，秘密不显示或覆盖新值 | 原配置/credential revision |
| A04 | 查看不可用能力 | 能分辨未配置、停用、未部署、未授权、运行失败 | capability 事实与采样时间 |
| A05 | 直接提问及后续补充 | 当前对象/原要求正确，继续同一互动 | 原话、输入、source_outcomes |
| A06 | 普通公共话题与别人互聊 | 可相关接话或合理沉默，不机械抢答 | 实际输入、表达、回执 |
| A07 | 本人要求停止、纠正误接 | 下一句收住，必要时撤销短期关注 | 当前原话、提交、focus |
| A08 | 指定照发/一般寒暄 | 不扩写、不强制搜索或建工作 | 工具账、实际消息 |
| A09 | 当前外部事实或指定来源 | 正确对象与时点，正文实际读取，回答有依据 | ToolResult、展示范围、answer_basis |
| A10 | 正常查询出现无结果或失败 | 区分本次范围与整体未知，不编造确定答案 | 错误原文、最终答复 |
| A11 | 数字计算与图表问题 | 用输入与单位核对，需要图时实际看到对应像素 | 计算结果、媒体清单 |
| A12 | 旧聊天回忆与人物/日期限制 | 找回正确原话，不跨范围、不冒充全量查过 | 查询条件、候选、实际呈现 |
| A13 | 明确称呼/偏好纠正后再次互动 | 当轮与后来均采用当前有效版本 | 原话、认识修订、后续输入 |
| A14 | 维护/索引在正常运行中完成或失败 | 摘要覆盖、候选采用、索引修订与失败分开 | batch、原表、索引状态 |
| A15 | 有依据的方法候选及后续适用工作 | 来源真实、版本固定、可发现并使用 | 候选、skill version、工作观察 |
| A16 | 工作长材料与压缩 | 原始资料可回读，完整交换保留，压缩计账 | checkpoint、result spans、calls |
| A17 | 正常工作修订/取消/显式恢复 | 原 ID/累计预算保留，旧版本不提交新结果 | job revision、控制回执 |
| A18 | 原预算不足以继续的自然情形 | 不偷偷追加调用，已有结果/缺口保留 | 预占、调用账、停止原因 |
| A19 | 获准离线资料计算/产物读取 | 当前工作归属，真实执行及文件可读 | execution、输入来源、产物 |
| A20 | 获准小文件交付 | 生成、资产、提案、上传和平台 file_id 可贯通 | file_asset、action、上传回执 |
| A21 | 正常传输失败/未知状态记录 | 不声称成功、不自动重传、不抹掉资产 | 原尝试与真实/未知回执 |
| A22 | 提醒、等待或睡眠延期 | 原请求人/目标/时间正确，送达后才期待回应 | task、open_loop、action |
| A23 | 已启用的公共研究/逐群分享 | 公私来源、系统预算、群选择与真实发布分开 | system source、interest、发布记录 |
| A24 | 已获准浏览器/媒体读取 | 正文/快照/帧与转写覆盖准确；未部署不伪称可用 | command、R、媒体范围 |
| A25 | 已获准账号动作 | 固定资源与预期状态，当前 grant 和回执真实 | platform action、审查、账号结果 |
| A26 | 已配置可选 Core 命令 | 不抢普通聊天，echo 与真实回应对应 | plugin event、Core 帧、message_id |
| A27 | 正常停机与再次启动 | 旧未知操作不重放，待处理状态可解释 | 原事件、执行/发送日志 |
| A28 | 正常调用的工具目录及终结 | 当前资格相同下目录稳定，终结不放宽额度 | 实际定义、调用与最终提交 |
| A29 | 多用途调用账查看 | 缓存/推理不重复计数，压缩/子调用归原账 | model_calls、预占/结算 |
| A30 | 前端宽/窄屏与键盘操作 | 主动作、焦点、返回、长内容、错误状态可用 | 人工查看记录，不自动截图 |

### 11.1 核心与可选范围的发布判定

- 核心体验须覆盖 A01/A02/A04—A13/A16/A17/A28—A30；没有依据链和纠正后的实际行为，不能宣布目标全部完成。
- 文件交付目标须取得 A19/A20 的真实链路；平台前置未满足时明确列为剩余工作，不以“可下载”冒充完成。
- A03/A14/A18/A21/A27 中未自然发生的失败/竞态分支可只记录源码核对与未确认，不制造故障补数字。
- A15 与已启用的提醒/主动研究/浏览器/媒体/账号/Core 按实际发布范围确认；未启用能力保持关闭并列明不适用，不阻塞普通群聊发布。
- 所有页面完成正常构建且人工查看；页面标题存在或路由可解析不算体验完成。

### 11.2 观察结果的使用

优先记录具体误接、重复表达、漏处理、错误回忆、无依据事实、纠正失效和未履约实例，再归属到代码路径。统计要注明版本、场景、时间范围和分母；沉默不默认是失败，completed 不默认是答案正确。不得用模型自评分、发言率、工具次数、记忆数量或缓存率替代人工业务判断。
