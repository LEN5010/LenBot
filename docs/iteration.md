## 本批实现

已有轨迹保存了多个阶段计时，但页面主要显示逐调用起止；缓存用量有汇总，缺少命中率适用分母和报告覆盖。本批只沿原只读查询与详情投影这些记录，没有增加运行计时器、执行入口、状态表或外部请求。

| 用户可见结果 | 范围与限制 |
|---|---|
| 从消息查看处理阶段耗时 | 按原来源／提交身份取关联轨迹，逐执行段显示初始读取、装配、提交和发布，展开逐请求准备、响应读取、工具执行和结果装配。缺失保持未记录，父子调用和并行阶段不相加。 |
| 从消息查看发送耗时 | 同场景、明确 action_id 归属的结果回执按事件 ID 去重，分别显示排队、发送处理与原起点到回执；保留失败、模拟和 Shadow 状态，不推算没有记录的计时。 |
| 工作及其他执行轨迹也可读计时 | 原轨迹详情复用同一阶段展示，保留目标版本与步骤身份；没有阶段字段不推断为零，不扩展原鉴权或关联范围。 |
| 调用账与工作预算可看缓存命中及覆盖 | 在当前全部筛选结果中，以有效缓存报告的输入量作分母；原始用量、用途／处置分组、工作身份和分页不变，不修改计费或结算。 |

缓存有效子集要求输入和缓存均为非负数值，且缓存不超过输入；显式零参与，缺失或无法配对的记录单列。命中率为子集缓存 token 总量 / 子集输入 token 总量；调用覆盖率为子集调用数 / 全部匹配调用数；输入量覆盖率为子集输入 token / 全部已知有效输入 token。零分母返回未知，不平均逐调用百分比，不从缺失值反推上游零命中。

计时是原边界的已存观察：模型计时不是首字延迟；工具执行不含全部回执处理；提交／发布包含各自等待和失败前时间。发送队列计时含准备、校验和发送名额等待，发送处理计时含尝试登记与适配器返回。event_to_delivery_ms 的起点可能是同轮最早来源，不是单条消息独占耗时，也不表示平台成功收到。具体字段见[上下文诊断](context.md#7-缓存与诊断边界)。
