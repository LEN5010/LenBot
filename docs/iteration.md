## 本批实现与核对

PluginRunHooks.apply 在入口和每次返回后执行本阶段既有字段核对，字段违规直接记录该 Hook 的 failed 和异常类型，不向后传递。before_model 保留终结工具和原允许工具集合，after_model 保留调用身份／名称／顺序，before_tool 保留工具名，after_tool 保留原回执，before_commit 保留消息数，after_delivery 保留已保存回执。六类公共视图和注册签名不变，接口世代保持 2。

Hook 执行通过已有 PluginHost.start_task 登记插件、场景和任务名，仍依原优先级逐个等待。视图深复制，调用中的 Event 也单独复制；不克隆 Ledger 或建立另一份读取／预算权限。取消记录 cancelled 与异常类型后传播至等待者，不转成普通成功结果；返回 None 不采用副本变更。后续请求装配、参数解析、Gate 和资料实际采用规则不变。

沿生命周期阅读还发现 _release_plugin 只记录 on_unload 错误，配置替换可继续加载新实例。本批先关闭实例调用资格，再取消所属任务；on_unload 失败或取消在 finally 清理该实例注册项后向上传播，停止本次替换，不假定远程已停止或资源已成功关闭。load、enable、disable 及 in_place 配置应用补捕获取消并记录 error／异常类型；加载、启用和原位应用沿原释放路径清理，停用失败不记作成功。全局关闭仍可记录失败并继续清理其他独立插件，不自动重建失败实例。
