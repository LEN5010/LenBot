## 没做完的部分和原因

**S2**

- 全部单元都只有源码核对，没有任何运行实证。
- 未确认的事项：
  - 供应商是否接受跨轮原样回传的续接字段；
  - 重建页的文字不逐字相同，前缀缓存会在哪里中断；
  - 原生交换随场景状态保存后，状态体积有多大。
- 离开的交换组的资料正文不另作摘要。这是按唯一压缩入口约束有意保留的缺口。
- 重建时遇到未列出的异常，不会自动换段，该群会停在同一处，需要人工离线处理（见[运行手册](operations.md#会话段字段的升级与回退)）。

**前端**

- ScenesView 的设置标签没有拆：本来就是 `SceneSettingsForm` 组件。
- ModelsView 的检索设置和额度预占留在页面：它们不属于任何标签。
- 以下读取没有改用 `useGuardedRead`，因为套上去会改变行为或错误文字：
  - 请求前有前置判断的；
  - 错误文字带前缀的；
  - loading 在请求前另有分支的，例如概览 `loadIssue`。
- 原本就没有命中任何元素的样式规则没有删除，留给审阅清单处理。
- 审阅清单里的小字数量与原计划的约 158 条口径不同。清单写明了实际统计方法（带 muted 类的 `<p>` 233 个），没有硬凑数字。
- 审阅清单所列的全部改动都会改变页面观感，按约定没有做，等维护者逐项决定。

## 需人工现场核对

### S2（同版构建、实际群聊）

1. **多轮续接**：
   - 一轮里查资料、读消息范围、查工作之后，下一轮追问，看模型能否用上重建的交换组；
   - trace 里的交换组数与缺口是否与实际一致；
   - 供应商是否接受原样回传的续接字段。
2. **结束分支**：分别触发成功终结、最后一步参数拒绝、新输入冲突、取消、提交成功但发布失败，核对：
   - 段是否保存；
   - `segment_close` 的记录。
3. **重启**：
   - 正常重启后第一轮是否开启 `process_restart` 段；
   - `material_changes` 是否列出人格、核心读取工具、插件指令等无法证明的项；
   - 已存交换组能否在同一模型绑定下重建，且不重新调用工具。
4. **等待恢复**：恢复后能带入上一段末尾的交换组，不在首次保存时冲突。
5. **撤销与失效**：
   - 停用插件或让插件退出本群后，含其资料的组以 `exchange_unrecoverable` 换段；
   - 纠正、撤销认识后，含该认识查询页的组不能重建；
   - 历史摘要来源不可用时，摘要区块撤下；
   - 工作被取消或修订后，旧 query_jobs 目录只留编号。
6. **历史维护与交接**：
   - 历史维护提交后，下一次段保存按 `knowledge_revision` 换段；
   - 交接区块的未完事项清单，以及只有本轮相关人物才登记可结束的 L 编号。
