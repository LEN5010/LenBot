## P0-C 行为变化（源码已接，仅编译与解释器核对）

- **C01 加载与后端入口**：`python_workspace` 与 `workspace` 共用 `WorkspacePluginConfig`，`python_workspace/config.py` 删除（旧 ID 原本会因缺 `call_timeout_seconds` 在加载时抛 `AttributeError`）。`execution_timeout_seconds`／`call_timeout_seconds` 只读取当前选中的后端，纯 gateway 配置不再解引用 `worker`。
- **C02 嵌套凭据**：新增 `plugins/credentials.py`，按 Schema 路径（任意深度、支持 `$ref`）扫描凭据字段；`query_service.plugins()` 返回的 `config` 在所有深度去掉凭据，另给 `config_set`（点路径 → 是否已配置）与 `secret_fields`。保存走 `merge_config`：省略／空串保持原值、非空替换、显式 `null` 清除；占位值不会作为真实密钥回写。
- **C03 取消与对账**：`run_python` 从提交前到轮询结束走同一条取消路径（`asyncio.shield` 保护取消调用再抛 `WorkspaceCancelled`）；`GatewayConflict` 不再重复提交，只轮询同一执行 ID；`GatewayRefused`／`GatewayUnavailable`／`GatewayResultUnknown` 分开处理；`_reconcile_workspace()` 对同一工作区的未终结行（含 `termination_unconfirmed`）给出 `available`／`occupied`／`unknown` 结论而非只记日志。宿主调用携带被准入时的 `job_revision`，跨修订不再续接。
- **C04 产物身份**：当前读取只取最新一次**已确认（终态）**执行的快照，没有记录时明确报错而不是返回空列表；历史产物必须显式带 `execution_id`，不再隐式回退到更早的执行；`artifact_chunks` 流式读取并用增量 UTF-8 解码按字符分页，文件名按 RFC 5987 编码。
- **C05／C08 预算与余额**：新增 `recorded_work_ceiling()` 区分“写出的无维度上限”和“没有可核对的上限记录”，后者按拒绝准入处理而不是当作无限；工作面板返回 `token_limit_state: recorded|unrecorded`。混策略账户不再显示由默认策略推导出的假余额，`policy_name`（曾是 grant id）改为 `grant_reference` + `policy_reference_names` 与 `mixed_scope_required` 状态。
- **C06 输入与收尾**：Gateway 输入文件先全部解码校验到暂存目录再 `os.replace` 就位，被拒绝的输入不留半成品；停止的执行会记录有限输出；权限准备改为核对实际组访问位，不满足时按部署错误结束本次执行而不是记成脚本失败。
- **C07 初次草稿**：`workspace` 的 `worker`／`gateway` 用 `x-lenbot-exclusive` 声明为互斥组，表单渲染成单选并在切换分支时清掉未选分支，初次配置不会再同时提交两个对象。
- **C09 单后端收口**：两条路径互斥、无运行时回落，切换是运营者改根配置的操作；本轮文档与面板按此描述。

## P1-U 面板改进

- 主导航按日常任务分组：概览／日常（群聊与播报、工作与文件、提醒与等待、插件、模型与额度）／资料／系统／排查。复用既有路由与深链接，诊断页面只是换组，没有被删除。
- **U01 首次配置的依赖清单**：概览页新增“当前依赖”卡片，逐项列出模型角色、业务时间、可用群、OneBot 连接与插件参数是否就绪，每行给出实际缺失原因（例如“还有 2 个角色不能用：维护整理（未配置模型）”）并可点击跳到对应填写位置；插件行只统计已声明插件的真实阻断——未填全局参数、加载或运行报错、已保存为启用但运行时没有装载，本群是否开放不在这里计入。全部数据来自已有接口（`/api/overview/status`、`/api/overview/stats`、`/api/plugins/list`），刷新只重读已保存记录，不请求外部服务、不发送、不打开任何能力；插件清单单独读取，它的失败不会让概览其余部分空白。顶部导航的状态文案把“名单实发”改为“按群规则发送”，并在状态卡里补一行业务时间口径。
- 群详情默认两个主入口“消息”和“配置”；注意力、摘要覆盖、参与者、互动偏好、工作与发送记录移到同一页的诊断入口。设置里明确“已保存／全局启用／插件加载成功／本群已加入插件”是四件独立事实。
- **U02 本群设置的依赖与说法**：“填为仅播报群”旁写明它只关掉普通成员闲聊（QQ 白名单仍可提问），不开启任何插件、也不代表已有播报来源，要真的播报还需在下方为本群开启对应插件；每个插件的状态改成一句话说明全局与开关的实际关系（未填全局参数／全局已停用／全局已配置并启用），没有全局参数的插件按钮改成“需先填全局参数”并保持禁用，避免按下去以为已经配好。
- 配置表单按 Schema 渲染，互斥组渲染为单选、隐藏未选分支；不含手写枚举或内部 ID。
- 凭据字段按 Schema 路径显示“已保存，留空保留／尚未配置”，不显示旧值。
- 额度页改为账户／预占中／已结算／准入余量／依据，并说明混策略时的范围要求。**额度策略改成表单**：每项策略是可增删的名与三个数字（单工作累计 token／主体日额度／群日额度），留空即不设该维度上限，并按模型的实际边界在提交前拒绝（单工作上限至少 1，日额度可填 0）；已保存的精确取值在只读区逐字对照，另有只读的 JSON 视图可复制，“按 JSON 编辑”不提供保存入口。形状不是这三个字段的策略不会被表单悄悄丢掉：它们原样保留并在保存时一起写回，这时禁用表单与 JSON 切换以免误改。服务端字段边界用解释器核对：留空与三个数字都被接受，单工作上限 0 被模型拒绝。
- 授权表单改为“谁 → 在哪个场景 → 允许什么 → 有效期 → 使用哪项额度策略”：能力改成多选（`GET /api/settings/capabilities` 提供名称与是否实现，未实现的标注为尚未实现），有效期改用日期时间选择器、保存时换算绝对时间，并在字段下方直接显示换算后的 UTC 时刻——选择器按浏览器本机时区填写，业务时区以另一把尺子解释它，不说清这两者会让同一串数字指向两个时刻；授予 ID 与版本由服务端按内容递增、签发者取当前登录账号；保存前给影响摘要并说明撤销只阻止后续操作。
- **U03 插件按用途查找与分区**：列表加轻量搜索与“全部／需要处理／当前可用／未配置”状态筛选（各带计数）；卡片按“用途”显示分类与一句话说明，并把“配置／全局保存／运行时／开放群／提供能力”分成五行独立事实，不再压成一个绿色开关。有源监测语义的插件才显示来源最近成功时间，Python 计算类不再因为没有源而看起来故障。详情默认开“配置”，其次“开放群”，最后“诊断”；工具名、事件、钩子、优先级、Schema 与来源目录留在诊断区。开放群按群名＋群号显示并跳到同一个本群设置表单，不维护第二份本群开关。`restart_plugin` 在保存前说明“会重新装载，未提交工作可能中断”。
- **U06 保存、生效与错误反馈**：插件参数保存后分别说明“已写入根配置”“已原位应用／已重新装载”“当前保存为停用，没有装载”，并区分保存失败与运行应用失败；“保存插件参数”在需要重装时改成“保存并重新装载该插件”。字段旁的说明与顶部错误摘要使用同一句文案，摘要可点回字段；提交前先做必填与 JSON 结构检查，服务端拒绝时按响应路径把错误落到对应字段并保留草稿；返回条数在授权表单里显示为“第 N 条授予”而不是 JSON 下标。状态一律带文字而不只靠颜色。对话框关闭后焦点回到触发按钮。Reset 移入“账户 → 高级危险区”，逐条列出真实删除／保留／不处理的范围。
- **U04 常用控件**：表单按 Schema 逐个渲染——布尔、枚举、数字、文本、简单列表（可增删与上下移动的行，删空即提交空列表）、有声明属性的嵌套对象（workspace 的 `worker`／`gateway` 作为子分区编辑，切换分支时按 Schema 默认值初始化）以及其余对象／列表的高级 JSON；字段标题、说明和上下限都取自 Schema，前端不另写一份。字段标题由模型侧补齐（`WorkspaceConfig`、`WorkerGatewayConfig`、`BrowserConfig` 及各插件的顶层字段），前端按标题渲染而不另写一份中文名；`$ref` 字段（`browser_agent.browser`、`workspace.worker`／`gateway`）按引用链解析成嵌套对象，不再落到高级 JSON。声明为必填的互斥组（`x-lenbot-exclusive` 的 `required`）在未选择时提交前即拒绝并定位到组内首字段；所选分支按自身默认值初始化，未选分支不写入。枚举在界面上显示中文名、保存原枚举值：三个入口是 `asoul_dynamics` 的排序字段与 `bilibili_live` 的播报模型角色，中文名用 `x-lenbot-enum-labels` 写在声明该字段的模型上，值与标签的覆盖已逐个核对（无遗漏、无多余），没有声明中文名的枚举回落显示原值。取值封闭的列表（`link_parser.enabled_platforms`）用 `x-lenbot-list-choices` 声明成勾选项，未声明的列表仍是可增删的行。授权表单的场景、插件、额度策略与本群已记录成员已改成下拉选择（复用 `/api/cockpit/scenes`、`/api/plugins/list`、`/api/settings/resources` 与群详情的参与者），仍可手填账号；额度策略的中文名与实现状态同样来自已有的服务端词表，前端没有第二份。
