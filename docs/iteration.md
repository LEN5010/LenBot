## 本批实现与核对

register_handler 增加可选 refresh_deferred 回调，记录中投影其存在标志；限定仅接 PLUGIN_EVENT／plugin_event 的 handler。最初考虑插件级描述符，但源码确认仅 live_started 行动需要重核，最终放在原 handler 注册而非 PluginSpec，避免其他工具或 handler 的延期行动误用。默认 None，不改原必填参数，API 世代仍为 2。

宿主按真实延期行动的 PluginOrigin 找到回调，复核启用／场景／版本，按原 Actor 已观察截点读取同场景原事件并核对插件生产者归属。回调只收到 Event 深副本和旧行动 ID，复用原插件／场景任务所有权执行；返回 None 表示旧业务来源失效，返回非空替代 ID 后宿主等待原队列并确认本插件事件已保存。没有把完整行动、Actor 或数据库交给插件。

直播回调保留原场次采样、订阅检查、房间及 started_at 比较、live-refresh 身份和 supersedes_action_id，仍用 context.emit_event 发布替代来源。原直播轮询的身份查询改为 context.has_emitted_event：查本场景本插件已保存身份，旧版本同业务身份仍算存在；其他生产者／非插件事件占用该 ID 时明确失败，不当作本插件重复来源。查询与发布仍非原子查重，不新增索引、指纹或内容摘要。插件文件不再直接访问 Runtime、EventStore 或 Actor 队列，业务协议未改。

Runtime 依据 handler 回调声明选择延期重核，不再写死直播插件 ID。成功说明改为“替代业务来源已保存”，不声称新邀请已提交或送达。成功、来源失效、异常或取消均沿原拒绝回执结束旧延期行动；取消继续传播，不能证明远程已停止或替代事件未保存。拒绝回执写入放在重核异常边界之外，记录本身失败直接抛出，不自动写第二次。后续新来源仍通过原 handler／Gate／出站资格和回执流程。

- 源码核对 _release_deferred 的旧闲聊／工作成果分支保持不变，未声明回调的入口仍走原队列；没有全量开放重核功能。当前只有 live_started 注册回调，live_ended 和读取工具未采用。
- 核对 source 读取仍使用原事件查询与当前已观察截点；替代身份检查只证明保存，不授予来源已读或发送资格。has_emitted_event 按真实事件封套核对所有者，不按当前业务载荷模型重解旧版本记录。
- 核对原 ActionQueue._reject 的事实判定及事件保存，未修改发送尝试、延期任务领取、队列状态或原始数据；取消结束的只是这条旧延期行动。
