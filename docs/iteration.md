## 已实现

- 每项工作、提醒绑定明确的人类请求原话；每条消息独立保存来源。创建确认、普通回应和结果履约分别关联，等待回应及发送回执沿该条来源保存。
- 实际读取与明确处理分别记录；只消费 handled 来源，读到但未处理的请求继续留在 pending。相关追加按真实请求人、事项与回复关系检查，空处理不反复取得预算。
- 工具使用同一参数模型注册与执行，提供用途、中文别名、确定性发现、重名失败和当前权限复核。目录淘汰不否决同批已经开放的合法调用；可处理错误保留独立回执，终结必须独占一次响应。
- 正文、记录与源端分页提供明确坐标及续读参数；当前输入和完整回执优先，旧正文外置、工作压缩与实际范围记录接入原预算。技能正文按需分页，维护可正常跳过并保存原因。
- 动态与二创续页保留原筛选和排序，公开图片及 PDF 接入原场景媒体登记链。媒体准备与实际像素采用分开，面板的来源 HTTP 失败返回明确错误。
- 工作保留目标版本、进度、实际资料范围和具体中断原因；修订或取消期间已经完成的读取及调用记录仍归属原工作。首次完成／部分结果绑定唯一交付行动；独立请求互不连带停止发送，未知回执不自动补发。
- 面板按真实 ID 展示请求、读取、处理、工具观察、版本、创建确认及最终回执；技能跳过与失败分开展示，省略原因和实际阅读范围可查。

现行契约分别见[产品行为](product.md)、[架构](architecture.md)和[运行手册](operations.md)。新业务字段使用已有 JSON，未新增表列或执行数据转换；旧请求锚点及历史阅读范围缺失时保留未知，不改写原身份。
