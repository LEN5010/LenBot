# LenBot

基于 Python、asyncio 和 SQLite 的群聊 Agent。接收原话与图片，决定接话或沉默；短查询直接调用工具，复杂研究、计算和资料整理交给后台工作。认识、提醒、技能和发送结果持续保存，可在管理面板查看与操作。

## 开始

首次使用按[唯一初始化与启动步骤](docs/operations.md#初始化与启动)准备依赖、根配置和同版面板，再分别核对启动、业务连接与首条真实回执。该入口同时说明本地源码路径与 Linux 容器路径，不提供跳过配置的“一条命令运行”。已有部署先走[停机与升级](docs/operations.md#停机备份与结构切换)，不要复制样例覆盖实际配置。

控制面板产物不进 Git。本地按运行手册构建；Linux 镜像由 Dockerfile 的 Node 阶段独立构建，不依赖本机产物。只有 API 可访问不表示面板已构建或前后端同版。

`lenbot.config.json` 是唯一运行配置来源：连接、账号、模型、群和插件都在其中，运行中由面板保存，不用 env、CLI 或数据库覆盖。样例是初始化模板，不参与运行合并。`runtime.bot_qq` 等占位值必须按真实情况填写；配置不合法时启动会指出具体位置并拒绝启动，不会带默认值继续运行。该文件含连接凭据与模型密钥，只留在本机并排除在 Git 之外。面板地址与登录来自该文件的初始化账号；初始化、停机、备份与故障处理见[运行手册](docs/operations.md)。

## 当前能做什么

- 在已启用的群里参与聊天：留言、真实 @ 提及、图片、语音与混排表达，也可以沉默；文字里的 @称呼不等于真实提及。
- 精确命令：日程（今天／明天／本周）、群报告、动态查询、开播订阅与提醒，只在对应插件对本群开放且本群已启用时生效。
- 后台工作：建立工作后分步检索、计算、归纳，产出带来源的结果；工作可查看进度、暂停、继续、修订和取消。
- 工作空间：在受控的离线 Python 环境里处理当前工作已取得的资料并产出文件；文件按工作归属在面板中读取或下载。
- 提醒：分别保存提出者、目标对象、请求原话与触发时间，不把被提醒的人当作请求者。
- 面板：查看原话、认识、工作、调用、回执与额度；保存插件参数与群设置。

## 当前能力边界

以下是当前实际状态，不是目标：

- 样例配置开启 Shadow，群列表和模型供应商为空；插件中仅 `web_search_tool` 启用，其余停用。样例不能直接收发群消息；实际运行状态以根配置及面板为准。
- `workspace`、`browser_agent`、`gscore_adapter` 在样例中都是停用状态，需要运营者按各自 Schema 配置后才可能生效。
- Python 与浏览器**尚不构成已验收的生产隔离**。worker 后端需要宿主容器运行时，Gateway 后端需要单独部署网关进程；源码已接线不等于已完成正式切换，也不是已通过实机验收。
- 社会 Agent 的主动参与、公共兴趣、心跳、睡眠与延期、媒体片段、持久文件、专用 B 站账号动作和可选 Core 桥接已接入源码。新增能力仍需明确配置、授权与实际部署核对；默认未配置/关闭不代表线上已开放，见[当前任务](docs/iteration.md)。
- 系统工作由真实 Scheduler 心跳槽建立，独立付额并保留来源；公共研究与群内分享分别准入。此链路已实现，真实模型、部署及群回执仍待获准环境核对。
- “不编造真实经历”目前只是提示层约束：运营可编辑的人格文本本身仍可能包含这类内容，没有校验。
- 群管理员不是运营者；群消息里的自报身份不提升权限。
