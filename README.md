# LenBot

基于 Python、asyncio 和 SQLite 的 QQ 群聊 Agent，通过 OneBot v11 接入。核心正在重写；以下说明以当前 `len-bot` 启动入口为准，不把旧代码中尚未接入的功能算作已可用。

## 项目状态

核心正在重写，目标是：每个群一个常驻的 Agent 会话、用角色口吻说话的表达器、可以浏览和编辑的文件式记忆、在沙箱里完成长任务的工作 Agent。现有核心已冻结，只修阻断运行的缺陷。开源发布前会补齐安装和使用文档。

## 运行

需要 Python 3.13、uv、Node 22，以及一个 OneBot v11 实现。

```sh
# 首次安装依赖；需要面板时再构建前端（产物不进 Git）
uv sync --locked --no-dev
(cd src/len_bot/web/frontend && npm ci && npm run build)

# 项目根目录，使用已经准备好的 lenbot.config.json
uv run --no-sync len-bot
```

- `len-bot` 直接启动当前多场景聊天核心，不按配置猜测版本，也不回退旧运行时。
- `lenbot.config.json` 是唯一的运行配置：OneBot、模型绑定、场景和数据库路径都在里面，不用环境变量、命令行或数据库覆盖。它含密钥，只留在本机，已排除在 Git 之外。开发工作树已有配置时直接沿用，不用初始化样例覆盖。
- 配置不合法时启动会指出具体字段并拒绝启动。
- `delivery: "onebot"` 为真实发送，`"simulated"` 只保存模拟表达。
- `panel` 可选；未配置时只运行聊天宿主，不启动网页。按 Ctrl+C 正常退出。
- 历史初始化样例和 Linux 部署配方尚未适配当前配置格式，不用于覆盖已转换的开发配置。

## 现在能做什么

- 配置场景的常驻聊天、注意力与合并窗口、会话压缩、角色表达或直出，以及实际文本发送回执。
- 聊天原文查询、等待补充、一次性提醒、角色资料查询；搜索、网页读取和看图须配置相应服务或模型。
- 管理面板显示连接、消息、原生会话、工具注册原因、模型调用与费用，并可保存模型、角色、场景和连接设置。保存配置与当前进程生效分别展示。
- 可选文件式记忆：本地 Markdown、全文检索、修改历史，或显式配置 embedding 后的混合检索；OpenViking 接口保留其原生目录与实际后台状态，不宣称两个后端已完全等价。
- 记忆内容管理、每轮召回与默认关闭的后台抽取。本地自动抽取须单独绑定记忆模型，首次启用不自动回填旧消息；失败范围由运营者明确处理，不自动重试。

工具还受角色允许列表约束，面板的能力页会显示缺失配置。后台工作任务、插件、MCP 和浏览器尚未接入统一运行入口；Pi RPC 和离线容器代码不等于这些功能已经交付。本地定向遗忘可排除明确选中的旧消息；OpenViking 的完整遗忘、实际部署及语义质量验证仍在推进。
